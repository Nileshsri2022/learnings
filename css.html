What is CSS?

Browser default stylesHeadings bade dikhte hain, links neele/underline hote hain — ye HTML se nahi, browser ke andar ki default CSS (user-agent stylesheet) se aata hai. Bina author CSS ke har site ek jaisi dikhegi.
CSS kya control karta haiText ka color/size, layout (grid, multi-column), aur special effects (animation) — matlab HTML element exactly kaisa dikhega.
CSS modules me organized haiRelated functionality ke modules hote hain, jaise Backgrounds and Borders module. Specs technologies ko define karte hain; MDN reference har module ki properties list karta hai.
Rule-based languageEk rule = selector + declaration block { }. Declaration = property: value.
h1 { color: red; font-size: 2.5em; }
Browser CSS kaise apply karta haiHTML milta hai → DOM tree banta hai → CSS rules “buckets” me sort hoti hain (kis element par selector match hua) → DOM par apply → render tree → screen par paint.
User agentUser agent matlab browser — ek program jo computer ke andar insaan ko represent karta hai.
Practice ideaEk paragraph add karo (dusri rule khud apply hogi), h2 ko alag color do (h1 rule copy karke selector + color badlo), nayi properties MDN CSS reference me dekho.

Getting started with CSS

CSS lagane ke 3 tareeke

1. External stylesheet (sabse common, sabse useful)Alag .css file, <head> me <link rel="stylesheet" href="styles.css" />. Ek file kai pages ko style kar sakti hai. Paths images jaise: styles/style.css, ../styles/style.css.
2. Internal stylesheet<head> me <style> element. CMS external file block kare to kaam ka, lekin multi-page site me har page par repeat karna padta hai — inefficient.
3. Inline styles (avoid karo)style attribute ek element par. Maintenance sabse mushkil, presentation HTML se mil jata hai. Legit uses: bahut restrictive CMS, HTML email, JavaScript se dynamic styling.

Selectors ki pehli jhalak

  • Element selector: p { color: green; }
  • Selector list: p, li { color: green; }
  • Class: .special { color: orange; font-weight: bold; } — kai elements par reuse hoti hai
  • Descendant (space): li em { color: rebeccapurple; } — sirf li ke andar wala em
  • Next-sibling (+): h1 + p { font-size: 200%; } — h1 ke turant baad wala p
  • Combine: h1 + p .special { color: yellow; background-color: black; padding: 5px; }
Link states (pseudo-classes)a:link pink, a:visited green, a:hover par underline hata sakte ho. Accessibility warning: underline hatana link ko pehchan-na mushkil bana sakta hai — underline ek important clue hai.
Functions as valueswidth: calc(90% - 30px); aur rotate(0.8turn) jaise transform functions. Function = naam + parentheses ke andar values.
@rulesCSS ke behaviour ke instructions. @media (width >= 30em) { body { background-color: blue; } } — viewport 30em ya zyada ho to blue.
Shorthand propertiespadding: 10px 15px 15px 5px; = top/right/bottom/left (ghadi ki sui ki direction, upar se). 2 values = top/bottom phir left/right. background, font, border, margin bhi shorthand hain.
Comments aur whitespace/* ... */ se comment; code ko temporarily disable karne ke liye bhi. Browser extra spaces ignore karta hai, lekin galtiyan tod deti hain: margin: 0auto; galat hai (0 auto chahiye — do values), padding- left galat hai (property naam me space kabhi nahi).

Pseudo-classes and pseudo-elements

Pseudo-class (: single colon)Element ki ek khaas state — jaise tumne ek class laga di ho. :hover, :first-child. Fayda: markup me extra classes nahi; article p:first-child hamesha pehle paragraph ko pakdega, chahe upar naya paragraph jud jaye (CMS-generated HTML me bahut kaam ka). Akele :first-child = *:first-child.
User-action pseudo-classes:hover (pointer upar), :focus (click ya keyboard se focus). Example: a:link, a:visited { color: rebeccapurple; font-weight: bold; } aur a:hover { color: hotpink; }.
Pseudo-element (:: double colon)Aisa jaise tumne markup me ek NAYA element jod diya ho. Kuch purane pseudo-elements single-colon se bhi chalte hain (backwards compatibility).
  • ::first-line — paragraph ki pehli formatted line; screen width badle to bhi sahi (span se robustly impossible). article p::first-line { font-size: 120%; font-weight: bold; }
  • ::selection — mouse se select kiya hua text
  • ::first-letter — pehla letter, drop caps ke liye
  • Chaining: article p:first-child::first-line — pehle p ki pehli line
Generated content — ::before / ::after + content.box::before { content: "This should show before… "; }. Warning: CSS se text daalna rarely karo — kuch screen readers use padh nahi pate, aur dhundhna/edit karna mushkil. Sahi uses: icon jaisi cheez (content: " ➥") jo read-out nahi chahiye, ya content: "" + display:block + width/height se styled shape banana. content ke bina ::before/::after kuch dikhata hi nahi.

The box model

Do box typesBlock aur inline — box page flow me dusro ke saath kaisa behave karta hai. Har box ka outer display type (dusro ke saath layout) aur inner display type (andar ke elements ka layout) hota hai, display se set hota hai. display: flex = outer block, inner flex. Default layout = normal flow.

width/heightRespect hote hainKoi asar nahi
Margin/padding/borderDusro ko dhakelte hainTop/bottom dusro ko NAHI dhakelte (overlap karte hain); left/right asar karte hain

Examplesh1, pa, span, em
Box model ki layers (andar se bahar)Content box (width/height) → Padding box → Border box → Margin box (sabse bahar, boxes ke beech ki khaali jagah).
Standard box model (browser default)width/height = sirf CONTENT. Padding + border JUD jate hain: width 350 + padding 25×2 + border 5×2 = asal 410px; height 150 + 50 + 10 = 210px. Margin box ke size me ginna nahi jata.
Alternative box model — box-sizing: border-boxwidth = dikhai dene wali poori width (350×150 hi rahega; content chhota ho jata hai). Sab par lagane ka pattern:
html { box-sizing: border-box; }
*, *::before, *::after { box-sizing: inherit; }
MarginBox ke chaaro or adrishya jagah; positive ya negative ho sakta hai (negative margin overlap kara sakta hai). Padding negative NAHI ho sakti.
Margin collapsingDo chhoote hue margins milein to: dono positive → sabse BADA rehta hai; dono negative → sabse chhota (zero se sabse door); positive + negative → subtract. Example: 50px bottom + 30px top = 50px gap (80 nahi); top −10px kar do to 40px gap.
Borderborder, side-wise border-top…, border-width/style/color, aur 12 granular longhands (border-top-width…). Styles: solid, dotted, double…
display: inline-block — beech ka rastaLine break nahi, LEKIN width/height respect hote hain aur padding/margin/border dusro ko dhakelte hain (overlap nahi). Classic use: nav links — <a> inline hai, uski padding ul ke border se overlap karti hai; inline-block lagate hi bada click area + sahi hover background.

Handling conflicts

CSS = Cascading Style Sheets. Ek hi element par do rules alag value dein to 3 cheezein faisla karti hain: cascade, specificity, inheritance.

Cascade (source order)Specificity barabar ho to stylesheet me AAKHRI rule jeet-ta hai.
SpecificityBrowser ka algorithm — kaunsi value lagegi. Type selector sabse kam, phir class (attribute aur pseudo-class bhi class ke barabar), phir ID sabse zyada. Pseudo-element = element ke barabar.
InheritanceKuch properties parent se bachcho ko milti hain (color, font-family body se sab tak). Kuch nahi milti (width, margin, padding, border — border inherit hota to har nested li par border aa jata!). MDN property page ke “Formal definition” me likha hota hai inherited hai ya nahi.

5 universal values (har property inhe leti hai)

ValueMatlab
inheritParent ki value (“inheritance on”)
initialProperty ki initial value (color ke liye black — browser ki blue link default NAHI)
revertBrowser ki default styling
revert-layerPichhli cascade layer ki value
unsetNatural value: property naturally inherited hai to inherit jaisa, warna initial jaisa
Link example (body color green).my-class-1 a { color: inherit; } → green · .my-class-2 a { color: initial; } → black · .my-class-3 a { color: unset; } → green (color inheritable hai). Trick: neeche a { color: hotpink; } jodne se sirf PEHLA link badlega — baakio ke class selectors ki specificity zyada hai.
all shorthandall: unset (etc.) ek saath (lagbhag) saari properties par ek inheritance value lagata hai — styles ko known starting point par wapas lane ka tareeka.

Golden ruleColumn-by-column, sabse upar wale se compare karo. Ek million class selectors bhi ek ID ko hara nahi sakte — har level neeche wale se overwrite nahi hota. *, combinators aur :where() ka specificity par ZERO asar.
IDs vs classesClasses prefer karo. ID hi ekmatra rasta ho (markup edit nahi kar sakte) to use attribute selector me daalo: p[id="header"] — class-level weight milega.
!importantSab kuch overrule karta hai, inline styles ko bhi. MDN: kabhi use mat karo jab tak bilkul zaroori na ho — cascade tod deta hai, bade stylesheet me debugging bahut mushkil. Use sirf ek aur important declaration (same specificity, baad me) ya higher specificity se hara sakte ho. Legit use: CMS jahan core CSS edit nahi ho sakta.
Origin precedence (baad wala pehle ko override)1. user-agent normal → 2. user normal → 3. author normal → 4. author !important → 5. user !important → 6. user-agent !important. Note: !important ke liye order ulta ho jata hai — user important author important ko harata hai (taaki jaise drishti-kamzor user font double kar sake).
Sirf takraane wali properties overwrite hoti hainPoori rule nahi. Isliye pattern: element par generic styles, phir classes se sirf kuch properties badlo (h2 generic + .small sirf font-size + .bright sirf color).

Sizing items in CSS

Intrinsic sizeElement ka natural size, CSS se pehle — image file apni size rakhti hai; khaali <div> ka koi size nahi (poori width, zero height — border collapse ho jata hai). Text dalo to height content se banti hai.
Extrinsic sizeJo size TUM do (width/height). Fixed height par content overflow ho sakta hai — bahut dhyaan se use karo.
Percentages containing block se resolve hote hainChild width % = parent ki width ka %. Gotcha: % margin/padding container ki WIDTH (inline size) se calculate hota hai — isliye margin: 10% chaaro taraf barabar hota hai, top/bottom bhi.
min-height / max-widthmin-height: 100px — kam se kam 100px, content zyada ho to badh jayega (overflow se bachav). Images par max-width: 100% — container chhota ho to shrink, par intrinsic se bada kabhi nahi (pixelation nahi). width: 100% chhoti image ko stretch karke pixelate kar dega. Note: bahut badi image load karke browser me shrink karna slow hai aur user ka data kharch hota hai — sahi size ki image serve karo.
Viewport unitswidth: 20vw; height: 20vh; font-size: 10vh; — window resize karo, sab badalta hai. Full-page banner: height: 100vh.

Overflowing content

Overflow kya haiContent box me fit na ho. Default: content dikhai dete hue bahar girta hai.
CSS overflow chhupati kyun nahi?Chhupana = data loss jo dikhega hi nahi (submit button gayab → form kabhi submit nahi hoga). Dikhai dene wala overflow notice hota hai. Box restrict kiya hai to overflow sambhalna tumhari zimmedari — khaas karke block dimension (text) me: zyada text ya user ka bada font size.

Ek axis scrolling (auto/scroll/hidden) aur dusri visible ho to visible auto ban jata hai — overflow: hidden visible asal me hidden auto behave karega.

Debugging CSS

View Source vs DevToolsView Source = server par rakha HTML. DevTools ka DOM browser ka NORMALIZED version dikhata hai (galat HTML sudhaar kar, jaise </h3> se band h2 → </h2>) aur JavaScript ke changes bhi — matlab jo asal me render ho raha hai.

Cascade layers

Cascade ke 7 stepsHar property in steps se guzarti hai: 1. Relevance (selector match) → 2. Importance (normal vs !important) → 3. Origin (author/user/user-agent) → 4. Cascade layers → 5. Specificity → 6. Scoping proximity (@scope) → 7. Order of appearance (aakhri jeet-ta hai).
Origin specificity ko hamesha harata haiSpecificity origins ke BEECH kabhi compare nahi hoti. Author ka :where(a.author) (0-0-0) user-agent ke a:any-link (0-1-1) ko hara dega — author origin upar hai.
8 precedence levels (neeche → upar)user-agent normal → user normal → author normal → animating → author important → user important → user-agent important → transitioning.
Layers kyun bane?Bade codebases me kai teams/libraries/frameworks ek hi author origin me ghus jate hain → specificity wars aur !important ke quick fixes (jo ladai ko bas important par le jate hain). Layer = sub-origin: har team/component ke liye ek layer, precedence layer order se. Layer precedence specificity ko hamesha harati hai; specificity sirf EK layer ke andar matter karti hai.
Layer order = creation orderEk baar ban jaye to RE-ORDER nahi ho sakta. Normal declarations: layers creation order me, phir unlayered normal sabse upar (kam specificity aur pehle likha hone par bhi saare layered normal ko harata hai). Legacy layout methods

Legacy “grids” asal grid nahi hainCSS me asli grid system bahut der se aaya; purane tareeke items ko size karke dhakel-dhakel kar line up karte hain taaki grid JAISA dikhe. Naye projects ke liye CSS grid hi basis hai — legacy samajhna purane projects aur fallback code ke liye zaroori hai.
Floats se 2-columnDono columns 48% + 48% = 96%, 4% gutter; pehla float:left, dusra float:right. Percentages = liquid layout (har width par same proportions).
12-column float grid ka mathWrapper 980px, 20px right padding (border-box) → 960px usable. Har column par margin-left 20px gutter → 12×20 = 240px gutters; 960−240 = 720 → ek column 60px. Span formula: width = (60 × n) + (20 × (n−1)) — span6 = 460px, span12 = 940px. .row { clear: both; } rows ko alag rakhta hai.
Fluid grid: target / context = resultColumn 60/960 = 6.25%; gutter 20/960 = 2.08333333%. calc() math CSS ke andar kar deta hai: width: calc((6.25% * 4) + (2.08333333% * 3));. Offset classes khaali column jagah chhodti hain (margin-left badhao, span GHATAO taaki jagah bane).
CautionsRow ke columns kul width se zyada hon to floats agli line par GIR jate hain aur grid toot jata hai. Sabse badi seema: one-dimensional — columns control hote hain, rows/heights nahi. “Unsemantic” classes (span2, span3) markup ko dikhawat se baandhti hain; alternative: sizing maujooda semantic classes par rakho.
Flexbox grids aur frameworks.row { display:flex } + flex: 1 1 auto columns — par flexbox bhi 1D hai, strict grid nahi banta, % math phir bhi chahiye. Third-party frameworks (Bootstrap, Foundation, Skeleton + Normalize) bas pehle se calculate ki hui classes dete hain — aaj native grid ki wajah se kai developers unse door ho rahe hain.

Interview FAQs

Current-era interviews me baar-baar puche jaane wale sawaal — jawab isi SPA ke sections se.

Specificity kya hai aur calculate kaise hoti hai?

Browser ka algorithm jo tay karta hai do takraati rules me kaunsi value lagegi. Teen columns: ID (hundreds) / CLASS — class, attribute, pseudo-class (tens) / ELEMENT — type, pseudo-element (ones). h1 = 0-0-1, #id = 1-0-0, inline style = 1-0-0-0. Column-by-column compare hota hai, sabse upar wale column se.

Kya ek million classes ek ID ko hara sakti hain?

Nahi. Har level neeche wale level se overwrite nahi hota — pehle ID column compare hoga; 0 IDs wala selector 1 ID wale se wahi haar jayega, classes kitni bhi hon.

* kya select karta hai, aur kab avoid karein?

Document ke saare elements. Reset stylesheets me common (* { margin: 0 }), par global changes karta hai isliye sparingly use karo. Specificity par iska asar zero hai.

:hover aur ::before me farak? (: vs ::)

Single colon = pseudo-class (element ki state, jaise ek class lagi ho). Double colon = pseudo-element (jaise markup me ek naya element jud gaya ho). ::before/::after ko dikhne ke liye content zaroori hai.

:is() / :where() / :not() ka specificity par kya asar hai?

:where() hamesha 0. :is() aur :not() khud ka score nahi rakhte — apne sabse specific argument ka score lete hain. :is() forgiving bhi hai: andar ek invalid selector poori list ko nahi maarta.

Comma list me ek selector invalid ho to kya hota hai?

Poori rule ignore ho jati hai — baaki valid selectors ko bhi style nahi milta. Isiliye naye/prefixed pseudo ke liye :is()/:where() forgiving lists use hoti hain.

+ aur ~ combinators me farak?

+ = turant baad wala sibling (same parent). ~ = baad ke koi bhi siblings, beech me dusre elements aa sakte hain.

Attribute selectors ^= $= *= ~= |= kya karte hain?

^= value se shuru, $= value par khatam, *= value kahin contain, ~= space-separated list me value, |= exactly value ya value-hyphen se shuru (language tags). Dhyaan do: [class="a"] class="a b" ko match NAHI karta, [class~="a"] karta hai.

Cascade kya hai? 7 steps ka order batao.

Jab kai rules ek property ke liye takraayein to faisla: 1 Relevance → 2 Importance → 3 Origin → 4 Cascade layers → 5 Specificity → 6 Scoping proximity → 7 Order of appearance. Origin specificity se upar hai — specificity origins ke beech compare hi nahi hoti.

inherit, initial, unset, revert me farak?

inherit = parent ki value. initial = property ki initial value (color ke liye black). revert = browser default. unset = natural: property inherited hai to inherit jaisa, warna initial jaisa. revert-layer = pichhli layer ki value. all inhe ek saath saari properties par lagata hai.

!important kab haarta hai, aur use karna kyun bura mana jata hai?

Sirf ek aur important declaration se haarta hai — same specificity par baad me likhi ho, ya zyada specificity wali. Ye normal cascade tod deta hai; bade stylesheet me debugging bahut mushkil ho jati hai, isliye MDN kehta hai bilkul zaroori ho tabhi use karo (jaise CMS ka core CSS override karna).

Cascade layers kya hain, kyun bane?

Ek origin ke andar sub-origin priority. Bade codebases me teams/libraries ke beech specificity wars aur !important ladai rokne ke liye. Layer order = creation order, kabhi badal nahi sakta. Normal me: baad wala layer upar, unlayered sabse upar. Important me ulta: pehle wala layer upar, unlayered sabse neeche — kyunki important ka poora precedence hi ulta chalta hai.

Standard vs alternative box model?

Standard (content-box): width = sirf content; padding+border judte hain (350 + 50 + 10 = 410px asal). Alternative (border-box): width = dikhai dene wali poori width (350 hi). Global pattern: html{box-sizing:border-box} *,*::before,*::after{box-sizing:inherit}.

Margin collapsing kya hai?

Chhoote hue vertical margins milein to ek reh jata hai: dono positive → sabse bada; dono negative → sabse chhota; mixed → subtract. Isiliye 50px + 30px = 50px gap, 80 nahi. Sirf vertical direction me hota hai; positioned elements par nahi hota.

Block, inline, inline-block me farak?

Block: nayi line, width/height respect, margins dusro ko dhakelte hain. Inline: same line, width/height aur top/bottom margin ka asar nahi, top/bottom padding overlap karta hai. Inline-block: line break nahi, par width/height respect aur sab kuch dusro ko dhakelta hai — nav links ke liye ideal.

Inline element par width/height kyun nahi lag sakte?

Inline boxes ka size unke content se tay hota hai — specification ke hisaab se width/height unpar apply hi nahi hote. Control chahiye to display: block ya inline-block lagao.

display: flow-root kis liye hai?

Float ko wrapper ke andar rakhne ke liye. Float flow se bahar hota hai, isliye wrapper ka background uske peeche bhagta hai; flow-root wrapper ko float contain karne par majboor karta hai — bina clearfix hacks ke.

em vs rem — kab kaunsa?

em = parent ka font-size (font-size ke liye) — nested me compound hota hai (1.3em har level bada). rem = root (html) ka font-size — hamesha predictable. Font-size ke liye rem prefer karo; component ke andar local scaling chahiye to em.

calc() / min() / max() / clamp() kya karte hain?

calc = units milakar hisaab (20% + 100px). min/max = sabse chhoti/badi value chunte hain. clamp(min, preferred, max) = beech wali value — responsive sizes ke liye: neeche min se kam nahi, upar max se zyada nahi.

Percentages kis ke relative hote hain?

Hamesha kisi aur value ke: width % containing block ki width ka, font-size % parent ke font-size ka. Aur mashhoor gotcha: margin/padding % chaaro sides ke liye container ki WIDTH se calculate hota hai.

Text ko sirf vw me kyun nahi rakhna chahiye?

vw se set text ko user zoom nahi kar sakta — accessibility toot-ti hai. Hal: calc(1.5rem + 4vw) ya clamp() — rem hissa zoomable rehta hai, vw viewport ke saath smooth growth deta hai.

Multiple backgrounds kaise layer hote hain? Shorthand ke rules?

Comma-separated list me AAKHRI wala sabse neeche, pehle wale upar stack. Shorthand me background-color sirf aakhri comma ke baad aa sakta hai; background-size sirf position ke turant baad / ke saath.

border aur outline me farak?

Outline box model ka hissa nahi — koi jagah nahi leta, background ke upar baithta hai, aur chaukor hona zaroori nahi (focus ring element ki shape follow kar sakti hai). Isiliye focus indicator ke liye outline sahi hai.

background-clip: text kya hai, -webkit- kyun?

Background ko text ki shape me clip karta hai. Ye official standard nahi par sab browsers me hai — aur itna zyada use hua ki non-WebKit browsers ko bhi -webkit- prefix implement karna pada. Seekh: non-standard features kabhi bhi badal sakte hain; production me test + fallback rakho.

Normal flow kya hai?

Bina kisi override ke default layout: block elements parent ki inline space bharkar ek ke neeche ek, inline elements same line par wrap hote hue. Achha document pehle normal flow me hi padhne layak hona chahiye.

Floats kaise kaam karte hain, aur layouts ke liye legacy kyun?

Float element ko normal flow se bahar karke parent ke ek side chipka deta hai; baad ka content uske gird wrap hota hai (line boxes chhote hote hain, boxes poori width ke rehte hain). Poore layouts ke liye floats ek workaround the — ab flexbox/grid usi kaam ke liye bane hain. Floats ka sahi use aaj bhi text ke andar image hai.

Float clear kaise karte hain?

Following element par clear: left/right/both. Ya wrapper ko contain karna ho to display: flow-root.

position ki paanch values me farak?

static = default flow. relative = flow me jagah lekar offsets se khisakna. absolute = flow se bahar, nearest positioned ancestor ke relative. fixed = viewport ke relative, scroll par bhi wahi. sticky = threshold tak relative, phir fixed.

Containing block kya hai?

Absolutely positioned element jis ke relative lagta hai: sabse paas wala positioned ancestor; koi na ho to initial containing block (viewport). Isiliye parent par position: relative lagana sabse common pattern hai.

z-index kab kaam NAHI karta?

Non-positioned (static) elements par z-index ka asar nahi hota (flex/grid items iske apvaad hain). Positioned elements non-positioned se upar rehte hain; barabar par source order me baad wala jeet-ta hai.

Flexbox vs Grid — kab kaunsa?

Flexbox one-dimensional hai (ek row YA ek column) — nav, toolbars, content ke hisaab se bantne wali jagah. Grid two-dimensional (rows + columns ek saath) — page layouts, card grids. Aksar dono saath use hote hain: page grid se, component ke andar flex se.

Main axis aur cross axis kya hain?

Main axis = items jis direction me lagte hain (flex-direction se tay); cross axis uske perpendicular. align-items cross par, justify-content main par kaam karta hai. Direction badlo to axes bhi badal jate hain.

flex: 1 ka matlab? grow/shrink/basis?

flex shorthand = flex-grow, flex-shrink, flex-basis. flex: 1 matlab grow=1: khaali jagah ka barabar hissa. grow = kitna badhe, shrink = jagah kam ho to kitna ghate, basis = bantware se pehle ka base size. flex: 1 100px = pehle 100px, phir bachi jagah proportion me.

space-around vs space-between?

Dono items ke beech barabar jagah baant-te hain; space-around kinaro par aadhi jagah bhi deta hai, space-between kinaro par kuch nahi deta (pehla item bilkul start, aakhri bilkul end).

order kya badalta hai — aur kya NAHI badalta?

Sirf visual/layout order. Source order aur isliye keyboard Tab order waisa ka waisa rehta hai — focusable elements par order badalna keyboard users ke liye confusing ho sakta hai.

fr unit kya hai? Explicit vs implicit grid?

fr = available jagah ka fraction (fixed tracks pehle jagah lete hain). Explicit grid = template se banaya hua; implicit = content ke bahar jaane par khud bane tracks, jinhe grid-auto-rows/columns size karte hain.

repeat(auto-fit, minmax(230px, 1fr)) kya karta hai? auto-fit vs auto-fill?

Jitne 230px columns fit hon utne bante hain, bachi jagah 1fr se barabar bant-ti hai — bina media query ke responsive grid. auto-fit khaali tracks ko collapse karke items ko stretch karta hai; auto-fill khaali tracks banaye rakhta hai.

Grid line placement me -1 kya hai? Areas ke rules?

Lines 1 se gin-ni hoti hain (writing mode ke hisaab se); -1 = explicit grid ki aakhri line. grid-template-areas: har cell bhara ho, . khaali cell, areas rectangular hi hon, ek area do jagah nahi ho sakta. Subgrid = nested grid jo parent ke tracks inherit kare.

Responsive web design kya hai? Mobile-first kya hai?

RWD ek approach hai (Marcotte, 2010): fluid grids + fluid images + media queries, taaki layout har device par respond kare. Mobile-first = pehle sabse chhoti screen ke liye simple single-column, phir width badhne par breakpoints par layout jodo. Breakpoint device size par nahi, jahan content tootne lage wahan rakho.

Viewport meta tag kyun mandatory hai?

<meta name="viewport" content="width=device-width"> mobile browser ko device ki asal width batata hai. Bina iske purane mobile browsers viewport 980px maan lete the — page zoomed-out desktop jaisa dikhta tha aur tumhare breakpoints fire hi nahi hote.

Media query kaise likhte hain? and, comma, not?

@media type and (feature) { rules } — type optional (default all). and = sab conditions, comma = OR (koi ek), not = negation. Nayi range syntax: @media (30em <= width <= 50em). Features: width/height, orientation, hover, pointer (none/fine/coarse).

Web-safe fonts vs web fonts? Font stack kyun?

Web-safe = lagbhag har system par maujood (Arial, Georgia…). Web fonts = @font-face se download hone wali files (WOFF2) — har browser me wahi font. Stack isliye: pehla font na mile to agla, aur aakhir me hamesha generic family (sans-serif/serif) taaki browser ka default Times na aa jaye.

@font-face aur font-display: swap?

@font-face font ka naam + src file (format ke saath) define karta hai; CSS me sabse upar rakho. font-display tay karta hai load hote waqt text kaisa dikhe — swap = pehle fallback font dikhao, web font aate hi badal do (text kabhi invisible nahi rehta).

font shorthand ka order aur required hisse?

Order: style, variant, weight, stretch, size, line-height, family. Required sirf size aur family hain; size aur line-height ke beech slash aata hai (3em/1.5).

line-height: 1.6 (unitless) vs 24px me farak?

Unitless ek multiplier hai jo element ke apne font-size par lagta hai aur bachcho ko multiplier ke roop me inherit hota hai. px ek fixed value hai jo waise hi inherit ho jati hai — chhote text par tang, bade par khula pad sakta hai. Isiliye unitless recommended hai.

Link states aur LVFHA order?

Link, Visited, Focus, Hover, Active — CSS isi order me likho (LoVe Fears HAte). Styles ek-dusre par build hote hain; galat order me baad wala rule pehle wale ko galat jagah override kar dega. Focus outline ko bina visible replacement ke kabhi mat hatao — keyboard users gum ho jayenge.

Custom bullets background se kyun, list-style-image se kyun nahi?

list-style-image par position/size ka control lagbhag nahi hai. list-style-type: none + li par background-image (size, position, no-repeat ke saath) poora control deta hai — bullet ka size text ke saath rem me scale bhi hota hai.

border-collapse vs border-spacing? table-layout: fixed?

collapse cell borders ko ek me mila deta hai (spacing khatam); separate (default) me borders alag rehte hain aur unke beech border-spacing jitni jagah hoti hai. table-layout: fixed columns ko heading/content ki pehli row se size karta hai — auto (content-based) se zyada predictable aur tez.

DevTools me CSS debug kaise karte hain? Reduced test case kya hai?

Rules view: applied/inherited CSS, crossed-out = invalid/unsupported/overridden, values live edit + toggle. Layout view: box-model diagram. Reduced test case = problem dikhane wala sabse chhota example (faltu HTML/CSS/JS hata kar) — banate-banate wajah aksar khud mil jati hai, aur help/bug report ke liye bhi yahi chahiye.

Browsers unsupported CSS ko kaise handle karte hain? @supports?

Chup-chaap discard — koi error nahi. Isiliye fallback pattern: purani value pehle, nayi baad me. @supports feature query hai: support ho tab hi andar ke styles. Baseline pehle likho jo sab par chale, enhancement @supports ke andar.

OOCSS, BEM, SMACSS/ITCSS kya hain? Sass kya hai?

CSS ko bade projects me organize karne ke methodologies: OOCSS = reusable objects (media object); BEM = Block__Element--Modifier naming; SMACSS/ITCSS = layering systems. Sass ek pre-processor hai — variables aur partials (@use se jodna) deta hai jo plain CSS me compile hote hain; native custom properties ne variables wali zaroorat kam kar di hai.

visibility: hidden vs display: none?

display: none element ko layout se hi hata deta hai — jagah bhi nahi rehti. visibility: hidden content chhupa deta hai par uski jagah layout me bani rehti hai. (Ye jodi MDN Reference ki hai — Learn me deep nahi padhayi gayi.)
