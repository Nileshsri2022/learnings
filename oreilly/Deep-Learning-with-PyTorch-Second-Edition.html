01Part 1 — Core PyTorch

1. Introducing Deep Learning and the PyTorch Library

1.1 Deep learning kya hai

Artificial intelligence ka matlab hai computers se woh kaam karwana jinme human intelligence chahiye hoti hai. Deep learning me ek deep neural network ko examples par train kiya jata hai, taaki woh complex nonlinear functions ko approximate kar sake.

Kitaab ka opening example ek language model hai jise ek billi (cat) par poem likhne ko kaha jata hai. Aise models probabilistic hote hain — ek hi prompt par alag-alag baar alag outputs aa sakte hain.

Ek mashhoor computer scientist ki line quote ki gayi hai: machines soch sakti hain ya nahi, yeh poochhna waise hi hai jaise poochhna ki submarines tair sakti hain ya nahi — sawaal hi galat frame me hai.

Training me loss (jise criterion, objective ya cost function bhi kehte hain) use hota hai — ek number jo tab kam hota hai jab model behtar hota hai, aur training use neeche le jati hai. Achha model woh hai jo aise data par bhi kaam kare jo usne kabhi dekha hi nahi — isey generalisation kehte hain.

1.2 Classical machine learning se deep learning tak ka shift

Classical machine learning me feature engineering chahiye hoti thi — haath se design kiye gaye features, jaise kisi edge ki direction, ya koi digit kisi hole ko enclose karta hai ya nahi (1 ko 0 se alag karne ke liye use hota tha).

Deep learning representations automatically seekhta hai — layers me, badhti hui abstraction ke saath. Pehli layers simple patterns pakdti hain, baad wali complex concepts.

1.3 Is kitaab se kya expect karein

Kitaab ke projects me ek language model, image generation aur medical image segmentation shamil hain. Current research ke liye arXiv ki taraf point kiya gaya hai.

Tensor ek multidimensional array hai — NumPy array jaisa. Yeh poori kitaab ki basic building block hai.

1.4 PyTorch kyun?

PyTorch Pythonic hai, debug karna aasan hai, aur isme tensors, GPU acceleration (CPU se 10–1000× tez — GPU me hazaaron cores hote hain jabki CPU me 4–8), automatic differentiation, C++ runtime, mobile support aur ONNX export milta hai.

Competitive landscape: Theano ka development band ho gaya hai; TensorFlow + Keras ne TensorFlow 2.0 me eager execution add kiya; JAX NumPy jaisa code, GPU support, autodiff aur just-in-time compilation deta hai; PyTorch ne Caffe2 ko absorb kiya aur CNTK aur Chainer ki jagah li; version 2.0 me 'torch.compile' just-in-time compilation aayi.

Hugging Face ka hub pretrained weights deta hai — iski keemat fine control kam milta hai.

1.5 PyTorch deep learning ko kaise support karta hai

PyTorch mostly C++ aur CUDA se bana hai, 'torch' module ke neeche. 'torch.nn' layers aur losses deta hai, 'torch.utils.data' Dataset aur DataLoader deta hai (jo parallel background processes me batches load karta hai), ek training loop batches par iterate karta hai, 'torch.optim' optimisers deta hai, aur 'torch.distributed' multi-GPU training support karta hai.

PyTorch eagerly run karta hai — operations turant execute hote hain — aur use compile ya export bhi kiya ja sakta hai.

1.6 Hardware aur software requirements

Part 1 kisi bhi laptop par chal jata hai. Part 2 ke liye kam se kam 8 GB RAM wala CUDA GPU chahiye (GTX 1070 ya behtar), jo CPU se typically 40–50× tez hota hai. Training me hours ya days lag sakte hain, aur free cloud GPUs (jaise Google Colab) ek option hain.

Supported operating systems: Linux, macOS aur Windows (Windows par Anaconda/Miniconda recommend kiya gaya hai). Installation pip aur ek requirements file se hoti hai, ya pytorch.org ke 'Get Started' page se.

1.7 Jupyter notebooks

Poori kitaab me Jupyter notebooks use hote hain: ek kernel code chalata hai, ek cell Shift-Enter se run hoti hai, cell ki last line print hoti hai, aur state memory me rehti hai. Server ko code checkout ke root se start karna chahiye.

1.8 Exercises aur summary

Exercises: Python 3.10 ya usse naya use karo, installed torch version check karo, CUDA available hai ya nahi check karo, aur Jupyter version aur location check karo.

Summary: deep learning automatically representations seekhta hai; loss training ko guide karta hai; PyTorch Pythonic, eager aur GPU-accelerated hai; aur aage ke chapters me tensor, training aur networks ki detail aayegi.

2. Pretrained Networks

2.1 AlexNet se shuruaat

ImageNet me 14 million se zyada images hain jo WordNet nouns se labelled hain. ILSVRC competition (2010) me 1.2 million training images aur 1,000 classes use hote the, aur scoring top-5 accuracy par hoti thi.

AlexNet ne 2012 me jeeta — top-5 error 15.4%, runner-up ke 26.2% ke against. Modern models lagbhag 3% par hain. Ek Vision Transformer ('vit_b_16') ka top-5 error lagbhag 5% hai jabki AlexNet ka 15.3% hai, aur usme 88.6 million parameters hain.

AlexNet paanch filter stacks se bana hai jo 4,096-element vector banate hain, aur phir 1,000 class probabilities dete hain.

Vision Transformer ki detail: ek Conv2d layer 3 input channels ko 768 me map karta hai, 16×16 kernel aur stride 16 ke saath; encoder blocks me 768 features ke saath LayerNorm aur 768→3072→768 ka MLP GELU activation ke saath hota hai; aur ek head 768→1000 map karta hai.

2.2 AlexNet use karna — preprocessing aur prediction

Preprocessing: image ko 256 par resize karo, centre se 224 par crop karo, tensor me convert karo, aur mean [0.485, 0.456, 0.406] aur standard deviation [0.229, 0.224, 0.225] se normalise karo. 'unsqueeze' se batch dimension add hoti hai, aur model ko evaluation mode me daala jata hai.

2.4 Diffusion models aur inpainting

Diffusion inpainting ek image ko mask ke andar edit karta hai — white matlab editable, black matlab protected — ek text prompt ke saath. Example me ek ghode (horse) ko zebra me badla gaya, pose aur lighting same rakhte hue.

Ek Hugging Face GPT-2 text-generation pipeline ne max_length 10 ke saath ek prompt ko aage badhaya — ek sentence ke saath jo AI models ke baare me tha. Yeh dikhata hai ki pretrained LLM ko bina training ke bhi directly use kiya ja sakta hai.

BLIP ('Salesforce/blip-image-captioning-large') ki encoder/decoder structure hai. Usne horse wali image ko caption diya — ek brown horse jo green grass me graze kar raha hai — aur zebra wali image ko caption diya — ek zebra jo green grass me graze kar raha hai, background me trees ke saath.

Yeh dikhata hai ki ek hi model image ko dekh kar text likh sakta hai — vision aur language ka combination.

3. It Starts with a Tensor

3.1 Data ki duniya

Tensor ek multidimensional array hai. Dimensions zero se number hoti hain, left se right. Ek shape jaise (4, 3, 3) batati hai ki har dimension along size kitna hai.

Tensors intermediate representations hain — data tensor ke roop me aata hai, model tensor par kaam karta hai, aur output bhi tensor hota hai.

3.2 Tensors banana aur index karna

Example points hain (4, 1), (5, 3) aur (2, 1). Inhe 'torch.ones', 'torch.zeros' ya 'torch.tensor' se banaya ja sakta hai — shape 'torch.Size([3, 2])' milti hai.

Indexing: 'points[0, 1]' se 1.0 milta hai aur 'points[0]' se [4, 1] milta hai. Slices jaise 'points[1:]', 'points[1:, :]' aur 'points[1:, 0]' rows aur columns select karte hain, aur 'points[None]' ek leading dimension add karta hai (jaise 'unsqueeze(0)').

Points tensor banana aur index karna reconstructed from notes — kitaab ka verbatim code nahi
points = torch.tensor([[4., 1.], [5., 3.], [2., 1.]])
points.shape        # torch.Size([3, 2])
points[0, 1]        # 1.0
points[0]           # tensor([4., 1.])
points[1:, 0]       # tensor([5., 2.])
points[None]        # shape [1, 3, 2] — leading dim add hui

3.3 Broadcasting

Broadcasting shapes ko right se align karta hai: dimensions ya to equal hone chahiye ya 1. Examples: scalar add karne se har element me 10 add hota hai; 1×3 tensor ko 3×1 tensor se multiply karne se 3×3 result milta hai [[10, 20, 30], [20, 40, 60], [30, 60, 90]]; aur 2×1×3 tensor plus 2×3 tensor se 2×2×3 result milta hai.

Broadcasting hi wajah hai ki chhote tensors bade tensors ke saath bina copy kiye kaam kar lete hain.

3.4 Named tensors

Named tensors dimensions ko label karte hain (jaise 'channels') aur naam se align aur sum kar sakte hain. Lekin yeh feature experimental hai, aur kitaab unnamed tensors use karti hai — isliye is SPA me bhi unnamed tensors hi use hue hain.

3.5 Tensor types — 12 data types

Kul 12 data types hain: float32 (default), float64/double, complex64/128, float16/half, bfloat16 (2019 me aaya — float16 se wider range lekin kam precision), int8, uint8, int16/short, int32/int, int64/long aur bool.

Indexing tensors ko int64 chahiye hota hai; 'torch.tensor([2, 2])' default se int64 banta hai; comparisons se bool tensors bante hain. Types '.to(dtype)', '.double()' ya '.short()' se badle jate hain; types mix karne par bada type promote hota hai.

3.6 Tensor API

Tensor API groups me bati hai: creation, indexing/slicing/joining/mutating, maths, pointwise operations (jaise abs aur cos), reductions (mean, std, norm), comparisons, spectral operations (jaise stft), other operations (cross, trace), BLAS/LAPACK routines, random operations (randn, normal), serialisation (load, save) aur parallelism (set_num_threads).

3.7 Storage, views, offset, stride aur size

Ek tensor ek one-dimensional Storage ka view hota hai, jise size, offset aur stride describe karte hain: element (i, j) par hota hai offset + stride0×i + stride1×j.

Example 'points' tensor ka stride (2, 1) hai; uske second point ka offset 2, size [2] aur stride (1,) hai. View ko modify karne se original modify hota hai; 'clone()' independent copy banata hai.

Transpose data copy nahi karta: transposed tensor ka stride (1, 2) hota hai aur wohi storage share karta hai. 3×4×5 ka ones tensor axes 0 aur 2 par transpose karne se shape (5, 4, 3) aur stride (1, 5, 20) milta hai, pehle (20, 5, 1) ke against. Tensor contiguous hota hai jab rightmost dimension sabse tez badle.

'view' ko contiguous tensor chahiye hota hai; '.contiguous()' storage rearrange karta hai — jaise transposed points stride (3, 1) aur storage [4, 5, 2, 1, 3, 1] ke saath.

Ek million float32 values 4 million bytes plus metadata occupy karti hain — isiliye contiguous storage itni important hai.

LAB 1Tensor stride calculator — element kahan store hai?

Points tensor shape [3, 2], stride (2, 1) hai. Row aur column daalo — lab batayega ki element storage me kis index par hai (offset + stride0×i + stride1×j). Transpose par stride (1, 2) ho jata hai — woh bhi try karo (Chapter 3).

Yahan storage index aayega.

3.8 GPU par tensor operations

GPU support CUDA, AMD ROCm, Apple MPS, TPU (torch_xla ke through) aur Intel XPU ko cover karta hai. Devices 'device=cuda', '.to(device=cuda)', 'cuda:0', '.cuda()' ya '.cpu()' se select hote hain, aur '.to' device aur dtype dono ek saath badal sakta hai.

3.9 NumPy interoperability

'.numpy()' se conversion CPU par zero-copy shared buffer hoti hai (GPU tensors pehle copy hote hain); 'torch.from_numpy' memory doosri direction me share karta hai. NumPy default float64 use karta hai jabki PyTorch default float32.

3.10 Generalised tensors aur serialisation

Generalised tensors me sparse tensors bhi hain — jo sirf non-zero values aur unke indices store karte hain; usual dense/strided layout default hai.

Serialisation 'torch.save'/'torch.load' (pickle plus storage) se hoti hai, aur HDF5 (h5py, 'create_dataset(coords, ...)') se data ko disk par index karke bina poora load kiye use kiya ja sakta hai.

3.11 Exercises aur summary

Exercises: nau numbers ki list ko 3×3 view me reshape karo, ek sub-view ki size/offset/stride examine karo, aur in-place cosine/square-root operations try karo.

Summary: tensor Storage + size + offset + stride ka view hai; broadcasting shapes ko right se align karta hai; views share karte hain, clone copy karta hai; aur GPU/NumPy ke saath kaam karna tensor API ka natural extension hai.

5. The Mechanics of Learning

5.1 Pehle data ko dekho — temperature dataset

Chapter 1609 ki ek kahani se shuru hota hai — ek astronomer ne apne mentor ke planet observations ko fit kiya; ellipse ke liye sirf do numbers chahiye the — eccentricity aur semi-latus rectum. Wahi idea aaj ka machine learning hai: observations se simple model fit karo.

Phir ek chhota temperature dataset aata hai: Fahrenheit readings [35.7, 55.9, 58.2, 81.9, 56.3, 48.9, 33.9, 21.8, 48.4, 60.3, 68.4] inputs hain aur Celsius values [0.5, 14, 15, 28, 11, 8, 3, −4, 6, 13, 21] targets hain. Model hai t_c = w × t_u + b — ek seedhi line.

5.2 Model use karna — loss function

Loss mean squared error hai — predictions aur actual values ke beech squared differences ka average. w = 1 aur b = 0 par loss 1,763.8846 hai aur gradient [4,517.2969, 82.6] hai — weight ka gradient bias ke gradient se lagbhag 50× bada hai. Yahi imbalance aage problems create karta hai.

5.3 Learning rate — bahut bada ya bahut chhota

Learning rate 1e-2 par parameters diverge karte hain: [−44.17, −0.826] se [2,568, 45.16] aur phir 3.2e17 order ke values aur phir infinity tak. Bahut bada step loss ko explode kar deta hai.

Learning rate 1e-4 par 100 epochs me parameters sirf [0.2327, −0.0438] tak pahunchte hain — bahut slow. Sahi learning rate beech me hoti hai.

5.4 Derivatives — numerical vs analytical

Central-difference estimate step 0.1 ke saath numerical gradients explain karne ke liye use hota hai. Analytical derivative exact hota hai — chain rule se.

Figure 5.6 numerical aur analytical derivatives ko contrast karta hai: numerical me function ko do baar evaluate karna padta hai, analytical me ek formula se gradient mil jata hai.

5.5 Autograd se derivatives

Autograd — gradient descent ka ek step reconstructed from notes — kitaab ka verbatim code nahi
w = torch.tensor(1.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
loss = ((w * t_u + b - t_c) ** 2).mean()
loss.backward()      # w.grad, b.grad bhar gaye
with torch.no_grad():
    w -= lr * w.grad
    b -= lr * b.grad
w.grad.zero_(); b.grad.zero_()

8.6 Model improve karna — depth, width, regularisation

Ek wider model (32 phir 16 channels) ke 38,386 parameters hote hain.

L2 regularisation loss me lambda × sum of squared parameters add karta hai (lambda = 0.001); SGD me yeh 'weight_decay = 2 × lambda' ke barabar hai. L1 regularisation (absolute values ka sum) sparsity encourage karta hai.

Batch normalisation (2015 ka paper) har mini-batch ko zero mean aur unit variance par rescale karta hai, kitaab ke code me convolution ke baad aur activation se pehle apply hoti hai, running estimates rakhta hai jo evaluation mode me frozen hote hain, learning rate aur initialisation me madad karta hai, aur regulariser ki tarah kaam karke dropout ko replace kar sakta hai.

Ek residual block me convolution (bias=False), batch normalisation, ReLU aur skip addition hota hai, ReLU ke liye designed initialisation, batch-norm weight 0.5 aur bias 0 ke saath. 100 blocks wala deep residual network slow aur fragile hota hai aur use chhota learning rate chahiye hota hai.

Initialisation: 2010 ka classic variance-preserving initialisation paper aur ReLU ke liye designed initialisation, plus 2019 ka paper initialisation par bina batch normalisation ke; PyTorch ke defaults ideal nahi maane jate (issue 18182).

10. Diffusion Models for Images

10.1 VAE vs GAN vs diffusion

Variational autoencoder (2013 ke aakhir ka paper, arXiv:1312.6114) image ko ek smooth, continuous latent space me encode karta hai aur wapas decode karta hai.

GAN (2014 ka paper) generator ko discriminator ke against khada karta hai; woh sharper images bana sakta hai lekin mode collapse aur unstable training se suffer karta hai, uski koi explicit likelihood nahi hoti aur latent space par kam control milta hai.

Diffusion models zyada stable hote hain kyunki woh ek gradual process seekhte hain. Examples hain DALL-E aur Stable Diffusion XL (prairie par astronaut).

10.2 Idea kahan se aaya

Idea 2015 ke ek paper se aaya hai — 'Deep Unsupervised Learning using Nonequilibrium Thermodynamics': structure ko noise se systematically destroy karo, phir process ko reverse karna seekho.

10.3 Forward diffusion — maths

Forward step hai x_t = sqrt(1 − beta_t) × x_{t−1} + sqrt(beta_t) × epsilon, linear beta schedule ke saath 0.0001 se 0.02 tak, T = 1,000 steps par.

Example image PyTorch logo hai, jise 2D points ke roop me represent kiya gaya hai — image outline se extract kiye gaye, points ke beech minimum distance 5 ke saath.

Closed form hai x_t = sqrt(alpha_bar_t) × x0 + sqrt(1 − alpha_bar_t) × epsilon, jahan alpha_t = 1 − beta_t aur alpha_bar_t alphas ka product hai. Code 'alphas_cumprod' aur ek 'extract()' helper use karta hai jo values ko broadcasting ke liye reshape karta hai.

10.4 Denoiser train karna

Training ('get_loss') ek forward-diffusion step sample karta hai, model se noise predict karwata hai, aur prediction aur true noise ke beech mean-squared error use karta hai. Yeh Adam ke saath 20,000 epochs chalti hai — epoch 1 par loss 1.0119 se start hoti hai.

Imaandaar note — kitaab me hi gap hai: final epoch ka loss reader me display nahi hua tha — notes me sirf starting loss 1.0119 hai. Isliye is SPA me final loss ka koi number invent nahi kiya gaya hai.

10.5 Reverse diffusion se sampling

Reverse sampling ('sample_timestep') 'alphas_cumprod_prev' (1.0 se padded), alphas ke reciprocal square roots aur per-step noise standard deviation use karta hai, 'torch.no_grad' ke andar. Yeh 1,000 random points se start karta hai aur t = 999 se 0 tak iterate karta hai — chaos se PyTorch logo dobara ban jata hai.

14. Improving Training with Metrics and Augmentation

14.1 Metrics — accuracy, precision, recall, F1

Do metaphorical models use hote hain: ek ki recall high hai lekin bahut false positives hain, doosre ki precision high hai lekin bahut false negatives hain. Confusion-matrix terms ko ek billi (false positive), ek chor (true positive), ek chuha (false negative) aur ek pakshi (true negative) se illustrate kiya gaya hai.

Recall = TP/(TP+FN); precision = TP/(TP+FP); F1 score harmonic mean hai, 2×P×R/(P+R).

Precision aur recall ka average lene se (1, 0) aur (0.5, 0.5) dono par 0.5 milta hai — average farak nahi batata. Minimum lene se higher metric me improvement ignore ho jata hai. Product (geometric mean) (0, 0) se (0.5, 0.5) ke region me near-zero rehta hai. Isiliye F1 use hota hai.

14.2 Unbalanced dataset ki problem

Unbalanced training, epoch 1: training loss 0.0025, 99.8% correct, precision 0, recall 0, F1 not a number (division by zero, RuntimeWarning ke saath), benign accuracy 100% (494,735 of 494,743) aur malignant accuracy 0% (0 of 1,215). Validation bhi same pattern dikhata hai — benign 100% (54,971 of 54,971), malignant 0% (0 of 136).

Imbalance lagbhag 400:1 hai, lagbhag 500,000 samples ke saath. Random initialisation hi failure explain karta hai: lagbhag 250,000 negatives predicted negative ko sirf chhota change chahiye, 250,000 negatives predicted positive strongly negative ki taraf pull karte hain, 500 positives predicted negative positive ki taraf pull karte hain, aur 500 positives predicted positive ko lagbhag koi change nahi chahiye. Batch size 32 par 16 me se lagbhag 15 batches me ek bhi positive nahi hota (500/32 ≈ 15).

Balancing alag positive aur negative lists rakhta hai, har epoch unhe shuffle karta hai aur 2:1 pattern me interleave karta hai (+ − − + − −). Balancing on hone par '__len__' 200,000 return karta hai, aur '--balanced' ratio ko 1 set karta hai.

16. Training Models on Multiple GPUs

16.1 Parallelism kyun chahiye

Chapter LLaMA 3.1 se shuru hota hai — 7B, 80B aur 405B parameter versions me. 405B model ko bina quantisation ke inference ke liye lagbhag 800 GB memory chahiye hoti hai. Itne bade models ek GPU par fit hi nahi hote — isiliye parallelism chahiye.

16.2 Sequential vs parallel

Sequential example (10 steps, har ek 0.5 s) 5.04 s leta hai aur sum 45 deta hai, jabki thread pool 0.51 s leta hai. Parallelism wall-clock time ko 10× kam kar deta hai.

16.3 World size aur rank

Parallel training ko world size (processes ki sankhya), rank (0 se world-size − 1 tak) aur process groups se describe kiya jata hai, SPMD (single program, multiple data) pattern ke hisaab se.

16.4 Process groups

Process groups 'init_process_group' se bante hain aur TCP store use karte hain ('MASTER_ADDR' localhost, 'MASTER_PORT' 12355), backends 'gloo' CPU ke liye, 'nccl' GPU ke liye aur 'mpi' ke saath. 'torchrun --nproc-per-node=4' RANK aur WORLD_SIZE environment variables set karta hai, aur 'mp.spawn' 4 processes launch kar sakta hai.

16.5 Broadcast aur reduce

Broadcast ek tensor (example value 123) rank 0 se saare ranks ko bhejta hai; 'all_reduce' ranks ki values ko sum karta hai (example me 0 + 1 + 2 = 3).

16.6 Data parallelism

Data parallelism me forward aur backward passes har GPU par independently chalte hain, phir gradients ko all-reduce karke average kiya jata hai, optimiser step se pehle. Model ko DDP me wrap kiya jata hai, aur MNIST ke saath DistributedSampler use hota hai.

16.7 Model parallelism aur pipeline parallelism

Model parallelism model ko hi split karta hai aur activations ko send/receive se pass karta hai (example Linear 1→2, 2→3, 3→1 hai). Pipeline parallelism (GPipe) micro-batches use karta hai — 'SplitPoint.BEGINNING', pipeline builder, stages aur schedule step ke saath.

Tensor parallelism ek layer ko rows ya columns se split karta hai (2019 ka paper, arXiv:1909.08053). Ek skinny, deep pipeline ko wide, shallow tensor-parallel split se contrast kiya gaya hai.

16.8 4D parallelism

4D parallelism (LLaMA 3 ke liye use hua) data, tensor, pipeline aur context parallelism ko combine karta hai. 2×4 ka DeviceMesh replicate aur model-parallel groups deta hai — row groups [0–3] aur [4–7], column groups [0, 4] aur aise hi — kul chhah process groups.

16.9 Fully sharded data parallelism

FSDP (2021, FAIR) ZeRO-3 par bana hai (arXiv:2101.06840): parameters forward pass ke liye all-gather hote hain aur backward pass me reduce-scatter hote hain. 'fully_shard' Linear layers aur root par apply hota hai, aur yeh 512 GPUs tak scale karta hai.

16.10 Context aur expert parallelism

Context parallelism sequence ko split karta hai kyunki attention ki cost sequence length ke square se badhti hai.

Expert parallelism (mixture of experts) top-1 ya top-2 experts ke saath ek router use karta hai, all-to-all communication aur auxiliary load-balancing loss ke saath.

16.11 TorchTitan

TorchTitan PyTorch ka reference implementation hai LLaMA, DeepSeek-V3 aur Hugging Face models ko train karne ke liye (paper arXiv:2410.06511).

16.12 Exercises aur summary

Summary: ek GPU kaafi nahi hota to parallelism ke chaar dimensions hain — data, tensor, pipeline aur context — aur FSDP parameters ko shard karke memory bachata hai. Sahi combination model ke size aur hardware par depend karta hai.

Interview FAQs — 36 sawaal

Tensors, autograd, activation functions, CNNs, attention, diffusion, class imbalance, metrics, SAM, parallelism aur deployment par interview-relevant sawaal.

Q1 Tensor kya hota hai aur NumPy array se kaise alag hai?

Tensor ek multidimensional array hai — scalar 0-D, vector 1-D, matrix 2-D, aur usse upar ke dimensions tensor kehlate hain. NumPy array se main farak yeh hai ki tensor GPU par chal sakta hai aur autograd ke saath gradients track kar sakta hai. PyTorch me default dtype float32 hota hai jabki NumPy me float64 hota hai, aur '.numpy()' se CPU par zero-copy conversion hoti hai.

Q2 Stride, offset aur size se tensor ka storage kaise samjhein?

Har tensor ek 1-D Storage ka view hota hai. Element (i, j) storage me offset + stride0×i + stride1×j par hota hai. Example: points tensor ka stride (2, 1) hai, second point ka offset 2 hai. Transpose karne par sirf stride badalta hai — data copy nahi hota, isiliye view modify karne se original bhi badal jata hai. Independent copy ke liye 'clone()' use karo.

Q3 Broadcasting ke rules kya hain?

Broadcasting shapes ko right se align karta hai — har dimension ya to equal honi chahiye ya 1 honi chahiye. Example: 1×3 tensor ko 3×1 se multiply karne par 3×3 result milta hai. Scalar add karne par har element me woh value add hoti hai. Yeh bina copy kiye chhote tensors ko bade tensors ke saath kaam karne deta hai.

Q4 PyTorch me 12 data types kaunse hain aur default kaunsa hai?

float32 (default), float64/double, complex64/128, float16/half, bfloat16, int8, uint8, int16/short, int32/int, int64/long aur bool — kul 12. bfloat16 2019 me aaya — float16 se wider range lekin kam precision. Indexing ke liye int64 chahiye hota hai, aur types mix karne par bada type promote hota hai.

Q5 Autograd kaise kaam karta hai — requires_grad, backward aur zero_() kyun zaroori hain?

Jis tensor par 'requires_grad=True' hota hai, PyTorch uske operations ka computation graph banata hai. 'loss.backward()' se gradients '.grad' me bhar jate hain. Gradients accumulate hote hain — har step ke baad 'zero_()' se clear karna padta hai warna purane gradients add hote rahenge. Parameter update 'no_grad' ke andar in-place karna chahiye taaki update khud graph me na aaye.

Q6 Learning rate bahut bada ya bahut chhota ho to kya hota hai?

Bahut bada learning rate (jaise 1e-2 bina normalisation ke) parameters ko diverge kar deta hai — kitaab ke example me values 3.2e17 aur phir infinity tak pahunch gayi. Bahut chhota (1e-4) 100 epochs me sirf [0.2327, −0.0438] tak pahunchta hai — bahut slow. Sahi rate beech me hoti hai, aur input normalisation se gradients comparable ho jate hain.

Q7 Input normalisation training ko kaise madad karta hai?

Temperature example me weight gradient bias gradient se lagbhag 50× bada tha, isliye ek hi learning rate dono ke liye sahi nahi tha. Input ko 0.1 se scale karne par dono gradients comparable ho gaye aur 5,000 epochs me parameters exact answer [5.5556, −17.7778] ke kareeb pahunch gaye. Normalisation loss landscape ko balanced banati hai.

Q8 Activation function kyun chahiye — linear layers kaafi kyun nahi?

Bina activation ke layers sirf linear functions compose karte hain — kitni bhi layers laga lo, result ek hi linear function rehta hai. Activation non-linearity add karta hai, jisse network complex functions approximate kar sakta hai. Achhi activation non-linear, differentiable, useful range me sensitive aur aksar bounded hoti hai. ReLU generally best choice mana jata hai.

Q9 ReLU, sigmoid aur tanh me kya farak hai?

Sigmoid output ko 0–1 me map karta hai, tanh −1–1 me, dono saturate hote hain — bade inputs par gradient lagbhag zero ho jata hai. ReLU negative par 0 aur positive par identity hota hai — saturate nahi hota, isliye deep networks me behtar train hota hai. LeakyReLU negative side par chhota slope (0.01) rakhta hai taaki neurons poori tarah mar na jayein.

Q10 nn.Module callable kaise hota hai — forward vs __call__?

Module ko call karne par '__call__' run hota hai, 'forward' directly nahi. '__call__' hooks support karta hai aur module ke setup/teardown ko handle karta hai. Isiliye custom module me 'forward' define karte hain lekin use call karte waqt module ko hi call karte hain — jaise model(x).

Q11 Overfitting kya hai aur use kaise pehchanein?

Jab training accuracy badhti hai lekin validation accuracy ruk jaye ya girne lage, to model overfit kar raha hai — woh data rat raha hai, pattern nahi seekh raha. Kitaab ke sequential model me validation outputs [−1.9930, 20.8729] true [−4, 21] se door the kyunki network noisy points ko chase kar raha tha. Train/validation split aur validation loss hi iska detector hai.

Q12 CIFAR-10 kya hai aur use kaise load karte hain?

CIFAR-10 me 60,000 colour images hain 32×32 ki — 50,000 training, 10,000 validation/testing. Classes: airplane, automobile, bird, cat, deer, dog, frog, horse, ship, truck. Dataset class ko '__len__' aur '__getitem__' chahiye hote hain. 'ToTensor' image ko [3, 32, 32] float32 tensor banata hai, aur normalisation mean [0.4914, 0.4822, 0.4465] aur std [0.2470, 0.2435, 0.2616] se hoti hai.

Q13 Softmax kya karta hai aur cross-entropy loss kyun use hoti hai?

Softmax logits ko probabilities me badalta hai jo sum karke 1 hoti hain — jaise [1, 2, 3] banta hai [0.09, 0.2447, 0.6652]. Cross-entropy LogSoftmax plus NLL hai — yeh true class ki probability ko maximize karta hai. MSE classification me poor choice hai kyunki woh saturate hota hai aur galat confidence par kam saza deta hai.

Q14 Fully connected networks images ke liye kyun bura choice hain?

1024×1024 RGB image par fully connected layer ko 3 billion se zyada parameters chahiye hote (lagbhag 12 GB). Aur unme translation invariance nahi hoti — kuch pixels shift hui bird ek naya pattern lagti hai. Convolutions weights share karke dono problems solve karte hain.

Q15 Convolution kaise kaam karta hai — kernel, padding, stride?

Convolution ek chhota kernel image par slide karta hai aur har position par weighted sum nikalta hai. 3×3 kernel ke liye output element nau products ka sum hota hai. Bina padding ke 32×32 input 30×30 ban jata hai; padding 1 se size preserve rehta hai. PyTorch ka convolution technically cross-correlation hai — kernel flip nahi hota.

Q16 Receptive field kya hota hai?

Receptive field woh input region hai jo ek output unit ko affect karta hai. 3×3 convolution, 2×2 pool aur phir 3×3 convolution ka receptive field 7×7 hota hai. Gehri layers ka receptive field bada hota hai — isiliye network pehle edges phir shapes phir objects dekh pata hai.

Q17 Max pooling kyun use hota hai?

MaxPool2d(2) har spatial dimension ko aadha kar deta hai — [1, 3, 32, 32] banta hai [1, 3, 16, 16]. Isse computation kam hota hai, receptive field badhta hai aur thodi translation invariance milti hai. Alternatives: average pooling aur strided convolutions.

Q18 Dropout kya hai aur evaluation mode kyun zaroori hai?

Dropout har iteration me activations ka ek random fraction zero kar deta hai, jisse network kisi ek neuron par depend nahi karta — yeh regularisation hai. 'Dropout2d' poore channels drop karta hai. Evaluation mode me wapas switch karna bhoolna silent failure hai — model test time par bhi randomly units drop karta rahega.

Q19 Batch normalisation kya karta hai?

BatchNorm har mini-batch ko zero mean aur unit variance par rescale karta hai. Yeh learning rate aur initialisation ke prati sensitivity kam karta hai aur regulariser ki tarah kaam karke dropout ko replace kar sakta hai. Training me running estimates maintain hote hain jo evaluation mode me frozen hote hain.

Q20 Residual connections (skip connections) kyun madad karte hain?

Residual block output me apna input add kar deta hai — block ko sirf residual (farak) seekhna padta hai. Isse gradients gehri networks me bhi flow karte hain (vanishing gradient kam hota hai) aur loss landscape smooth hota hai. 100 blocks wala network phir bhi slow aur fragile hota hai aur use chhota learning rate chahiye.

Q21 Attention mechanism kaise kaam karta hai — Q, K, V kya hain?

Query ko keys se dot product se compare kiya jata hai, scores ko softmax se weights me badla jata hai, aur values ko un weights se combine kiya jata hai. Causal attention future positions ko mask karta hai (lower-triangular mask, −inf) taaki model aage na dekh sake. Scaled attention key dimension ke square root se divide karta hai taaki scores bahut bade na hon.

Q22 Transformer me LayerNorm aur BatchNorm me kya farak hai?

BatchNorm batch dimension par normalise karta hai — har feature ke liye batch ke samples ka mean/variance. LayerNorm ek hi sample ke andar, uske features par normalise karta hai — isliye woh sequence length aur batch size se independent hota hai. Transformers me LayerNorm use hota hai kyunki sequences ki length vary karti hai.

Q23 Self-supervised learning kya hai?

Self-supervised learning me targets data se hi derive hote hain — manual labels nahi chahiye. Language model me agla character hi target hota hai: input [0, 1, 4] ka target 1 hai. Isiliye bade text corpora par bina labelling ke train kiya ja sakta hai.

Q24 Diffusion models VAE aur GAN se kaise alag hain?

VAE image ko smooth latent space me encode-decode karta hai. GAN generator ko discriminator ke against train karta hai — sharp images lekin mode collapse aur unstable training. Diffusion models noise ko gradually add karna seekhne ki jagah noise hatana seekhte hain — 1,000 chhote steps me, isliye training stable hoti hai aur quality high milti hai.

Q25 Forward diffusion ka formula kya hai?

x_t = sqrt(1 − beta_t) × x_{t−1} + sqrt(beta_t) × epsilon, linear beta schedule 0.0001 se 0.02 tak, T = 1,000 steps. Closed form: x_t = sqrt(alpha_bar_t) × x0 + sqrt(1 − alpha_bar_t) × epsilon, jahan alpha_t = 1 − beta_t aur alpha_bar_t alphas ka product hai.

Q26 CT scan aur Hounsfield units kya hain?

CT scan ek 3D X-ray hai; voxel 3D pixel hai — ek scan me lagbhag 32 million voxels. Hounsfield units radiodensity measure karte hain: air −1000, water 0, bone 1000 ya zyada. Kitaab me values [−1000, 1000] par clip ki jati hain.

Q27 Class imbalance se model kyun fail hota hai — 99.7% accuracy ke saath bhi?

Jab 99.7% samples negative hon, to 'hamesha negative bolo' se bhi 99.7% accuracy mil jati hai — lekin ek bhi cancer nahi pakda jata. Kitaab ke model ne epoch 1 me sirf 3 of 1,215 nodules pakde. Accuracy yahan misleading metric hai; precision, recall aur F1 sach batate hain.

Q28 Precision, recall aur F1 me kya farak hai?

Precision = TP/(TP+FP) — jitne positive predict kiye, unme se kitne sahi the. Recall = TP/(TP+FN) — jitne asal positive the, unme se kitne pakde. F1 harmonic mean hai: 2×P×R/(P+R). Cancer detection me recall zyada important hai — ek missed cancer ek false alarm se zyada dangerous hai.

Q29 Balanced dataset kaise banate hain aur kyun?

Alag positive aur negative lists rakhkar, har epoch shuffle karke, 2:1 pattern me interleave karke (+ − − + − −). Balanced epoch 1 me precision 0.9363, recall 0.9194 aur F1 0.9277 mile — unbalanced training me precision aur recall dono 0 the. Lekin validation malignant loss badhta hai — model sirf 1,215 positive samples ko memorise kar leta hai.

Q30 Augmentation kya hai aur rotation sirf XY plane me kyun?

Augmentation training data ko artificially vary karta hai: random flips, offsets 0.1, scaling 0.2, rotation aur noise 25.0. Rotation sirf XY plane me hoti hai kyunki Z axis non-cubic hai — voxels Z me alag size ke hote hain. Combined augmentation recall ke liye parts ke sum se behtar hai; sirf noise no-augmentation se bhi bura hai.

Q31 SAM (Segment Anything Model) kya hai?

SAM Meta ka 2023 ka model hai — 11 million images aur 1.1 billion masks par train hua, zero-shot kaam karta hai. Isme ViT image encoder, prompt encoder (points, boxes, masks) aur mask decoder hote hain; yeh teen masks deta hai (whole, part, sub-part) confidence score ke saath. Medical images par domain gap hota hai, isliye use fine-tune karna padta hai.

Q32 Segmentation ke teen types kaunse hain?

Semantic segmentation har pixel ko class deti hai. Instance segmentation har object ko alag karti hai — do nodules do objects hain. Panoptic segmentation dono ko combine karti hai. Kitaab me semantic segmentation use hoti hai — har pixel background ya nodule.

Q33 Data parallelism aur model parallelism me kya farak hai?

Data parallelism me har GPU ko data ka alag batch milta hai, model ki copy same rehti hai, aur gradients all-reduce karke average hote hain. Model parallelism me model hi split hota hai — activations send/receive se pass hote hain. DDP (DistributedDataParallel) data parallelism ka recommended tareeqa hai; DataParallel slow hota hai.

Q34 FSDP kya hai aur ZeRO-3 se kya rishta hai?

FSDP (Fully Sharded Data Parallelism) parameters, gradients aur optimiser states ko GPUs par shard karta hai. Forward pass ke liye parameters all-gather hote hain, backward me reduce-scatter hote hain. Yeh ZeRO-3 par bana hai aur 512 GPUs tak scale karta hai — 405B parameter model jaisi cheezon ke liye zaroori hai.

Q35 torch.compile kya karta hai aur kitna speedup deta hai?

torch.compile (PyTorch 2.0) model ko just-in-time compile karta hai — kernel fusion aur operator reordering ke saath — aur 20%–200% inference speedup deta hai. Model ko compile karne se pehle uske device par move karna chahiye. Yeh TorchDynamo aur TorchInductor/Triton backend use karta hai; purana JIT ab maintenance mode me hai.

Q36 Quantization se model kitna chhota hota hai?

fp32 se int8 me jaane par har parameter 4 bytes se 1 byte ka ho jata hai — lagbhag 4× chhota. Kitaab ka custom int8 linear layer model ko 6.5 GB se 1.8 GB tak le gaya — 70% se zyada reduction. 'quantize_dynamic' sirf Linear layers ko quantise karta hai. Quantisation-aware training post-training quantisation se behtar accuracy deta hai.
