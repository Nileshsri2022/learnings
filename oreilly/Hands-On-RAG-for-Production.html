Prastavna 1 — Agent Stack me RAG

Prastavna 1 ek AI company ke pramukh dwara likhi gayi hai. Isme koi alag headings nahi hain — ek hi flow me kitab ki tareef aur uska central message hai.

1 Agents kya hain, aur RAG sabse important hissa kyun hai

AI agents aise software entities hain jo perceive karte hain, decisions lete hain aur act karte hain — matlab aas-paas ki jaankari lete hain, soch kar faisla karte hain aur kaam karte hain. Ye agents large language models (LLMs) aur retrieval-augmented generation (RAG) par khade hain. Prastavna RAG ko agent stack ka sabse important hissa kehti hai — kyunki agent tabhi sahi kaam karega jab uske paas sahi, taaza aur grounded jaankari ho.

Kitab ki tareef me kaha gaya hai ki ye practical hai aur asli deployments par grounded hai — matlab sirf theory nahi, asli systems me jo hota hai us par based hai. Ye newcomers aur practitioners dono ke liye useful hai.

  • Code search karne wale agents — codebase me se relevant code dhoondhna.
  • Support tickets ka jawab dene wale agents — customer ke sawal ka grounded jawab dena.
  • Sales calls ko summarize karne wale agents — lambi calls se main points nikaalna.

Prastavna ka sabse bada lesson ye hai: retrieval pipeline ko engineer karna, measure karna aur continuously improve karna hota hai. Data, models aur evaluation — ye koi afterthought nahi hain, ye pipeline ke core hain. Jo team retrieval ko casually treat karti hai, uska agent production me fail hoga.

Yaad rakhne wali baat: Agent sirf LLM se nahi banta — uski taakat us retrieval pipeline se aati hai jo use sahi context deti hai. RAG ko ek baar bana kar bhoolna nahi hai; use lagatar measure aur improve karna hai.

Prastavna 2 — Private Data ke saath LLM

Prastavna 2 ek data-platform company ke sansthapak aur ek university ke professor dwara likhi gayi hai. Isme bhi koi alag headings nahi hain — ek hi flow me RAG ki taakat, uski limits aur kitab ka motto hai.

1 RAG kya deta hai — private, real-time, up-to-date data

RAG LLMs ko private, real-time aur up-to-date data ke saath kaam karne deta hai — woh data jo ek pretrained model ko pata hi nahi hota. Sahi context ke saath, model specialists se bhi behtar perform kar sakta hai. Matlab model ko retrain kiye bina, nayi aur private jaankari use karne ka rasta RAG hai.

2 Koi system fully hallucination-free nahi

Prastavna imaandari se kehti hai: koi bhi system poori tarah hallucination-free nahi hota. Lekin ek achhe se tuned aur measured RAG stack iske bahut kareeb pahunch sakta hai. Yahan engineering choices aur experimentation, newest model ke peeche bhaagne se zyada matter karte hain. Model badalne se pehle, apni retrieval aur evaluation ko sudhaaro.

3 Vector databases sirf vector store nahi hain

Vector databases sirf vectors store nahi karte — ye metadata filtering, full-text search aur hybrid search bhi dete hain. Matlab retrieval sirf similarity par nahi, filters aur keyword search ke saath bhi chalti hai.

4 Retrieval kis taraf badh rahi hai

  • Chhote, open embedding models — jaise Jina aur BGE — ki taraf shift ho raha hai, bade proprietary models se door.
  • Multimodal data — audio, video, graphs, structured aur unstructured data — sab RAG me aa raha hai.
  • Agents — lekin agents non-determinism laate hain, isliye observability aur evaluation critical ho jaate hain. Prastavna khaas taur par kitab ke Chapter 6 (evaluation, RAGAs) aur vendor lock-in se bachne wali guidance ki taraf ishara karti hai.

Ch 1 — RAG kya hai?

Chapter 1 RAG ka introduction hai. Iske headings order me ye hain: 1.1 What Is RAG?; 1.2 RAG by Example: A Tutoring Application; 1.3 RAG in Action: Common RAG Use Cases; 1.4 The Main Building Blocks of a RAG System; 1.5 RAG Stack; 1.6 RAG Use Cases in Action (a worked scenario); 1.7 Where RAG Falls Short; 1.8 The Evolution of RAG; 1.9 The Architecture of RAG; 1.10 RAG and LLM Agents; 1.11 Summary. Is chapter me koi table aur koi code example nahi hai.

1.1 RAG kya hai?

RAG — Retrieval-Augmented Generation — 2020 ke ek mashhoor paper se introduce hua tha, jiska title tha "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks". Ye ek aisa framework hai jo LLM ko inference time par external documents use karke jawab dene deta hai, sirf apni training par bharosa karne ke bajay.

Iske teen core ideas hain: grounding (jawab ko asal documents se jodna), factuality (jawab ka sach par based hona), aur real-time data use karne ki ability — plus ye ki retrieved passages user ko dikhaye ja sakte hain, matlab sources cite kiye ja sakte hain.

RAG in problems me madad karta hai: hallucination (model ke banaye hue jhooth jawab), stale knowledge (training ke baad ki purani jaankari), privacy (sensitive data ko training me daale bina use karna), aur cost (naye facts ke liye retraining nahi chahiye). Ye khaas taur par conversational, knowledge-heavy question answering over proprietary data ke liye suit karta hai — matlab company ke apne documents par sawal-jawab.

1.2 RAG by Example — ek tutoring application

Example: ek student poochta hai — "French Revolution ke causes kya the?" Ek traditional LLM shayad shallow jawab de ya hallucinate kare. Ek RAG system relevant passages retrieve karta hai — social inequality, fiscal crisis aur Enlightenment ideas ke baare me — aur phir unse ek rich, grounded answer synthesize karta hai.

Kitab system ka poora output deti hai: ek framing sentence se shuru hota hai, phir paanch causes list hote hain —

  1. Social inequality — Estates system aur taxation.
  2. Economic crisis — karz (debt), bread prices, kharab harvests.
  3. Political factors — absolute monarchy, us samay ke raja.
  4. Enlightenment ideas — liberty, equality, democracy.
  5. Badlaav ki ichha — Estates General aur National Assembly.

Aur aakhir me note karta hai ki ye saare causes mil kar revolution me badal gaye.

1.3 RAG in Action — aam use cases

  • Personalized ads — ad system user ke past behavior retrieve karta hai (jaise fitness searches aur gym visits) aur us hisaab se sports-equipment ka ad tailor karta hai.
  • Customer support — model manuals, FAQs aur knowledge-base articles se grounded jawab deta hai; sources se agents quality check kar sakte hain.
  • Content generation — up-to-date jaankari par based content banata hai.
  • Personalized recommendations — profile aur history par based suggestions deta hai.
  • Document search and retrieval — relevant material dhoondhta hai aur answers synthesize karta hai.
  • Research assistants, education aur healthcare support — knowledge-heavy domains me madad karta hai.

1.4 RAG system ke main building blocks

Building blocks ye hain: user query; retrieval; generation; grounding; prompt construction; vector database (jaise pgvector, Pinecone); indexing; chunking; embeddings; aur LLM.

1.5 RAG Stack — flow kaise chalta hai

Flow ye hai: (1) user sawal poochta hai; (2) system knowledge base se relevant jaankari retrieve karta hai; (3) woh context prompt me combine kiya jaata hai; (4) model jawab generate karta hai; (5) jawab user ko wapas milta hai.

1.6 Worked scenario — personalized ads

Ek user ne fitness equipment search kiya aur gyms visit kiye. Retrieval ye behavioral context deti hai jo model ke paas akele nahi hoti — aur isliye use ek tailored sports-equipment advertisement milta hai. Ye wahi example hai jo 1.3 me tha, ab detail me: retrieval user ke behavior ko context me laati hai, aur ad usi par based hota hai.

1.7 RAG kahan kam padta hai — limits

  • Retrieval irrelevant results de sakti hai — galat passages milne par jawab bhi galat hoga.
  • Context windows limited hain — har retrieved passage prompt me nahi sama sakta.
  • Retrieval aur generation compute-heavy hain — cost aur latency badhti hai.
  • Accuracy data quality par depend karti hai — kharab data, kharab jawab.
  • Privacy aur security risks — data ko model ke saamne expose karne me risk hai.

1.8 RAG ka evolution — simple se advanced tak

RAG simple retrieval + generation se shuru hua tha, aur ab hybrid retrieval, agentic RAG, multimodal RAG aur GraphRAG tak pahunch gaya hai.

1.9 Architecture ke main patterns

Kitab paanch main architectural patterns batati hai: modular RAG, knowledge-graph RAG, hybrid RAG, agentic RAG aur multimodal RAG. Har pattern alag problem solve karta hai — aage ke chapters me in par detail me baat hogi.

1.10 RAG aur LLM Agents

Chapter aakhir me ek shift ki taraf ishara karta hai: sirf retrieval se agents ki taraf — aise systems jo tools use karte hain aur plan karte hain. Ye Chapter 7 ka topic hai.

1.11 Summary

RAG LLM ko external documents se jodkar grounded, up-to-date aur cite karne layak jawab deta hai. Iske building blocks — retrieval, generation, embeddings, vector database — mil kar ek stack banate hain. Lekin RAG ki limits bhi hain, aur iska evolution agents, multimodal aur graphs ki taraf badh raha hai.

2.1 Base stack ka overview — do pipelines

Base stack me do pipelines hain: indexing pipeline (parse → chunk → embed → store) aur query pipeline (query embed karo → retrieve karo → prompt banao → generate karo).

2.2 Document parsing aur chunking

Document parsing PDFs, HTML aur doosre formats se text nikaalta hai — tables, images aur layout ko handle karte hue. Chunking text ko aise tukdon me todta hai jo model ke context me sama sakein aur meaning bhi preserve karein.

Chunking me do key trade-offs hain: chunk size aur overlap. Chunk bahut bada ho to precision kho jaati hai (relevant hissa ek bade chunk me dab jaata hai); chunk bahut chhota ho to context kho jaata hai (tukda akele me bekaar lagta hai).

2.3 Embeddings — text ko numbers me badlo

Embeddings text ko dense numeric vectors me badalte hain jo meaning capture karte hain — semantically similar texts vector space me paas-paas baithte hain. Similarity measure karne ke teen tareeke hain: cosine similarity, Euclidean distance ya dot product.

2.4 Vector database

Ek vector database embeddings store karta hai aur fast similarity search support karta hai, saath me metadata filtering aur hybrid search bhi. Query vector ko stored vectors se match kiya jaata hai.

2.5 Prompting aur generation

Prompting me user ka sawal retrieved passages ke saath combine kiya jaata hai. Achhe prompts me teen cheezein hoti hain: role batao (model kis roop me jawab de), context do (retrieved passages), aur instruct karo ki model sirf us context se jawab de — aur agar jawab context me nahi hai to "pata nahi" kahe, hallucinate na kare.

2.6 RAG application banana — step by step, numbers ke saath

Step 1 — Install: pip install langchain langchain-community langchain-openai pymupdf sentence-transformers pgvector psycopg2-binary aur ek API key set karo.

Step 2 — Parse (PyMuPDF): PDF kholo, har page ka text collect karo. Example text climate change par hai — rising temperatures aur sea levels ke baare me ek passage — aur parser uska text wapas deta hai.

Parse — PyMuPDF se PDF padhna
import fitz  # PyMuPDF

doc = fitz.open("climate.pdf")
text = ""
for page in doc:
    text += page.get_text()
# text me ab climate change par passage hai:
# "rising temperatures and sea levels..."

Step 3 — Chunk (recursive splitter, size 500, overlap 50): ek lambe climate-change document par recursive character splitter lagaya jaata hai. Output chunks ki list hoti hai — pehla chunk rising temperatures wale sentence se shuru hota hai, doosra usi topic ko aage badhata hai.

Chunk — recursive splitter, size 500, overlap 50
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
)
chunks = splitter.split_text(text)
# chunks[0] rising temperatures se shuru hota hai
# chunks[1] usi topic ko continue karta hai

Step 4 — Embed (SentenceTransformer "all-MiniLM-L6-v2"): sentence "The cat sits on the mat" ko embed kiya jaata hai; resulting vector truncated dikhaya jaata hai, jo [0.123, -0.456, ...] se shuru hota hai. Cats ke baare me query karne par cosine similarity se sabse similar chunks wapas milte hain.

Embed — SentenceTransformer
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")
vec = model.encode("The cat sits on the mat")
# vec shuru hota hai: [0.123, -0.456, ...]  (truncated)

Step 5 — Store (pgvector, PostgreSQL): ek table banayi jaati hai jisme id, text aur dimension 384 ka vector column hota hai. Similarity query <-> cosine-distance operator se chalti hai — distance ke hisaab se order karke top 5 limit kiye jaate hain.

Store — pgvector me table aur similarity query
CREATE TABLE docs (
    id SERIAL PRIMARY KEY,
    text TEXT,
    embedding vector(384)
);

-- cosine distance se top 5 sabse kareeb chunks:
SELECT text FROM docs
ORDER BY embedding <-> %s
LIMIT 5;

Step 6 — Prompt aur generate (LangChain + OpenAI): ek prompt template banaya jaata hai jo retrieved context aur sawal ko insert karta hai, phir model ko call kiya jaata hai. Example: query "What is the capital of France?" aur Paris ke baare me retrieved context se jawab aata hai — "The capital of France is Paris."

Prompt + generate — LangChain template
from langchain_core.prompts import ChatPromptTemplate

template = """Answer ONLY from the context below.
If the answer is not in the context, say you do not know.

Context:
{context}

Question: {question}
"""
prompt = ChatPromptTemplate.from_template(template)
chain = prompt | llm
answer = chain.invoke({"context": retrieved, "question": question})

Step 7 — Helper "retrieve_and_answer": ek chhota helper saare steps ko jodta hai — query embed karo, top chunks retrieve karo, prompt banao aur generate karo. Poori application ka example climate change par sawal poochta hai aur grounded jawab deta hai — rising temperatures, greenhouse gases aur sea-level rise ke baare me, retrieved passages ko cite karte hue.

Helper — retrieve_and_answer
def retrieve_and_answer(question):

    chunks = retrieve_top(q_vec, k=5)   # pgvector se

Ch 3 — RAG Stack ko Scale karo

Chapter 3 scaling ke baare me hai. Iske headings order me ye hain: 3.1 Scaling the RAG Stack (overview); 3.2 Scaling the Indexing Pipeline; 3.3 Scaling the Query Pipeline; 3.4 Advanced Retrieval Techniques; 3.5 Optimizing the RAG Pipeline; 3.6 Scaling the Vector Database; 3.7 Monitoring and Observability; 3.8 Summary. 3.1 Scaling ka matlab kya hai

Scaling ka matlab hai: zyada documents, zyada queries, kam latency aur zyada quality — ek saath. Sirf load badhana scaling nahi hai; quality girne na paaye, ye bhi scaling ka hissa hai.

3.2 Indexing pipeline ko scale karna

Indexing scaling me ye aata hai: parallel parsing, batch embedding, incremental updates aur deduplication. Matlab documents ko ek saath parallel me parse karo, embeddings ko batches me banao, sirf badle hue documents ko dobaara index karo, aur duplicates hatao.

3.3 Query pipeline ko scale karna

Query scaling me ye aata hai: caching, load balancing, aur read aur write paths ko alag karna. Repeated queries ka jawab cache se do, load ko kai servers par baanto, aur reads ko writes se alag rakho.

3.4 Advanced retrieval techniques

Hybrid search — dense retrieval + sparse/BM25, dono ko reciprocal rank fusion (RRF) se fuse kiya jaata hai. Reranking — ek cross-encoder top candidates ko dobaara score karta hai. Query expansion — query ko rewrite ya expand kiya jaata hai. Metadata filtering — document type ya date jaise filters se retrieval narrow ki jaati hai.

3.4.1 Worked examples aur numbers

Hybrid search: ek query dense retrieval aur BM25 dono se parallel chalti hai; do ranked lists RRF se fuse hoti hain, aur fused list combined scores ke saath dikhayi jaati hai.

Reranking: cross-encoder "cross-encoder/ms-marco-MiniLM-L-6-v2" top 10 candidates ko rescore karta hai aur top 3 rakhe jaate hain. Example me best passage ka score 0.95 aur agle ka 0.87 hai.

Query expansion: query "What is RAG?" ko variants me expand kiya jaata hai — jaise "What is retrieval-augmented generation?" aur "How does RAG work?"

Metadata filtering: document type aur date par filter lagakar retrieval ko recent technical documents tak narrow kiya jaata hai.

Caching: ek Redis cache query results ko query text se key karke store karta hai — repeated query seconds ke bajay milliseconds me wapas aati hai.

Monitoring: ek Prometheus-style metrics example query latency aur retrieval quality record karta hai. Chapter me example targets hain: retrieval ke liye 500 ms se kam, end-to-end 2 seconds se kam.

3.5 RAG pipeline ko optimize karna

Optimization me ye aata hai: chunk-size tuning, top-k tuning, prompt compression aur model choice. Matlab chunk size aur kitne passages retrieve karne hain (top-k) — inhe tune karo; prompt ko compress karo taaki kam tokens lagein; aur sahi model chuno — hamesha sabse bada model zaroori nahi.

3.6 Vector database ko scale karna

Vector-database scaling me ye aata hai: sharding, replication, approximate nearest-neighbor (ANN) indexes — HNSW, IVF — aur recall/latency trade-off. ANN indexes exact search se tez hote hain lekin thoda recall khote hain — ye trade-off samajhna scaling ka core hai.

3.7 Monitoring aur observability

Monitor karne wali cheezein: latency, throughput, error rate, retrieval quality aur user feedback. Metrics, logs aur traces dashboards aur alerts ko feed karte hain — taaki problem user se pehle team ko dikhe.

3.8 Code — step by step

(1) Parallel indexing (thread pool): documents ko parallel batches me parse aur embed karo.

Parallel indexing — thread pool
from concurrent.futures import ThreadPoolExecutor

def index_one(doc):
    text = parse(doc)
    chunks = split(text)
    vectors = model.encode(chunks)
    store(chunks, vectors)

Metrics — recall, precision, MRR, nDCG
def recall_precision(retrieved, relevant):
    retrieved, relevant = set(retrieved), set(relevant)
    hit = retrieved & relevant
    recall = len(hit) / len(relevant)      # 4/10 = 0.4
    precision = len(hit) / len(retrieved)  # 4/5 = 0.8
    return recall, precision

def mrr(first_relevant_rank):
    return 1.0 / first_relevant_rank  # rank 2 -> 0.5

def dcg(gains):
    import math
    return sum(g / math.log2(i + 2) for i, g in enumerate(gains))
# nDCG = DCG / ideal DCG  (perfect ranking = 1.0)

9.1 Knowledge Graphs aur RAG

Ek knowledge graph entities (people, places, concepts) aur unke relationships ko nodes aur edges ke roop me store karta hai — jo structure capture karta hai jo flat text chunks kho dete hain. Chunks me "Paris" aur "France" alag-alag jagah hote hain; graph me unke beech ka relation saaf dikhta hai.

9.2 GraphRAG — Microsoft ka approach

GraphRAG documents se ek graph banata hai, related entities ki communities detect karta hai, har community ko summarize karta hai, aur jawab dete hue relevant community summaries plus entities retrieve karta hai.

Ye un sawalon me madad karta hai jinhe kai documents me synthesis chahiye — jaise "Is corpus ke main themes kya hain?" — jahan plain retrieval scattered chunks wapas deti hai aur poori picture nahi banti.

GraphRAG example: ek corpus ko entities, relationships aur community summaries me process kiya jaata hai. Ek global query ("main themes kya hain?") community summaries retrieve karke synthesized answer deti hai; ek local query specific entities aur unke neighbors retrieve karti hai. Chapter GraphRAG ki pipeline dikhata hai: indexing (entity extraction), community detection (Leiden), summarization, aur query-time retrieval — aur note karta hai ki community summaries hi global questions ki kunji hain.

9.3 Knowledge Graph banana — step by step

Graph banane me ye steps hain: entity aur relation extraction (aksar LLM se), deduplication (ek hi entity do baar na aaye), graph database me storage (jaise Neo4j), aur hybrid retrieval jo graph traversal ko vector search ke saath combine karta hai.

Trade-offs: build cost, graph quality aur freshness. Graph banana mehenga hai, graph ki quality extraction par depend karti hai, aur data badalne par graph ko update karna padta hai.

9.3.1 Code — step by step

(1) Text se entities aur relations extract karo — LLM ko (subject, relation, object) triples ke liye prompt karo.

Entity extraction — (subject, relation, object) triples

Text: {text}
Return JSON list of (subject, relation, object).

(2) Graph banao (NetworkX/Neo4j): nodes aur edges jodo, entities deduplicate karo. (3) Communities detect karo (Leiden) aur har community ko LLM se summarize karo.

Example: ek audit trail record karta hai ki har answer ke liye kaunse documents retrieve hue the — taaki ek regulated answer ko uske sources tak trace kiya ja sake.

RAG ka bhavishya agentic, multimodal, personalized aur federated hai. Federated retrieval data ko centralize kiye bina kai sources ko query karta hai. SLMs retrieval ke saath mil kar saste aur tez grounded answers dete hain. Governance — lineage, access control, audit trails, GDPR — ab design ka core hissa hai, add-on nahi.

FAQs — Interview Sawal-Jawab

Current-era interviews ke liye 36 sawal-jawab — har chapter se, kitab ke concepts, numbers aur examples par based. Har jawab khud me poora hai.

Q1RAG kya hai, ek line me samjhao?
RAG — Retrieval-Augmented Generation — ek framework hai jo LLM ko inference time par external documents se jawab dene deta hai, sirf training par bharosa karne ke bajay. Flow: sawal poochho, relevant passages retrieve karo, unhe prompt me daalo, grounded jawab generate karo. Isse hallucination kam hoti hai, taaza jaankari milti hai aur sources cite kiye ja sakte hain.
Q2RAG aur fine-tuning me kya farak hai?
Fine-tuning model ke weights badalta hai — nayi jaankari model ke andar daalni hoti hai, jo mehenga aur slow hai. RAG model ko badle bina external documents se context deta hai — naye facts ke liye retraining nahi chahiye. Dono combine bhi ho sakte hain, lekin RAG privacy aur cost me behtar hai kyunki sensitive data training me nahi jaata.
Q3RAG hallucination ko poori tarah khatm kar deta hai?
Nahi. Koi bhi system fully hallucination-free nahi hota. RAG hallucination ko kam karta hai kyunki jawab retrieved passages se grounded hota hai, lekin retrieval galat ho sakti hai ya model context ko galat padh sakta hai. Isliye faithfulness measure karna aur evaluation pipeline chalana zaroori hai — Chapter 6 dekho.
Q4Base RAG stack ke components kaunse hain?
Do pipelines: indexing (parse, chunk, embed, store) aur query (embed, retrieve, prompt, generate). Components: user query, retrieval, generation, grounding, prompt construction, vector database (jaise pgvector, Pinecone), indexing, chunking, embeddings aur LLM.
Q5Chunking me chunk size aur overlap kyun matter karte hain?
Chunk bahut bada ho to precision kho jaati hai — relevant hissa ek bade chunk me dab jaata hai. Chunk bahut chhota ho to context kho jaata hai — tukda akele me bekaar lagta hai. Kitab ka example recursive splitter size 500, overlap 50 use karta hai. Lab 1 me dono badal kar dekho.
Q6Embeddings kaise kaam karte hain?
Embeddings text ko dense numeric vectors me badalte hain jo meaning capture karte hain — semantically similar texts vector space me paas-paas hote hain. Similarity cosine similarity, Euclidean distance ya dot product se measure hoti hai. Kitab SentenceTransformer 'all-MiniLM-L6-v2' use karti hai.
Q7Vector database sirf vectors store karta hai?
Nahi. Vector database embeddings store karne ke saath fast similarity search, metadata filtering aur hybrid search bhi deta hai. Kitab me pgvector (PostgreSQL ke andar) use hota hai — table me id, text aur dimension 384 ka vector column, aur '<->' operator se cosine-distance query.
Q8Prompt me model ko 'pata nahi' kehna kyun sikhate hain?
Kyunki agar jawab retrieved context me nahi hai, to model ko hallucinate karne ke bajay 'pata nahi' kehna chahiye. Achha prompt role batata hai, context deta hai aur instruct karta hai ki sirf context se jawab do. Ye grounding ka core rule hai — Chapter 2 dekho.
Q9Hybrid search kya hai aur RRF kya karta hai?
Hybrid search dense retrieval (embedding similarity) aur sparse retrieval (BM25 keyword matching) dono ko parallel chalata hai. Reciprocal rank fusion (RRF) dono ranked lists ko ek fused list me mila deta hai — jo document dono me upar aata hai, woh fused list me bhi upar aata hai. Lab 4 me live try karo.
Q10Reranking kyun karte hain? Bi-encoder kaafi nahi?
Bi-encoder (embedding) retrieval tez hai lekin rough hoti hai — woh query aur passage ko alag-alag encode karta hai. Cross-encoder (query, passage) pair ko ek saath padhkar dobaara score karta hai, isliye zyada accurate hota hai. Kitab ka example: cross-encoder 'cross-encoder/ms-marco-MiniLM-L-6-v2' top 10 ko rescore karke top 3 rakhta hai — best 0.95, next 0.87.
Q11Query expansion kab useful hai?
Jab user ki query chhoti ya ambiguous ho. Query ko variants me expand kiya jaata hai — jaise 'What is RAG?' se 'What is retrieval-augmented generation?' aur 'How does RAG work?' — aur har variant ke liye retrieve kiya jaata hai. Isse recall badhta hai.
Q12HNSW aur IVF kya hain?
Ye approximate nearest-neighbor (ANN) indexes hain jo vector database ko scale karne me madad karte hain. Exact search slow hota hai; ANN tez hota hai lekin thoda recall khota hai — ye recall/latency trade-off scaling ka core hai. Sharding aur replication ke saath ye vector DB scaling ke main tools hain.
Q13Production RAG me latency ka sabse bada hissa kaunsa hai?
Generation — kitab ke example me embedding ~50 ms, retrieval ~100 ms, reranking ~200 ms aur generation ~1,500 ms — kul ~1,850 ms. Isliye generation ko optimize karna ya chhota model use karna sabse zyada farak daalta hai. Caching se repeated queries dasion milliseconds me aati hain.
Q14Caching se cost kitni kam hoti hai?
Kitab ke worked example me caching se model calls lagbhag 30% kam ho jaati hain — kyunki repeated queries ka jawab cache se mil jaata hai, model call hi nahi hoti. Redis cache query text se key karke results store karta hai, TTL ke saath. Lab 6 me breakdown dekho.
Q15RAG me PII aur security kaise handle karte hain?
Teen rules: sensitive data ko index karne se pehle filter/redact karo (regular-expression pass se), retrieval ke time per-user access enforce karo (metadata filter — user_id / access level), aur audit karo. Example: PII wala document redact karke index hota hai, aur filter sirf wahi documents deta hai jinhe requesting user dekh sakta hai.
Q16Build vs buy ka decision kaise lein?
Build karo jab deep customization chahiye ya strict data controls hon. Buy karo jab speed chahiye aur infrastructure operate nahi karna. Dekhne wale criteria: retrieval quality, multimodal support, security, observability, evaluation tooling, integrations — plus data residency, SLAs aur lock-in. Table 4-1 dekho.
Q17Total Cost of Ownership me kya-kya aata hai?
Sirf API bills nahi — build, run, maintenance aur evaluation costs bhi. Jo team sirf API bill dekhti hai, use asli cost ka andaza nahi hota. Cost per query aur per user track karo — Table 4-2 ke KPIs dekho.
Q18RAG platform kya deta hai? Vectara example samjhao.
RAG platform ek managed service hai jo parsing, chunking, embedding, storage, retrieval, reranking aur generation handle karti hai. Vectara example: pet policy corpus par query 'What is the pet policy?' ka top result score 0.777 ke saath aaya, aur generated answer ne bataya ki pets allowed hain, restrictions ke saath — citations ke saath. Platform ki built-in reranking aur hallucination detection (HHEM) main differences hain.
Q19Evaluation kyun zaroori hai — user feedback kaafi nahi?
Kyunki RAG quality drift karti hai — data, models aur prompts badalte hain to quality bhi badalti hai. User feedback slow aur noisy hota hai. Evaluation fixed test set par har change ko measure karti hai aur releases ko gate karti hai — scores girne par release ruk jaati hai.
Q20Recall aur precision me farak samjhao, numbers ke saath.
Kul 10 relevant documents hain, 5 retrieve hue, unme se 4 relevant — recall = 4/10 = 0.4 (kul relevant me se kitne mile), precision = 4/5 = 0.8 (mile hue me se kitne relevant the). Dono alag hain: recall coverage batata hai, precision noise batata hai. Lab 3 me calculate karo.
Q21MRR aur nDCG kab use karte hain?
MRR — jab pehla relevant result sabse important ho: pehle relevant ki rank ka reciprocal (1/rank) ka average. Rank 2 ho to MRR 0.5. nDCG — rank-aware quality: relevant documents ko upar rakhne par reward deta hai, perfect ranking = 1.0. Dono ranked lists ke liye hain, set-based recall/precision ke alag.
Q22Faithfulness, relevance aur correctness me kya farak hai?
Faithfulness — jawab retrieved context se supported hai ya nahi (hallucination pakadta hai). Relevance — jawab sawal ka jawab deta hai ya nahi (off-topic pakadta hai). Correctness — jawab ground truth se match karta hai ya nahi (final accuracy). Teenon generation metrics hain — Table 6-1 dekho.
Q23Evaluation dataset kaise banayein?
Teen tareeke: haath se, real user queries se, ya synthetically (LLM se documents par questions generate karwa kar). Har test case ko ground-truth answers aur relevant-passage labels chahiye. Bina ground truth ke score ka matlab nahi hota.
Q24LLM-as-a-judge kya hai aur iski limit kya hai?
Ek strong model ko rubric ke saath answers score karne ke liye use karna — factuality aur relevance 1 se 5 tak, reasoning note ke saath. Ye tez hai lekin apne hi style ki taraf biased ho sakta hai, isliye human judgments ke against calibrate karna chahiye. Lab 7 me try karo.
Q25Agentic RAG normal RAG se kaise alag hai?
Normal RAG ek fixed pipeline hai: retrieve, phir generate. Agentic RAG me reasoning loop hota hai — agent decide karta hai ki retrieve karna hai ya nahi, kya retrieve karna hai, aur results ko kaise use karna hai, aur iterate kar sakta hai. Patterns: ReAct (thought, action, observation), tool use, planning, memory.
Q26ReAct kya hai? Example do.
ReAct — reason + act. Har step me thought, action aur observation hoti hai. Example: query 'What is the population of Paris?' — agent sochta hai ('mujhe current population data chahiye'), act karta hai (search tool call karta hai), observation dekhta hai (result aata hai), phir retrieved figure ke saath jawab deta hai. Lab 8 me trace live dekho.
Q27Multi-agent RAG me orchestrator kya karta hai?
Kaam ko specialized agents me baantta hai — planner (steps banao), retriever (documents nikalo), generator (jawab banao) — aur unhe coordinate karta hai. Example: research task me ek agent retrieve karta hai, doosra synthesize karta hai, teesra jawab ko sources ke against check karta hai.
Q28Agents evaluate karna mushkil kyun hai?
Kyunki agent ka path har baar alag ho sakta hai (non-determinism), errors ek step se agle step me propagate karte hain, aur cost zyada hoti hai. Fixed test se measure karna mushkil hota hai — isliye Chapter 6 ki evaluation agents ke liye aur bhi important ho jaati hai.
Q29Multimodal RAG me tables ki structure kyun preserve karni hoti hai?
Kyunki table ko flat text me convert karne par rows, columns aur headers ka matlab kho jaata hai. Camelot/tabula se parse karke headers ke saath store karna hota hai — tabhi 'What was Q2 revenue?' jaise sawal ka jawab mil sakta hai.
Q30Image retrieval me 0.8323 ka kya matlab hai?
Pizza image example me text query aur pizza image ke beech cosine similarity 0.8323 thi — example set ki doosri images se zyada. SigLIP ('google/siglip-base-patch16-224') text aur images ko ek shared embedding space me daalta hai, jahan similarity se match hota hai.
Q31Audio aur video RAG me kaise aate hain?
Audio ko Whisper/Deepgram se transcribe kiya jaata hai, speaker diarization se speakers alag kiye jaate hain, phir transcript ko chunk karke text ki tarah index kiya jaata hai. Video me frames extract karke caption kiye jaate hain aur captions + transcript dono index hote hain, taaki query se relevant segment mil sake.
Q32Knowledge graph flat chunks se behtar kyun hai?
Kyunki graph entities aur unke relationships ko nodes aur edges me store karta hai — structure capture hoti hai jo flat chunks kho dete hain. Example: 'Paris is in France' aur 'Eiffel Tower is in Paris' — graph traverse karke Eiffel Tower se related facts mil jaate hain.
Q33GraphRAG global aur local queries ko alag kaise handle karta hai?
GraphRAG documents se graph banata hai, Leiden se communities detect karta hai aur har community ko summarize karta hai. Global query ('main themes kya hain?') community summaries retrieve karke synthesized answer deti hai; local query specific entities aur unke neighbors retrieve karti hai.
Q34Federated retrieval kya hai aur iski mushkil kya hai?
Kai independent sources (alag teams, regions ya organizations) ko data centralize kiye bina query karna. Fayda: privacy aur data residency. Mushkil: coordination aur ranking — alag sources ke results ko mila kar rank karna padta hai. Example: ek query HR, engineering aur legal corpora me fan-out hoti hai, phir results merge aur rerank hote hain.
Q35Small language models RAG ke saath kaise kaam karte hain?
SLMs RAG ko sasta aur tez banate hain aur on-device/edge deployment enable karte hain. Trade-off: raw capability vs cost aur latency. Retrieval zyada knowledge ka kaam kar leti hai, to chhota model bhi grounded answers de sakta hai — jaise support-chatbot example me.
Q36RAG me governance aur compliance kya hota hai?
Data lineage (data kahan se aaya), access control (kaun kya dekh sakta hai), audit trails (kisne kya kiya) aur GDPR jaise regulations. Jaise-jaise RAG zyada sensitive data chhoota hai, ye first-class design requirements ban jaate hain — add-on nahi. Example: audit trail har answer ke liye retrieved documents record karta hai.
