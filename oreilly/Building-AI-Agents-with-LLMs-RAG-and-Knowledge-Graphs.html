Text Ko Represent Karna — Pehla Kadam

Corpus matlab texts ka collection — aur usse machine ko samjhane se pehle use chhote tukdon me todna padta hai. Is process ke chaar basic steps hain.

  • Tokenisation — text ko tokens (words ya sub-words) me todna.
  • Segmentation — text ko sentences me baantna.
  • Normalisation — lower-case karna aur cleaning karna, taaki 'Hello' aur 'hello' ek hi maane jayein.
  • Lemmatisation — word ko uske dictionary form me le aana (jaise alag-alag verb forms ko ek lemma me).
  • Stemming — word ko uske crude root tak kaatna (lemma se kam precise, lekin tez).

Ek chhoti si baat jo aasani se chhoot jati hai: punctuation bhi khud ek token ho sakta hai — jaise '?' ya '!' ka apna matlab hota hai, use hamesha phenkna nahi chahiye.

Ye pipeline poori kitab ki neev hai. Aage ke har representation — one-hot se lekar embeddings tak — isi pipeline ke upar khada hai.

Lemmatisation vs stemming: lemma sahi dictionary word deta hai ('running' → 'run'), stemming sirf kaat-ta hai ('running' → 'run', lekin 'studies' → 'studi' bhi ho sakta hai). Accuracy chahiye to lemma, speed chahiye to stem.

One-Hot Encoding

One-hot encoding text ko numbers me badalne ka sabse seedha tareeka hai: har word ek vector ban jata hai, jiski length poori vocabulary ke barabar hoti hai. Us vector me sirf ek jagah 1 hota hai — us word ki jagah — baaki sab 0.

Worked example: ek 9-word vocabulary ke saath ek sentence — pizzeria chunne ya restaurant jaane ke baare me. Har word ka vector 9 numbers ka hota hai, jisme ek 1 aur aath 0 hain.

WordVector (9 dims)
pizzeria[0, 0, 1, 0, 0, 0, 0, 0, 0]
restaurant[0, 0, 0, 0, 0, 1, 0, 0, 0]
choose[1, 0, 0, 0, 0, 0, 0, 0, 0]

Code — step by step

Code ye karta hai: sentence ko lower-case karo, split karo, sorted vocabulary banao, phir (tokens × vocabulary) shape ki zero matrix banao aur har token ke column me 1 set karo.

python
sentence = sentence.lower().split()
 vocab = sorted(set(sentence))
 matrix = np.zeros((len(sentence), len(vocab)))
 for i, token in enumerate(sentence):
     matrix[i, vocab.index(token)] = 1

Taakat aur kamzoriyan

  • Taakat: bahut simple — samajhne aur implement karne me aasan.
  • Kamzori 1: sirf presence record karta hai — meaning nahi. 'pizzeria' aur 'restaurant' ka vector ek doosre se utna hi door hai jitna 'pizzeria' aur 'car' ka.
  • Kamzori 2: order nahi — words ka kram kho jata hai.
  • Kamzori 3: vectors sparse hote hain aur vocabulary badhne par bahut bade ho jate hain.
One-hot ek shuruaat hai, manzil nahi. Iska kaam hai ye dikhana ki text ko vector banana kyun zaroori hai — aur kyun is tareeke se kaam nahi chalega.

Bag of Words

Bag of Words (BoW) me document ek word counts ka vector ban jata hai. Figure 1.1 me Hamlet ka example hai — wahi idea document level par dikhaya gaya hai: har word kitni baar aaya, bas ye gin-ti hai.

Steps: tokenise karo, vocabulary map banao, aur document × word matrix bharo. Code ye kaam teen chhoti film reviews par karta hai — jisme awesome, boring aur great jaise words hain.

Reviewawesomeboringgreat
Review 1101
Review 2010
Review 3102

Code — step by step

Har review ko tokenise karo, poori vocabulary ka map banao (har word ko ek index do), phir har document ke liye uske words ki gin-ti se vector bharo.

python
vocab = {}
for doc in docs:
    for word in doc.split():
        if word not in vocab:
            vocab[word] = len(vocab)
# har document -> counts ka vector

Limitations — kya nahi kar sakta

  • Context nahi samajhta: awesome positive bhi ho sakta hai, neutral bhi, ironic bhi — BoW farak nahi bata sakta.
  • Word order kho jata hai: 'dog bites man' aur 'man bites dog' dono ka BoW ek jaisa hoga.
  • Curse of dimensionality: vocabulary badhte hi dimensions explode ho jate hain — har naya word ek naya dimension.

TF-IDF

TF-IDF ka idea seedha hai: jo word bahut se documents me aata hai, uska weight kam kar do — kyunki wo document ko pehchanne me madad nahi karta. Figure 1.2 ye intuition dikhati hai.

Code teen cheezein compute karta hai: TF (term frequency — word document me kitni baar aaya), phir IDF base-10 logarithm se, aur phir unka product — wahi TF-IDF score hai.

TF-IDF(word, doc) = TF(word, doc) × log10(total_docs / docs_with_word)

Wahi teen film reviews ab alag score dete hain: jo word sab reviews me common hai, wo down-weight ho jata hai; jo word distinctive hai — sirf ek review me hai — wo up-weight ho jata hai.

common word (sab me)15
rare word (ek me)85
medium word50
TF-IDF search engines ki pehli peedhi ki jaan tha — aur aaj bhi BM25 jaise rankers isi idea par khade hain. Chapter 5 me ye wapas aayega.

02.5Part 1 · AI Agent Engine

Word Embeddings aur Polysemy

Word embedding me words chhote, dense vectors ban jate hain — real numbers ke. Jo words similar contexts me istemal hote hain, wo vector space me paas-paas hote hain. Ye one-hot aur BoW se ek kadam aage hai: yahan meaning bhi vector me hai.

Lekin ek badi problem hai — polysemy. bank ka example lo: ek spelling ke do matlab ho sakte hain — financial institution ya nadi ka kinara. Ek fixed vector in dono senses ko alag nahi kar sakta.

  • Bank (financial): 'I went to the bank to deposit money.'
  • Bank (river): 'We sat on the bank of the river.'
  • Dono me word ek hi hai, vector ek hi hai — lekin matlab bilkul alag.

Isi problem ka jawab aage milega — contextual embeddings (jaise Transformer me), jahan word ka vector uske aas-paas ke words par depend karta hai. Lekin pehle static embeddings ko poori tarah samajhna zaroori hai.

Embedding ka matlab hai: meaning ko geometry bana do. Similar words paas, alag words door — aur ye geometry hi aage similarity, analogy aur retrieval ka kaam karti hai.

Word2vec

Word2vec (2013 me propose hua) ek self-supervised model hai: ye ek word ko uske context se predict karta hai — ya ulta, context ko word se. Koi labelled data nahi chahiye — text khud hi training data hai.

Training ko ek binary yes/no sawaal ki tarah frame kiya jata hai — 'kya ye word is context me belong karta hai?' Score dot product se milta hai, phir sigmoid se guzarta hai, aur training negative sampling aur cross-entropy loss se hoti hai.

Quality kis par depend karti hai

  • Data ki quality aur matra: saaf text (Wikipedia jaisa) noisy news se behtar result deta hai.
  • Dimension: 300 ek common sweet spot hai.
  • Window size: aam taur par lagbhag 4, lekin jab syntax matter kare to 2.

Code — Gensim Word2Vec

Code Gensim ka Word2Vec istemal karta hai — skip-gram (sg=1) aur vector_size=100 ke saath.

python
from gensim.models import Word2Vec
model = Word2Vec(sentences, vector_size=100, sg=1, window=4)
model.wv.most_similar('good')

Words Ke Beech Similarity

Do vectors kitne similar hain — ye naapne ke do tareeke hain. Dot product vector ki length ke saath badhta hai, isliye wo lambe ya frequent vectors ko favour karta hai — aur unbounded hota hai.

Cosine similarity do vectors ke beech ke angle ka cosine hai: -1 se 1 ke beech rehta hai, scale-invariant hai (vector ki length se farak nahi padta) aur tez hai. Figure 1.8 iski geometry dikhati hai.

cosine(a, b) = (a · b) / (|a| × |b|) → -1 se 1 tak

Embeddings ki properties

  • Most-similar words: kisi word ke sabse kareeb ke words nikaal sakte ho.
  • Grammatical relations: jaise superlatives ke patterns.
  • Analogies: a is to a* as b is to ? — formula hai a - a* + b.

Code good ke sabse similar words maangta hai, aur great aur bad ke synonyms/antonyms. Lekin yahan do failures samajhna zaroori hai:

  • Antonyms alag nahi hote: opposite words similar contexts me aate hain ('good' aur 'bad' dono 'movie was __' ke baad aate hain) — isliye embeddings unhe paas rakhte hain.
  • Meaning waqt ke saath badalta hai: Figure 1.9 words jaise gay, broadcast aur awful ka matlab waqt ke saath kaise badla, ye trace karti hai.

Figure 1.10 (Q18-1034) apple:red :: banana:? analogy problem dikhati hai — analogy ka jawab hamesha seedha nahi hota, kyunki relation ka type (colour? shape? taste?) khud ambiguous hai.

Recurrent Neural Networks

Ek plain feed-forward net, y = σ(Wx + b), ke paas koi memory nahi hoti — har input ko wo pehli baar ki tarah dekhta hai. RNN ek hidden state jodta hai, jo ek step se agle step tak carry hoti hai.

a_t = b + U·h(t-1) + W·x_t h_t = tanh(a_t) o_t = c + V·h_t y_t = σ(o_t)

Code — PyTorch RNN

Code ek PyTorch RNN banata hai — input size 10, hidden size 5, output 3.

python
import torch.nn as nn
rnn = nn.RNN(input_size=10, hidden_size=5, num_layers=1, batch_first=True)
# output: (output, hidden state)

Fayde aur nuksaan

  • Fayda 1: kisi bhi length ki sequence accept karta hai.
  • Fayda 2: weights share karta hai — har step par wahi weights.
  • Nuksaan: vanishing gradients — lambi sequences par gradient dheere-dheere gayab ho jata hai, aur network door ki cheezein bhool jata hai.
Vanishing gradient hi wo problem hai jiske liye LSTM aur GRU bane — agle do sections me wahi hain.

02.9Part 1 · AI Agent Engine

LSTM — Yaad Rakhne Wala Network

LSTM me teen gates ek cell state ko protect karte hain — taaki important information lambi sequence me bhi bachi rahe. Figure 1.13 gates ko dikhati hai.

Gates ke beech element-wise (Hadamard) multiplication hota hai — har gate decide karta hai ki kitni information aage jaye. Network do states rakhta hai: h (short-term) aur c (long-term).

  • Forget gate (f_t): purani cell state me se kya hatao.
  • Input gate (i_t) + candidate (g_t): nayi information kya jodo.
  • Output gate (o_t): cell state se kya output banao.

Initialisation 1 hoti hai, aur book kehti hai ki ek LSTM lagbhag 100 steps tak yaad rakh sakta hai — plain RNN ke lagbhag 7 steps ke muqable me. Yehi farak hai jo LSTM ko lambi sequences ke liye kaam ka banata hai.

Code — PyTorch LSTM

python
import torch.nn as nn
lstm = nn.LSTM(input_size=10, hidden_size=5, num_layers=1, batch_first=True)
# output: (output, (h_n, c_n)) — do states wapas milti hain
LSTM ka kharcha: zyada parameters, dheemi training. Isliye jab sequence chhoti ho ya speed chahiye, to GRU dekha jata hai — agla section.

GRU — Halka Aur Tez Gated Cell

GRU ek simpler gated cell hai — LSTM se kam parameters, tez training, aur lambi sequences par achha. Isme sirf do gates hote hain.

h_t = z ⊙ h(t-1) + (1-z) ⊙ h~

Update gate z_t forget ka role nibhata hai, aur reset gate r_t decide karta hai ki purani memory candidate banate waqt kitni istemal ho. Aakhir me blend hota hai: purani hidden state aur nayi candidate memory ka weighted mix.

LSTMGRU
Gates3 (forget, input, output)2 (update, reset)
States2 (h aur c)1 (h)
ParametersZyadaKam
TrainingDheemiTez
Rule of thumb: jab performance same ho to GRU chuno — kam parameters, tez training. Jab bahut lambi memory chahiye to LSTM aazmao.

Seq2seq Se Attention Tak

Machine translation 1950s se chal rahi hai — lekin 1990s me data explosion ke baad encoder–decoder (seq2seq) models aaye. Idea: encoder poori sentence ko padhe, aur decoder usse translation banaye.

Attention Mechanism

Attention (2014 ka idea) ka tareeka: har output step par, har encoder state ko score karo — pichhle decoder state ke against. Phir scores ko softmax se weights me badlo, aur un weights se context vector banao.

e_ij = score(s(i-1), h_j) a_ij = softmax(e_ij) c_t = Σ a_ij · h_j

Matlab: decoder har baar khud tay karta hai ki input ke kis hisse par dhyaan dena hai. Fixed vector ki zaroorat khatam — context har step par naya banta hai.

Attention ke fayde

  • Bottleneck ka shortcut: har step par poori input available.
  • Koi fixed vector nahi: context har baar naya banta hai.
  • Interpretable weights: heat map se dikhta hai model ne kya dekha.
  • Behtar performance: khaas taur par lambi sentences par.
Heat map sirf sundar diagram nahi hai — ye model ki reasoning ka window hai. Agar alignment galat hai, to translation galat hogi — aur tumhe dikhega kyun.

Self-Attention — Q, K, V

Self-attention me word ka matlab uske hi sentence ke doosre words se tay hota hai. Book ka example: 'book' ka matlab badal jata hai jab sentence French Revolution ke baare me ho — context hi meaning banata hai.

Attention(Q, K, V) = softmax(QK^T / √d_k) · V

Teen cheezein: Query (Q) — main kya dhoondh raha hoon; Key (K) — har word kya offer karta hai; Value (V) — asal information. Formula: Q = XW_Q, K = XW_K, V = XW_V — input X ko teen alag matrices se multiply karke Q, K, V banaye jate hain.

√d_k scaling kyun? Bina scaling ke dot products bahut bade ho jate hain, softmax saturate ho jata hai, aur gradients shrink ho jate hain. Root se divide karne se gradients zinda rehte hain.

Multi-head attention

Multi-head me kai attention heads parallel chalte hain — har head ek alag relation dekh sakta hai (ek head grammar dekhe, doosra meaning). Phir sab heads ko concatenate karke ek linear projection lagti hai (Figure 2.6).

Keemat: cost sequence length me quadratic hai — O(T² + d) time aur space dono me. Aur self-attention ke paas order ka koi notion nahi — 'dog bites man' aur 'man bites dog' uske liye ek jaise hain, jab tak position ki information na di jaye.

Multi-head ka matlab hai: ek hi sentence ko kai nazariyon se dekho — aur phir sab nazariye jod do. Ek head sab kuch nahi dekh sakta.

The Transformer — Architecture

The Transformer (2016, 'Attention Is All You Need') ne RNN ko poori tarah hata diya — sirf attention par khada model. Shuruaat tokenisation plus positional encoding se hoti hai.

PE(pos, 2i) = sin(pos / 10000^(2i/d_model)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))

Positional encoding zaroori hai kyunki self-attention ko order nahi pata. Sine aur cosine waves har position ko ek unique pattern dete hain — aur relative distances bhi preserve hoti hain. Ek caveat: absolute positional encoding sequence ki shuruaat ko over-represent karta hai.

Ek Transformer block

Har block me do cheezein hain — multi-head self-attention, phir feed-forward network — aur har ek residual connection aur layer normalisation se wrapped hai (Figure 2.8).

FFN(x) = max(0, xW1 + b1)W2 + b2 (ReLU)
H = LayerNorm(X + MHSA(X)) H = LayerNorm(H + FFN(H))

Figure 2.9 dikhati hai ki residual connections loss landscape ko smooth karte hain — isliye deep networks train ho pati hain. LayerNorm mean aur variance se normalise karta hai, phir learned γ aur β se rescale karta hai. Stacks 96 blocks tak pahunchte hain.

Residual connection ka matlab: 'jo tha, use bhi rakho; jo naya seekha, use jodo.' Bina iske 96 layers ka network train hi nahi hota.

Scaling Laws

Scaling laws kehte hain: performance power law se improve hoti hai — parameters N, data D aur compute C ke saath. L(N), L(D), L(C) — loss in teeno ke saath power law se girta hai.

L(N) ∝ N^(-α) L(D) ∝ D^(-β) L(C) ∝ C^(-γ)

Ek model apne size ke liye under-trained ya over-trained ho sakta hai. Chinchilla finding kehta hai: data aur parameters ko saath-saath scale karna chahiye — ek chhota model jo zyada tokens par train hua ho, bade under-trained model ko hara sakta hai.

Data finite hai: GPT-3 ka training mix tha — Common Crawl 410 billion tokens, Books1 12 billion, Books2 55 billion — aur modern models 1 trillion se zyada tokens istemal karte hain.

  • Model collapse: model-generated data par dobara train karo to quality girne lagti hai — model apni hi galtiyan seekhne lagta hai.
  • Catastrophic forgetting: naye tasks seekhte waqt purane bhool jana.
Chinchilla ka lesson: sirf bada model banana kaafi nahi hai — data bhi utna hi badhao. Nahi to tumhara bada model ek chhote, achhe se train hue model se haar jayega.

Evaluation — Precision, Recall, MAP, MRR, RAGAS

Retrieval achha hai ya nahi — ye naapne ke metrics hain (Figures 5.19–5.20).

precision = R_q / D_q recall = R_q / R

Precision = retrieved-relevant / retrieved (jo laya, usme se kitna kaam ka tha). Recall = retrieved-relevant / all relevant (jo kaam ka tha, usme se kitna laya). Dono ke rank-aware versions bhi hain — pehle rank par sahi jawab ki value zyada hai.

Worked MAP example

Precisions ranks 1, 3 aur 5 par hain: 1, 0.67 aur 0.6 — inka average AP = 0.76. Teen queries ke AP hain 0.76, 0.5, 0.67 — inka average MAP = 0.64.

MRR = 1/Q · Σ 1/rank_i — pehla sahi jawab jis rank par mila, uska reciprocal

RAGAS metrics poori RAG pipeline ko naapte hain: faithfulness, context recall, context precision, context relevancy, entity recall, answer correctness — plus summarisation, relevance, fluency aur coherence.

FaithfulnessJawab context se consistent hai ya nahi
Context recallZaroori context retrieve hua ya nahi
Context precisionRetrieved context me se kitna kaam ka tha
Answer correctnessJawab sahi hai ya nahi

Reinforcement Learning Ki Foundations

Reinforcement learning (RL) me agent trial aur error se seekhta hai — labelled examples se nahi. Uske paanch hisse hain: agent, environment, states, actions, rewards aur policy.

Return = r_0 + γ·r_1 + γ²·r_2 + ... — discounted sum of rewards

Markov decision process (MDP) iska mathematical framework hai. Value functions V(s) aur Q(s,a) batati hain ki ek state ya state-action pair kitna achha hai. Bellman equation in values ko ek doosre se jodti hai.

  • Exploration vs exploitation: naya try karo ya jo pata hai use hi karo?
  • Model-free vs model-based: environment ka model banao ya seedha experience se seekho?
  • Tabular methods — Q-learning aur SARSA: Q ko observed reward plus discounted next value ki taraf move karo.
Q(s,a) ← Q(s,a) + α [r + γ·max Q(s',a') − Q(s,a)] — Q-learning update
Exploration-exploitation har agent ka dilemma hai: hamesha safe kheloge to naya kuch nahi seekhoge; hamesha naya try karoge to jo pata hai wo bhi barbaad kar doge.

Interview FAQs

36 interview FAQs — current-era interviews ke liye, kitab ke concepts par based.

01One-hot encoding aur word embeddings me asal farak kya hai?
One-hot me har word ek lamba sparse vector hota hai jisme sirf ek 1 hota hai — meaning bilkul nahi hoti, aur 'pizzeria' aur 'restaurant' utne hi door hote hain jitne 'pizzeria' aur 'car'. Embeddings me words chhote dense vectors hote hain, aur similar contexts me aane wale words paas hote hain — isliye meaning geometry me aa jati hai. Interview me ye bhi batao ki one-hot ka dimension vocabulary ke saath badhta hai, jabki embedding ka dimension fixed rehta hai (jaise 300).
02TF-IDF kaam kaise karta hai aur ye BoW se behtar kyun hai?
TF-IDF term frequency ko is baat se weight karta hai ki word kitne documents me aata hai — common words ka weight kam, distinctive words ka zyada. Formula hai TF × log10(total_docs / docs_with_word). BoW sirf counts gin-ta hai, isliye 'the' jaise common words bhi bade counts de dete hain. TF-IDF se search aur retrieval me relevant documents upar aate hain, aur yehi idea BM25 jaise rankers ki neev hai.
03Word2vec self-supervised kaise hai — labels kahan se aate hain?
Word2vec ko koi bahar se labels nahi chahiye — text khud hi training data hai. Model ek word ko uske context se predict karta hai (ya ulta), aur training ko binary yes/no sawaal ki tarah frame kiya jata hai: 'kya ye word is context me belong karta hai?' Score dot product se, sigmoid se, aur training negative sampling aur cross-entropy loss se hoti hai. Code me Gensim Word2Vec skip-gram (sg=1) aur vector_size=100 ke saath istemal hota hai.
04Cosine similarity dot product se behtar kyun hai?
Dot product vector ki length ke saath badhta hai — lambe ya frequent vectors ko favour karta hai aur unbounded hota hai. Cosine similarity angle ka cosine hai: -1 se 1 ke beech, scale-invariant (length se farak nahi padta) aur tez. Isliye embeddings compare karne ke liye cosine standard hai. Lekin yaad rakho: cosine bhi antonyms ko alag nahi kar sakta, kyunki opposites similar contexts me aate hain.
05RNN me vanishing gradient problem kya hai?
RNN me gradient backpropagate hote waqt har step par multiply hota hai — lambi sequences par wo ya to gayab (vanish) ho jata hai ya explode ho jata hai. Isliye RNN door ki cheezein bhool jata hai — book kehti hai plain RNN lagbhag 7 steps tak yaad rakh sakta hai. Isi problem ke liye LSTM aaya, jiske gates cell state ko protect karte hain aur lagbhag 100 steps tak yaad rakh sakta hai.
06LSTM ke teen gates kya karte hain?
Forget gate (f_t) tay karta hai purani cell state me se kya bhoolna hai, input gate (i_t) aur candidate (g_t) tay karte hain nayi information kya jodni hai, aur output gate (o_t) tay karta hai cell state se kya output banana hai. Gates ke beech element-wise (Hadamard) multiplication hota hai, aur network do states rakhta hai: h (short-term) aur c (long-term). Initialisation 1 hoti hai.
07GRU LSTM se kab behtar hai?
GRU me sirf do gates hote hain (update gate z_t aur reset gate r_t) aur ek hi state (h), isliye uske parameters kam hote hain aur training tez hoti hai. Jab performance same ho to GRU chuno — kam parameters, tez training. LSTM tab chuno jab bahut lambi memory chahiye. Blend formula hai h_t = z ⊙ h(t-1) + (1-z) ⊙ h~, jahan z_t forget ka role nibhata hai.
08Attention mechanism ne seq2seq ka bottleneck kaise toda?
Seq2seq me encoder poori sentence ko ek fixed-size vector me compress karta tha — bottleneck. Attention me decoder har output step par har encoder state ko score karta hai (e_ij = score(s(i-1), h_j)), softmax se weights banata hai, aur context vector c_t = Σ a_ij·h_j banata hai. Matlab har step par naya context — koi fixed vector nahi, interpretable weights, aur lambi sentences par behtar performance.
09Self-attention ka formula kya hai aur √d_k se divide kyun karte hain?
Formula hai Attention(Q,K,V) = softmax(QK^T / √d_k)·V, jahan Q = XW_Q, K = XW_K, V = XW_V. Bina scaling ke dot products bahut bade ho jate hain, softmax saturate ho jata hai aur gradients shrink ho jate hain. √d_k se divide karne se gradients zinda rehte hain. Multi-head me kai heads parallel chalte hain — har head alag relation dekhta hai — phir concatenate karke linear projection lagti hai.
10Transformer block ke andar kya-kya hota hai?
Har block me multi-head self-attention hota hai, phir feed-forward network (FFN(x) = max(0, xW1+b1)W2+b2, ReLU ke saath), aur har ek residual connection aur layer normalisation se wrapped hota hai: H = LayerNorm(X + MHSA(X)), phir H = LayerNorm(H + FFN(H)). Residual connections loss landscape ko smooth karte hain, isliye 96 blocks tak ke stacks train ho pate hain. Shuruaat me tokenisation plus positional encoding (sine/cosine) hoti hai.
11Encoder-only, decoder-only aur encoder-decoder me farak kya hai?
Encoder-only (BERT) bidirectional hota hai — har word aage aur peechhe dono dekh sakta hai, classification ke liye best. Decoder-only (GPT) causal hota hai — sirf peechhe dekh sakta hai, generation ke liye best. Encoder-decoder (translation) dono karta hai — encoder samajhta hai, decoder banata hai, aur cross-attention se decoder encoder ko dekhta hai. Masked attention decoder me future ko block karta hai taaki model cheat na kare.
12Teacher forcing kya hai aur iski problem kya hai?
Teacher forcing me training ke dauran true previous tokens feed kiye jate hain — model ko sahi jawab dikha kar sikhaya jata hai, aur training parallel hoti hai. Problem hai exposure bias: inference me model ko apne hi output par bharosa karna padta hai, jo training me kabhi nahi hua. Isliye training me achha model inference me kabhi-kabhi bhatak jata hai.
13Greedy decoding, top-k aur top-p me kya farak hai?
Greedy har step par argmax leta hai — sabse likely token — lekin repetitive ho jata hai. Sampling probability se sample karta hai. Top-k sirf top k tokens me se sample karta hai (k fix karna padta hai). Top-p (nucleus) cumulative probability p tak ke tokens leta hai — adaptive hai, isliye behtar. Temperature 1 se neeche distribution sharp karta hai (kam variety, zyada coherence) aur 1 se upar flat karta hai (zyada variety, kam coherence).
14BERT aur GPT me asal farak kya hai?
BERT masked language modelling karta hai — 15% tokens mask karke predict karta hai, bidirectional hai, aur samajhne (classification, QA) me best hai. GPT causal language modelling karta hai — sirf peechhe dekh kar agla token predict karta hai, aur generation me best hai. Dono ka attention ek hi hai — farak sirf itna hai ki BERT aage bhi dekhta hai, GPT nahi. BERT ko train karne me 64 TPUs aur 4 din lage the.
15Knowledge distillation kaise kaam karti hai?
Distillation me ek bada teacher model ek chhote student ko sikhata hai — sirf hard labels nahi, teacher ki soft probabilities bhi. Code me distillation loss temperature 2.0 ke saath istemal hoti hai: pehle teacher inference chalao, phir student ko train karo. Figure dikhati hai ki teacher aur student ki confusion matrices kareeb-kareeb ek jaisi hain — matlab student ne teacher ka zyada tar knowledge pakad liya, kam size me.
16Chinchilla finding kya hai?
Chinchilla finding kehta hai ki data aur parameters ko saath-saath scale karna chahiye — ek chhota model jo zyada tokens par train hua ho, bade under-trained model ko hara sakta hai. Scaling laws kehte hain performance power law se improve hoti hai (L(N), L(D), L(C)), lekin model apne size ke liye under-trained ya over-trained ho sakta hai. Sirf bada model banana kaafi nahi hai — data bhi utna hi badhao.
17Emergent abilities kya hain — aur in par debate kyun hai?
Emergent abilities wo hain jo achanak ek scale threshold ke baad dikhai deti hain: arithmetic ~10B parameters ke upar, few-shot learning aur logical deduction ~100B ke upar, causal judgement ~500B ke upar. Debate ye hai ki emergence sach me achanak aati hai ya partly measurement artefact hai — ho sakta hai ability pehle se ho, bas hamara metric use achanak dikhane laga ho. Interview me dono side batao.
18LoRA kaise kaam karta hai aur ye poori fine-tuning se behtar kyun hai?
LoRA frozen weight matrix par ek low-rank update jodta hai — poora model train karne ke bajaye sirf chhota update train hota hai. GPT-3 175B ke example me sirf ek chhota fraction parameters train hote hain. Fayda dohra hai: adaptation sasti hoti hai aur forgetting kam hoti hai, kyunki original weights chhede hi nahi gaye. Adapters chhoti trainable layers daalte hain (BERT ke ~3.6% parameters), aur prefix tuning sirf soft prompts seekhti hai.
19RLHF ke teen stages kya hain aur DPO isse kaise alag hai?
RLHF ke teen stages hain: supervised fine-tuning (SFT), reward model (human preference pairs se), aur PPO optimisation — KL penalty ke saath jo policy ko SFT model ke kareeb rakhta hai. DPO reward model aur PPO dono ko hata kar ek direct loss istemal karta hai, jo (prompt, worse answer, better answer) pairs par chalti hai. DPO simple aur stable hai, RLHF zyada established hai — dono ka goal ek hai: model ko human preference se align karna.
20Agent chatbot se kaise alag hai?
Chatbot sawal ka jawab deta hai; agent kaam karke deta hai. Agent ke paas chaar properties hoti hain: autonomy (khud kaam kare), reactivity (environment badle to react kare), pro-activeness (goal ki taraf initiative le), aur social ability (doosron se communicate kare). Agent perceive karta hai, reason karta hai aur action leta hai — brain (LLM), perception (inputs) aur action (tools) ke saath. ReAct loop (thought → action → observation) iska core pattern hai.
21BM25 kya hai aur ye TF-IDF se kaise behtar hai?
BM25 classic sparse ranker hai: term frequency ka saturation (ek word 100 baar aane se 10 guna zyada important nahi hota), length normalisation b = 0.75 ke saath, aur k 1.2–2 ke range me. TF-IDF se behtar isliye hai kyunki wo frequency ko saturate karta hai aur document length ko normalise karta hai — lamba document sirf isliye upar nahi aata kyunki usme words zyada hain.
22Bi-encoder aur cross-encoder me kya trade-off hai?
Bi-encoder query aur document ko alag-alag encode karta hai — tez hai, kyunki documents pehle se encode karke rakhe ja sakte hain, lekin accuracy kam hai. Cross-encoder dono ko saath encode karta hai — accuracy zyada, lekin dheema hai. Practical pattern: bi-encoder se 100 candidates lao, cross-encoder se top 5 chuno. Yehi combination Chapter 6 me re-ranking ke naam se aata hai.

Indexing (documents ko chunks me todo, embed karo, store karo), retrieval (sawal ke liye relevant passages lao), aur generation (passages + sawal se jawab banao). Formula hai p(x) = Π p(x_i | Pr; R; q; x_
24Chunking RAG me itni important kyun hai?
Chunking tay karta hai ki retrieval ko kya milega — chunk bahut bada ho to irrelevant content aa jata hai, bahut chhota ho to context toot jata hai. Strategies hain: fixed-size, overlapping, context-aware, recursive, hierarchical, semantic, k-means, proposition-level, statistical merging aur multimodal. Guidelines: document structure se align karo, resources optimize karo, context window ka samman karo, aur query pattern se match karo.
25MAP aur MRR kya naapte hain?
Precision = retrieved-relevant / retrieved, recall = retrieved-relevant / all relevant. MAP (mean average precision) saare relevant results ki ranking dekhta hai — worked example me precisions 1, 0.67 aur 0.6 se AP 0.76 aata hai, aur teen queries (0.76, 0.5, 0.67) ka MAP 0.64 hai. RAGAS poori pipeline ko naapta hai: faithfulness, context recall, context precision, relevancy, entity recall aur answer correctness.
26RAG vs fine-tuning — kab kya chunein?
RAG jeetta hai knowledge updates, data processing, customisation, interpretability, resources, hallucinations aur privacy par. Fine-tuning jeetta hai jab model ka behaviour ya style deeply badalna ho. Rule: RAG knowledge ke liye, fine-tuning behaviour ke liye. Dono ko combine bhi kar sakte ho — RAG knowledge ke liye, fine-tuning behaviour ke liye. Movie agent me RAG se grounded recommendations milti hain, fine-tuning se nahi.

HyDE (Hypothetical Document Embeddings) me pehle model se ek hypothetical answer document generate karwate hain, phir us answer se search karte hain. Hypothetical answer me wohi words honge jo asal answer me honge — isliye search behtar hota hai. Ye query expansion ka ek clever tareeka hai: user ki pehli wording rarely behtareen search query hoti hai, isliye sawal ko behtar banao, phir search karo.
28Self-RAG kya hai aur ye normal RAG se kaise alag hai?
Self-RAG me model khud decide karta hai ki kab retrieve karna hai — har sawal par retrieve karna zaroori nahi hai — aur generate karne ke baad apne output ko khud critique bhi karta hai. Ye advanced augmentation hai: contextual compression, parent/child retrieval aur summarisation ke saath. Chapter in techniques ko latency, cost aur accuracy se compare karta hai.
29Knowledge graph RAG se kaise alag hai?
RAG text chunks par chalta hai — flat, similarity-based. Knowledge graph entities ko typed relations se jodta hai — triples (subject, predicate, object) ke roop me. Graph structured, queryable aur explainable hai: tum path dikha sakte ho. GraphRAG multi-hop questions par behtar hai, jahan jawab ke liye do ya zyada linked facts chahiye, aur relation questions par — 'X aur Y ka kya connection hai?'
30Cypher query language kya hai?
Cypher Neo4j graph database ki query language hai. Nodes aur relationships Cypher se banaye jate hain, aur MATCH se patterns likh kar RETURN se results lete hain. Example: MATCH (f:Film)-[:DIRECTED_BY]->(d:Person) RETURN f.title, d.name. Path queries me [*1..3] ka matlab hai 1 se 3 hops tak ka path. LLM natural-language sawal ko Cypher me badal kar graph se jawab la sakta hai.
31GraphRAG flat RAG se kab behtar hai?
Jab jawab ek hi document me nahi hai — multi-hop questions, jahan do ya zyada linked facts chahiye — aur jab sawal entities ke relations ke baare me ho. GraphRAG documents se entities aur relations extract karke graph banata hai, relevant subgraph retrieve karta hai (sirf text chunks nahi), aur usse generate karta hai. Flat RAG single-hop factual questions par kaafi hai.
32RL me exploration vs exploitation kya hai?
Exploration matlab naya try karna — jo pata nahi wo seekhna. Exploitation matlab jo pata hai use hi karna — best action lena. Hamesha safe kheloge to naya kuch nahi seekhoge; hamesha naya try karoge to jo pata hai wo bhi barbaad kar doge. Q-learning aur SARSA tabular methods hain jo Q ko observed reward plus discounted next value ki taraf move karte hain. Bellman equation values ko ek doosre se jodti hai.
33DQN, PPO aur actor-critic me kya farak hai?
DQN neural network se Q ko approximate karta hai — experience replay aur target networks use stabilise karte hain. Policy gradients (REINFORCE) policy ko directly approximate karte hain. Actor-critic dono combine karta hai — actor action leta hai, critic evaluate karta hai. PPO stable, clipped policy-gradient method hai jo practice me sabse zyada istemal hota hai, RLHF me bhi.
34Reward hacking kya hai?
Reward hacking tab hota hai jab policy reward badhane ka sasta tareeka dhoondh leti hai — bina kaam kiye score badha leti hai. Example: model lamba jawab dekar reward badha le, kyunki reward model ko lamba jawab pasand hai. LLM agents me reward human, verifier ya environment se aata hai (jaise test pass hona). Isliye reward design karna hi aadhi RL hai — aur KL penalty (RLHF me) policy ko SFT model ke kareeb rakhta hai taaki wo hack na kare.
35Single-agent vs multi-agent — kab kya chunein?
Single agent simple hai — ek decision chain, kam cost aur latency, lekin single point of failure. Multi-agent me capability aur fault tolerance zyada hai, lekin cost, latency aur communication overhead bhi zyada hai. Table 11.1 ke hisaab se koi clear winner nahi hai. Rule: shuruaat single agent se karo; multi-agent tab jab single agent ki limits dikhne lagein — jaise travel planner me flights, hotels, activities aur budget alag specialists chahiye.
36Agent application deploy karte waqt kin cheezon ka dhyaan rakhein?
Backend me agent, tools, prompts aur memory ek service ki tarah assemble hote hain; API endpoints sawal lekar agent loop chalate hain aur jawab sources ke saath dete hain. Error handling aur timeouts zaroori hain — bina timeout ke ek stuck LLM call poora server rok dega. Docker se containerise karo, API keys environment variables me rakho (kabhi code me nahi), aur testing (unit + end-to-end) aur monitoring (latency, failure rate, hallucination signals) lagao.
