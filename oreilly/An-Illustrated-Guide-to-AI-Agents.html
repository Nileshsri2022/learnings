Preface — Book kis liye hai

Ye book un logon ke liye hai jo AI agents ko samajhna aur banana chahte hain, sirf use karna nahi. Software developers, data scientists, aur field me aane wale students aur researchers — jinhe LLMs, Python aur machine learning ki basic samajh hai, lekin agent banane ka pehle se koi experience nahi hai.

Book ki shuruaat ek seedhi baat se hoti hai: agent ek single model call nahi hai. Agent ek system hai — ek language model jo reason karta hai, uske saath memory, tools, planning aur reflection, sab ek loop me bandhe hue: environment ko perceive karo, us par act karo, result ko observe karo, aur phir se aage badho.

Poori book me ek hi chhota agent saath-saath banta hai — TinyAgent. Har chapter me usme ek naya building block judta hai, taaki har naya idea turant working code me dikhe. Illustrations yahan sirf decoration nahi hain — zyadatar concepts pehle tasveer se samjhaye gaye hain, phir code se.

Chapter 1 — Introduction: Agent kya hota hai

Ek agent wo system hai jo environment ko perceive karta hai, uske baare me reason karta hai, aur goal ki taraf badhte hue us par act karta hai — kai steps tak, bina har step par bataye hue. Ek plain LLM call jo ek jawab dekar ruk jaye, wo agent nahi hai. Ek loop jo result dekh kar dobara act kar sake, wo agent hai.

Single-turn vs agent loop

Figure 1-1 ek single-turn interaction dikhata hai: user prompt bhejta hai, model jawab deta hai, aur baat wahin khatam. Figure 1-2 agent loop dikhata hai: prompt aur goal model ko milte hain, model ek action chunta hai, action environment ko badalta hai, observation wapas aata hai, aur loop tab tak chalta hai jab tak goal poora na ho ya limit na aa jaye.

Agent ki vocabulary — Figure 1-3

Classic agent wali bhasha LLM agent par aise map hoti hai:

Classic agent termLLM agent me matlab
Brain / agent programLLM — jo decide karta hai ki aage kya karna hai
ActuatorsTools — search, file likhna, code chalana, message bhejna
SensorsContext — user message, tool outputs, file contents, retrieved facts

Environment wo kuch bhi hai jise agent observe kar sakta hai aur badal sakta hai — ek web page, file system, database, terminal, API, game, ya robot ke through physical duniya. Figure 1-4 ek kitchen jaise environment me agent ko dikhata hai: wo state sense karta hai aur objects ko move karke act karta hai.

Software agent ke liye sensors wo text hai jo use milta hai (user message, tool output, file contents) aur actuators wo tools hain jinhe wo call kar sakta hai. Robot ke liye wahi loop cameras/microphones (sensors) aur motors (actuators) se chalta hai.

Agency vs automation: ek script ek fixed sequence chalata hai. Ek agent sequence khud chunta hai — uncertainty ke beech decision-making, feedback ke saath. Ye farak hi agency hai.

The TinyAgent — pehla version

Book ka running example chhote-chhote steps me banta hai. Figure 1-5 uska sabse minimal roop dikhata hai: ek model ke around ek loop. Pehla version jaan-boojh kar abhi agentic nahi hai — ek call, koi tool nahi, koi memory nahi.

Python · TinyAgent — pehla version (notes se reconstruct)
class TinyAgent:
    def __init__(self, model, max_steps=10):
        self.model = model
        self.max_steps = max_steps

    def run(self, prompt):
        response = self.model.generate(prompt)
        return response

Model ke roop me book Gemma models ko default local/open-weight choice banati hai, jo OpenAI-compatible endpoint (jaise Ollama / LM Studio / llama.cpp) se access hote hain — taaki wahi code model badal kar bhi chal jaye. Figure 1-6 LLM ko reasoning engine ke roop me dikhata hai.

Figure 1-7 me ek Messages class / conversation history judti hai: agent ab tak ki baat-cheet ko save karta hai aur har turn par wapas bhejta hai. Figure 1-8 batata hai ki single-turn exchange khatam hote hi sab bhool jata hai, jabki multi-turn exchange me history rehti hai — isliye "aur doosra wala kaisa hai?" jaise follow-up samajh me aate hain. TinyAgent update hota hai: messages store karta hai, har user turn aur model reply ko append karta hai. Figure 1-9 is back-and-forth ko dikhata hai — jaise user joke maange, phir ek follow-up jo sirf history ke saath samajh aaye.

An Agentic System — Figure 1-10 aur 1-11

Zoom out karke dekho to agent program ek bade system ke andar baitha hai — user, environment, tools, memory stores, aur model. Behaviour sirf model se nahi, poore system se banta hai. Figure 1-11 un components ki list deta hai jo book aage jodti hai: LLM, memory, tools, planning, reflection, evaluation.

Scaffolding (harness): model ke aas-paas ka code aur prompts — loop, tool parsing, history handling. Alag-alag harness (code-based, hosted, terminal-based, UI-based, personal-assistant) ek hi model se bilkul alag agents bana dete hain. Naam wale examples: Claude Code, OpenAI Codex CLI, Gemini CLI, OpenCode, OpenClaw, Cursor, Windsurf, GitHub Copilot, Antigravity, Manus, Replit, v0, Smolagents, Pydantic AI, LangGraph, Hermes Agent.

Agentic applications — ye itne useful kyun hain?

  • Deep research (Figure 1-12): agent search karta hai, kai sources padhta hai, synthesis karta hai aur cite karta hai — jaise kisi topic par Google Scholar / arXiv se research karna, sirf memory se jawab dene ke bajaye.
  • Coding (Figure 1-13): repository me code likhna, test karna aur fix karna — jaise OpenAI Codex / Claude Code karte hain.
  • Automation (Figure 1-14): multi-step digital kaam — booking, filing, data entry, monitoring — jo warna kai manual steps maangta.
  • Common pattern (Figure 1-15): ek goal jise kai steps, tool use, aur wapas aane wale results ke hisaab se adapt hone ki zaroorat ho.

Autonomy — spectrum, switch nahi

Autonomy ka matlab hai: agent bina poochhe, apne aap, kitna kar sakta hai. Ye ek spectrum hai, on/off switch nahi (Figures 1-16–1-18).

  • Level 0 — No autonomy (Figure 1-19): human sab kuch karta hai; model sirf suggest karta hai.
  • Level 1 — Assisted (Figure 1-20): agent draft karta hai, human har step approve karta hai.
  • Level 2 — Supervised autonomy: agent clear limits ke andar act karta hai aur checkpoints par check-in karta hai.
  • Level 3 — Full autonomy (Figure 1-21): agent goal ko end-to-end pursue karta hai aur report karta hai; human goal aur guardrails set karta hai.

Orchestrated workflows full autonomy se neeche hote hain: human ke design kiye hue agent steps ka fixed sequence. Level jaan-boojh kar chunna chahiye — zyada autonomy mehnat bachati hai, lekin ek galti ki keemat bhi badha deti hai.

The agent program — Figure 1-22 aur 1-23

Agent program wo policy hai — ab tak sense ki hui har cheez ko dekh kar, agla action kaun sa? LLM agent me ye policy khaas taur par model + system prompt + tools + history se banti hai. Figure 1-23 program ko ek loop ke roop me dikhata hai: observe → think → act → observe…

Step aur trajectory (Figures 1-24, 1-25): ek step = ek thought + ek action + uska observation. Steps ka poora sequence trajectory kehlata hai. Trajectories hi wo unit hain jinhe aage wale chapters evaluate karte hain aur jinse agent seekhta hai.

Responsible agent development and usage — Figures 1-26, 1-27

Wahi capabilities jo madad karti hain, nuksaan bhi pahuncha sakti hain — confidently present kiye gaye hallucinated facts, scale par misinformation, real side-effects wale actions (mail bhejna, paise kharch karna, files delete karna), aur tools ke through private data ka leak.

Book poori tarah ye guardrails recommend karti hai — ye afterthought nahi, autonomy chunne ka hissa hain:

  • Irreversible ya costly actions ke liye human-in-the-loop approval.
  • Tools ke liye least privilege — sirf utni permission jitni zaroorat hai.
  • Trajectories ko log karna, taaki behaviour ko audit kiya ja sake.
  • Agent ko wo credentials ya data na dena jo use chahiye hi nahi.

Summary (Chapter 1)

Agent perceive karta hai, reason karta hai aur goal ki taraf loop me act karta hai. Uska core ek LLM hai, lekin uske aas-paas ka system — memory, tools, planning, reflection — hi use agent banata hai. TinyAgent ek-ek component karke badhega, aur autonomy ka level uske actions ke risk ko dekh kar chunna chahiye.

Chapter 2 — Large Language Models

Ek LLM wo model hai jo ab tak ke tokens ko dekh kar agla token predict karne ke liye train hua hai — autoregression. Har step par ye vocabulary par ek probability distribution deta hai; usme se sample karke text banta hai.

LLM kya hai, token kya hai

Figure 2-1 next-token idea ko "The cat sat on the ___" wale sentence se dikhata hai: iske baad model "mat" ko high probability deta hai aur baaki continuations ko kam. Tokens (Figures 2-2, 2-3): text sub-word pieces me toota hai. Example "Hello, world!" tokenised dikhaya gaya hai — aur point ye hai ki ek word ek token nahi hota: common words ek token ho sakte hain, rare words kai tokens, aur token count hi cost aur context limit decide karta hai.

Input aur output tokens: prompt input tokens hai; generate kiya gaya jawab output (completion) tokens hai. Dono context window me count hote hain aur hosted models me price me bhi.

The Transformer — Figure 2-4 aur 2-5

Figure 2-4 architecture ko ek nazar me dikhata hai: embedding/tokenizer stage, Transformer blocks ka stack, aur language-modeling (LM) head jo final hidden state ko wapas vocabulary probabilities me map karta hai. Figure 2-5 ek forward pass trace karta hai: tokens → embeddings → blocks → logits → sampled token, jo phir agle token ke liye input ki tarah feed hota hai.

Tokenizer + LM head: tokenizer text ko integer IDs me map karta hai (start/end, padding aur chat templates ke liye special tokens ke saath); LM head ek bada linear layer hai (vocabulary × hidden size) plus softmax.

Decoding strategy: greedy (hamesha sabse likely token), temperature sampling (zyada temperature = flatter distribution = zyada varied/risky text), top-k aur top-p (nucleus) sampling jo sample karne se pehle candidate set ko restrict karte hain.

Transformer block ke andar — Figures 2-6–2-10

Har block me self-attention hota hai (har token doosre tokens se information le sake), uske baad ek feed-forward network (MLP), dono residual connection aur normalisation se wrapped — book isko aise draw karti hai: input → attention → add & norm → feed-forward → add & norm → output.

Self-attention kaise kaam karta hai — Figures 2-11–2-16

Figure 2-11 ek sentence dikhata hai jisme ek word se un words tak arrows hain jin par wo attend karta hai. Har token ke liye learned projection matrices se teen vectors bante hain:

VectorSawaalMatlab
Query"Main kya dhoondh raha hoon?"Token kya chahta hai
Key"Main kya offer karta hoon?"Token kya provide karta hai
Value"Main kya contribute karta hoon?"Token ka actual content

Relevance = query aur key ka dot product, scaled aur softmax se guzra hua; output = values ka weighted sum. Ek worked example me score kiya gaya hai ki "it" ek sentence me candidate nouns par kitna strongly attend karta hai.

Multi-head attention: kai attention heads parallel chalte hain, har ek alag tarah ka relation seekhta hai (jaise syntax vs coreference), aur unke outputs concatenate hote hain.

Feed-forward network: har token position par independently lagne wala two-layer MLP — hidden size ko expand karta hai (aksar ×4) phir wapas project karta hai, ek non-linearity ke saath. Model ka zyadatar stored "knowledge" yahin rehta hai.

KV-caching (Figures 2-17–2-19): naye token ke liye attention ko sirf past tokens ke keys/values chahiye hote hain, isliye unhe recompute karne ke bajaye cache kar liya jata hai. Cache sequence length ke saath badhta hai aur ek bada memory cost hai; prefix-caching / prompt-caching shared prompt prefix ke liye cache reuse karta hai.

Zyada efficient self-attention: Multi-Query Attention (MQA) saare query heads ke liye ek hi key/value head share karta hai; Grouped-Query Attention (GQA) kam KV heads share karta hai; Flash Attention poora attention matrix memory me banaye bina, tiles me recompute karke attention karta hai. Sab speed/memory ke liye thodi quality ya complexity trade karte hain.

Training ke dauraan gate scores me Gaussian noise add kiya jata hai taaki exploration badhe. Open-weight MoE implementations me Nemotron 3 aur Qwen-style MoEs ka naam hai.

Multi-head Latent Attention (MLA) aur DeepSeek Sparse Attention (DSA)

MLA (Figures 2-27–2-31): har head ke liye poore keys aur values cache karne ke bajaye, model har token ke liye ek hi low-rank compressed "latent KV" vector cache karta hai, plus ek latent query, aur head-specific keys/values ko on the fly reconstruct karta hai. Isse lambi contexts ke liye KV cache bahut chhota ho jata hai. Ye Rotary Position Embedding (RoPE) ko decoupled form me use karta hai, aur ye ek badi wajah hai ki DeepSeek models lambe contexts ko saste me serve kar sakte hain.

DSA (Figures 2-32–2-33): lambe sequences ke liye sparse attention — ek Lightning Indexer har query ke liye sabse relevant token blocks chunta hai, aur ek Top-K Selector sirf top-k blocks ko attend karne ke liye rakhta hai, taaki attention cost poore sequence par quadratic na badhe.

Figure 2-34 context me rakhta hai: context badhne par attention cost hi bottleneck hai, aur MLA/DSA iske do alag jawab hain — cache ko compress karo vs kam tokens par attend karo.

Training — pre-training, SFT, RL

Pre-training (Figures 2-35–2-37): ek bade, diverse text corpus par language modelling. Base model grammar, facts, reasoning patterns aur style seekh leta hai, lekin abhi helpful assistant nahi hai — wo sirf text continue karega. GPT-3 base model ka classic example hai.

Post-training — Supervised fine-tuning / SFT (Figure 2-38): instruction/response pairs par fine-tune karna (instruction-tuning, jaise Flan-PaLM). Model helpful answers ka format seekhta hai. Worked example me ek prompt/completion pair dikhaya gaya hai jisme loss sirf completion tokens par compute hota hai.

Post-training — Reinforcement learning (Figures 2-39–2-40): SFT ke baad, model ko ek reward signal ke against aur tune kiya jata hai. RLHF human preference rankings se seekhe gaye reward model ka use karta hai; RLVR (RL with verifiable rewards) automatically check hone wale rewards use karta hai, jaise unit test pass hona ya maths answer match karna — Chapter 3 ke reasoning models ka route.

GRPO — Group Relative Policy Optimization (Figures 2-41–2-43): alag value/critic model ki jagah, GRPO ek hi prompt ke liye completions ka ek group sample karta hai, har ek ko score karta hai, aur group ke mean aur standard deviation ko baseline banata hai: advantage = (reward − group mean) / group std. Chapter ka worked reward example: format reward 0.3 (required <think>/<answer> tags use karne par) + accuracy reward 0.7 (sahi jawab) = 1.0 total. Galat format ya galat jawab wali completion kam score karti hai, aur policy group ki behtar completions ki taraf nudge hoti hai, KL penalty ke saath jo use reference model ke paas rakhta hai.

Reward models (Figure 2-44): ek Outcome Reward Model (ORM) sirf final answer ko score karta hai; ek Process Reward Model (PRM) intermediate reasoning steps ko score karta hai. PRMs dense feedback dete hain lekin step-level labels chahiye hote hain.

Scaling laws (Figures 2-45–2-47): loss model size, data aur compute ke saath power law ki tarah girta hai, lekin diminishing returns ke saath. Ek mashhoor study ka point hai ki kai models apne size ke hisaab se under-trained the — Chinchilla model se ye seekh mili ki kam tokens par train kiya gaya bada model, zyada tokens par train kiye gaye chhote model se same compute par haar sakta hai. Chapter log-log plots aur rating-style comparison se ye trade-off padhna sikhata hai.

Prompt engineering aur in-context learning

  • Zero-shot: seedha poochho, koi example nahi.
  • One-shot / few-shot: prompt me ek ya kuch input/output examples do; model bina weight updates ke pattern infer kar leta hai — yahi in-context learning hai.
  • Zero-shot Chain-of-Thought: "Let's think step by step" (ya iske jaisa) add karne se model jawab se pehle intermediate reasoning karta hai, jo aksar maths/logic me kaafi sudhaar deta hai.

Chapter 3 — Reasoning Large Language Models

Reasoning ka zyadatar hissa ek test-time phenomenon hai: har question par zyada compute kharch karo (search, self-consistency, lambe traces) ya model ki distribution badlo (SFT, RL), to accuracy badhti hai — keemat par. Efficiency — chhoti, budget-aware, ya latent reasoning — iska counter-pressure hai.

Train-time vs test-time compute

Figure 3-1 dono budgets ko contrast karta hai: train-time compute ek baar kharch hota hai, deployment se pehle (model size × dataset size, FLOPs me measure); test-time compute har query par kharch hota hai, inference ke time — zyada tokens, zyada samples, ya zyada search.

Figure 3-2 shift dikhata hai: pehle gains bade training runs se aate the; ab gains ka bada hissa model ko test time par "zyada der sochne" dene se aata hai. Dual-process theory wali analogy use hoti hai: tez, sahaj jawab System 1 hai; dheema, deliberate, step-by-step reasoning System 2 hai — aur reasoning models ko tokens me baad wala karne ke liye train kiya jata hai.

Figure 3-3: ek reasoning LLM final answer se pehle <think> jaise tags ke andar kai "thinking tokens" kharch karta hai; ek non-reasoning LLM seedha jawab deta hai. Thinking trace jawab nahi hai — wo kaam hai jo jawab ko behtar banata hai.

Test-time compute ki do families — Figure 3-4

Chapter ka baaki sab kuch inhi do me se ek ka variant hai.

Search against verifiers

  • Best-of-N (Figures 3-5–3-6): N independent answers sample karo (temperature > 0 par) aur verifier jise highest score de, use rakho. Weighted Best-of-N identical answers ko unke summed scores se weight karta hai. Cost N ke saath linearly badhti hai; gains N badhne par saturate ho jate hain.
  • Self-consistency (Figure 3-7): kai reasoning chains sample karo aur majority answer lo. Worked example: kai chains alag jawab dete hain, sabse frequent jeetta hai — ye tab kaam karta hai jab model ka modal answer aksar sahi ho, aur tab fail hota hai jab model systematically galat ho.
  • Reward models (Figure 3-8): ORM vs PRM phir se, ab search ke verifiers ke roop me. PRM step-by-step search guide kar sakta hai (jaise beam search / Monte Carlo Tree Search reasoning steps par, highest-scoring partial chains rakhte hue).
  • s1: Simple test-time scaling (Figures 3-9–3-10): jaan-boojh kar minimal recipe — model ko lambe reasoning traces ke chhote set par SFT karo, phir test time par use sochte rehne par force karo ("Wait" append karke / budget forcing) ya jaldi roko. Ye simple scaling bhi maths performance sudhaarti hai, jo dikhata hai ki "reasoning" ka kitna hissa test-time behaviour hai.
  • Chain-of-Thought (Figures 3-11–3-12): model ko step by step reason karne ke liye prompt karo; Tree-of-Thoughts isko thoughts par branching search tak generalise karta hai. Beam search har step par top kuch partial chains rakhta hai.

Proposal distribution badalna

  • SFT for reasoning (Figures 3-13–3-14): high-quality reasoning traces (aksar ek strong teacher model se distil karke) par train karo, taaki student khud aise traces produce karna seekhe. Risk: student style copy kar le, bina underlying reliability ke.
  • RL for reasoning (Figures 3-15–3-17): verifiable rewards (sahi final answer, sahi format) ke saath GRPO se train karo. Chapter 2 wala reward example yahan phir aata hai: accuracy + format.
  • DeepSeek-R1 Zero (Figures 3-18–3-20): hairan karne wala result — base model DeepSeek-V3-Base se shuru karo, verifiable rewards ke saath RL lagao aur koi SFT nahi, aur reasoning behaviours khud emerge ho jate hain: self-verification, backtracking, doosra approach try karna, aur lamba sochna. "Cold start problem" ye hai ki bina kisi SFT ke, shuruwaati RL unstable hota hai kyunki model ke paas samajhdaar starting format nahi hota.

Efficient reasoning

Problem: lambe thinking traces tokens, time aur paise kharch karte hain, aur kabhi nuksaan bhi karte hain (overthinking, ya sahi early answer ko baat karke galat kar dena).

Techniques (Figures 3-27–3-31):

  • Chain-of-Draft (CoD) — poore sentences ke bajaye terse drafts likho.
  • Token-budget-aware LLMs (jaise L1, Kimi k1.5) — model ko token budget respect karne ke liye train karo, ya reward me length ko penalise karo.
  • Hybrid reasoning — model khud decide kare ki har question par chhota soche ya lamba.
  • O1-Pruner — redundant reasoning steps ko prune karo.

Chapter ka example ek lambe trace ko chhote draft me compress karke dikhata hai — wahi jawab, kam tokens.

Ye promising hai lekin inspect karna mushkil hai.

Definition (Figures 4-33–4-36): context engineering context window me daali jaane wali har cheez ka deliberate design hai — system prompt, conversation history, retrieved information, past experiences, tool outputs — kyunki context hi wo specification hai jisse model kaam karta hai.   • Evaluation of context (Figure 4-37): Needle-in-a-Haystack test (NIAH) ek fact ko lambe context me chhupata hai aur use maangta hai; RULER long-context recall/reasoning tests ka broader suite hai.   • Multi-agent systems ke liye context engineering: har agent ko apna tailored context milta hai; orchestrator ka context doosron ka summary hota hai, unki poori histories nahi — warna har agent sabki context ki keemat chukata.

Definition (Figures 6-20–6-21): reflection matlab agent apni past trajectory ko examine kare aur ek lesson nikale jise wo agli baar apply kar sake — loop ka learning step.

  • Self-improvement (Figure 6-25): general pattern — attempts generate karo, achhe ones ko rakho, un par train karo (ya lessons store karo), repeat karo. RISE ek method hai jo model ko uski apni improved trajectories par train karta hai.

TTRL (Figure 6-26): Test-Time Reinforcement Learning — test time par, ek hi problem par, kai attempts sample karo (chapter ka example 16 samples use karta hai), majority-vote answer ko pseudo-label banao, aur uski taraf ek chhota RL update karo, taaki model is problem ke liye adapt ho jaye. "Lucky hit" problem note ki gayi hai: flawed reasoning se pahuncha sahi jawab bhi reinforce ho sakta hai.

Chapter ki implementation Qwen3 aur Llama 3.1 models use karti hai.

Capability vs reliability — pass@k aur pass^k

  • pass@k (Figures 7-11–7-12): k independent attempts me se kam se kam ek succeed hone ki probability. Ye capability measure karta hai — agent kai tries milne par kya kar sakta hai. Chapter ka example: ek model (illustration me Opus 4.7) ka pass@3 = 60 hai (dikhaayi gayi units me) — wo teen tries me kam se kam ek baar task solve karta hai 60% time.
  • pass^k: saare k attempts succeed hone ki probability. Ye reliability measure karta hai — agent har baar kya karta hai. Formula combination ratio hai (n attempts me se k successes chunna): pass^k = C(c, k) / C(n, k), jahan c n attempts me se successful attempts ki sankhya hai. Ek agent ka pass@k high aur pass^k low ho sakta hai — capable lekin flaky — aur deployed agent ke liye aam taur par baad wala hi matter karta hai.
  • Reliability (Figure 7-13): wahi task kai baar repeat karo; ek production agent ko har baar succeed karna chahiye, sirf ek baar nahi.
Python · pass@k aur pass^k (notes se reconstruct)
from math import comb

def pass_at_k(n, c, k):
    # Kam se kam ek success: 1 - C(n-c, k) / C(n, k)
    if n - c < k:
        return 1.0
    return 1.0 - comb(n - c, k) / comb(n, k)

def pass_pow_k(n, c, k):
    # Saare k success: C(c, k) / C(n, k)
    if c < k:
        return 0.0
    return comb(c, k) / comb(n, k)

Encoding modalities

Text (Figure 9-4): Chapter 2 ki tarah tokenised; ek text encoder tokens ko embeddings me map karta hai.

Images — Vision Transformer / ViT (Figures 9-5–9-8): image ko patches me split karo (jaise 16×16 pixels), har patch ko flatten karo, vector me project karo, position embedding add karo, aur sequence ko Transformer encoder se chalao. CLIP (Figures 9-27–9-30): Contrastive Language-Image Pre-training. F1End Matter · Interview FAQs

Interview FAQs

AI agent interviews (current era) ke liye — foundations se lekar production tak, 36 sawaal-jawaab. Har jawaab isi book ke concepts par aadharit hai.

Q01Agent kya hota hai — ek LLM call se ye kaise alag hai?
Agent wo system hai jo environment ko perceive karta hai, reason karta hai aur goal ki taraf kai steps tak act karta hai — bina har step par bataye hue. Ek plain LLM call ek jawab dekar ruk jati hai; agent loop me observation dekh kar dobara act karta hai. Farak decision-making aur feedback hai, sirf text generation nahi. Interview me ye definition aur single-turn vs loop ka example (Figure 1-1 vs 1-2) dono do.
Q02Agent loop ke steps kya hain aur trajectory kya hoti hai?
Loop hai: perceive → think → act → observe, goal poora hone ya limit tak. Ek step = ek thought + ek action + uska observation. Steps ka poora sequence trajectory kehlata hai — aur trajectory hi wo unit hai jise evaluate kiya jata hai aur jisse agent seekhta hai. Chapter 6 ka ReAct trace iska best example hai.
Q03Autonomy ke levels kya hain — production me kaun sa level chunna chahiye?
Level 0 (koi autonomy nahi, model sirf suggest kare), Level 1 (assisted — agent draft kare, human har step approve kare), Level 2 (supervised autonomy — clear limits, checkpoints par check-in), Level 3 (full autonomy — goal end-to-end, human sirf goal aur guardrails de). Level risk dekh kar chuno: irreversible ya costly actions (mail, paise, delete) ke liye Level 1–2, safe reversible kaam ke liye Level 3. Orchestrated workflows fixed sequence hote hain, full autonomy se neeche.
Q04Scaffolding / harness kya hai aur ye agent ko kaise badalta hai?
Scaffolding model ke aas-paas ka code aur prompts hai — loop, tool parsing, history handling. Ek hi model alag harness se bilkul alag agent ban jata hai: code-based, hosted, terminal-based, UI-based ya personal-assistant harness. Examples: Claude Code, OpenAI Codex CLI, Gemini CLI, LangGraph, Smolagents. Interview point: model capability ka aadha hissa harness me hota hai.
Q05LLM agla token kaise predict karta hai — autoregression kya hai?
LLM ab tak ke tokens ko dekh kar vocabulary par probability distribution deta hai; usme se sample karke agla token banta hai, jo phir input me feed hota hai. Isi ko autoregression kehte hain. Decoding strategies: greedy (sabse likely), temperature sampling (zyada temperature = zyada varied/risky), top-k aur top-p (nucleus) sampling jo candidate set ko pehle restrict karte hain.
Q06Transformer block ke andar kya hota hai?
Har block me self-attention hota hai (har token doosre tokens se information leta hai), uske baad feed-forward network (MLP), dono residual connection aur normalisation se wrapped: input → attention → add & norm → feed-forward → add & norm → output. Uske upar tokenizer/embeddings aur neeche LM head (vocabulary × hidden size linear layer + softmax) hota hai.
Q07Self-attention me query, key aur value kya hain?
Har token ke liye teen vectors bante hain: query ('main kya dhoondh raha hoon?'), key ('main kya offer karta hoon?'), value ('main kya contribute karta hoon?'). Relevance = query·key dot product, scaled aur softmax se guzra; output = values ka weighted sum. Multi-head attention me kai heads parallel chalte hain, har ek alag relation seekhta hai — jaise syntax vs coreference.
Q08KV cache kya hai aur ye kyun zaroori hai?
Naye token ke liye attention ko sirf past tokens ke keys/values chahiye hote hain, isliye unhe recompute karne ke bajaye cache kar liya jata hai. Cache sequence length ke saath badhta hai aur bada memory cost hai. Prefix-caching shared prompt prefix ke liye cache reuse karta hai. MLA is cache ko latent vector me compress karke chhota karta hai; MQA/GQA kam KV heads share karke; Flash Attention matrix ko memory me banaye bina tiles me compute karke.
Q09Mixture of Experts (MoE) kaise kaam karta hai — dense se kya farak hai?
MoE me har block ka feed-forward network kai chhote expert networks + ek router (gate network) se replace hota hai jo har token ke liye kuch experts chunta hai. Dense model me sabhi parameters har token ke liye active hote hain; MoE me total parameters bade hote hain lekin per token sirf routed experts active hote hain — capacity badhti hai, compute per token chhota rehta hai. Keemat: routing complexity, load-balancing aur saare experts ki memory. Load-balancing loss router ko ek expert par collapse hone se rokta hai.
Q10GRPO kya hai aur ye RLHF se kaise alag hai?
GRPO (Group Relative Policy Optimization) me alag value/critic model nahi hota. Ek prompt ke liye completions ka group sample karke, har ek ko score karke, group ke mean aur standard deviation ko baseline banaya jata hai: advantage = (reward − group mean) / group std. RLHF human preference se seekhe reward model par chalta hai; RLVR automatically verifiable rewards (jaise unit test pass) par. GRPO ka worked example: format reward 0.3 + accuracy reward 0.7 = 1.0 total.
Q11Train-time compute aur test-time compute me kya farak hai?
Train-time compute ek baar kharch hota hai, deployment se pehle (model size × dataset size, FLOPs me). Test-time compute har query par kharch hota hai — zyada tokens, zyada samples, ya zyada search. Pehle gains bade training runs se aate the; ab bada hissa model ko test time par zyada der sochne dene se aata hai. Dual-process analogy: tez sahaj jawab System 1, dheema deliberate reasoning System 2.
Q12Best-of-N, self-consistency aur s1 me kya farak hai?
Best-of-N: N independent answers sample karo, verifier jise highest score de use rakho — cost N ke saath linear badhti hai, gains saturate hote hain. Self-consistency: kai reasoning chains sample karo, majority answer lo — tab kaam karta hai jab model ka modal answer aksar sahi ho. s1: minimal recipe — lambe reasoning traces par SFT, phir test time par 'Wait' append karke sochte rehne par force karo ya jaldi roko. Teeno search-against-verifiers family hain.
Q13DeepSeek-R1 Zero ka result itna striking kyun tha?
R1-Zero ne base model DeepSeek-V3-Base se shuru karke, verifiable rewards ke saath RL lagaya aur koi SFT nahi — phir bhi reasoning behaviours khud emerge ho gaye: self-verification, backtracking, doosra approach try karna, lamba sochna. Cold start problem ye hai ki bina SFT ke shuruwaati RL unstable hota hai. R1 isko fix karta hai: pehle chhota SFT cold-start, phir RL, phir synthetic data se ek aur SFT+RL round — aur phir chhote models me distil kiya ja sakta hai.
Q14Efficient reasoning ki techniques kya hain — overthinking ka kya karein?
Lambe traces tokens, time aur paise kharch karte hain aur kabhi nuksaan bhi karte hain. Techniques: Chain-of-Draft (terse drafts, poore sentences nahi), token-budget-aware LLMs (budget respect karna ya length ko reward me penalise karna), hybrid reasoning (model khud decide kare chhota soche ya lamba), O1-Pruner (redundant steps prune karo). Latent-space reasoning (Chain-of-Continuous-Thought, CODI) kuch steps ko continuous vectors me karta hai — tokens bachte hain, lekin inspect karna mushkil hai.
Q15Memory ke kitne types hain aur trimming vs summarization kab use karein?
Working/short-term memory (context window me jo hai), episodic (specific past events ka record), semantic (duniya aur user ke general facts), procedural (skills, routines — skill files), parametric (weights me baked). Agent me mapping: context window, conversation history, vector/RAG store, skill files. LLM apne aap me stateless hai — memory hi calls ke sequence ko continuing agent banati hai. Trimming sirf last N turns rakhta hai (chapter ka code last 2 turns) — sasta aur predictable, lekin purani baat bhool jata hai. Summarization history badhne par model se compact paragraph banwata hai aur summary + recent turns rakhta hai — jaise user ki flamingos wali pasand summary me bach jati hai. Trade-off: trimming sasta lekin bhoolne wala; summarization gist bachata hai lekin ek extra model call aur summary me detail loss ki keemat par.
Q16RAG pipeline kaise kaam karta hai — naive RAG se agentic RAG tak?
Ingestion: documents ko chunks me split karo, embed karo, vector database me store karo. Inference: query embed karo, cosine similarity se nearest chunks retrieve karo, prompt me daalo, generate karo. Worked numbers: EmbeddingGemma (308M params, 768-dim) — sahi document 0.6387 similarity, unrelated 0.3547. Agentic RAG me agent khud decide karta hai ki retrieve karna hai ya nahi, kya aur kitne rounds — retrieval loop ke andar tool call ban jata hai. Search-o1 searching ko thinking ke saath interleave karta hai.
Q17Context engineering kya hai — lost-in-the-middle aur context rot kya hain?
Context engineering context window me daali har cheez ka deliberate design hai — system prompt, history, retrieved info, tool outputs — kyunki context hi specification hai: jo context me nahi, model use kar hi nahi sakta. Lost-in-the-middle: lambe context me models start aur end par achha attend karte hain, beech me kharab. Context rot: zyada (khaas taur par irrelevant) material add karne se original task par performance girti hai. Fixes: re-ranking, ordering, MMR (relevance vs redundancy balance), summarisation, cache-friendly prefix.
Q18Tool kaise define karte hain — structured function calling vs natural language?
Structured function calling: model JSON Schema se match karta JSON output karta hai (naam + arguments), scaffold validate karta hai (Pydantic/jsonschema) — best practices: required vs optional, types, enums, chhoti precise descriptions. Natural language: model call prose me likhta hai, parser extract karta hai — zyada flexible, kam reliable; parser hi weak point hai. Tool design rule: ek clear purpose, descriptive naam, aur docstring jo bataye kab use karna hai — docstring hi interface ka hissa hai.
Q19Toolformer, ToolRL aur Search-R1 me kya farak hai?
Toolformer SFT hai: jahan tool call next-token prediction sudhaare, wahan call insert karke training data banao — model seekhta hai tool kab madad karta hai. ToolRL RL hai tool-use trajectories par (Qwen2.5, ~4,000 samples; reward = correctness + format) — trial-error se seekhta hai kaun si strategies kaam karti hain, isliye SFT se behtar. Search-R1 search-augmented reasoning ke liye RL hai, loss masking ke saath taaki model retrieved tokens ko predict na seekhe, sirf apne decisions ko.
Q20MCP kya hai — N×M problem ko kaise solve karta hai?
Bina standard ke har agent (N) ko har tool/service (M) ke liye custom integration chahiye — N×M kaam. MCP (Model Context Protocol) components: MCP host (application), MCP client (host ke andar connection), MCP server (ek service ke tools, resources, prompts expose karta hai). Flow JSON-RPC 2.0 hai: list karo, chuno, invoke karo, result lo. A2A/IoA agent-to-agent counterparts hain, agent card capabilities advertise karta hai.
Q21Skills kya hain aur progressive disclosure kyun matter karta hai?
Skill ek recurring task ke liye procedural knowledge ka bundle hai — instructions, scripts, resources — jo agent tab load karta hai jab chahiye ho; ye file form me procedural memory hai. Progressive disclosure: Layer 1 (~100 tokens — naam + one-line description, hamesha loaded), Layer 2 (~5,000 tokens se kam — poori SKILL.md, activate hone par), Layer 3 (bundled scripts/resources, zaroorat par). Agent us skill ki context cost nahi chukata jise use hi nahi kar raha. SKILL.md me YAML frontmatter + instructions hote hain.
Q22ReAct pattern kya hai — ek worked trajectory samjhao
ReAct Thought, Action aur Observation ko interleave karta hai, Answer tak. Example: (4.6 + 6.685) × 4 − 3.14. Thought — pehle sum chahiye; Action — add(4.6, 6.685); Observation — 11.285; Thought — 4 se multiply; Action — multiply(11.285, 4); Observation — 45.14; Thought — 3.14 subtract; Action — subtract(45.14, 3.14); Answer — 42.0. Har step checkable hai aur galat intermediate result trace me dikhta hai. Chapter me NativeReAct loop max_steps 10 ke saath Gemma 4 E4B par 325 prompt + 267 completion tokens me chala.
Q23FireAct aur ETO me kya farak hai — ReAct ko train kaise karte hain?
FireAct SFT hai: strong teacher se ReAct trajectories generate karo, chhote model (Llama-2, LoRA) ko un par fine-tune karo — behaviour cloning. ETO (Exploration-based Trajectory Optimisation) RL hai: agent khud explore karta hai, successful trajectories rakhta hai, DPO se successful ko failed par prefer karna seekhta hai (Llama-2-7B-Chat, ALFWorld). ETO SFT se behtar hai kyunki wo teacher ki nahi, agent ki apni successes aur failures se seekhta hai.
Q24Reflection ke methods — Self-Refine vs Reflexion?
Self-Refine: generate → critique (wahi model critic ki tarah) → refine, external feedback ke bina — apni galtiyon ko reinforce bhi kar sakta hai. Reflexion: teen roles — Actor (act kare), Evaluator (trajectory score kare, jaise unit tests se), Self-Reflection (verbal lesson likhe, jaise 'edit se pehle file existence check karo') jo store karke agle attempt se pehle prepend hota hai. CRITIC variant me evaluator facts check karne ke liye external tools call kar sakta hai.
Q25TTRL aur R-Zero kya hain?
TTRL (Test-Time Reinforcement Learning): test time par ek hi problem par kai attempts sample karo (example me 16 samples), majority-vote answer ko pseudo-label banao, uski taraf chhota RL update karo — model is problem ke liye adapt ho jata hai. Lucky-hit problem: flawed reasoning se pahuncha sahi jawab bhi reinforce ho sakta hai. R-Zero: Challenger (naye tasks invent kare) aur Solver (solve kare) ka coevolving system — Challenger ko reward hard-lekin-solvable, non-repetitive, well-formed tasks ke liye milta hai, bina human-labelled data ke curriculum banta hai.
Q26Benchmark scores ko critically kaise padhein — saturation aur contamination kya hain?
Saturation: scores ceiling ke paas discriminate karna band kar dete hain (SWE-bench 2% se ~70% tak 2026 me — ab wo kam informative hai). Contamination: test items training data me leak ho gaye. Harness differences: wahi model alag prompts/scaffolds par alag score karta hai. Partial credit: near-miss ki scoring ranking badal deti hai. Leaderboard Illusion: ek number in saari choices ko chhupa deta hai. Cross-check: arenas (Elo ratings) aur Artificial Analysis.
Q27Outcome evaluation ke methods — exact match, programmatic, LLM-as-judge, rubric?
Exact match: jawab expected string se match kare (MMLU-Pro example: 3 me se 1 sahi = 0.333) — paraphrases ko maaf nahi karta. Programmatic: code chala kar verify karo (unit tests; IFEval format instructions ke liye). LLM-as-judge: doosra model grade kare (example: 1.0, 0.4, 1.0 — average 0.8) — judge biased ho sakta hai (style, verbosity, order). Rubric-based: human-written rubric criteria me todta hai (coverage, correctness, clarity — 1–5) — zyada informative, zyada expensive.
Q28Trajectory evaluation kyun zaroori hai — pass@k vs pass^k kya hain?
Wahi sahi final answer achhi trajectory (efficient, sahi tool use) ya buri trajectory (lucky guess, wasted calls, harmful side-effect) se aa sakta hai — trajectory evaluation path ko score karti hai. pass@k = kam se kam ek baar k attempts me succeed karne ki probability (capability; example pass@3 = 60). pass^k = C(c,k)/C(n,k) = saare k attempts succeed karne ki probability (reliability). Capable lekin flaky agent ka pass@k high, pass^k low hota hai — production me pass^k matter karta hai.
Q29Apne evals kaise banayein — kahan se shuru karein?
Apne real kaam jaise dikhne wale 5–10 tasks se shuru karo, har ek ke liye checker likho (exact match, programmatic test, ya chhota rubric), agent chalao, evals ko regression suite ki tarah rakho. Harness: harbor. Salah: evals optimise karne se pehle banao, taaki improvements measure hon, assume na kiye jayein. Safety bhi evaluation ka hissa hai — attack success rate, refusal rate, harm score; suites: AgentHarm, ASB, AgentDojo; risk: memory poisoning aur tool outputs se prompt injection.
Q30Multi-agent patterns kaun se hain aur CAMEL aur MetaGPT kya hain?
Centralised: ek orchestrator/supervisor workers ko direct kare. Decentralised: agents peer-to-peer baat karein. Hierarchical: supervisors aur workers ki layers. Federated: independent groups loosely coordinate karein. Orchestrator goal decompose karta hai, sub-tasks assign karta hai, results synthesise karta hai. Cost example: €4/day wala orchestrator 1,691 days (15 May 2026–31 Dec 2030) me €6,764 cost karta hai. Context rule: orchestrator summary rakhe, workers sirf apna sub-task context. CAMEL: role-playing agents — instructor aur assistant agent character me converse karke task solve karte hain. MetaGPT: software-company simulation — product manager, architect, engineer, QA — SOPs aur iterative programming loop follow karte hue, shared documents se communicate karte hain. Production frameworks: AutoGen, LangGraph, CrewAI (code-first, graphs/state machines) aur n8n (visual builder). Salah: us framework ko prefer karo jiska control flow inspect kar sako.
Q31Smallville / Generative Agents kya hai — memory stream kaise kaam karta hai?
Smallville me 25 agents ek simulated town me rehte hain. Har agent ke paas memory stream hoti hai — observations ka chronological record, recency, importance aur relevance se score kiya gaya. Agent us par reflect karke higher-level conclusions banata hai aur din plan karta hai. Example: café chalane wala agent Valentine's Day party organise karta hai — behaviour memory aur reflection se emerge hota hai, script se nahi. Agent Hospital aur SimClass wahi idea doctors ki training aur classroom par apply karte hain.
Q32Theory of Mind aur social identity agents par kaise apply hote hain?
Theory of Mind: doosre agent ke beliefs, wants aur knowledge (false beliefs samet) ko model karna — jo agents doosre party ke beliefs track karte hain, wo behtar persuade aur collaborate karte hain (Change My View setting, GPT-4, Zephyr-7B, Llama-2-Chat-13B). Social identity: agents in-group/out-group bias dikhate hain — group labels cooperation rates badal dete hain, anthropomorphism effect ko amplify karta hai. Implication: agents ko ek doosre ke saamne kaise present kiya jata hai, ye unke collaboration ko badal deta hai.
Q33MLLM ke teen parts kya hain aur ViT image ko kaise encode karta hai?
Encoder modality ko vectors me badalta hai (images: ViT; audio: wav2vec/Whisper/CLAP; video: ViViT/TimeSformer). Connector un vectors ko LLM ki space me map karta hai. Generator/LLM backbone reason karta hai aur text produce karta hai. Kangaroo-cover test: bina image dikhaye model guess karta hai, dikha kar sahi jawab deta hai — multi-modal understanding input me grounded hoti hai, training se recall nahi. ViT image ko patches me split karta hai (jaise 16×16 pixels), har patch ko flatten karta hai, vector me project karta hai, position embedding add karta hai, aur sequence ko Transformer encoder se chalata hai. Output image tokens ka set hota hai jin par LLM attend kar sakta hai. CLIP iske upar contrastive learning karta hai: image aur text encoders aise train hote hain ki sahi image/caption pair highest score kare — test time par zero-shot classification, bina task-specific training ke.
Q34Connectors me kya farak hai — projection vs query-based vs fusion?
Projection (LLaVA): linear projection/MLP, simple aur sasta, lekin LLM ko image ka fixed unfiltered view milta hai; do stages — feature alignment pre-train, phir end-to-end fine-tune. Query-based (BLIP-2 Q-Former): learned query vectors cross-attention se fixed visual tokens banate hain; LLM frozen rakh kar train ho sakta hai, lekin detail kho sakta hai. Fusion (Flamingo): vision LLM ke andar gated cross-attention se fuse hota hai, tanh(α) gate ke saath — sabse rich interaction, sabse expensive aur mushkil.
Q35Coding agent ke tools aur repository map/planning kyun matter karte hain?
File manipulation (read/write/edit/list — sabse basic aur sabse dangerous), SQL tool (schema linking + semantic layer — bina semantic layer ke syntactically sahi SQL galat question ka jawab deta hai), code interpreter sandbox (E2B, Daytona, Modal — least privilege, sirf utni permissions jitni chahiye), command-line tools (tests, linters, git — allow-list + human approval), computer use tools (GUI click/type/screenshot), code search (embedding retrieval + AST search jaise ast-grep). Sandbox isliye kyunki generated code host ko nuksaan pahuncha sakta hai aur prompt injection file/data se aa sakta hai. Edit karne se pehle agent ko codebase ka map chahiye: kaun si files hain, kya karti hain, kaise depend karti hain (Aider repo map, Gitingest). Planning: pehle issue localise karo, phir patch plan karo, phir implement karo aur tests chalao — planning ko implementation se alag karne se accuracy badhti hai kyunki kharab plan kharab patch se aasani se spot hota hai. Agentless (localisation → repair → validation, koi agent loop nahi) SWE-bench par hairan karne wali had tak achha hai — hamesha strong non-agentic baseline se compare karo.
Q36Code LLMs kaise bante hain — Qwen3 Coder aur GLM-5 ke numbers kya kehte hain?
Pipeline: pre-training code (aur text) par, mid-training high-quality code aur reasoning data par, post-training SFT phir RLVR (unit tests verifier hain). Data types: unit-test data, tool-use data, multi-step trajectory data, software-engineering task data (GitHub issues + fixes). Numbers: Qwen3 Coder — 7.5 trillion tokens, 70% code; GLM-5 — 28 trillion tokens, 200K-token context; North Mini Code — 30B-parameter MoE. Distillation aur synthetic-data feedback loop do scaling mechanisms hain. Code ideal domain hai kyunki tests objectively batate hain ki program kaam karta hai ya nahi.
