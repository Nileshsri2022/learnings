Preface — Kyun khud LLM banana?

Chhota model vs bada model

Preface ek simple example se shuru hota hai: ek chhota flower classifier jo sirf do measurements (petal length aur width) se kaam karta hai, Iris data par lagbhag 90% accuracy tak pahunch jata hai — sirf do-chaar parameters se. Us model ko poora samjha ja sakta hai: kaunsa parameter kya kar raha hai, sab dikhta hai.

LLMs iske bilkul opposite hain — millions se billions parameters, aur kaafi had tak opaque. Isiliye bahut log unhe black box maan kar chhod dete hain. Kitaab ka premise hai ki samajhne ka ek hi tareeka hai: khud ek LLM banana, step by step.

Chapter 1 — Understanding Large Language Models

LLM kya hota hai? Ek bahut bada transformer-based neural network jo next word predict karna seekhta hai — aur yahi simple kaam, bade scale par, translation, summarization, code generation aur question answering jaisi taakat deta hai.

1.1 — LLM kya hota hai?

Large language model ek bada neural network hai jo transformer architecture par bana hota hai aur human language ko samajhne, generate karne aur manipulate karne ke liye design kiya gaya hai. Iski pehchan teen cheezein hain: scale (parameters ki badi sankhya), bade text corpora par training, aur generality (kai language tasks par kaam karna).

Ek chhota decision-tree ya logistic model inspect karke samjhaya ja sakta hai, lekin LLM itna bada hota hai ki aisa mumkin nahi — yahi uski “black box” reputation ki wajah hai, jise ye kitaab khatm karna chahti hai.

Ek kaam ki mental picture: LLM ek next-word predictor hai — diye gaye pehle wale words ke basis par ye har possible next word ko ek probability deta hai, phir us distribution se sample karta hai. Yahi simple objective, bade scale par, translation, summarization, code generation aur question answering jaisi abilities paida karta hai.

1.2 — LLMs ke applications

LLMs ka use hota hai: text classification (jaise spam detection), summarization, translation, information extraction, question answering, conversational agents, aur code generation.

Do worked examples kitaab deti hai:

  • Sentiment classification: model “The movie was great!” padh kar positive label deta hai, aur “The movie was terrible!” padh kar negative.
  • Summarization aur translation: wahi core model fine-tuning se naye task ke liye adapt ho jata hai.

Zor is baat par hai ki LLM sirf ek task tak limited nahi — ek hi pretrained model kai tasks ke liye adapt ho sakta hai, aur yahi pretraining ko worthwhile banata hai. Chat interface bhi usi model ke upar ek patli layer hai — andar model abhi bhi tokens hi predict kar raha hai.

1.3 — LLMs banane aur use karne ke teen stages

  1. Pretraining — bade, bina label wale text corpus par next token predict karna sikhao. Ye mehenga hota hai aur ek baar hota hai; result ek “base” ya “foundation” model hota hai.
  2. Fine-tuning — pretrained model ko chhote, task-specific dataset par aur train karo (jaise spam classification ya instruction following). Ye pretraining ke muqable sasta hota hai — aur asal me most practitioners yahi karte hain.
  3. Using / inference — taiyaar model ko chalakar text generate karo, classify karo, ya sawaal ka jawaab lo.

Key point: fine-tuning architecture nahi badalta — Chapter 6 me GPT model apni saari layers waisi hi rakhta hai, sirf ek classification head add hota hai (aur output layer replace hoti hai).

Encoder-only, decoder-only, encoder–decoder — farak kya hai?

  • Encoder-only (jaise BERT) — samajhne/classification ke liye achha; poora input dekh sakta hai.
  • Decoder-only (jaise GPT) — generation ke liye achha; sirf past dekh sakta hai. Ye kitaab ka choice hai.
  • Encoder–decoder (original transformer) — translation ke liye achha.

Farak is baat se samjho ki model sequence ka kaunsa hissa dekh sakta hai: encoder poora input dekhta hai, decoder sirf pehle wale tokens.

1.4 — Transformer architecture ko samajhna

Transformer 2017 ke paper “Attention Is All You Need” me aaya, aur isne recurrent networks ko self-attention se replace kar diya: har token sequence ke baaki saare tokens ko dekh kar unki relevance tolta hai.

Original transformer ka diagram (Figure 1.5): encoder stack (chhah encoder blocks, har ek me self-attention + feed-forward network) aur decoder stack, jinke beech encoder–decoder attention hota hai. GPT sirf decoder side rakhta hai.

Data flow, ek line me: token embeddings + positional embeddings → identical transformer blocks ka stack → final layer norm → linear output layer (har vocabulary token ke liye ek score/logit) → softmax → probabilities.

Scaling — bada kyun behtar hota hai?

Zyada parameters, zyada data aur zyada compute — teeno badhane se performance predictable tareeke se behtar hoti hai (yehi “scaling laws” ka idea hai). Isiliye field millions se hundreds of billions parameters ki taraf badha.

Practical consequence: GPT-3 jitne bade model ko train karne ki cost ka estimate lagbhag $4.6 million tha (chapter me ek Lambda estimate ke hawale se). Isiliye most readers chhota model pretrain karenge aur bade model ko fine-tune karenge.

  • Stage 1 (Chapters 2–5): text data taiyaar karo (Ch 2), attention banao (Ch 3), GPT model assemble karo (Ch 4), unlabeled text par pretrain karo (Ch 5).

Chapter 2 — Working with Text Data

Neural network ko words nahi, numbers chahiye. Is chapter me text tokens me tootta hai, tokens IDs bante hain, aur IDs se embeddings — plus position ki jaankari. Yahi GPT ka input banta hai.

2.1 — Word embeddings ko samajhna

Neural network raw words consume nahi kar sakta; words ko numbers banna padega. Sabse simple representation hai one-hot encoding — aur chapter dikhata hai ki ye kyun fail hota hai: tens of thousands words ki vocabulary se bahut lambe, sparse vectors bante hain jinme similarity ka koi sense nahi — “cat” aur “dog” utne hi door hain jitne “cat” aur “car”.

Word embeddings iska hal hain: har word ko continuous numbers ka ek chhota, dense vector milta hai (toy examples me 3–5 dimensions, asal GPT-2 small model me 768), jo training ke dauraan seekha jata hai — taaki similar contexts me use hone wale words paas aa jayein. Embedding layer asal me sirf ek lookup hai: token ID → matrix ki ek row.

2.2 — Text ko tokenize karna

Tokenization matlab text ko un units me todna jinhe model process kar sake. Pehle chapter ek simple word-level tokenizer banata hai — regular expression se (re.split, whitespace aur punctuation par) — phir uski kamzoriyan batata hai: har naye word se vocabulary badhti hai, rare words unseen rehte hain, aur punctuation handling crude hoti hai.

Phir aata hai byte-pair encoding (BPE) — GPT-2 aur GPT-3 ka subword tokenizer: common words poore rehte hain, rare words frequent subword pieces me toot jate hain (jaise “unhappiness” → “un” + “happiness”), aur koi bhi text represent ho sakta hai — made-up words bhi — kyunki pieces ek fixed vocabulary se aate hain: GPT-2 ki vocabulary size 50,257 tokens. Chapter BPE ke liye tiktoken library use karta hai.

Worked example: sentence “Hello, do you like tea?” — simple tokenizer deta hai ["Hello", ",", "do", "you", "like", "tea", "?"]. Phir ek vocabulary dictionary banti hai jo har unique token ko ek integer ID map karti hai, aur inverse mapping decoding ke liye. Key code pattern: token_ids = [vocab[token] for token in tokens] aur decoding me har ID ke liye inv_vocab[id] join karna.

Special tokens: <|endoftext|> (text ke end ko mark karne ke liye) aur <|unk|> (unknown tokens ke liye) — dono vocabulary me add kiye jate hain.

2.3 — Token embeddings banana

Language modeling ke liye data loading aise hota hai: text ko ek baar tokenize karke IDs ki ek lambi list banao, phir use input–target pairs me kaato — jahan target, input ko ek position shift karke banta hai (next token). Code me GPTDatasetV1 class (ek PyTorch Dataset) token list, max_length aur stride leti hai aur (input_chunk, target_chunk) pairs deti hai; DataLoader phir unhe batch karta hai.

Table 2.1 — stride ka asar: max_length=4 aur stride=1 par text “Hello, do you like tea?” se kai overlapping windows bante hain; stride=4 par windows overlap nahi karte aur kam bante hain.

Worked numbers: max_length=4, stride=1 par pehla input hai [15496, 11, 466, 345] (“Hello, do you”) aur uska target [11, 466, 345, 617] (“, do you like”); agla input [11, 466, 345, 617] aur target [466, 345, 617, 423] (“do you like tea”). Kitaab ki training settings (max_length=256, stride=128) me 8 windows ke har batch ki shape hoti hai 8 × 256.

Embedding layer banana: torch.nn.Embedding(vocab_size, output_dim) — weights randomly initialize hote hain aur training me seekhe jate hain.

One-hot vs embedding: one-hot vectors sparse aur fixed hote hain; embeddings dense aur learned hote hain. Table 2.2 token probabilities ki baat karti hai: model ke baad softmax output har vocabulary token ke liye ek probability deta hai — example me “do you” ke baad token “like” ki probability high hoti hai.

2.4 — Word positions ko encode karna

Transformer saare tokens ko parallel process karta hai, isliye uske paas order ka built-in sense nahi hota. Isiliye positional embeddings add ki jati hain: ek doosri embedding table, jo position (0, 1, 2, …) se index hoti hai, aur jiske vectors token embeddings me add kar diye jate hain. Dono vectors ka sum hi model ka input hota hai, aur positional vectors bhi training me seekhe jate hain.

Alternative tha original transformer ka sinusoidal positional encoding — chapter batata hai ki GPT-2 learned positional embeddings kyun use karta hai. Context length limit: GPT-2 small ko maximum 1,024 positions ke saath train kiya gaya tha, isliye model us window se aage attend nahi kar sakta jab tak use extend na kiya jaye.

  2. Regex tokenizer se tokenize karo aur vocab/inv_vocab banao.
  3. Poora text token IDs me encode karo.
  4. GPTDatasetV1 define karo (max_length/stride) aur create_dataloader_v1 banao.
  5. Token aur positional embedding layers banao aur unhe add karo.

Chapter 3 — Coding Attention Mechanisms

RNN ek-ek token karke chalta tha aur purani baat bhool jata tha. Attention har token ko seedha har doosre token se jod deta hai — aur yahi transformer ki jaan hai. Is chapter me attention ko pehle bina weights ke, phir trainable weights ke saath, phir causal mask aur multi-head tak likha gaya hai.

3.1 — Lambi sequences ko model karne ki problem

Recurrent networks text ko ek token at a time process karte hain aur poori history ko ek hi hidden state me compress karna padta hai — isliye shuru wale tokens ki jaankari fade ho jati hai. Chapter ek lambi sentence ka example deta hai jisme baad wale word ka matlab pehle wale word par depend karta hai. Attention is problem ko solve karta hai — har token seedha har doosre token ko dekh sakta hai.

3.2 — Attention se data dependencies pakadna

Attention ki definition: ek weighted average. Kisi query token ke liye, har doosre token ke saath ek similarity score nikalo (attention scores), unhe softmax se normalize karo to attention weights milte hain (jinka sum 1 hota hai), aur un weights se doosre tokens ke value vectors ko weight karo.

Chapter ek chhota numeric example deta hai — sentence “Your journey starts with one step” (6 tokens, embedding dimension 3): “journey” ke query vector ka baaki saare token vectors ke saath dot product nikala jata hai, softmax lagaya jata hai, aur weights dikhte hain — “journey” sabse zyada khud ko aur “starts” ko attend karta hai.

3.3 — Self-attention: input ke alag-alag hisson par dhyaan

Self-attention matlab ek hi sequence ke andar attention (cross-attention ke opposite, jo do sequences ke beech hota hai — jaise translation me encoder–decoder attention). Chapter pehle ise pure PyTorch me, bina trainable weights ke implement karta hai:

  1. Attention scores nikalo: inputs @ inputs.T
  2. 1/sqrt(d_k) se scale karo (key dimension ka square root) — taaki dot products zyada bade na ho jayein.
  3. Softmax lagao.
  4. Input vectors se multiply karo.

Worked numbers: 6-token example me bina scale kiye dot products lagbhag 30 tak pahunch jate hain; 1/sqrt(3) ≈ 0.577 se scale karne par wo us range me aa jate hain jahan softmax saturate nahi hota. Chapter ye bhi batata hai ki scaling factor stable gradients ke liye kyun zaroori hai.

3.4 — Trainable weights ke saath self-attention likhna

Asli attention input ke teen alag linear projections seekhta hai:

  • Query — token kya dhoondh raha hai
  • Key — token kya offer karta hai
  • Value — token kya contribute karta hai

Chapter SelfAttention_v1 class banata hai — teen nn.Linear layers (no bias), har ek toy example me 3-dimensional input ko 2-dimensional query/key/value space me map karta hai — aur compute karta hai attention_scores = queries @ keys.T, phir softmax(scores / sqrt(d_k)) @ values. Phir ise SelfAttention_v2 me refactor kiya jata hai: ek hi combined weight matrix (query, key aur value projections ko concatenate karke) — wahi computation, zyada efficient, aur final model me yahi form use hoti hai.

d_k notation: key vectors ki dimensionality — scaling factor ke liye use hoti hai.

Code, step by step

  1. Q, K, V ke liye nn.Linear layers banao.
  2. Input ko multiply karke Q, K, V nikalo.
  3. Scores nikalo: Q @ K.T.
  4. d_k ** -0.5 se scale karo.
  5. Last dimension par softmax lagao.
  6. Weights ko V se multiply karke context vectors nikalo.

Output shape verify ki gayi hai: 6 × 3 input se toy example me 6 × 2 context matrix milti hai.

3.5 — Future words ko chhupana: causal attention

Language model ko next token predict karte waqt future nahi dekhna chahiye, isliye attention matrix ko mask kiya jata hai: diagonal ke upar ki saari positions ko softmax se pehle -inf set kar diya jata hai, taaki unke weights zero ho jayein. Mask ek lower-triangular matrix hota hai (diagonal par aur uske neeche 1, upar 0), aur chapter ise torch.triu (upper-triangular mask) aur masked_fill se demonstrate karta hai.

Phir attention weights par dropout add hota hai: training ke dauraan weights ka ek random fraction (model me dropout rate 0.1, toy demonstration me 0.5) zero kar diya jata hai aur baaki ko 1/(1-rate) se scale up kiya jata hai, taaki expected sum wahi rahe. Dropout attention weights par regularization ke liye lagaya jata hai, aur inference par band kar diya jata hai (model.eval()).

3.6 — Single-head attention ko multi-head attention me badhana

Ek attention head sirf ek tarah ka relationship pakad sakta hai. Multi-head attention kai heads ko parallel chalata hai — har head ke apne Q/K/V projections hote hain — phir unke outputs ko concatenate karke ek final linear layer se model ki embedding dimension me wapas project kar deta hai.

Chapter ki MultiHeadAttention class:

  1. Input ko Q, K, V me project karo — ek linear layer size d_out * 3 (ya teen alag layers).
  2. Q, K, V ko num_heads heads me baanto — har head ki dimension d_out / num_heads hoti hai (kitaab ke model me d_out=768, num_heads=12, to har head 64-dimensional).
  3. Har head me independently causal self-attention compute karo.
  4. Heads ko concatenate karo.
  5. Output projection lagao.

Chapter grouped-query aur multi-query variants ka bhi zikr karta hai jo naye models me use hote hain, aur note karta hai ki kitaab ka implementation classic form hai.

Efficient attention par note: naive implementation poori attention matrix materialize karta hai (jo sequence length ke saath quadratically badhti hai), aur FlashAttention jaisi libraries isse bachti hain — lekin kitaab clarity ke liye explicit form rakhti hai. CausalAttention class masking, scaling, softmax aur dropout ko ek reusable module me lapet deti hai, aur yahi class Chapter 4 me reuse hoti hai.

Chapter 3 summary

Self-attention har token ke liye baaki saare tokens ke value vectors ka weighted sum nikalta hai, jahan weights softmaxed, scaled query–key dot products se aate hain; causal masking future tokens ko chhupata hai; dropout weights ko regularize karta hai; aur multi-head attention kai heads ko parallel chalakar unhe concatenate karta hai — model ko ek hi sequence ke kai “views” milte hain.

python
import torch
import torch.nn as nn

class CausalAttention(nn.Module):
    def __init__(self, d_in, d_out, context_length, dropout, qkv_bias=False):
        super().__init__()
        self.d_out = d_out
        # ek hi layer se Q, K, V (SelfAttention_v2 wala efficient form)
        self.W_query = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_key = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.W_value = nn.Linear(d_in, d_out, bias=qkv_bias)
        self.dropout = nn.Dropout(dropout)
        # causal mask: upper-triangular, diagonal ke upar 1
        self.register_buffer(
            'mask',
            torch.triu(torch.ones(context_length, context_length), diagonal=1)
        )

    def forward(self, x):
        b, num_tokens, d_in = x.shape
        keys = self.W_key(x)
        queries = self.W_query(x)
        values = self.W_value(x)
        # scores + scaling: d_k ** -0.5
        attn_scores = queries @ keys.transpose(1, 2)
        attn_scores.masked_fill_(self.mask.bool()[:num_tokens, :num_tokens], -torch.inf)
        attn_weights = torch.softmax(attn_scores / keys.shape[-1] ** 0.5, dim=-1)
        attn_weights = self.dropout(attn_weights)
        return attn_weights @ values  # context vectors

4.2 — Layer normalization se activations normalize karna

Layer normalization har token ke vector ko independently normalize karta hai (uske features par) — zero mean aur unit variance — phir ek learned scale aur shift apply karta hai. Isse training me madad milti hai (activations stable range me rehte hain). Chapter iska batch normalization se contrast karta hai (jo batch ke across normalize karta hai aur inference par alag behave karta hai).

LayerNorm class last dimension par mean aur variance nikalti hai, normalize karti hai, phir learnable scale se multiply aur learnable shift add karti hai. Worked numbers: ek toy input par normalized output ka mean ≈ 0 aur variance ≈ 1 hota hai — chapter ise numerically verify karta hai.

4.3 — GELU activations ke saath neural network

Har transformer block ke andar ka feed-forward network ReLU ke bajaye GELU (Gaussian Error Linear Unit) activation use karta hai. GELU ReLU ka ek smooth, probabilistic version hai — ye input ko is probability se weight karta hai ki ek standard normal variable usse neeche hai — aur GPT-2 approximate GELU (tanh approximation) use karta hai. Code me use hone wala standard approximation formula hai: 0.5 * x * (1 + tanh(sqrt(2/pi) * (x + 0.044715 * x^3))).

FeedForward class ek two-layer network hai: Linear(768 → 3072) → GELU → Linear(3072 → 768) — matlab hidden layer embedding dimension ka chaar guna hai.

4.4 — Shortcut connections add karna

Shortcut (residual) connections ek layer ke input ko uske output me add kar dete hain (x + sublayer(x)) — isse gradients seedha network se beh sakte hain aur model kisi sub-layer ko skip karna seekh sakta hai agar wo useful na ho.

Chapter asar ko numerically demonstrate karta hai: bina shortcuts ke, deep network me gradients dramatically shrink ho jate hain (chapter ke example me early layers me gradient magnitudes lagbhag 0.0002–0.005); shortcuts ke saath wo healthy range me rehte hain (lagbhag 0.22–1.33).

4.5 — Attention aur transformer block ko jodna

TransformerBlock class sab kuch combine karti hai:

  1. Layer norm → multi-head causal attention → dropout → residual add karo.
  2. Layer norm → feed-forward network → dropout → residual add karo.

python
import torch

def generate(model, idx, max_new_tokens, context_size,
              temperature=0.0, top_k=None, eos_id=None):
    for _ in range(max_new_tokens):
        # 1) context ko last context_size tokens tak kaato
        idx_cond = idx[:, -context_size:]
        with torch.no_grad():
            logits = model(idx_cond)
        # 2) last position ke logits lo
        logits = logits[:, -1, :]
        # 3) top-k: top-k ke alawa sab ko -inf se mask karo
        if top_k is not None:
            top_logits, _ = torch.topk(logits, top_k)
            min_val = top_logits[:, -1]
            logits = torch.where(
                logits < min_val, torch.tensor(float('-inf')), logits)
        # 4) temperature: 0 ho to argmax, warna divide + sample
        if temperature > 0.0:
            logits = logits / temperature
            probs = torch.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
        else:
            idx_next = torch.argmax(logits, dim=-1, keepdim=True)
        if idx_next == eos_id:
            break
        idx = torch.cat((idx, idx_next), dim=1)
    return idx

Appendix D — Adding Bells and Whistles to the Training Loop

Training loop ko behtar banane ke teen tareeke: learning rate warmup, cosine decay aur gradient clipping — aur phir teeno ko ek modified training function me jodna.

D.1 — Learning rate warmup

Learning rate ko kam se shuru karo (0.0001) aur training ke pehle 20% steps me linearly peak (0.01) tak badhao — taaki shuru me bade, destabilizing updates na aayein. Chapter ke example run me warmup 27 steps ka hai.

Note (notes me darj discrepancy): chapter ke text me warmup ke liye do jagah do alag numbers hain — “20 steps” aur “27 steps”. 27 wahi value hai jo us run ke 135 total steps ke 20% se consistent hai.

D.2 — Cosine decay

Warmup ke baad learning rate ko cosine curve ke saath decay karo — minimum tak (10% of initial rate, min_lr = 0.1 * initial_lr) — constant rakhne ke bajaye. Isse smooth, gradual reduction milti hai.

D.3 — Gradient clipping

Total gradient norm ko cap karo (chapter max_norm=1.0 use karta hai, torch.nn.utils.clip_grad_norm_ se). Worked example: norm 5 wala gradient vector 1/5 se scale hota hai. Chapter ke training run me clipping se pehle sabse bada gradient norm 0.0411 aur clipping ke baad 0.0185 hai. Clipping kabhi-kabhi aane wale bahut bade updates ko training ko destabilize karne se rokta hai.

D.4 — Modified training function

train_model ka ek variant jo warmup_steps, initial_lr (default 3e-05) aur min_lr (default 1e-06) leta hai — warmup apply karta hai, phir cosine decay, aur gradient clipping sirf warmup phase ke baad apply karta hai. Is loop se 124M model ko 15 epochs train karne me lagbhag 5 minutes lagte hain aur final training loss 0.041 aur validation loss 6.915 milta hai — phir wahi overfitting, jaise Chapter 5 me, kyunki text chhota hai.

python
import torch
import math

# D.1 + D.2 — warmup phir cosine decay
def get_lr(step, warmup_steps, total_steps, initial_lr, min_lr):
    if step < warmup_steps:
        # linear warmup: 0.0001 se peak tak (chapter example: 27 steps)
        return initial_lr * step / max(1, warmup_steps)
    # cosine decay: peak se min_lr (10% of initial) tak
    progress = (step - warmup_steps) / max(1, total_steps - warmup_steps)
    cosine = 0.5 * (1 + math.cos(math.pi * progress))
    return min_lr + cosine * (initial_lr - min_lr)

# D.3 — gradient clipping (max_norm=1.0)
# chapter run: sabse bada grad norm clipping se pehle 0.0411, baad me 0.0185
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

Appendix E — Parameter-Efficient Fine-Tuning with LoRA

Poora model train karne ke bajaye sirf ek chhota low-rank update seekho — trainable parameters lagbhag 50× kam, aur test accuracy Chapter 6 se bhi behtar: 98.00%.

E.1 — LoRA ka introduction

LoRA (Low-Rank Adaptation) pretrained weights ko freeze kar deta hai aur har weight matrix ke liye sirf ek chhota low-rank update seekhta hai: update ΔW ko do chhoti matrices ke product ke roop me factorize kiya jata hai — ΔW ≈ A × B, jahan A hai (d × r) aur B hai (r × d), aur rank r chhota hota hai (kitaab r = 16, alpha = 16 use karti hai). Kyunki r, d se bahut chhota hota hai, trainable parameters dramatically kam ho jate hain — aur inference time par update ko original weights me wapas merge kiya ja sakta hai (isliye koi extra latency nahi).

E.2 — Dataset taiyaar karna

Wahi SMS spam dataset aur loaders jo Chapter 6 me the (balanced 747/747, max length 120, batch size 8).

E.3 — LoRA implement karna

LoRALayer class ek linear layer ko wrap karti hai aur do low-rank matrices add karti hai (A randomly initialize hoti hai, B zero se initialize hoti hai — taaki model shuru me unchanged rahe). LinearWithLoRA class attention aur feed-forward modules ke linear layers ko replace karti hai. Sirf LoRA matrices (aur classification head) train hote hain; baaki sab frozen rehta hai.

Worked numbers: 2,666,528 trainable parameters vs 124,441,346 frozen parameters — lagbhag 50× reduction. Scaling factor alpha/r (yahan 16/16 = 1) LoRA update ko multiply karta hai.

E.4 — Efficient training implement karna

LoRA model ko spam task par 6 epochs train karne se (AdamW, learning rate 5e-05) — shuru ki accuracy lagbhag 46% (training) / 45% (validation) / 49% (test) se — final accuracy milti hai: training 100%, validation 96.64%, test 98.00% — Chapter 6 ke full-last-block run (95.67% test) se behtar, bahut kam trainable parameters ke saath. import torch.nn as nn

# E.1 + E.3 — LoRA: W frozen, sirf A aur B train hote hain
#   delta_W = A @ B,  A: (d, r), B: (r, d), r=16, alpha=16
#   scaling = alpha / r = 16 / 16 = 1
class LoRALayer(nn.Module):
    def __init__(self, in_dim, out_dim, rank=16, alpha=16):
        super().__init__()
        self.A = nn.Parameter(torch.randn(in_dim, rank) * 0.01)
        self.B = nn.Parameter(torch.zeros(rank, out_dim))
        self.scaling = alpha / rank  # yahan 1.0

    def forward(self, x, base_layer):
        # base output + low-rank update
        return base_layer(x) + (x @ self.A @ self.B) * self.scaling

Interview FAQs

Current-era interviews me is kitaab se poochhe jaane wale sabse kaam ke 36 sawaal — har jawaab wahi hai jo is SPA ke chapters me detail me samjhaya gaya hai. Kisi bhi sawaal par click karke jawaab kholo.

Q01LLM kya hota hai, ek line me?
Ek bada transformer-based neural network jo next token predict karna seekhta hai — bade text corpus par train hota hai aur kai language tasks (translation, summarization, code generation, question answering) kar sakta hai.
Q02LLM ko “black box” kyun kaha jata hai?
Kyunki isme millions se billions parameters hote hain — chhote model ki tarah har parameter ko inspect karke samjhaya nahi ja sakta. Is kitaab ka jawab hai: khud ek bana lo, step by step, to black box khul jata hai.
Q03Pretraining, fine-tuning aur inference — farak kya hai?
Pretraining: bade bina-label corpus par next-token prediction — mehenga, ek baar. Fine-tuning: pretrained model ko chhote task-specific data par aur train karna — sasta, most practitioners yahi karte hain. Inference: taiyaar model ko chalana.
Q04Teeno stages me architecture same kyun rehta hai?
Kyunki transformer architecture nahi badalta — sirf data aur training objective badalta hai. Classification me sirf output head badalta hai (label prediction), instruction fine-tuning me phir next-token prediction hoti hai, bas instruction–response pairs par.
Q05Encoder-only, decoder-only aur encoder–decoder me kya farak hai?
Encoder-only (jaise BERT) poora input dekhta hai — understanding/classification ke liye. Decoder-only (jaise GPT) sirf past dekhta hai — generation ke liye; ye kitaab ka choice hai. Encoder–decoder (original transformer) translation ke liye.
Q06Transformer ne RNN ko kyun replace kiya?
RNN ek-ek token karke chalta hai aur history ko ek hidden state me compress karta hai — purani jaankari fade ho jati hai. Self-attention me har token seedha har doosre token ko dekh sakta hai, isliye lambi dependencies pakdi jati hain.
Q07Tokenization kya hai? BPE kyun chahiye?
Tokenization text ko model-processable units me todna hai. Simple word-level tokenizer me har naya word vocabulary badhata hai aur rare words unseen rehte hain. BPE subword pieces use karta hai — common words poore, rare words pieces me — isliye koi bhi text represent ho sakta hai. GPT-2 vocab: 50,257 tokens.
Q08Token embeddings aur positional embeddings me kya farak hai?
Token embeddings batati hain token kya hai (ID → dense vector, 768-dim GPT-2 small me). Positional embeddings batati hain token kahan hai (position 0, 1, 2…). Dono ka sum model ka input hota hai — kyunki transformer parallel process karta hai, use order ka built-in sense nahi hota.
Q09Input–target pairs kaise bante hain?
Text ko tokenize karke IDs ki list banao, phir sliding windows kaato: target, input ko ek token shift karke banta hai. max_length=4, stride=1 par “Hello, do you” ka target “, do you like” hota hai.
Q10Self-attention ka formula kya hai?
Har token ke liye: scores = Q @ K.T, phir 1/sqrt(d_k) se scale karo, softmax lagao, phir weights @ V. Weights ka sum 1 hota hai — ye ek weighted average hai.
Q11Query, Key aur Value ka matlab kya hai?
Query: token kya dhoondh raha hai. Key: token kya offer karta hai. Value: token kya contribute karta hai. Attention query–key similarity se weights nikalta hai aur value vectors ko weight karta hai.
Q12Scaling factor 1/sqrt(d_k) kyun zaroori hai?
Bina scale kiye dot products bahut bade ho jate hain (toy example me lagbhag 30) aur softmax saturate ho jata hai — gradients chhote ho jate hain. Scale karne se (1/sqrt(3) ≈ 0.577) values stable range me rehti hain.
Q13Causal mask kya karta hai?
Diagonal ke upar ki positions ko softmax se pehle -inf set kar deta hai, taaki unke weights zero ho jayein — model future tokens ko nahi dekh sakta. Mask lower-triangular hota hai; code me torch.triu + masked_fill se banta hai.
Q14Dropout attention me kyun lagaya jata hai?
Regularization ke liye: training me weights ka ek random fraction (model me 0.1) zero kar diya jata hai aur baaki ko 1/(1-rate) se scale kiya jata hai. Inference par dropout band hota hai (model.eval()).
Q15Multi-head attention single-head se behtar kyun hai?
Ek head sirf ek tarah ka relationship pakad sakta hai. Multi-head me kai heads parallel chalte hain — har head ke apne Q/K/V projections — phir outputs concatenate karke project kiye jate hain. 124M model me 12 heads, har head 64-dimensional.
Q16GPT-2 small (124M) ka configuration kya hai?
vocab_size=50,257, context_length=1,024, emb_dim=768, n_heads=12, n_layers=12, drop_rate=0.1, qkv_bias=False. Chaar sizes: small 124M, medium 355M, large 774M, XL 1.5B.
Q17LayerNorm kya karta hai?
Har token ke vector ko uske features par normalize karta hai — zero mean, unit variance — phir learned scale aur shift apply karta hai. Isse activations stable range me rehte hain aur training behtar hoti hai. BatchNorm se farak: wo batch ke across normalize karta hai.
Q18GELU ReLU se kaise alag hai?
GELU ReLU ka smooth, probabilistic version hai — input ko is probability se weight karta hai ki standard normal variable usse neeche hai. GPT-2 tanh approximation wala GELU use karta hai. Feed-forward network: Linear(768 → 3072) → GELU → Linear(3072 → 768).
Q19Residual (shortcut) connections kyun zaroori hain?
Wo layer ke input ko output me add kar dete hain (x + sublayer(x)) — gradients seedha beh sakte hain. Bina shortcuts ke gradients shrink ho jate hain (example: 0.0002–0.005); shortcuts ke saath healthy range me rehte hain (0.22–1.33).
Q20Pre-norm aur post-norm me kya farak hai?
Pre-norm me normalization har sub-layer se pehle hoti hai (GPT-2 ka style) — training zyada stable hoti hai. Post-norm (original transformer) me normalization sub-layer ke baad hoti hai.
Q21Weight tying kya hai? 124M number kahan se aaya?
Token embedding matrix aur output head ke weights share kiye jate hain. Tying ke bina model me 163,009,536 parameters hote; tying ke saath 124,412,160 — yahi “124M” hai. Float32 me ye 621.83 MB lete hain.
Q22Untrained model gibberish kyun generate karta hai?
Kyunki architecture akele kuch nahi jaanta — knowledge training se aati hai. “Hello, I am” par untrained model random-looking text deta hai; training ke baad wahi function coherent text deta hai.
Q23Cross-entropy loss aur perplexity kya hain?
Cross-entropy loss predicted next-token distribution aur asal next token ke beech ka average loss hai. Perplexity = exp(loss) — har step par effectively kitne choices hain. Untrained model: loss 10.794, perplexity 48,725.8 (lagbhag random guess, vocab 50,257).
Q24Overfitting kya hai? Is kitaab me kab dikha?
Jab model training data ko memorize karne lage aur validation par behtar na ho. 10 epochs ke baad training loss 0.391 ho gaya lekin validation loss 6.452 par ruk gaya (epoch 2 ke baad improve nahi hua) — chhote text par ye expected hai.
Q25Temperature sampling kaise kaam karta hai?
Softmax se pehle logits ko temperature se divide karo: 0 par sharp/greedy, 1 par unchanged, zyada par flat/random. “The food is” ke baad “pizza” temperature 0/0.1 par 1,000 tokens me 0 baar, 1.0 par 32 baar aaya.
Q26Top-k sampling kya hai?
Sirf k sabse likely tokens rakho aur unhi me se sample karo. top_k=1 matlab greedy; top_k=50 variety deta hai lekin implausible tokens ki tail ko exclude karta hai.
Q27Model weights kaise save/load karte hain?
torch.save(model.state_dict(), 'model.pth') se save, torch.load + load_state_dict se load. State dict parameter names se tensors ka mapping hota hai. 124M model ki file float32 me lagbhag 500 MB hoti hai.
Q28Pretrained GPT-2 weights load karne ka kya fayda hai?
Ye prove karta hai ki scratch se bana architecture bilkul GPT-2 ka hi hai — aur weights load karte hi model fluent text generate karne lagta hai. 124M checkpoint lagbhag 498 MB ka hota hai.
Q29Classification fine-tuning me last token kyun use hota hai?
Kyunki GPT causal hai — sirf last token ki hidden state ne poora message dekha hota hai (pehle tokens future nahi dekh sakte). Pehle token se classify karne par accuracy bahut buri hoti hai (Exercise 6.3).
Q30Spam dataset ka balance kyun zaroori tha?
Dataset imbalanced tha: 4,825 ham vs 747 spam — hamesha “ham” bolne wala model bhi 86.6% accurate ho jata. Downsampling se 747/747 balance banaya gaya (total 1,494), split 70/10/20 (1,045/149/300).
Q31Spam classifier ki final accuracy kya thi?
5 epochs, AdamW (lr 5e-05), sirf last block + final norm + head train karke: training 97.21%, validation 97.32%, test 95.67%. max_length=1,024 karne par test accuracy 78.33% gir gayi; saari layers train karne par 96.67% mili.
Q32Instruction fine-tuning base model se kaise alag hai?
Base model text complete karta hai; instruction fine-tuning use instruction → response examples (yahan 1,100 entries, 935/55/110 split) par train karta hai — output abhi bhi text hai, objective abhi bhi next-token prediction, bas Alpaca-style template me format karke.
Q33Instruction tokens ko loss me mask karna chahiye ya nahi?
Kitaab ka main run loss poori sequence par compute karta hai (mask nahi karta) — cited 2024 paper ke mutabiq masking se hamesha fayda nahi hota. Exercise 7.2 me masking se average score thoda bura aaya.
Q34LLM judge se evaluation kaise hoti hai?
Instruction, reference answer aur model ka jawaab ek bade model (Ollama se Llama 3 8B, 4.7 GB) ko bhej kar 0–100 score karwaya jata hai. 110 test entries par fine-tuned 355M model ka average score 50s me aaya — base model se clearly upar.
Q35LoRA kya hai aur ye itna efficient kyun hai?
LoRA pretrained weights ko freeze karke sirf ek chhota low-rank update seekhta hai: ΔW ≈ A × B (r=16, alpha=16). Poore 124M model me sirf 2,666,528 trainable parameters vs 124,441,346 frozen — lagbhag 50× kam — aur test accuracy 98.00% (Chapter 6 ke 95.67% se behtar).
Q36Learning rate warmup, cosine decay aur gradient clipping kya karte hain?
Warmup: LR ko 0.0001 se shuru karke pehle 20% steps (27 steps) me 0.01 tak badhao — shuru ke bade updates se bacho. Cosine decay: phir LR ko cosine curve se min (10% of initial) tak girao. Gradient clipping: gradient norm ko max_norm=1.0 par cap karo — bade updates training ko destabilize na karein.
