Ch 1 — First Principles se State-of-the-Art Transformers tak

Chapter 1 poori kitab ki vocabulary banata hai: tokenization, embeddings, attention, encoder–decoder, scaling laws aur long-context — ye sab aane wale 11 chapters me baar-baar aayega. 2017 ka "Attention Is All You Need" paper yahan se shuru hota hai aur aaj ke sabse bade models tak pahunchta hai.

Transformers itne important kyun hain?

2017 ke paper ne transformer introduce kiya; isne RNNs / LSTMs ko peeche chhod diya aur BERT, GPT, Llama aur ViT — sab ki neev bana. Ye text, vision, audio, time series aur RL — har jagah kaam karta hai kyunki ye long-range dependencies ko parallel me seekhta hai. Kitab ka zor: wahi architecture, bas alag tokeniser, har modality cover karta hai.

Tokenization–Embeddings–Attention trinity

Raw data (text, image patches, audio frames) ko pehle tokens me badlo, phir vectors (embeddings) me, phir attention se unhe ek doosre se relate karo. Chapter in teeno ko ek pipeline ki tarah treat karta hai.

Tokenization — 3 tareeke

MethodKaise kaam karta haiFaydaNuksan
Word-levelHar word ek tokenSimpleUnknown words, huge vocabulary
Character-levelHar character ek tokenRobust, kabhi unknown nahiBahut lambi sequences

BPE characters se shuru karke sabse frequent adjacent pair ko baar-baar merge karta hai. WordPiece raw frequency se nahi, likelihood gain se merge karta hai. GPT-4 example: "The cat sat on the mat" tokens bante hain jaise ["The", " cat", " sat", " on", " the", " mat"] — token IDs ke saath. Worked BPE walk-through "l o w" / "l o w e r" style pieces merge karta hai. Practical guidance: domain vocabulary bahut alag na ho to pretrained tokeniser (jaise GPT-2 / Llama wala) use karo; token counts check karo kyunki cost aur context limits words me nahi, tokens me gine jate hain.

Embeddings

Word2Vec (CBOW vs skip-gram), GloVe aur contextual embeddings (ELMo, BERT) ka contrast: static embeddings har word ko ek hi vector dete hain, contextual embeddings har occurrence ko alag vector dete hain. Classic illustration: king − man + woman ≈ queen — Word2Vec me vector arithmetic. Transformer embeddings task ke saath jointly seekhe jate hain, frozen nahi rehte.

Positional embeddings — order kahan se aata hai?

Attention me built-in order nahi hota, isliye position add karni padti hai. Sinusoidal: even dimensions ke liye sine, odd ke liye cosine, wavelengths geometrically badhti hain (base 10,000), isliye relative positions absolute ones ka linear function hoti hain. Learned: BERT/GPT wala tareeka, lekin trained length se aage extrapolate nahi karta. RoPE (rotary): query/key vectors ko position ke proportion me angle se rotate karta hai, isliye attention score relative distance (m − n) par depend karta hai — Llama/Qwen ka standard. ALiBi: distance ke proportion me linear penalty add karta hai, har head ka alag slope, aur achhe se extrapolate karta hai. Tip: absolute sinusoidal encodings fixed hote hain, seekhe nahi ja sakte.

Jaise render hua (discrepancy 9): sinusoidal formula me "k" render hua hai jahan position index expected tha — p_i,2t = sin(k / 10000^(2t/d)). RoPE derivation me second rotation me query aur key dono ke liye wahi index m dikhaya gaya hai. Ye waise hi likha gaya hai.

Encoder–decoder architecture

Original transformer: 6-layer encoder (self-attention + feed-forward, residual connections aur layer normalisation ke saath) aur 6-layer decoder (masked self-attention + encoder par cross-attention + feed-forward). Encoder-only (BERT), decoder-only (GPT) aur encoder–decoder (T5) — task ke hisab se alag.

Self-attention — transformer ka secret weapon

Queries, keys aur values input ke linear projections hain; scores hain QKᵀ/√d_k, soft-max karo, phir V par apply karo. √d_k se scaling isliye kyunki d_k bada hone par soft-max saturate ho jata hai. Multi-head attention kai heads parallel me chalata hai, alag projections ke saath, phir concatenate karta hai — alag heads alag relations track karte hain (jaise syntax vs coreference). Worked example: "The animal didn't cross the street because it was too tired" — isme "it" strongly "animal" ko attend karta hai.

Masked self-attention — decoder ka hidden advantage

Decoder me future positions mask kar diye jate hain (soft-max se pehle −∞ set kar do) taaki generation causal rahe — yahi autoregressive generation ko possible banata hai.

Scaling laws

2020 ka OpenAI scaling paper aur 2022 ka Chinchilla paper: loss parameters, data aur compute me power law se girta hai. Chinchilla ka rule of thumb hai lagbhag 20 tokens per parameter — isliye 70B-parameter model ko lagbhag 1.4T tokens chahiye, aur pehle ke bohot saare models undertrained the. Warning: sirf scaling se data quality ya reasoning fix nahi hota.

LiveCheck — 20 tokens/param
70B params × 20 tokens = 1,400B = 1.4T tokens. Lab 3 me khud calculate karo.

Self-attention se aage — naye architectures

Sparse attention, linear attention, state-space models (Mamba), RWKV aur hybrid architectures — sab quadratic cost se bachne ki koshish hain. Chapter ki position: attention abhi bhi dominant hai, lekin bahut lambi sequences ke liye hybrids aage badh rahe hain.

Attention complexity — lambi sequences se dikkat kyun?

Self-attention ki cost sequence length me O(n²) time aur memory hai; n = 100,000 par ye 10 billion attention scores hote hain. Remedies: chunking, sparse patterns, sliding windows, aur KV-cache (keys/values store kar lo taaki har naya token O(n) me aaye, sab kuch dobara compute na karna pade).

Ch 2 — Transformers for Time Series

Time series sequential hoti hai, long-range dependent hoti hai, multivariate hoti hai aur aksar irregularly sampled hoti hai. Attention poori history ko ek saath dekh sakta hai — RNN ki tarah step-by-step state nahi. Running examples: energy demand, stock prices aur sensor readings.

Transformers time series ke liye kyun fit hain?

Attention ye weigh kar sakta hai ki kisi forecast ke liye past ke kaunse moments matter karte hain. RNN ko har step se guzarna padta hai; transformer ek hi baar me poori history par nazar daal sakta hai.

Time series ko tokenise karna — 3 tareeke

Text ke opposite, yahan koi natural vocabulary nahi hai:

MethodIdeaFayda

Quantisation (Chronos)Continuous values ko discrete bins me daaloLanguage-model style cross-entropy loss use ho sakta hai

Time series transformer architecture

Forecasting/classification ke liye encoder-only transformer, sequence-to-sequence forecasting ke liye encoder–decoder. Inputs ko linear layer se project kiya jata hai (embedding lookup nahi), time features add kiye jate hain. Informer / Autoformer / FEDformer family wo lineage hai jisne vanilla attention ko lambi series ke liye fix karne ki koshish ki.

Time series ke liye attention mechanisms

Full attention history length me O(n²) hai, isliye chapter 3 fixes cover karta hai:

  • ProbSparse attention (Informer): sirf sabse "active" queries compute karo.
  • Auto-correlation attention (Autoformer): autocorrelation se mile lags par similar sub-series ko attend karo — frequency domain me, FFT ke through.
  • Frequency-enhanced attention (FEDformer): Fourier/wavelet space me attention. Point: time series me periodicity hoti hai, isliye frequency domain me attend karna natural hai.

Time information encode karna

Absolute position kaafi nahi hai: calendar features (hour of day, day of week, month), irregular sampling ke liye time-delta features, aur learned time embeddings — Time2Vec: ek linear term (trend) plus k sine terms (periodicity). Ye ek chhota, general-purpose encoding hai.

Ch 3 — Transformers for Vision Tasks

Vision transformer image ko sequence ki tarah treat karta hai: image ko patches me todo, har patch ek token. Chapter ka arc hai ViT → efficient variants (Swin) → promptable segmentation (SAM family).

Overview

Chapter ViT se Swin tak aur phir SAM family tak jata hai. Object detection aur classification baad ke chapters me dobara aayenge — ye Chapter 3 ka promise hai (discrepancy 13 dekho: uske baad koi dedicated object-detection chapter nahi aata; detection mainly SAM / video / agent chapters ke andar treat hoti hai).

Embeddings aur tokenization — ViT

ViT (2020): 224×224 image ko 16×16 patches me todo → 14×14 = 196 patches; har patch ko flatten karo, linearly project karo model dimension par, ek learnable [CLS] token aur learned positional embeddings add karo. [CLS] token ka final vector classification ke liye use hota hai. Patch size kyun matter karta hai: chhote patches se finer detail milti hai lekin sequence quadratically lambi ho jati hai — jaise 8×8 patches se usi image ke 784 tokens ban jate hain. Data augmentation (RandAugment, Mixup, CutMix) aur ye fact ki ViT ko CNNs ko beat karne ke liye large-scale pretraining chahiye (ImageNet-21k ya JFT-300M) — chhote data par CNN ke inductive biases abhi bhi help karte hain.

LiveCheck — patch maths
224 ÷ 16 = 14, 14 × 14 = 196 patches. 224 ÷ 8 = 28, 28 × 28 = 784 tokens. Lab 2 me khud calculate karo.

Vision transformers ko train karne ki key strategies

  • Pretraining phir fine-tuning — standard recipe.
  • Knowledge distillation CNN teacher se (DeiT).
  • Self-supervised pretraining (MAE — masked autoencoding, DINO).
  • Practical recipe: pretrained checkpoint se shuru karo, low learning rate se fine-tune karo, strong augmentation use karo, aur chhote datasets par overfitting monitor karo.

Swin Transformer V2

Swin shifted windows use karta hai: attention chhote windows ke andar compute hoti hai (jaise 7×7 patches) aur windows layers ke beech shift ho jati hain taaki information window boundaries cross kare — isse image size me linear cost milti hai (quadratic nahi) aur CNN jaisa hierarchical feature pyramid banta hai. V2 me post-normalisation, scaled cosine attention aur log-spaced continuous position bias add hua — in teeno se higher resolution par training possible hui (paper me 1,536×1,536 tak) aur bahut bade models ki training zyada stable hui.

Segment Anything (SAM)

Meta ka SAM (2023): image encoder (ViT) + prompt encoder (points, boxes, masks, text) + lightweight mask decoder; train hua SA-1B par — 11M images, 1.1B masks. User ek point click karta hai aur SAM mask return karta hai; ye promptable hai aur naye objects ke liye zero-shot hai. Chapter teeno components aur data engine samjhata hai (assisted manual → semi-automatic → fully automatic labelling).

SAM 2 (video)

SAM 2 (2024) ek memory mechanism add karta hai (memory encoder, memory bank, memory attention) taaki ek frame par diye gaye prompt se mask poori video me track ho sake; ye images par bhi kaam karta hai aur SAM se faster hai. Memory past frame features aur masks store karti hai, aur memory par attention se model occlusions ke across object identity banaye rakhta hai.

SAM 3 (concept prompts)

SAM 3 (2025) concept prompting add karta hai: point ki jagah prompt ek concept ho sakta hai ("all the snacks", ek text description ya ek example image), aur model har matching instance ko segment karta hai. Chapter ka worked example lekhak ka khud ka hai: shelf ki photo par "snacks" prompt karne se snack items segment hote hain, reported result 91.41% (reader me jaisa dikhaya gaya hai — segmentation accuracy / IoU-style figure). SAM 3 video aur open-vocabulary segmentation ke liye bhi use hota hai.

Ch 4 — Transformers for Image Generation

Image generation GANs se diffusion models tak, aur phir diffusion transformers tak pahuncha: denoising network ab latent image patches par kaam karne wala transformer hai. Chapter ka running contrast hai U-Net denoisers (convolutional, local) vs DiT denoisers (attention, global).

Overview

GANs → diffusion → diffusion transformers. Denoising network ab ek transformer hai jo latent image patches par operate karta hai.

Embeddings aur tokenization

Text prompts ko text encoder encode karta hai (CLIP aur/ya T5); images ko VAE latent space me encode karta hai (jaise 8× downsampled latent), aur latent ko patches me toda jata hai jo tokens ban jate hain — bilkul ViT ki tarah. Latent space me kaam karna (pixel space ki jagah) hi high-resolution generation ko tractable banata hai.

Training ki key strategies

  • Large-scale image–text pairs.
  • Classifier-free guidance: training me text condition kabhi-kabhi drop kar do, phir inference par conditional aur unconditional predictions ke beech extrapolate karo — guidance scale ~7.5 classic Stable Diffusion default hai.
  • Caption quality matter karti hai — VLM se recaptioning karne se alignment improve hota hai.

DiT (Diffusion Transformer)

DiT (2022/2023 paper) U-Net ko transformer se replace karta hai: noisy latent patches plus timestep aur class/text conditioning vector (adaptive layer-norm, adaLN ke through) input lekar noise predict karta hai. DiT ko scale karne (depth, width, patch size) se FID smoothly improve hota hai; paper ki headline hai ki DiT-XL/2 ImageNet 256×256 par FID 2.27 tak pahunchta hai (jaise chapter me report kiya gaya hai).

Stable Diffusion 3

SD3 (2024): Multimodal Diffusion Transformer (MMDiT) use karta hai — text aur image tokens alag streams me process hote hain jo ek doosre ko attend karte hain (joint attention), teen text encoders ke saath (do CLIP variants + T5-XXL). Ye classic DDPM noise schedule ki jagah rectified-flow (flow matching) use karta hai — straighter sampling paths aur behtar text rendering.

Flux

Flux (2024, Black Forest Labs): 12B-parameter rectified-flow transformer, MMDiT-style joint attention aur rotary positional embeddings ke saath; chapter isse us time ka open-weight state of the art batata hai prompt adherence ke liye. Variants: Flux.1 [pro], [dev] aur [schnell] — distillation/speed me farak hai.

Overview

Embeddings aur tokenization

Training ki key strategies

  • Pehle images par pretrain karo, phir video par.

  • Curriculum: chhote clips se lambi clips tak.

Sora

Ch 7 — Reinforcement Learning Transformers

RL ko sequence modelling ki tarah dobara frame karo: trajectory (return, state, action, reward) tokens ki sequence hai, to transformer desired return dekar agla action predict kar sakta hai. Chapter ki thesis: is se value-function bootstrapping ki zaroorat khatam ho jati hai aur RL language modelling wali scaling recipe use kar sakta hai.

Overview

Trajectory ko tokens ki sequence banao, transformer ko train karo, aur inference par high target return set karke actions generate karwao. Offline RL aur world models — dono directions is chapter me hain.

Embeddings aur tokenization

States, actions aur rewards ko alag-alag embed kiya jata hai (images ke liye states CNN/ViT se ya vectors ke liye MLP se, actions lookup ya MLP se, rewards/returns linear layer se), phir time order me interleave kiya jata hai positional embeddings aur timestep embedding ke saath.

Training ki key strategies

  • Offline RL: trajectories ke fixed dataset se seekho, training ke dauraan environment interaction nahi.
  • Return-conditioning: desired return-to-go ko pehla token bana kar do.
  • Warning: offline models data me na hone wale actions ke baare me over-optimistic ho sakte hain (distribution shift / extrapolation error).

Decision Transformer

2021 ka paper: GPT-style decoder, cross-entropy (discrete actions) ya MSE (continuous actions) se train hota hai — past trajectory aur return-to-go dekar action predict karta hai. Inference par high target return set karo aur model aise actions generate karta hai jo (uske hisab se) wo return achieve karenge. Chapter zor deta hai: ye simple hai (supervised learning) lekin dynamic-programming methods ki tarah kharab trajectories ke achhe parts ko "stitch" nahi kar sakta.

Trajectory Transformer

2021 ka paper: states, actions aur rewards ko discretise karke poori trajectory ko jointly model karta hai, phir predicted trajectories par beam search se plan karta hai. Decision Transformer se zyada expressive hai lekin inference par slower hai kyunki planning ek search hai.

STORM

STORM (2024): stochastic transformer-based world model jo current latent state aur action se agla latent state aur reward predict karta hai, categorical latent representation ke saath. Chapter ka worked example STORM ko Atari par train karta hai (notebook "ch03_STORM.ipynb" — discrepancy 7, ye Chapter 7 ka hai lekin naam me ch03 hai) aur report karta hai, 40 Atari games par mean human-normalised score: STORM 16,960 vs DreamerV3 15,565 vs humans 7,845 (discrepancy 15 — dono models human mean se upar dikhaye gaye hain, waise hi likha gaya hai).

Overview — era of experience

"Era of experience" argument: human data ke era ke baad AI apna khud ka experience generate karke aur usse seekh kar improve hota hai. Chapter reasoning ko train karne (RL/GRPO) aur test time par search karne (MCTS/A*/S*) — dono ke baare me hai.

Pretraining se test-time compute tak

Pretraining data aur parameters ke saath scale hoti hai; test-time compute is baat se scale hoti hai ki model har problem par kitna "sochta" hai (zyada samples, lambi chains of thought, search). Chapter ka argument hai ki marginal return ab test time ki taraf shift ho gaya hai, aur inference-time scaling (best-of-n, self-consistency, tree search) ab first-class design choice hai.

RLHF — classic 3-stage pipeline

(1) Demonstrations par supervised fine-tuning (SFT); (2) human preference pairs (chosen vs rejected) se reward model train karo; (3) reward model ke against policy ko PPO se optimise karo, SFT model se KL penalty ke saath taaki reward hacking na ho. DeepSeek-R1 (2025): large-scale RL seedha base model se, long chains of thought par alag SFT stage ke bina, rule-based rewards (sahi jawab, sahi format) ke saath — aur isne emergently lambi chains of thought, self-verification aur backtracking develop kar li. DeepSeek-R1-Zero pure-RL variant hai; R1 me thoda cold-start data add hai. Chapter isse proof batata hai ki RL akela reasoning elicit kar sakta hai.

GRPO (Group Relative Policy Optimization)

GRPO (2024): har prompt ke liye G outputs ka group sample karo, unhe score karo, aur group ke mean aur standard deviation ko baseline banao (advantage = (reward − group mean) / group std) — isliye alag value/critic network ki zaroorat nahi hoti. Overview

Chapter agents ko scripts se alag karta hai: scripts fixed steps hote hain, chatbots single-turn hote hain, agents goal-directed loops hote hain — state aur tools ke saath.

AI agent kya hai?

Agent perceive → reason → act ka loop chalata hai. Scripts fixed steps follow karte hain; chatbots ek sawal ka ek jawab dete hain; agents goal ki taraf kaam karte hain — tools aur state ke saath, kai steps tak.

ReAct pattern

ReAct (2022 ka paper): reasoning traces (Thought) ko actions (Action) aur observations (Observation) ke saath interleave karo — Thought → Action → Observation → Thought … — taaki model plan kar sake, tool call kar sake, result dekh sake, aur revise kar sake. Practical points: precise tool descriptions, typed arguments, error messages model ko wapas do, aur tool set ko limit karo taaki model confuse na ho.

Multi-agent systems

Specialised agents (researcher, coder, reviewer, planner) collaborate karte hain. Patterns: supervisor (ek agent delegate karta hai), sequential pipeline (handoff), aur debate (agents ek doosre ko critique karte hain). Chapter ki advice: har agent ka role narrow rakho aur handoffs explicit banao.

Memory aur state

Planning aur reflection

Ch 11 — Deploying Transformer Models

Notebook me chalne wala model production me latency, memory (KV cache), cost ya drift par fail ho sakta hai. Deployment checklist hai: serving target define karo (latency, throughput, cost) → optimisation chuno → serving stack chuno → monitor karo.

Overview — development se production tak

Chapter production counterpart hai Chapter 1 ki notebook warning ka: notebook me kaam karne wala model production me latency, memory, cost ya drift ki wajah se fail ho sakta hai.

Model optimisation techniques

  • Quantisation: FP16 → INT8 → INT4. Note: INT4 INT8 ke muqable memory phir aadhi kar deta hai lekin accuracy cost hoti hai.
  • Pruning: unimportant weights/heads hatao.
  • Distillation: bade teacher ke outputs par chhota student train karo.
  • KV-cache optimisation: paged attention, prefix caching.
  • Rule: quantisation pehla lever hai kyunki iske liye retraining nahi chahiye.

LoRA

Low-Rank Adaptation (2021 ka paper): base weights W ko freeze karo aur low-rank update ΔW = BA train karo, jahan B hai d×r aur A hai r×k, rank r ≪ d (jaise r = 8 ya 16). Sirf chhote A/B matrices train hote hain, isliye 7B model ko kuch million trainable parameters se adapt kiya ja sakta hai; inference par adapter ko W me wapas merge kiya ja sakta hai.

QLoRA

Quantized LoRA (2023 ka paper): base model ko 4-bit (NF4) me quantise karo aur upar LoRA adapters train karo, paged optimisers ke saath taaki memory spikes na hon. Headline: 65B model ko ek 48 GB GPU par fine-tune kiya ja sakta hai. Cost: LoRA se slower training aur chhota quality gap.

DoRA

Weight-Decomposed Low-Rank Adaptation (2024 ka paper): har weight ko magnitude vector aur direction matrix me decompose karta hai, magnitude ko alag train karta hai aur direction par LoRA update karta hai. Ye LoRA aur full fine-tuning ke beech ka gap mostly close karta hai, modest extra cost par.

LoftQ

LoftQ (2023 ka paper): quantisation aur low-rank approximation ko alternate karta hai taaki quantisation error ko LoRA initialisation se hi fit kar liya jaye. Ye best option bataya gaya hai jab base model ko heavily quantise karna ho (2-bit) aur LoRA/QLoRA warna bahut accuracy kho de.

Interview FAQs — Transformers: The Definitive Guide

36 sawal-jawab jo aaj ke interviews me is kitab ke topics par poochhe jate hain. Har jawab kitab ke content par based hai.

Q1Transformer kya hota hai aur ye itna important kyun hai?

Transformer ek neural architecture hai jo 2017 ke 'Attention Is All You Need' paper me introduce hua tha. Isne RNNs/LSTMs ko peeche chhod diya aur BERT, GPT, Llama aur ViT — sab ki neev bana. Ye text, vision, audio, time series aur RL — har jagah kaam karta hai kyunki ye long-range dependencies ko parallel me seekhta hai. Kitab ka thesis hai: wahi core logic tokens, image patches aur spectrogram frames par chalta hai, sirf representation ka axis badalta hai.

Q2Tokenization, embeddings aur attention — in teeno ka rishta kya hai?

Ye ek pipeline hai: pehle raw data (text, image patches, audio frames) ko tokens me todo, phir tokens ko vectors (embeddings) me badlo, phir attention se tokens ko ek doosre se relate karo. Chapter 1 in teeno ko 'trinity' kehta hai — ek ke bina doosra adhura hai.

Q3BPE aur WordPiece me kya farak hai?

Dono subword tokenisation methods hain. BPE characters se shuru karke sabse frequent adjacent pair ko baar-baar merge karta hai. WordPiece raw frequency se nahi, likelihood gain se merge karta hai. Dono ka goal ek hai: unknown words se bachna aur vocabulary ko manageable rakhna. Practical advice: domain vocabulary bahut alag na ho to pretrained tokeniser use karo.

Q4Positional embeddings kyun chahiye? RoPE kya hai?

Attention me built-in order nahi hota, isliye position add karni padti hai. Sinusoidal encodings sine/cosine use karte hain (base 10,000); learned embeddings BERT/GPT me hain lekin trained length se aage extrapolate nahi karte; RoPE (rotary) query/key vectors ko position ke angle se rotate karta hai taaki attention score relative distance (m − n) par depend kare — ye Llama/Qwen ka standard hai; ALiBi distance-proportional penalty add karta hai aur achhe se extrapolate karta hai.

Q5Self-attention ka formula kya hai aur √d_k kyun hai?

Scores hain QKᵀ/√d_k, phir soft-max, phir V par apply karo. √d_k se scaling isliye hai kyunki d_k bada hone par dot products bade ho jate hain aur soft-max saturate ho jata hai. Multi-head attention kai heads parallel me chalata hai — alag heads alag relations track karte hain, jaise syntax vs coreference. Example: 'The animal didn't cross the street because it was too tired' me 'it' strongly 'animal' ko attend karta hai.

Q6Masked self-attention kya karta hai?

Decoder me future positions ko mask kar diya jata hai (soft-max se pehle −∞ set kar do) taaki generation causal rahe — model sirf past dekh kar agla token generate kare. Yahi autoregressive generation ko possible banata hai.

Q7Chinchilla rule kya hai? 70B model ko kitne tokens chahiye?

Chinchilla ka rule of thumb hai lagbhag 20 tokens per parameter. Isliye 70B-parameter model ko lagbhag 1.4T tokens chahiye — aur pehle ke bohot saare models is hisab se undertrained the. Loss parameters, data aur compute me power law se girta hai, lekin sirf scaling se data quality ya reasoning fix nahi hota.

Q8Attention O(n²) kyun hai aur isse kaise bachte hain?

Self-attention ki cost sequence length me O(n²) time aur memory hai — n = 100,000 par 10 billion attention scores bante hain. Remedies: chunking, sparse patterns, sliding windows, aur KV-cache (keys/values store kar lo taaki har naya token O(n) me aaye). FlashAttention tiling + recomputation se memory movement kam karta hai.

Q9MQA, GQA, MLA aur sliding-window attention me kya farak hai?

MQA (multi-query): saare heads ek hi K/V head share karte hain — fast inference, kam quality. GQA (grouped-query): heads grouped hote hain, jaise 32 heads ke liye 8 groups — Llama-2/3 ka compromise. MLA (multi-head latent): K/V ko low-rank latent me compress karta hai — kam KV-cache, quality barkarar. Sliding-window (Mistral): har token sirf recent window dekhta hai, jaise 4,096 tokens.

Q10Time series ko tokenise karne ke 3 tareeke kaunse hain?

Point-wise tokens (har time step ek token), patching (jaise 16 consecutive steps ka window = ek token, PatchTST), aur quantisation (continuous values ko discrete bins me daalo, Chronos — 256 bins). Patching sequence ko patch length se chhota karta hai; quantisation se language-model style cross-entropy loss use ho sakta hai.

Q11Chronos, TimesFM, Lag-Llama aur Moirai me kya farak hai?

Chronos (2024) values ko 256 bins me quantise karke T5-style model se forecast sampling karta hai aur zero-shot kaam karta hai. TimesFM decoder-only hai, patch length 32, ek forward pass me horizon forecast karta hai, aur '100B time points' par pretrained hai. Lag-Llama Llama-style hai jisme lag features covariates hain. Moirai masked-encoder hai jo kisi bhi variates aur frequency ko handle karta hai. Advice: pehle foundation model zero-shot try karo.

Q12ViT image ko kaise tokenise karta hai?

224×224 image ko 16×16 patches me todo → 14×14 = 196 patches; har patch ko flatten karke linearly project karo, ek learnable [CLS] token aur learned positional embeddings add karo. [CLS] token ka final vector classification ke liye use hota hai. 8×8 patches se wahi image 784 tokens ban jati hai — chhote patches matlab finer detail lekin quadratically lambi sequence.

Q13Swin Transformer V2 kya improve karta hai?

Swin shifted windows use karta hai — attention chhote windows (jaise 7×7 patches) ke andar compute hoti hai aur windows layers ke beech shift hoti hain, isse image size me linear cost milti hai aur CNN jaisa hierarchical pyramid banta hai. V2 me post-normalisation, scaled cosine attention aur log-spaced continuous position bias hain, jinse 1,536×1,536 tak resolution par stable training hoti hai.

Q14SAM, SAM 2 aur SAM 3 me kya farak hai?

SAM (2023) image encoder + prompt encoder (points, boxes, masks, text) + mask decoder hai, SA-1B par train hua (11M images, 1.1B masks) — point click karo, mask pao. SAM 2 (2024) memory mechanism add karta hai taaki mask video me track ho sake. SAM 3 (2025) concept prompting add karta hai — 'all the snacks' jaise concept se har matching instance segment hoti hai; kitab ke worked example me result 91.41% hai.

Q15DiT kya hai aur FID 2.27 ka kya matlab hai?

DiT (Diffusion Transformer) U-Net denoiser ko transformer se replace karta hai — noisy latent patches plus timestep aur conditioning (adaLN) se noise predict karta hai. DiT ko scale karne se FID smoothly improve hota hai; DiT-XL/2 ImageNet 256×256 par FID 2.27 tak pahunchta hai (jaise chapter me report kiya gaya hai) — kam FID matlab behtar image quality.

Q16Stable Diffusion 3 aur Flux me kya khaas hai?

SD3 (2024) Multimodal Diffusion Transformer (MMDiT) use karta hai — text aur image tokens alag streams me joint attention se process hote hain, teen text encoders (do CLIP variants + T5-XXL) ke saath, aur DDPM ki jagah rectified-flow (flow matching) use karta hai. Flux (2024) 12B-parameter rectified-flow transformer hai, MMDiT-style joint attention aur RoPE ke saath — us time ka open-weight state of the art prompt adherence ke liye.

Q17Classifier-free guidance kya hai aur 7.5 kyun famous hai?

Training me text condition kabhi-kabhi drop kar do, phir inference par conditional aur unconditional predictions ke beech extrapolate karo — guidance scale ~7.5 classic Stable Diffusion default hai. Formula: output = uncond + scale × (cond − uncond). Zyada scale matlab prompt se zyada chipkna, lekin artefacts ka risk bhi badhta hai.

Q18Video generation me 3D VAE aur spacetime patches kyun chahiye?

Video ko 3D VAE se compress kiya jata hai (8× spatial, 4× temporal) ek latent me, phir spatiotemporal patches (tubelets) tokens ban jate hain. Temporal compression hi video transformers ko affordable banata hai. Sora ek minute tak video banata hai; LTX-Video ka VAE 1:192 compression ratio deta hai aur 2B parameters ke saath real-time generation karta hai; Step-Video-T2V 30B parameters ke saath 204 frames tak banata hai.

Q19Audio ke liye spectrogram, waveform ya discrete tokens — kab kya?

Spectrograms (80 Mel bins, ~10 ms hop, 100 frames/second) understanding models ke liye hain (Whisper). Discrete tokens (EnCodec, ~75 tokens/second) generation models ke liye hain (MusicGen) kyunki unhe language ki tarah model kiya ja sakta hai. Raw waveform (16 kHz = 16,000 samples/second) attend karne ke liye bahut lamba hota hai.

Q20Whisper kaise kaam karta hai?

Whisper (2022) encoder–decoder transformer hai, 680,000 hours labelled audio par train hua. Encoder log-Mel spectrogram padhta hai (30-second windows), decoder text generate karta hai — language, task (transcribe/translate) aur timestamps ke liye special tokens ke saath. Ye multilingual hai aur accents/noise ke prati robust hai. Metric: word error rate (WER).

Q21Qwen2-Audio aur Kimi-Audio kya karte hain?

Qwen2-Audio (2024) Whisper-large-v3 encoder plus Qwen language model hai, 32k-token audio context ke saath — speech, sounds aur music handle karta hai, audio QA aur audio chat kar sakta hai. Kimi-Audio (2025) 13B-parameter LLM backbone ke saath long audio aur speaker diarisation (kaun kab bola) ke liye design kiya gaya hai.

Q22Decision Transformer kya hai aur ye RL ko kaise badalta hai?

Decision Transformer (2021) trajectory ko (return, state, action, reward) tokens ki sequence banakar GPT-style decoder se agla action predict karta hai — desired return-to-go dekar. Isse value-function bootstrapping ki zaroorat khatam ho jati hai aur RL supervised learning ban jata hai. Limitation: ye kharab trajectories ke achhe parts ko dynamic-programming methods ki tarah 'stitch' nahi kar sakta.

Q23STORM aur DreamerV3 me kya farak hai? Atari numbers kya hain?

STORM (2024) stochastic transformer-based world model hai jo latent state aur reward predict karta hai. DreamerV3 (2023) RSSM world model + actor–critic hai jo imagination me train hota hai aur Atari, continuous control aur Minecraft me kaam karta hai. 40 Atari games par mean scores: STORM 16,960, DreamerV3 15,565, human mean 7,845 — dono models human mean se upar dikhaye gaye hain (kitab me jaisa hai, waisa hi).

Q24Era of experience ka matlab kya hai?

Human data ke era ke baad AI khud ka experience generate karke (self-play, trial and error, test-time search) usse seekhta hai aur improve hota hai. Isliye reasoning ab train bhi hoti hai (RL/GRPO) aur test time par search bhi hoti hai (MCTS/A*/S*) — sirf prompt nahi. Thinking budget allocate karne wala resource hai.

Q25RLHF aur GRPO me kya farak hai?

RLHF classic 3-stage pipeline hai: SFT → human preferences se reward model → PPO with KL penalty. Isme human labels, alag reward model aur PPO instability ki cost hai. GRPO (2024) har prompt ke liye G outputs ka group sample karke group ke mean/std ko baseline banata hai — advantage = (reward − group mean) / group std — isliye koi critic network nahi chahiye; ye simpler aur zyada memory-efficient hai.

Q26DeepSeek-R1 ne reasoning kaise seekhi?

DeepSeek-R1 (2025) large-scale RL se seedha base model se train hua — long chains of thought par alag SFT stage ke bina, rule-based rewards (sahi jawab, sahi format) ke saath. Isne emergently lambi chains of thought, self-verification aur backtracking develop kar li. R1-Zero pure-RL variant hai; R1 me thoda cold-start data hai.

Q27Qwen3 ka thinking mode kya hai?

Qwen3 (2025) 0.6B se 235B parameters tak ki family hai (MoE variants samet) jisme hybrid thinking mode hai — model step-by-step soch sakta hai jab kaha jaye, ya seedha jawab de sakta hai, ek hi weights me token/flag se control hota hai. Thinking budget (thinking tokens) badhane se accuracy badhti hai, diminishing returns ke saath.

Q28MCTS, A* aur S* — kab kaunsa use karein?

MCTS selection (UCB), expansion, simulation aur backpropagation se tree search karta hai — hard reasoning ke liye, jab search afford kar sakte ho. A* best-first search hai, f(n) = g(n) + h(n), admissible heuristic ke saath optimal — deterministic planning ke liye. S* (2025) sampling ko learned value estimate ke saath combine karta hai — MCTS ka zyada fayda, search cost ke fraction par.

Q29ReAct pattern kya hai?

ReAct (2022) reasoning traces (Thought) ko actions (Action) aur observations (Observation) ke saath interleave karta hai — Thought → Action → Observation → Thought… — taaki model plan kar sake, tool call kar sake, result dekh sake aur revise kar sake. Ye agents ka core loop hai.

Q30LangGraph plain chain se kaise alag hai?

LangGraph me agents graphs hote hain: nodes steps hain (LLM calls, tool calls), edges transitions hain, conditional edges routing decisions hain, aur graph ke paas persistent state hoti hai. Plain chain sirf aage badhta hai; graph loop kar sakta hai, branch kar sakta hai aur errors se recover kar sakta hai.

Q31Agents me memory ki problem kya hai?

Short-term memory graph me conversation/state hai; long-term memory past interactions ka vector store ya database hai. Unbounded memory context aur cost dono badhata hai, isliye summarisation/compaction chahiye. Plan-then-execute aur reflection (failure ke baad khud ki trace critique karke retry) agents ko ek run ke andar improve karte hain, lekin latency aur cost add karte hain.

Q32Checkpoint Engine, ART/RULER, DeepCoder aur AdaptThink — ye chaaro kya karte hain?

Checkpoint Engine data-centric optimisation hai — checkpoints aur data subsets select karta hai jo target metric ko sabse zyada improve karte hain. ART agents ko kai baar chalakar reliability measure karta hai; RULER check karta hai ki actions rules follow karte hain ya nahi. DeepCoder 14B-parameter coding model hai jo RL (rLLM) se train hua — 33.75% pass@1 aur 55% pass@k, 20 problems par. AdaptThink threshold δ se seekhta hai kab lamba sochna hai aur kab seedha jawab dena hai.

Q33LoRA, QLoRA, DoRA aur LoftQ me kaunsa kab chunein?

LoRA: W freeze karke low-rank update ΔW = BA train karo (r = 8 ya 16) — simplest case. QLoRA: 4-bit base + LoRA — 65B model ek 48GB GPU par fine-tune hota hai, lekin ~17% zyada latency. DoRA: magnitude aur direction alag train karke full fine-tuning ke kareeb quality. LoftQ: quantisation-aware initialisation — heavy (2-bit) quantisation me best; reward ~0.05 tak step 75 par pahunchta hai jabki LoRA ko step 190 aur QLoRA/DoRA ko 400+ steps chahiye. LoftQ ki throughput sabse zyada hai: 15.9 TPS.

Q34Model deploy karte time kya monitor karna chahiye?

Latency (p50/p95/p99), throughput, error rate, cost per request, aur output quality (held-out evaluation set regular chalakar). Data/concept drift aur KV-cache memory growth par nazar rakho; alerts aur rollback plan set karo — previous model version deployable rakho. Serving ke liye vLLM recommend kiya gaya hai (PagedAttention + continuous batching).

Honest out-of-scope list

  • Index: reader me alphabetical index hai (A–Y headings — J aur Z nahi) — ye ek lookup reference hai; iska scope Section 15 me summarise kiya gaya hai, entry-by-entry reproduce nahi kiya gaya kyunki isme koi naya prose, figures ya results nahi hain.
  • Appendices: kitab me koi appendix nahi hai — kuch omit nahi kiya gaya.
  • ISBN: kitab me do alag numbers dikhe (URL 9781098167004; Preface example 978-1-098-16701-1) — dono waise hi likhe gaye hain, kaunsa print/electronic hai ye decide nahi kiya gaya.
  • Original figures: kitab ke figures ke descriptions se dobara banaye gaye diagrams hain — original pixels nahi. Jahan reader text me figure ka number tha lekin poora data table prose me nahi tha, wahan subject describe kiya gaya hai — cell values invent nahi ki gayi.
  • Code: code blocks kitab ke descriptions se step-by-step reconstruct kiye gaye hain — verbatim claim nahi kiya gaya. Code slips (Ex. 4-7, 4-8, 9-1, 9-2, 9-4, 1-7) jaise dikhe waise hi note kiye gaye hain.
  • Personal names: SPA me koi personal names nahi likhe gaye hain (standing rule) — lekhak, editors, reviewers aur cited paper-authors ko generic tareeke se describe kiya gaya hai; model/product names (jaise GPT-4, Claude, Sora, Whisper) content ka hissa hain, isliye rakhe gaye hain.
  • Formulas: GRPO objective, pass@k, sinusoidal encoding aur RoPE derivation reader me garbled render hue the — waise hi report kiye gaye hain, silently repair nahi kiye gaye.
  • Footnote years: bohot saari footnotes 2017 deti hain un papers ke liye jinhe chapter text baad ka batata hai — footnote years waise hi likhe gaye hain, correct nahi kiye gaye.
  • Table 12-1: caption "rLLM components" kehta hai lekin table paper counts deti hai, aur topic rows ka sum stated total (820 / 2,520) se match nahi karta — dono waise hi likhe gaye hain.
