1. Context Engineering

1.1 Context engineering kya hai

Context engineering ka matlab hai jaan-boojh kar design karna ki AI agent kaam karte waqt kya dekh aur use kar sakta hai: prompt, files, history, tools, rules, examples aur feedback — sab kuch. Yeh tay karna hai ki model ki working memory me kya jaye, kis order me, kis form me, aur kya bahar rahe.

Chapter ka central claim hai ki agentic coding ke liye context ek single prompt ki wording se zyada matter karta hai — kyunki agent kai steps me kaam karta hai aur har step ko pehle wale steps ka context inherit hota hai.

1.2 Kyun zaroori hai — chaar reasons

1. Quality tay karta hai. Wahi model achhe context ke saath correct, idiomatic code deta hai; kharab context ke saath plausible lekin galat code deta hai.

2. Cost aur speed tay karta hai. Irrelevant context tokens, time aur paisa waste karta hai; missing context se correction ke extra rounds lagte hain.

3. Safety tay karta hai. Context me secrets, credentials ya unrelated private data ho to leakage aur security risk banta hai.

4. Reliability tay karta hai. Achhe se engineered context agent ka behaviour repeatable banata hai; messy context use unpredictable bana deta hai.

1.3 Teen rules

Rule 1 — Agent ko woh do jo use chahiye, aur kuch bhi extra nahi. Context ki har item apni jagah tabhi earn kare jab woh agle decision me madad kare.

Rule 2 — Important cheezon ko aasan banao dhoondhna. Sabse relevant instructions, constraints aur examples wahan rakho jahan agent unhe notice kare, saaf order me.

Rule 3 — Context ko fresh rakho. Jo information out of date ho, baad ki findings se contradict karti ho, ya current task se relevant na ho — use hatao ya replace karo.

1.4 Chaar strategies

1. Write — likh do. Context ko files me likh do jinhe agent padh sake — jaise CLAUDE.md, rules aur project documentation — taaki woh sessions ke across persist kare.

2. Select — chuno. Task ke liye files, symbols aur history ka sahi subset chuno, poora repository dump karne ki jagah.

3. Compress — sankshipt karo. Lambi histories, logs aur documents ko chhote, dense notes me summarise karo jo decisions aur unke reasons preserve karein.

4. Isolate — alag rakho. Alag tasks, agents aur concerns ko alag contexts me rakho taaki woh ek doosre ko contaminate na karein.

1.5 Chaar practices

1. Project memory file use karo (CLAUDE.md) — project ki conventions, architecture, commands aur common pitfalls record karne ke liye.

2. Rules files use karo — focused, reusable guidance ke liye (jaise ek testing rule ya ek style rule) jo sirf tab load ho jab relevant ho.

3. Examples use karo — desired output ke kuch achhe examples ek lambi description se zyada keemti hote hain.

4. Feedback loops use karo — agent ka apna output, test results aur error messages agle step ka naya context ban jayein, taaki woh khud ko correct kar sake.

1.6 Chaar scenarios

1. Naya project: existing context bahut kam hai, isliye agent ko up front ek clear brief, ek plan aur conventions ka set chahiye.

2. Existing project: agent ko sahi files, existing patterns aur tests ki taraf point karna hota hai, aur fragile parts ke baare me warn karna hota hai.

3. Bada project: ek bhi context sab kuch hold nahi kar sakta, isliye kaam ko modules me split karna hota hai, har module ka apna focused context.

4. Team project: context ko share, version aur agree karna hota hai, taaki har developer aur har agent session wahi understanding se shuru kare.

1.7 Paanch steps — workflow

Step 1: Goal aur success criteria define karo. Step 2: Relevant context gather karo (files, docs, history, constraints). Step 3: Organise karo — order do, label karo, irrelevant hatao. Step 4: Agent ko aise form me do jise woh use kar sake. Step 5: Result review karo, jo kaam kiya use rakho, aur jo seekha use stored context me update karo.

1.8 Chaar mistakes

1. Too much context — agent ko poora codebase de dena, jisse relevant detail dab jaye. 2. Too little context — vague request dena aur expect karna ki agent project ki conventions guess kar le. 3. Stale context — documentation ya memory files par bharosa karna jo code se ab match nahi karte. 4. Conflicting context — do instructions dena jo disagree karti hon, jisse agent ko guess karna pade ki kaunsi jeetegi.

1.9 Context engineering vs prompt engineering — aur context debt

Prompt engineering ek single request ko achhe se word karne ke baare me hai. Context engineering multi-step agent ke liye poora information environment design karne ke baare me hai.

Prompt engineering ek subset hai: achha prompt achhe context ka ek piece hai, lekin context engineering me files, memory, tools, history, examples aur feedback bhi aate hain — aur yeh ek message me nahi, sessions ke across persist karta hai.

Context debt outdated, contradictory ya irrelevant context ka accumulation hai. Use pay down karne ke teen steps hain: (1) audit karo ki context me abhi kya hai, (2) jo galat hai use hatao ya correct karo, (3) use ek chhote, verified summary se replace karo jo ab sach hai.

1.10 System prompt kaise banayein — teen steps aur Goldilocks zone

Chapter system prompt banane ke teen steps deta hai: pehle role aur goal batao, phir constraints aur definition of done batao, aur phir output format aur examples batao.

Do extremes se warn kiya gaya hai: prompt itna chhota ki agent ko guess karna pade, aur prompt itna lamba ki important instructions kho jayein. Beech ka useful zone Goldilocks zone kehlata hai — itna detail ki ambiguity na rahe, itna chhota ki important baatein visible rahein.

1.11 Context window vs working context — chaar failure modes aur paanch tools

Context window woh total text hai jo model ek session me accept kar sakta hai. Working context us window ka woh part hai jo current decision ke liye actually useful hai. Chapter stress karta hai ki bada window engineering ki zaroorat khatam nahi karta: bade window ko noise se bharna bhi results degrade karta hai.

Chaar failure modes hain: 1. Context overload — zyada information, agent key fact miss kar deta hai. 2. Context starvation — kam information, agent plausible answer invent kar leta hai. 3. Context contamination — doosre task ki irrelevant ya galat information leak ho jati hai. 4. Context drift — conversation original goal se door chali jati hai aur shuru ki instructions effectively bhool jati hain.

Context engineering ke liye paanch kinds ke tools list kiye gaye hain: project memory files, rules files, retrieval / search tools, summarisation / compression tools, aur subagents jo main agent ki taraf se context gather aur filter kar sakte hain.

1.12 Summary

Context engineering agentic coding ki core skill hai: prompt likhne se pehle information environment design karo, use chhota, fresh aur ordered rakho, aur project badalne par use maintain karo.

2. The Gist of Claude Code

2.1 Claude Code kya hai

Claude Code ek agentic coding tool hai: ek command-line (aur baad me desktop) agent jo Claude model par bana hai — codebase padh sakta hai, plan bana sakta hai, code likh aur edit kar sakta hai, commands aur tests chala sakta hai, tools use kar sakta hai, aur task poora hone tak iterate kar sakta hai.

Yeh ek chatbot nahi hai jo ek turn me jawab de, aur na hi ek autocomplete jo ek line complete kare — yeh ek agent hai jo reasoning, action aur observation ke loop me task par kaam karta hai.

2.2 Teen core principles aur teen characteristics

Teen core principles: 1. Agent-first — tool ek agent ke around design kiya gaya hai jo act kar sakta hai, ek single response ke around nahi. 2. Terminal-first / developer-first — yeh wahin rehta hai jahan developers pehle se kaam karte hain — terminal aur codebase. 3. Safety aur control — insaan loop me rehta hai; dangerous actions ko permission chahiye, aur agent ka kaam visible aur reviewable hota hai.

Teen characteristics: 1. Conversational — developer usse natural language me baat karta hai. 2. Tool-using — files padh sakta hai, search kar sakta hai, shell commands chala sakta hai, code edit kar sakta hai aur MCP servers use kar sakta hai. 3. Iterative — cycles me kaam karta hai: try karo, test karo, result observe karo, fix karo, repeat karo.

2.3 Chaar pillars, teen levels, paanch tools

Chaar pillars: 1. Understanding — codebase ko padhna aur us par reasoning karna. 2. Planning — act karne se pehle task ko steps me todna. 3. Execution — code likhna aur badalna, commands chalana. 4. Verification — test karna, check karna aur result correct karna.

Use ke teen levels: 1. Assisted — developer snippet ya explanation maangta hai. 2. Collaborative — developer aur agent feature par saath kaam karte hain, insaan har step review karta hai. 3. Autonomous — agent ko well-defined task diya jata hai aur woh use completion tak chalata hai, insaan result check karta hai.

Paanch built-in tools: 1. Read / file tools code inspect karne ke liye. 2. Search tools (grep / glob) symbols aur patterns dhoondhne ke liye. 3. Edit tools files ko precisely badalne ke liye. 4. Shell / Bash tool commands, tests aur builds chalane ke liye. 5. Task / subagent tool doosre agents ko kaam delegate karne ke liye.

2.4 Agent kya hai — teen sawaal, chaar layers, chaar principles

Agent ek system hai jo apne environment ko perceive karta hai, goal par reason karta hai, tools se act karta hai, aur result se seekhta hai. Chapter teen sawaal deta hai ye test karne ke liye ki kuch really agent hai ya nahi: (1) kya uska koi goal hai? (2) kya woh khud act karke use pursue kar sakta hai? (3) kya woh result observe karke adjust kar sakta hai? Agar kisi ka bhi jawab na ho to woh script ya chatbot hai, agent nahi.

Agent ki chaar layers: 1. Model — language model jo reason karta hai. 2. Tools — actions jo agent le sakta hai. 3. Memory / context — woh kya yaad rakhta hai aur kya dekh sakta hai. 4. Orchestration — loop jo decide karta hai ki aage kya karna hai.

Agent design ke chaar principles (is chapter me restated): goal explicit rakho; agent ko woh tools do jo use chahiye aur usse zyada nahi; uske actions observable banao; irreversible actions par insaan ka control rakho.

2.5 Chaar features aur chaar benefits

Claude Code ki chaar features: yeh poora project samajhta hai, code karne se pehle plan banata hai, execute aur test karta hai, aur explain karta hai ki usne kya kiya. Chaar benefits: faster delivery, kam routine errors, project conventions ke saath behtar consistency, aur unfamiliar code explore karne ki lower barrier.

2.6 Agentic coding kya hai — teen shifts aur chaar components

Agentic coding software development hai jisme AI agent coding ka substantial part karta hai — padhna, planning, likhna, testing aur fixing — human direction aur review ke under. Agent ki chaar features se define hota hai (goal-directed, tool-using, iterative, context-aware) aur coding ki chaar features se (code agent likhta hai, agent test karta hai, insaan review karta hai, aur code project ke normal version control me store hota hai).

Teen shifts jo yeh laata hai: 1. Code likhne se code direct karne tak — developer ka main kaam intent specify karna aur results review karna ban jata hai. 2. Single files se whole systems tak — agent files aur layers ke across kaam karta hai. 3. One-off answers se workflows tak — value repeatable, automated processes me hai, ek clever prompt me nahi.

Agentic coding workflow ke chaar components: 1. Intent — insaan kya chahta hai. 2. Context — agent kya jaanta hai. 3. Execution — agent kya karta hai. 4. Verification — result kaise check hota hai.

2.7 Paanch workflow steps aur chhah roles

Paanch workflow steps: 1. Task describe karo. 2. Agent ko explore aur plan karne do. 3. Implement karne do. 4. Tests chalao aur review karo. 5. Commit karo ya iterate karo.

Developer ke chhah roles jo abhi bhi uske hain: 1. Product thinker (kya banana hai). 2. Architect (yeh kaise fit hota hai). 3. Reviewer (kya yeh correct hai?). 4. Tester (kya yeh kaam karta hai?). 5. Operator (kya yeh safely chalta hai?). 6. Learner (agent ne mujhe kya sikhaya, aur context ko kya yaad rakhna chahiye?).

2.8 Paanch practices, benefits, challenges, risks, mitigations

Paanch practices: 1. Chhota shuru karo. 2. Specific raho. 3. Har change review karo. 4. Context clean rakho. 5. Repeatable parts automate karo.

Agentic coding ke chaar benefits: speed, consistency, unfamiliar code ki exploration, aur kam toil. Paanch challenges: agent hallucinate kar sakta hai, over-confident ho sakta hai, tokens me expensive ho sakta hai, debug karna mushkil ho sakta hai, aur aisa code produce kar sakta hai jo insaan samajhta hi nahi.

Teen risks: security (secrets, unsafe commands), quality (subtle bugs), aur dependence (team apna hi code samajhna band kar de). Chaar mitigations: har change ka human review, tests aur CI, least-privilege permissions, aur context aur memory files ko version control me rakhna.

2.9 Adopt karne ke chhah steps — history aur future

Chhah steps: 1. Install karo aur chhote task par try karo. 2. Project memory file likho. 3. Core commands seekho. 4. Ek automation add karo. 5. Practice team ke saath share karo. 6. Measure karo kya improve hua aur iterate karo.

Chapter Claude Code ki history sketch karta hai — ek research / command-line tool se ek product tak jisme desktop, mobile aur GitHub integrations hain — aur argue karta hai ki direction lambe samay tak chalne wale, zyada autonomous agents ki taraf hai jo bade tasks ko kam supervision me handle karte hain — jo Chapter 11 ka subject hai.

2.10 Summary

Claude Code chatbot nahi, agent hai: goal-directed, tool-using, iterative aur context-aware. Developer ka kaam code likhne se badal kar intent, review aur verification ka ho gaya hai — aur yeh tabhi kaam karta hai jab context clean ho aur har change review ho.

4. Extending Claude Code with MCP Servers and Plugins

4.1 MCP kya hai — chaar components

MCP (Model Context Protocol) ek open protocol hai, originally Anthropic se, jo ek AI application (host) ko external data aur tools se standard interface ke through connect karne deta hai. Har tool ko custom integration ki zaroorat nahi — host MCP bolta hai ek server se, aur server tools, resources aur prompts standard tareeqe se expose karta hai. Chapter ki analogy hai ki MCP AI tools ke liye wahi hai jo USB hardware ke liye hai: ek common plug.

Chaar components: 1. Host — application jisse user interact karta hai (yahan, Claude Code). Yeh connections aur permissions manage karta hai. 2. Client — host ke andar ka piece jo ek server se baat karta hai, connection maintain karta hai aur requests translate karta hai. 3. Server — external program jo tools, data ya prompts deta hai (jaise database, documentation service ya browser tool). 4. Transport — client aur server messages kaise exchange karte hain, typically local server ke liye standard input/output ya remote server ke liye HTTP.

4.2 Teen types ke MCP servers aur paanch MCP tools

11. Understanding Deep Agents

11.1 Deep agent kya hai — teen levels

Deep agent ek long-running agent hai jo bada, open-ended task khud handle kar sakta hai: woh plan banata hai, tools use karta hai, kai steps tak state rakhta hai, apna kaam check karta hai, aur galat hone par khud ko correct karta hai. Jahan normal agent kuch steps me ek task karta hai, deep agent poora project carry karta hai — researching, building, testing aur fixing — lambe session me, insaan har step par nahi, milestones par check karta hai.

Teen levels: 1. Single deep agent — ek agent poora task karta hai. 2. Deep agent with subagents — deep agent kaam ke parts subagents ko delegate karta hai. 3. Deep agent with skills aur MCP — deep agent skills bhi load karta hai aur external data aur tools ke liye MCP servers use karta hai.

11.2 Chaar components aur paanch steps

Deep agent ke chaar components: 1. Planner — task ko steps me todta hai aur seekhte hue plan revise karta hai. 2. Executor — kaam karta hai (code likhta hai, commands chalata hai). 3. Memory / state — yaad rakhta hai kya ho gaya, kya kaam kiya, aur kya baaki hai. 4. Evaluator / critic — result ko goal ke against check karta hai aur shortfall ho to agent ko fix karne ke liye wapas bhejta hai.

Deep-agent run ke paanch steps: 1. Goal aur constraints define karo. 2. Agent ko plan karne do. 3. Plan ko step by step execute karne do. 4. Evaluate aur correct karne do. 5. Insaan final result review kare.

11.3 Chaar types aur teen features

Chaar types: 1. Research agent — information gather karke synthesise karta hai. 2. Build agent — feature ya project implement karta hai. 3. Review / audit agent — code, security ya compliance check karta hai. 4. Maintenance agent — project ko up to date rakhta hai (dependencies, tests, documentation).

Achhe deep agent ki teen features: woh persistent hota hai (lambe run me state rakhta hai), self-correcting hota hai (apni galtiyan detect aur fix kar sakta hai), aur transparent hota hai (insaan dekh sakta hai usne kya kiya aur kyun).

11.4 Deep agent banane ke chaar steps

1. Clear, detailed brief likho. 2. Plan format aur checkpoints define karo. 3. Tools, skills aur MCP servers do jo use chahiye. 4. Poora task dene se pehle task ke chhote version par test karo.

Chapter ka worked example ek deep research / build task hai: deep agent ko bada task diya jata hai (research karke phir feature banana), woh use research, planning, implementation, testing aur review me todta hai, har stage par checkpoints ke saath. Agent ka apna evaluation step ek error pakad kar kaam ko fix ke liye wapas bhejta dikhaya gaya hai, galat result ko finished batane ki jagah.

FInterview FAQs

Interview FAQs — 36 sawaal

Context engineering, Claude Code, MCP, GitHub automation, planning, subagents, skills, Desktop aur deep agents par interview-relevant sawaal.

Q1 Context engineering kya hai?

Agent ko dikhai dene wali poori information environment ka deliberate design — prompt, files, history, tools, rules, examples aur feedback. Agentic coding me yeh ek single prompt ki wording se zyada matter karta hai.

Q2 Context engineering prompt engineering se kaise alag hai?

Prompt engineering ek request ko achhe se word karna hai; context engineering multi-step agent ke liye poora information environment design karna hai — files, memory, tools, history, examples, feedback — jo sessions ke across persist karta hai.

Q3 Context engineering ki teen rules kaunsi hain?

Agent ko woh do jo use chahiye aur kuch extra nahi; important cheezon ko dhoondhna aasan banao; aur context ko fresh rakho.

Q4 Context engineering ki chaar strategies kaunsi hain?

Write (files me likh do), Select (sahi subset chuno), Compress (summarise karo), Isolate (alag tasks ko alag contexts me rakho).

Q5 Context debt kya hai aur use kaise pay down karein?

Outdated, contradictory ya irrelevant context ka accumulation. Teen steps: audit karo kya hai, jo galat hai use hatao ya correct karo, aur chhote verified summary se replace karo.

Q6 Goldilocks zone kya hai?

System prompt ka useful middle — itna detail ki ambiguity na rahe, itna chhota ki important instructions visible rahein. Bahut chhota prompt guess karwata hai, bahut lamba important baatein daba deta hai.

Q7 Context window aur working context me kya farq hai?

Context window woh total text hai jo model ek session me accept kar sakta hai; working context uska woh part hai jo current decision ke liye actually useful hai. Bada window noise se bharna bhi results kharab karta hai.

Q8 Context ke chaar failure modes kaunse hain?

Context overload (zyada info, key fact miss), context starvation (kam info, agent invent karta hai), context contamination (doosre task ki info leak), context drift (goal se door chale jana).

Q9 Claude Code kya hai?

Ek agentic coding tool — command-line (aur desktop) agent jo codebase padhta hai, plan banata hai, code likhta aur edit karta hai, commands aur tests chalata hai, aur task poora hone tak iterate karta hai. Yeh chatbot ya autocomplete nahi hai.

Q10 Agent hai ya nahi — kaise test karein?

Teen sawaal: kya uska goal hai? Kya woh khud act karke use pursue kar sakta hai? Kya woh result observe karke adjust kar sakta hai? Kisi ka bhi jawab na ho to woh script ya chatbot hai, agent nahi.

Q11 Agentic coding kya hai?

Development jisme AI agent coding ka substantial part karta hai — padhna, planning, likhna, testing, fixing — human direction aur review ke under. Code agent likhta hai, agent test karta hai, insaan review karta hai.

Q12 Claude Code install karne ke liye kya chahiye?

Supported OS (macOS, Windows, Linux), jahan zaroorat ho Node.js, ek terminal, aur ek Claude subscription ya API key. GitHub account ki zaroorat nahi hai.

Q13 Claude Code ke paanch modes kaunse hain?

Normal (default, interactive), Plan (plan pehle, approval ke baad build), Auto-accept (edits bina poochhe), Read-only (padh sakta hai, badal nahi sakta), Non-interactive / print (scripts ke liye).

Q14 Pehla session kaise start karein?

Project folder me terminal kholo, claude chalao, sign in karo, pehla chhota sawaal poochho, chhota safe change karne ko kaho, aur accept karne se pehle diff review karo.

Q15 MCP kya hai?

Model Context Protocol — ek open standard jisse host (Claude Code) external data aur tools se connect hota hai. Server tools, resources aur prompts expose karta hai; analogy: MCP AI tools ke liye wahi hai jo USB hardware ke liye hai.

Q16 MCP ke chaar components kaunse hain?

Host (user se interact karta hai), Client (host ke andar, ek server se baat karta hai), Server (tools/data/prompts deta hai), Transport (stdio local ke liye, HTTP remote ke liye).

Q17 MCP scope local, project aur user me kya farq hai?

Local sirf is machine + is user ke liye, share nahi hota — secrets ke liye. Project repo me share hota hai, team ke liye — conventions ke liye. User is user ke saare projects par lagta hai — personal preferences ke liye.

Q18 Context pollution kya hai — 20% aur 2.4% ka kya matlab hai?

Bina limits ke MCP servers add karne se context tool descriptions se pollute ho jata hai. Kitaab ke experiment me loose config me error rate lagbhag 20% thi, strict config me lagbhag 2.4% — sirf task ke tools expose karo.

Q19 Credentials MCP config file me kyun nahi likhne chahiye?

Kyunki config file leak ho sakti hai. Credentials environment variables ya secrets store me rakho; server ko clear error se fail hona chahiye, chupchaap nahi.

Q20 Plugin kya hota hai?

Packaged extension jo ek install me commands, agents, skills, MCP servers aur hooks add karta hai. Achha plugin self-contained hota hai, permissions declare karta hai, aur bina project edit kiye enable/disable ho sakta hai.

Q21 GitHub ke saath Claude Code ke teen workflows kaunse hain?

Issue-to-PR (issue se pull request), PR review (diff ka automated review), CI fix (CI fail ho to agent fix karke dobara push kare).

Q22 gh CLI ke chhah commands kaunse hain?

gh auth login, gh repo list, gh repo create, gh repo clone, gh pr create, gh pr status — authenticate, list, create, clone, PR kholna aur status check karna.

Q23 Planning multi-agent kaam me kyun zaroori hai?

Likhhi hui, testable plan, kaam ka clear split, aur plan approve + merged result review karne wala insaan — yahi multi-agent kaam ko reliable banata hai.

Q24 6 ghante wale example se kya seekh milti hai?

Plan aur parallel agents se wall-clock time girta hai kyunki independent chunks parallel chalte hain — lekin total kaam disappear nahi hota, woh redistribute hota hai aur end me merge aur review chahiye.

Q25 Subagent kya hai?

Main agent se launch kiya gaya alag agent instance — apna context, apne tools, apni instructions — jo focused kaam karke sirf summary wapas deta hai. Isi se context isolation practical banta hai.

Q26 Subagent ke chaar types kaunse hain?

Explore (search aur report), Plan (plan likho), Implement (defined piece ka code), Review (code/tests/docs check karo).

Q27 Infinite Agentic Loop kya hai?

Chhah subagents se Hero component ke chhah parallel variants generate karwana, phir compare karke best pick karna — aur feedback se repeat karna jab tak insaan satisfied na ho. Steps chhote hote hain (30, 15, 10, 5, 2, 1 second); value parallelism aur comparison me hai.

Q28 Output style kya hai?

Instructions ka named set jo control karta hai ki agent kaise communicate kare — length, formality, detail, structure. Kaam nahi badalta, sirf reporting badalti hai — taaki ek hi agent alag audiences ko serve kar sake.

Q29 Agent skill kya hai?

Packaged, reusable expertise — SKILL.md + optional scripts, templates, examples wala folder. Agent description se match hone par load karta hai. Progressive disclosure: pehle sirf description dikhti hai, poori instructions sirf on demand.

Q30 Skill, slash command, subagent, memory file aur plugin me kya farq hai?

Command insaan invoke karta hai; skill agent invoke karta hai jab task match kare; subagent alag agent hai apne context ke saath; memory file hamesha load hoti hai; plugin ek package hai jisme skills, commands, agents aur MCP servers ho sakte hain.

Q31 SKILL.md kahan rehti hai aur usme kya hota hai?

Path: .claude/skills//SKILL.md. Frontmatter (name aur description) aur body jo workflow sikhata hai. Description distinctive rakho — agent isi se skill choose karta hai.

Q32 Claude Code Desktop terminal version se kaise alag hai?

Wahi agent, graphical window me — Code tab, sessions/history tab, settings tab; cloud sessions aur mobile access; parallel agents ke liye worktrees aur merge step.

Q33 HookHub example me teen agents kaun kaam karte hain?

Animations agent (animations), Hooks agent (hooks.json), Hero agent (Hero component) — har ek apne worktree me parallel, phir merge step se combine.

Q34 Deep agent kya hai?

Long-running agent jo bada, open-ended task khud carry karta hai — plan, tools, persistent state, self-evaluation aur correction — insaan milestones par check karta hai, har step par nahi.

Q35 Deep agent ko safely chalane ki checklist kya hai?

Clear brief, defined checkpoints, limited permissions, rokne ka tareeqa, aur har milestone par human review (Table 11.3). Irreversible actions approval ke bina kabhi mat do.

Q36 Packt ke benefits kaise unlock karein?

packtpub.com/unlock par jao ya QR code scan karo, kitaab search karke sahi edition select karo, Packt account me sign in karo ya free account banao, aur invoice upload karo (PDF, PNG ya JPG, 10 MB tak). Benefits: code bundle, DRM-free PDF/ePub, 7-day library access (8,000+ books/videos), next-gen reader.
