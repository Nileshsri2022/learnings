01Part 1 — Fundamentals

1. What Is Deep Learning?

1.1 AI, machine learning aur deep learning

AI ka matlab hai woh tasks automate karna jinme human intelligence chahiye hoti hai. Machine learning AI ka subfield hai jo data ko rules me badal deta hai — patterns dhoondh kar, haath se rules likhe bina. Deep learning machine learning ka subfield hai jo layered representations seekhta hai — successive layers, jo dheere-dheere zyada meaningful representations banati hain, zyada tar neural networks se.

Classic non-ML pipeline me input rules haath se likhe jate hain, ek human-written answer key hoti hai aur hard-coded answers hote hain. ML me inputs aur answers diye jate hain, aur system rules seekh leta hai.

Figure 1.2 layered representations ki chain dikhati hai: digit ki image pehle pixels se represent hoti hai, phir edges, phir local patterns, phir digit ke parts, aur ant me digit ki identity.

1.2 Deep learning se pehle — machine learning ka brief history

Early ML me symbolic AI tha (1950s–1980s), jaise haath se likhe gaye expert systems, aur baad me probabilistic models aaye. Kai AI boom-and-bust cycles aaye aur gaye — hype badhta, phir expectations poori na hone par funding aur interest girta.

Deep networks pehle ke approaches se khaas taur par depth me alag hain: bahut saari chained transformations se woh bahut complex functions seekh sakte hain.

1.3 Deep learning ab kyun? Teen ingredients

Pehla ingredient — data: roz-marra ki zindagi ke digitisation se bade labelled datasets bante hain. Dusra — hardware: GPUs aur TPUs massive parallel computation dete hain; chapter me example hai ki jo training pehle hafton me hoti thi, woh ab ghanton me hoti hai, aur bade GPU clusters ka zikr hai. Teesra — algorithmic progress: behtar training methods, architectures aur initialisation.

Do aur ideas par zor diya gaya hai: deep learning end-to-end representations seekhta hai — network apni saari layers ek saath jointly seekhta hai, isliye features aur classifier ek saath tune hote hain — aur iski sabse badi taakat hai ki yeh raw data se seekh sakta hai, bina manual feature engineering ke.

1.4 Hype se savdhaan

Chapter hype cycle aur over-claims ke khilaf warn karta hai: deep learning magic nahi hai, abhi general intelligence nahi hai, aur kai problems ab bhi classical methods se behtar solve hoti hain.

Iska long-term promise phir bhi real hai, kyunki yeh zyada data aur compute ke saath behtar hota ja raha hai, aur pehle se hi products me embedded hai.

Is chapter me koi code example numerical result ke saath nahi chalaya gaya hai — yeh ek concept chapter hai.

2. The Mathematical Building Blocks of Neural Networks

2.1 Pehli jhalak — MNIST neural network

Example handwritten digits (MNIST) classify karta hai: 60,000 training images aur 10,000 test images, har ek 28x28 grayscale pixels ki.

Step by step: keras.datasets.mnist.load_data() se data load karo, images ko 784 numbers ke vectors me reshape karo, pixel values ko 0–255 se 0–1 par scale karo, aur labels ko 10-dimensional vectors me one-hot encode karo.

Model ek Sequential network hai: Dense layer 512 units aur relu activation ke saath, phir Dense layer 10 units aur softmax activation ke saath. Compile rmsprop optimiser, categorical_crossentropy loss aur accuracy metric ke saath hota hai, phir 5 epochs, batch size 128 ke saath fit kiya jata hai.

Reported result: training accuracy 98.9% (loss 0.0362) aur test accuracy 97.85% (test loss 0.0783) — printed run ke numbers 0.9891 / 0.9785 hain.

MNIST — pehla neural network (reconstructed) reconstructed from notes — kitaab ka verbatim code nahi

    keras.layers.Dense(512, activation="relu"),
    keras.layers.Dense(10, activation="softmax"),
])
model.compile(optimizer="rmsprop",

2.2 Data representations — tensors

Scalars rank-0 hain, vectors rank-1, matrices rank-2, aur higher-rank tensors inhi ko generalise karte hain. Key attributes hain ndim, shape aur dtype.

MNIST images ki batch ki shape hoti hai (60000, 28, 28). Video ke 5 axes hote hain — samples, frames, height, width, channels — aur example me 5-second, 60 fps, 144x256 video ka size 5,400 MB bataya gaya hai (byte arithmetic text me dikhayi gayi hai). Image batch ki shape hoti hai (samples, height, width, channels).

2.3 Tensor operations

Element-wise operations (relu, addition), broadcasting (matrix ki har row me ek vector add karna), tensor dot products (jaise dot(x, W) ek dense layer implement karta hai), aur reshaping/transposing — yeh sab tensor operations hain.

Figure 2.2 broadcasting dikhati hai — chhota tensor bade tensor ke shape me 'stretch' hokar har row par apply hota hai.

2.4 Gradient-based optimization — engine

Neural network ek differentiable function hai; loss batata hai ki predictions targets se kitni door hain; gradient loss ke sabse tez badhne ki direction hai; gradient descent weights ko gradient ke opposite direction me step karta hai, learning rate se scaled.

Stochastic gradient descent mini-batches use karta hai — text batch size 1, batch 128 aur poora dataset ka contrast dikhata hai, aur note karta hai ki SGD with momentum, Adam, Adagrad, Adadelta aur RMSprop common variants hain, example me RMSprop use hua hai.

Backpropagation chain rule ko efficiently apply karna hai — loss ka gradient har weight ke respect me, layers ke peeche se derivatives propagate karke compute hota hai. Koi bhi differentiable operation chain kiya ja sakta hai, isliye layers stack karne se differentiable model banta hai.

Local minima aur non-convex loss landscape par discussion hai: high dimensions me zyada tar critical points saddle points hote hain, aur practice me optimisation problem tractable hai.

2.5 Pehle example par wapas — representation ki nazar se

MNIST example ko learned representation ki tarah reinterpret kiya gaya hai: pehli layer pixels se 512 features seekhti hai, dusri unhe class scores me map karti hai; loss softmax probabilities par negative log-likelihood hai.

Phir ek pure-NumPy re-implementation scratch se banayi gayi hai: NaiveDense (weights W aur b, forward pass relu(dot(inputs, W) + b)), NaiveSequential, BatchGenerator, aur manual gradient computation (grad_W = dot(inputs.T, grad_output), grad_b = batch par sum).

10 epochs train karne par yeh lagbhag 0.83 accuracy (83%) tak pahunchti hai — Keras version se kam, jo dikhata hai ki framework ka optimiser aur initialisation kitna contribute karta hai.

Chapter me ek naive element-wise relu loop ko bhi time kiya gaya hai: 2.45 seconds, vectorised NumPy version ke 0.02 seconds ke mukable — isiliye tensor operations matter karte hain.

2.6 Summary

Neural network differentiable function hai jise gradient descent se train kiya jata hai. Tensors data ka container hain, tensor operations computation hain, aur backpropagation gradients compute karne ka efficient tareeqa hai.

Framework (optimiser, initialisation, vectorisation) kaam ka bada hissa karta hai — scratch implementation 83% par atakti hai, jabki Keras wala model 97.85% test accuracy deta hai.

4. Classification and Regression

4.1 Movie-review classification — IMDb

IMDb dataset: 25,000 training reviews aur 25,000 test reviews, binary positive/negative, pehle se tokenised integer word indices ke roop me.

Bahut bada model kuch hi epochs me overfit karta hai, aur bahut chhote units wala model underfit karta hai. Text me benchmarks: basic dense model ~88%, state-of-the-art approaches ~95% tak pahunchte hain.

4.2 Newswire classification — Reuters

Reuters newswires: 8,982 training documents, 2,246 test documents, 46 topics. One-hot encoding wahi hai, lekin final layer Dense(46, softmax) hai, categorical_crossentropy loss ke saath.

Random classifier ko lagbhag 1/46 ≈ 2% milta; text ka worked baseline alag hai — majority class predict karne par lagbhag 19% milta hai.

Results: pehla model ~80% validation accuracy tak pahunchta hai. Bottleneck layer add karne par (Dense(64) → Dense(4) → Dense(46)) information flow jaan-boojh kar restrict hota hai aur accuracy lagbhag 71% tak gir jati hai — information-bottleneck idea ko illustrate karta hai (Figure 4.3 bottleneck architecture dikhati hai).

5. Fundamentals of Machine Learning

5.1 Generalization — machine learning ka goal

Machine learning training data fit karne ke baare me nahi hai — unseen data par generalise karne ke baare me hai. Overfitting matlab training set ko yaad kar lena; underfitting matlab underlying pattern ko pakad hi nahi paana.

Figure 5.1 model capacity badhne par training vs validation error ki classic U-shaped curve dikhati hai; Figure 5.2 ek aisa model dikhati hai jo training data ko perfectly fit karta hai lekin generalise buri tarah karta hai.

Data manifold hypothesis: real data high-dimensional space me embedded low-dimensional manifold par hote hain, isliye manifold par nearby points ke beech interpolation kaam karta hai, lekin manifold se bahar extrapolation fail hota hai. Figure 5.3 ise 3-D me ek curved 2-D manifold se illustrate karti hai.

5.2 ML models ko evaluate karna

Simple hold-out split (train/validation/test), K-fold cross-validation, aur chhote datasets ke liye shuffling ke saath iterated K-fold — yeh evaluation protocols hain.

Text zor deta hai ki test set sirf ek baar use hota hai, saari tuning ke baad, aur data leakage (jaise test-set statistics se normalise karna) evaluation ko invalid kar deta hai.

ProtocolKab use karein
Hold-out splitData kaafi ho — train / validation / test
K-fold cross-validationData medium ho — har fold ek baar validation bane
Iterated K-fold with shufflingData chhota ho — kai shuffled runs average karo

5.3 Fit aur generalization improve karna

(a) Zyada data lo; (b) capacity kam karo — kam layers/units, ya chhota model; (c) weight regularisation add karo, khaas taur par L2 (example me IMDb model par kernel_regularizer=regularizers.l2(0.002) use hua hai); (d) dropout add karo — training ke dauraan randomly ek fraction units drop kar do (example rate 0.5, yaani aadhi units).

Chapter IMDb example ko har technique ke saath dobara chalata hai aur validation curves improve hoti dikhati hai: L2 regularisation aur dropout dono validation accuracy upar le jate hain aur overfitting ko delay karte hain.

Aur salah: pehle simpler architecture use karo, learning rate tune karo, aur yaad rakho ki model ki capacity data ki matra se match karni chahiye. Figure 5.4 regularisation ka validation curve par effect dikhati hai.

Goal generalisation hai, training accuracy nahi. Evaluation protocol pehle tay karo, test set ko ek baar use karo, aur leakage se bacho.

input_b = keras.Input(shape=(16,))

class MyDense(keras.layers.Layer):
    def build(self, input_shape):
        self.w = self.add_weight(shape=(input_shape[-1], 32),
                                 initializer="random_normal", trainable=True)
        self.b = self.add_weight(shape=(32,),
                                 initializer="zeros", trainable=True)
    def call(self, inputs):
        return keras.ops.relu(keras.ops.matmul(inputs, self.w) + self.b)

9. ConvNet Architecture Patterns

9.1 Residual connections

Residual connection me block ka input uske output me add kar diya jata hai (x + F(x)), isliye network ek residual correction seekhta hai. Isse gradients bahut deep networks se beh sakte hain — yahi ResNet ka core hai.

Figure 9.1 residual block dikhati hai; Figure 9.2 gradient-flow ki intuition dikhati hai.

9.2 Batch normalization

Batch normalization har mini-batch ko zero mean aur unit variance par normalise karta hai, phir learned parameters se rescale karta hai. Yeh training stabilise karta hai, bade learning rates allow karta hai, aur halka regulariser ki tarah bhi kaam karta hai.

Formula dikhaya gaya hai: (x − mean) / sqrt(var + epsilon) × gamma + beta.

9.3 Depthwise separable convolutions

Standard convolution ko replace kiya jata hai: pehle depthwise convolution (har input channel ke liye ek kernel), phir 1x1 pointwise convolution. Worked arithmetic: 32 se 64 channels tak 3x3 convolution 28x28 input par 36,864 parameters use karta hai (3x3x32x64 + biases), jabki separable version sirf 4,672 parameters use karta hai — lagbhag 8x ki bachat — kam accuracy loss ke saath. Yahi Xception aur MobileNet ka core hai.

9.4 Mini-Xception model

Chapter ek chhota Xception-style model banata hai (entry flow, middle flow me 8 repeated residual separable-convolution blocks, exit flow) aur use dogs vs cats par train karta hai.

Result: 90.8% test accuracy, Chapter 8 ke plain ConvNet ke 83.9% ke mukable, sirf 721,857 parameters ke saath, bade plain model ke 1,569,089 ke mukable — aadhe se kam parameters me behtar accuracy.

9.5 Image classification ke liye Transformers

Vision Transformers (ViT): images ko patches me split kiya jata hai, har patch embed hota hai, aur ek Transformer encoder sequence ko process karta hai. ViT bade scale par achha kaam karta hai lekin chhote scale par ConvNets se zyada data chahiye hota hai.

17. Image Generation

17.1 Image generation ka task

Generative image models images ki distribution seekhte hain, isliye woh nayi images sample kar sakte hain. Chapter GANs (jinhe kitaab ab centre me nahi rakhti) ko VAEs aur diffusion models se contrast karta hai.

17.2 Variational autoencoders

VAE: encoder image ko low-dimensional latent space me ek distribution par map karta hai (mean aur log-variance), usse ek sample draw hota hai (reparameterisation trick: z = mean + exp(0.5 × log_var) × epsilon), aur decoder image reconstruct karta hai.

Example MNIST par VAE hai, latent_dim = 2: encoder ke 69,076 parameters aur decoder ke 65,089, 30 epochs train kiya gaya. Loss reconstruction loss plus KL-divergence term hai, jo latent distribution ko standard normal ke kareeb rakhta hai.

Results: 2-D latent space ko 30x30 grid ke roop me visualise kiya ja sakta hai generated digits ki (Figure 17.1), jahan grid par move karne se ek digit dheere-dheere dusre me morph hota hai — yahi latent space ka point hai. Figure 17.2 VAE architecture dikhati hai.

Reparameterisation trick (reconstructed) reconstructed from notes — kitaab ka verbatim code nahi
def sample(mean, log_var):
    epsilon = keras.random.normal(shape=keras.ops.shape(mean))
    return mean + keras.ops.exp(0.5 * log_var) * epsilon
# latent_dim = 2; encoder 69,076 params; decoder 65,089 params

17.3 Diffusion models

Diffusion: forward process image me dheere-dheere Gaussian noise add karta hai jab tak woh pure noise na ban jaye; reverse process ek neural network (U-Net) hai jo har step par noise predict karna seekhta hai, isliye pure noise se shuru karke baar-baar denoise karne se nayi image generate hoti hai.

Example Oxford Flowers 102 par diffusion model train karta hai (8,189 images, 102 flower species), 128x128 par resize karke. U-Net widths [32, 64, 96, 128] use karta hai, cosine noise schedule 0.02 se 0.95 tak, aur 100 epochs train hota hai — Colab T4 GPU par lagbhag 90 minutes.

Chapter classifier-free guidance samjhata hai (class label ke saath aur bina, dono tarah train karke, phir labelled prediction ki taraf extrapolate karke) — controllable generation ki key.

17.4 Stable Diffusion

Stable Diffusion ek latent diffusion model hai — diffusion pixel space ki jagah VAE ke compressed latent space me chalta hai, jo bahut sasta hai.

18. Best Practices for the Real World

18.1 Hyperparameter tuning

Hyperparameters (learning rate, batch size, layers/units ki sankhya, dropout rate, regularisation strength) KerasTuner se tune kiye jate hain. Example me BayesianOptimization use hoti hai, max_trials=20 ke saath, aur ek HyperXception model (tunable Xception-style model) aur ek HyperResNet model define kiye gaye hain, jo filters ki sankhya, dropout rate aur learning rate par search karte hain.

Search dogs-vs-cats data par chalaya jata hai aur best model ko dobara train kiya jata hai. Figure 18.1 loop of progress dikhati hai (idea → experiment → evaluation → idea).

18.2 Model ensembling

Ensembling: kai alag models ki predictions average karne se variance kam hoti hai aur aam taur par kisi bhi single model se behtar result milta hai.

Example chaar models ko weights 0.5, 0.25, 0.1 aur 0.15 ke saath ensemble karta hai (weights ka sum 1.0 hai), aur ensemble ko Kaggle ke Higgs dataset (particle-physics classification task) par evaluate karta hai — best single model se chhota lekin consistent improvement dikhata hai.

18.3 Data parallelism

Data parallelism: model ko kai GPUs/TPUs par replicate karo, har batch ko unme split karo, aur gradients ko average karo. Chapter speedups report karta hai: 2 GPUs par lagbhag 2x, 4 GPUs par 3.8x aur 8 GPUs par 7.3x (yaani near-linear, thodi overhead ke saath).

Keras ka distribute API dikhaya gaya hai (jaise MirroredStrategy / multi-GPU setup).

18.4 Model parallelism

Model parallelism: ek hi model ko devices par split karo jab woh ek device par fit na ho. Chapter ek DeviceMesh dikhata hai shape 2x4 ki (2 data-parallel replicas × 4 model-parallel shards) aur ek LayoutMap jo layers ko devices par assign karta hai, plus TPU-specific advice (steps_per_execution=8 ke saath step fusing, yaani overhead kam karne ke liye har TPU call par 8 steps chalana).

18.5 Mixed precision aur quantization

Table 18.1 floating-point formats compare karti hai — float32 (8 exponent bits, 23 mantissa bits), float16 (5 exponent, 10 mantissa) aur bfloat16 (8 exponent, 7 mantissa) — aur text samjhata hai ki bfloat16 ki range float32 jaisi hai lekin precision kam hai, jabki float16 ki range kam hai aur use loss scaling chahiye.

Mixed_float16 use karne se (float16 me compute, master weights float32 me) memory lagbhag aadhi ho jati hai aur modern GPUs par training fast hoti hai. Float8 bahut bade models ke liye introduce kiya gaya hai (lagbhag 5 billion parameters se upar).

Post-training int8 quantisation abs-max method se dikhayi gayi hai: weights ko [−127, 127] range par scale kiya jata hai. Worked example me float32 matrix [[0.98, 0.409], [−1.0, −3.1]] (lagbhag) quantise hokar de-quantisation ke baad int8 values [[0.984, 0.393], [−1.015, −3.197]] deti hai — yaani chhoti rounding errors.

19. The Future of AI

19.1 Deep learning ki limitations

Deep learning ki limitations list ki gayi hain — ise bade labelled data chahiye, yeh abstraction ki jagah interpolation se generalise karta hai (isliye out-of-distribution inputs par fail hota hai), adversarial examples se brittle hai, symbolically reason nahi karta, aur train aur run karna expensive hai.

Chapter zor deta hai ki yeh chhoti engineering details nahi hain, balki paradigm ki structural properties hain.

19.2 Machine intelligence ka test — ARC-AGI

ARC-AGI (Abstraction and Reasoning Corpus for AI) fluid intelligence ka test hai jisme har task kuch input/output grid examples deta hai aur naye input par output maangta hai. 20. Conclusions

20.1 Key takeaways

(1) Deep learning representation learning hai — simple, differentiable transformations stack karne se model raw data se useful features seekh leta hai.

(2) Hamesha simple se shuru karo, ek strong baseline ke saath, aur complexity sirf tab badhao jab evaluation dikhaye ki woh madad karti hai.

(3) Generalisation goal hai, training accuracy nahi — validation, regularisation aur data augmentation use karo.

(4) Transfer learning aur pretrained models zyada tar real problems ke liye default hain.

(5) Workflow (define → develop → deploy) kisi bhi single architecture se zyada matter karta hai.

(6) Generative models (language models aur diffusion models) sabse important recent development hain, aur woh distribution seekh kar usse sample karke kaam karte hain.

FInterview FAQs

Interview FAQs — 36 sawaal

Tensors, gradients, Keras, generalisation, ConvNets, segmentation, detection, timeseries, embeddings, Transformer, LoRA, VAEs, diffusion, quantisation aur ARC-AGI par interview-relevant sawaal.

Q1. Deep learning kya hai, machine learning se kaise alag hai?

Machine learning data se rules seekhta hai, haath se likhe bina. Deep learning machine learning ka subfield hai jo layered representations seekhta hai — successive layers jo dheere-dheere zyada meaningful representations banati hain, zyada tar neural networks se. Depth hi farak hai: bahut saari chained transformations se complex functions seekhe ja sakte hain.

Q2. MNIST example me model kya tha aur result kya aaya?

Model Sequential tha: Dense(512, relu) → Dense(10, softmax), rmsprop optimiser, categorical_crossentropy loss, 5 epochs, batch size 128. Training accuracy 98.9% (0.9891) aur test accuracy 97.85% (0.9785) aayi. Data: 60,000 train / 10,000 test images, 28x28 grayscale.

Q3. Tensor kya hota hai? Rank, shape, dtype ka matlab kya hai?

Tensor multi-dimensional array hai. Scalar rank-0, vector rank-1, matrix rank-2 hai. ndim axes ki sankhya, shape har axis ka size, aur dtype element ka type batata hai. MNIST batch ki shape (60000, 28, 28) hoti hai.

Q4. Gradient descent aur backpropagation kaise kaam karte hain?

Loss batata hai ki predictions targets se kitni door hain. Gradient loss ke sabse tez badhne ki direction hai; gradient descent weights ko gradient ke opposite direction me step karta hai, learning rate se scaled. Backpropagation chain rule ko efficiently apply karke har weight ke liye gradient compute karta hai.

Q5. Naive NumPy implementation sirf 83% kyun pahunchi jabki Keras 97.85% deta hai?

Kyunki framework ka optimiser (RMSprop), initialisation aur vectorisation bada farak dalte hain. Naive implementation me manual gradients aur simple optimiser tha. Yeh dikhata hai ki framework sirf convenience nahi hai — woh performance ka bada hissa hai.

Q6. Keras multi-backend ka matlab kya hai?

Ek hi Keras program TensorFlow, PyTorch ya JAX par chal sakta hai — backend KERAS_BACKEND environment variable se chuna jata hai. TensorFlow production-oriented, PyTorch research-oriented, JAX functional/transform-based hai; Keras sabhi me sabse approachable hai.

Q7. IMDb par 88% accuracy kaise mili? Overfitting kab dikha?

Model Dense(16, relu) → Dense(16, relu) → Dense(1, sigmoid) tha, binary_crossentropy loss, 20 epochs, batch 512, 10,000-sample validation split. Validation accuracy ~88% aayi. Epoch 4–5 ke baad validation loss badhne laga jabki training loss girta raha — yahi overfitting ka sign hai.

Q8. Reuters par bottleneck layer ne accuracy kyun girayi?

Bottleneck (Dense(64) → Dense(4) → Dense(46)) jaan-boojh kar information flow restrict karta hai — 4 units se saari information squeeze hoti hai. Accuracy ~80% se ~71% gir gayi, jo information-bottleneck idea ko illustrate karta hai.

Q9. Regression me output activation kyun nahi hoti?

Regression me target continuous value hoti hai (jaise house price), isliye output layer par koi activation nahi lagate — linear output + mean_squared_error loss use hota hai. California housing par test MAE lagbhag $31,000 aaya.

Q10. Overfitting aur underfitting me farak kya hai?

Overfitting matlab training set ko yaad kar lena — training error kam, validation error zyada. Underfitting matlab underlying pattern ko pakad hi nahi paana — dono error zyada. U-shaped curve dikhati hai ki capacity badhne par validation error pehle girta hai, phir badhta hai.

Q11. Evaluation me test set ko ek baar hi kyun use karte hain?

Kyunki test set tuning me use karne se woh validation set ban jata hai — phir woh unseen performance nahi batata. Data leakage (jaise test-set statistics se normalise karna) evaluation ko invalid kar deta hai. Pehle hold-out/K-fold se tune karo, ant me ek baar test karo.

Q12. L2 regularisation aur dropout kaise kaam karte hain?

L2 weights ko chhota rehne par penalise karta hai (example: l2(0.002)), jisse model simple rehta hai. Dropout training ke dauraan randomly units drop karta hai (example rate 0.5), jisse model kisi ek unit par depend nahi karta. Dono IMDb par validation accuracy badhate hain aur overfitting delay karte hain.

Q13. Universal workflow ke teen stages kya hain?

Define (problem, input/output, metric, dataset), Develop (architecture, loss, evaluation protocol, baseline, regularise, tune, retrain) aur Deploy (REST API, on-device, ya browser; compression — pruning aur quantisation). Deployment wahi jagah hai jahan zyada tar real projects fail hote hain.

Q14. Binary vs multiclass vs multilabel me activation aur loss kya hota hai?

Binary: sigmoid + binary_crossentropy. Multiclass (single label): softmax + categorical_crossentropy. Multilabel: sigmoid + binary_crossentropy. Regression: linear output + mean_squared_error. Bounded regression: sigmoid/tanh + mean_squared_error.

Q15. Keras me teen abstraction levels kaun se hain?

High-level Sequential/Functional API, intermediate custom Model subclass, aur low-level backend operations. Guidance: highest-level API se shuru karo jo fit baithta hai, lower level par sirf zaroorat par jao.

Q16. ConvNet dense model se MNIST par behtar kyun hai?

Convolution spatial structure use karta hai — local patterns share karta hai. ConvNet ~99.1% test accuracy deta hai, dense model ke 97.8% ke mukable — wahi data, lagbhag 1.3 points ka improvement.

Q17. Dogs vs cats par overfitting kaise fix hua?

Pehla ConvNet 30 epochs me training accuracy ~95% lekin test accuracy sirf 78.6% — bhaari overfitting. Augmentation (RandomFlip, RandomRotation(0.1), RandomZoom(0.2)) + Dropout(0.5) se 83.9% mila. Transfer learning (VGG16 frozen) se 98.1%, +augmentation se 98.4%, aur fine-tuning se 98.6% mila.

Q18. Transfer learning me fine-tuning karte waqt learning rate chhota kyun rakhte hain?

Kyunki bada learning rate pretrained weights ko kharab kar deta hai — woh ImageNet par seekhe gaye useful features bhool jate hain. Chhota learning rate sirf aakhri block ko halke se adjust karta hai.

Q19. Residual connections deep networks ko kaise madad karte hain?

Block ka input uske output me add hota hai (x + F(x)), isliye network sirf residual correction seekhta hai aur gradients seedha skip connection se beh sakte hain. Isse bahut deep networks trainable hote hain — yahi ResNet ka core hai.

Q20. Depthwise separable convolution itne parameters kyun bachata hai?

Standard 3x3 conv 32→64 channels par 36,864 params use karta hai; separable version (depthwise + 1x1 pointwise) sirf 4,672 — lagbhag 8x ki bachat, kam accuracy loss ke saath. Yahi Xception aur MobileNet ka core hai.

Q21. Grad-CAM kya hai? Elephant example me kya hua?

Grad-CAM class score ka gradient aakhri conv layer ke feature maps se lekar har channel ka weight banata hai, aur heatmap ko image par overlay karta hai. Elephant photo par model ne 90.3% confidence se 'African elephant' predict kiya aur heatmap body aur kaan par focus karta tha.

Q22. Segmentation classification se kaise alag hai?

Segmentation per-pixel classification hai — har pixel ko label milta hai. Oxford-IIIT Pet (7,390 images, trimap masks 1 pet / 2 background / 3 border) par U-Net encoder-decoder use hota hai, loss sparse_categorical_crossentropy, metric mean IoU. Model ~25 epochs ke baad overfit karta hai.

Q23. Object detection me IoU aur mAP kya hain?

IoU (intersection over union) predicted aur ground-truth box ke overlap ko measure karta hai. mAP (mean average precision) IoU thresholds par average precision hai. COCO me 117,266 training images, 91 categories, har image me 1–63 boxes hain.

Q24. Jena weather par kaunsa model best tha aur kyun?

Stacked GRU ~2.39 test MAE ke saath best tha. Baseline 2.44/2.62 °C, LSTM 2.39/2.55, LSTM + dropout 2.27/2.45. Bidirectional LSTM bura tha kyunki forecasting me future context available nahi hota. Transformer is chhote dataset par recurrent models ko beat nahi kar paya.

Q25. Bag-of-words + bigrams 90.116% kaise de deta hai jabki LSTM 84% par atak jata hai?

IMDb jaisi chhoti dataset par simple bag-of-words strong baseline hai — bigrams word order ki thodi information add karte hain. LSTM ko zyada data chahiye hota hai; learned embeddings par woh 84.436% deta hai, lekin pretrained (CBOW) embeddings se 89.139% tak pahunch jata hai.

Q26. Transformer me positional embeddings zaroori kyun hain?

Bina positional embeddings ke Transformer 58% token accuracy deta hai; unke saath 67% — kyunki self-attention khud order-blind hota hai. Position ki information ke bina model ko pata hi nahi chalta ki kaunsa token pehle aaya.

Q27. RoBERTa fine-tune IMDb par itna achha kyun hai?

Pretrained RoBERTa (124,052,736 params) pehle se language samajhta hai — sirf 1 epoch fine-tune karne par 93.66% test accuracy, 0.168 test loss. Scratch se train kiya LSTM 84% par atak jata hai. Fine-tuning pretrained Transformer ab default hai.

Q28. Mini-GPT kitna bada tha aur generation slow kyun thi?

Mini-GPT 41M params ka Transformer decoder hai, ~1B tokens par train hua, ~36% val accuracy. Eager mode me generation slow thi (minutes), compiled generate function + KV cache se wahi passage 0.49 seconds me ban gaya.

Q29. LoRA kya hai? Gemma 3 par kitne params train hue?

LoRA base model freeze karke sirf chhote low-rank adapters train karta hai. Gemma 3 (999,885,952 params) par rank 8 se trainable params 1,304,576 ho gaye (~0.13%). Dolly (15,000 pairs) par fine-tuning ke baad ~55% sahi jawab mile, pehle lagbhag zero ke mukable.

Q30. VAE ka reparameterisation trick kya hai?

Encoder mean aur log-variance deta hai; sample z = mean + exp(0.5 × log_var) × epsilon se draw hota hai, taaki gradients sample ke through beh sakein. MNIST VAE (latent_dim 2, encoder 69,076 / decoder 65,089 params) ki 2-D latent space 30x30 grid me digits ko smoothly morph karti hai.

Q31. Diffusion model image kaise banata hai?

Forward process image me Gaussian noise add karta hai jab tak woh pure noise na ban jaye. Reverse process (U-Net) har step par noise predict karna seekhta hai — pure noise se shuru karke baar-baar denoise karne se nayi image banti hai. Oxford Flowers 102 (8,189 images) par 100 epochs, ~90 min T4 GPU par.

Q32. KerasTuner me BayesianOptimization kaise kaam karta hai?

Yeh pichle trials se seekh kar agle hyperparameters suggest karta hai — random search se zyada efficient. Example me max_trials=20, HyperXception aur HyperResNet models, filters, dropout rate aur learning rate par search, dogs-vs-cats data par.

Q33. float16 vs bfloat16 me kya farak hai?

float16: 5 exponent bits, 10 mantissa — kam range, loss scaling chahiye. bfloat16: 8 exponent bits, 7 mantissa — float32 jaisi range, kam precision. Mixed_float16 (float16 compute, float32 master weights) memory lagbhag aadhi kar deta hai aur training fast karta hai.

Q34. int8 quantisation me abs-max method kya hai?

Weights ko [−127, 127] range par scale kiya jata hai — sabse bade absolute value ko 127 se map karke. Example: [[0.98, 0.409], [−1.0, −3.1]] de-quantisation ke baad [[0.984, 0.393], [−1.015, −3.197]] deta hai — chhoti rounding errors. Keras me model.quantize('int8').

Q35. ARC-AGI kya measure karta hai aur o3 ne kya kiya?

ARC-AGI fluid intelligence ka test hai — kuch input/output grid examples dekar naye input par output maangta hai. GPT-2 era ~0%, GPT-4 era ~10% (50,000x scale ke bawjood), humans >95%. o3 ne 76% kiya ~$200/task par, aur 88% jab >$20,000/task kharch kiya. Key: test-time adaptation — inference par compute se program search karna.

Q36. Deep learning ki sabse badi structural limitations kya hain?

Bade labelled data ki zaroorat, interpolation se generalisation (abstraction nahi), adversarial examples se brittleness, symbolic reasoning ki kami, aur training/running ki cost. Yeh engineering details nahi, paradigm ki structural properties hain.
