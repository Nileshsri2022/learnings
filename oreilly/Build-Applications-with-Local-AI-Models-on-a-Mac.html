Preface

Terminal ki kaali screen se lekar apne Mac par chalne wale voice-enabled AI chat app tak — ye book ek aise reader ke liye hai jisko programming ka koi experience nahi hai, lekin jo apne computer par AI chalana chahta hai. Shuruaat me terminal daraane wala lagta hai; ant me wahi terminal tumhara sabse powerful tool ban jata hai.

00.1 Pehla terminal experience

Pehli baar terminal kholna aasaan nahi hota — kaali screen, ajeeb symbols, commands jo kuch karte hue dikhte hi nahi, aur aisa lagta hai jaise tum kisi aur ki duniya me ghus gaye ho. Ye book isi feeling se shuru hoti hai: likhne wale ka khud ka pehla terminal experience bilkul aisa hi tha. Phir 20 saal se zyada ke engineering experience ne use ye sikhaya ki terminal se dosti ho sakti hai — chhote steps me, ek command ek baar me.

Book ka aim ye hai ki reader ko terminal me ghar jaisa feel ho, aur wo "wow" moment mile jab ek LLM pehli baar tumhare apne Mac par jawaab deta hai — bina internet ke, bina kisi server ke, bina per-use fee ke.

00.2 Local AI kyun matter karta hai

Local AI ke paanch bade fayde hain jo poori book me baar-baar aate hain:

  • Fast — network ka wait nahi, jawaab turant milta hai.
  • Private — tumhara text tumhare Mac se bahar nahi jata.
  • Free of usage fees — model ek baar download kar lo, phir har question free hai.
  • Offline — plane me, remote jagah par, bina Wi-Fi ke bhi kaam karta hai.
  • Control — model tum chunte ho, rules tum banate ho.

Isi liye ye book cloud chat services se ek kadam aage badhne wale Mac users ke liye hai — jo sirf AI use nahi karna chahte, use banana bhi chahte hain.

00.3 Kis ke liye hai ye book

Target reader wo Mac user hai jo cloud chat services use karta hai aur aage badhna chahta hai — khaas taur par wo log jinke paas koi programming experience nahi hai. Book ka promise hai: ant tak ek reader jisko coding nahi aati, wo bhi ek real AI application bana lega.

Ye book unke liye bhi kaam ki hai jinke paas thoda programming experience hai — shuru ke chapters unke liye easy honge, lekin aage RAG, fine-tuning aur agents wale chapters naye honge.

00.4 Do cautions — sabr aur speed

Do cautions pehle se samajh lo:

  • Sabr rakho — seekhne me time lagta hai. Galtiyan process ka hissa hain, aur zyada tar troubleshooting kuch hi minutes me ho jati hai. Ek error ka matlab ye nahi ki tumse nahi hoga.
  • Field bahut tez badalta hai — tools aur versions badalte rehte hain. Hamesha latest tools use karo aur version badle to official documentation check karo.

Book ka closing wish ye hai ki tum kuch aisa banao jise tum sach me care karte ho — kyunki wahi project tumhe sabse zyada sikhayega.

Chapter 1 — Getting Started with Local AI

Computer se baat karne ke do tareeke hain — GUI aur CLI. Terminal pehle daraane wala lagta hai, lekin ye precision, speed, automation aur AI agents ke liye zaroori hai. Is chapter me terminal kholna, basic commands, local AI kya hai, aur cloud vs local ka farak — sab hai.

01.1 Terminal se computer se baat karo

Computer se baat karne ke do tareeke hain: GUI (windows, buttons, mouse) aur CLI (commands type karke). Book command line ke paanch reasons deti hai:

  • Precision — command exactly wahi karta hai jo tum type karte ho.
  • Speed — ek command kai clicks ki jagah le leta hai.
  • Automation — ek command baar-baar repeat ho sakta hai.
  • Portability — commands alag machines par bhi kaam karte hain.
  • AI agents ke liye suitability — agents bhi commands hi chalate hain.

Terminal wo program hai jo typed commands accept karta hai aur results dikhata hai; shell (modern Macs par zsh) wo language interpreter hai jo commands padhta hai. Terminal computer ke file system ka text interface hai.

macOS par terminal kholne ke do tareeke: Spotlight search (⌘+Space, "terminal" type karo, Return dabao) ya Applications folder → Utilities → Terminal. Khulte hi tumhe dikhega: machine ka naam aur current user ka naam, ek prompt (jo % par end hota hai), aur ek cursor. Try karo: echo hello type karke Return dabao — terminal hello print karega.

01.2 Appearance customize karo

Terminal ki look badal sakte ho: Settings > Profiles me jao aur font aur background colour badlo. Light aur dark — dono themes milte hain. Ye sirf looks ke liye nahi hai — jo theme aankhon ko comfortable lage, usi me zyada der kaam kar paoge.

Chapter 2 — Installing and Using Homebrew

Homebrew command line ka app store hai — ek command se software install ho jata hai, .dmg download karke drag karne ki zaroorat nahi. Is chapter me install karna, core commands, GUI apps (casks), aur common problems fix karna — sab hai.

02.1 Homebrew kya hai aur kyun chahiye?

Homebrew macOS (aur Linux) ke liye ek free package manager hai jo terminal se software install karta hai. Analogy simple hai: ye command line ka app store hai — .dmg download karke Applications me drag karne ki jagah, ek command se program install ho jata hai.

Requirements: Apple silicon (M1 ya later) ya Intel wala Mac, macOS, aur internet connection. Book ki machine Apple silicon hai.

02.2 Homebrew install karna

Install command standard Homebrew shell script hai jo curl se raw.githubusercontent.com/Homebrew/install/HEAD/install.sh se fetch karke /bin/bash se run hota hai (book me full command printed hai). Installation ke dauraan Return dabao aur apna Mac password dalo — type karte waqt characters dikhte nahi, ye normal hai.

Output me "Installation successful!" dikhega. Phir, Apple silicon par, installer do lines print karta hai jo shell configuration me add karni hain:

terminal
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

Verification: brew --version version print karta hai (book ka example: Homebrew 4.x). Figure 2.1 successful installation screen dikhata hai. Agar "command not found" aaye to PATH step miss hua hai.

Chapter me demonstrate kiya gaya hai: brew update (output ant me "Already up-to-date."); brew upgrade (saare installed packages upgrade karta hai — time lag sakta hai); brew list (installed packages dikhata hai, jaise book ke example me "ca-certificates", "git", "openssl@3").

02.4 Applications install karna

brew install wget se wget install hota hai; wget --version se verify karo (book ka example: GNU Wget 1.21.4). brew install git aur git --version (example: git version 2.46.0).

Formulae vs casks: formulae command-line tools hote hain; casks GUI apps hote hain, jo brew install --cask <app> se install hote hain — example: brew install --cask google-chrome. Cellar folder (/opt/homebrew/Cellar) wahan hai jahan Homebrew installed packages store karta hai.

$ brew install --cask google-chrome

Chapter 3 — Installing and Setting Up Ollama

Ollama local LLMs chalane ka free, open-source tool hai — models download karta hai, manage karta hai, aur ek server deta hai jisse applications baat karti hain. Server port 11434 par sunta hai. Is chapter me install, start, verify aur setup script — sab hai.

03.1 Ollama kya hai aur kyun chahiye?

Ollama LLMs ko locally chalane ka free, open-source tool hai; ye models download karta hai, unhe manage karta hai, aur ek server provide karta hai jisse applications baat karti hain. Use karne ke reasons: ye free hai; Mac, Windows aur Linux par kaam karta hai; model files handle karta hai; aur simple API aur Python library deta hai.

03.2 Ollama architecture

Figure 3.1 me Ollama server user/applications aur model files ke beech me baitha dikhaya gaya hai — Ollama CLI aur Python library dono server se HTTP par baat karte hain. Figure 3.2 cloud AI vs local AI with Ollama ka contrast dobara dikhata hai, local flow me Ollama ke saath.

Ollama ka kaam simple hai: model ek baar download karo, disk par rakho, zaroorat padne par memory me load karo, aur requests ka jawaab do.

03.3 Ollama install karna

brew install ollama se install hota hai (book ka example output download aur installation complete hote hue dikhata hai). Verification: ollama --version version print karta hai (book ke screenshot me example: ollama version 0.11.x, jo 0.11.10 ke roop me dikhaya gaya hai).

terminal
$ brew install ollama
$ ollama --version
ollama version is 0.11.10

03.4 Ollama service start karna

ollama serve chalao — ye print karta hai ki server 127.0.0.1:11434 par sun raha hai aur logs me "listening" dikhata hai. Verification: doosra terminal tab kholo aur curl http://localhost:11434 chalao — server reply karta hai "Ollama is running".

Interview FAQs
Build Applications with Local AI Models on a Mac par interview me sabse zyada poochhe jaane wale 36 sawaal — har jawaab is book ke content par based hai.


01Terminal kya hai aur GUI se kaise alag hai?
Terminal ek text interface hai jo typed commands accept karta hai aur results dikhata hai; shell (Mac par zsh) wo interpreter hai jo commands padhta hai. GUI me windows, buttons aur mouse se kaam hota hai, CLI me commands type karke. Terminal precision, speed, automation, portability aur AI agents ke liye zaroori hai — agents bhi commands hi chalate hain.


02pwd, ls, cd aur mkdir commands kya karte hain?
pwd current directory print karta hai (jaise /Users/yourname). ls files aur folders list karta hai. cd directory badalta hai — cd Desktop se Desktop me jao, cd .. se ek level upar, cd ~ se home. mkdir folder banata hai, jaise mkdir my-project. Ye paanch commands poori book me baar-baar aate hain, isliye inhe yaad kar lo.


03Local AI model kya hai aur cloud AI se kya farak hai?
Local AI ka matlab hai model file tumhare Mac par hai aur bina server ko text bheje jawaab deta hai. Cloud me data internet se server tak jata hai aur wapas aata hai. Local fast, private, per-use fee se free aur offline kaam karta hai; cloud sabse powerful model aur latest features deta hai. Privacy, offline kaam, cost ya learning ke liye local behtar hai.


04Homebrew kya hai aur ise kaise install karte hain?
Homebrew macOS ke liye free package manager hai — command line ka app store. Ek command se software install hota hai, .dmg download karke drag karne ki zaroorat nahi. Install karne ke liye Homebrew ka shell script curl se fetch karke /bin/bash se chalao, phir Apple silicon par PATH lines ~/.zprofile me add karo, aur brew --version se verify karo. brew doctor installation check karta hai.


05Ollama kya hai aur iska server kis port par sunta hai?
Ollama LLMs ko locally chalane ka free, open-source tool hai — models download karta hai, manage karta hai, aur ek server deta hai jisse applications baat karti hain. Server 127.0.0.1:11434 par sunta hai. ollama serve se start karo, aur curl http://localhost:11434 se verify karo — server reply karta hai 'Ollama is running'.


06ollama pull, run, list, show, rm aur ps kya karte hain?
ollama pull  model download karta hai, ollama run  chat start karta hai, ollama list downloaded models dikhata hai, ollama show  details dikhata hai (parameters, context length), ollama rm  model remove karke disk space free karta hai, aur ollama ps running models dikhata hai. Chat ke andar /bye exit karta hai, /help commands list karta hai, aur Ctrl+D bhi exit karta hai.


07Book ka starting model Gemma 3:4b kyun hai?
Gemma 3:4b 4 billion parameters ka hai, disk par lagbhag 2.5–3 GB ka hai, aur general chat me achha hai. Ye Mac par achhe se chalne ke liye kaafi chhota hai aur conversation me achha hai — isiliye book isi se shuru karti hai. Qwen2.5:3b coding me strong hai, Llama 3.2:3b general use ke liye hai, aur Mistral:7b longer text ke liye hai.


08Python virtual environment kyun zaroori hai?
Virtual environment ek project ke liye isolated Python installation hai — apna interpreter aur apne packages. Bina iske, ek package install karna machine ke saare Python projects ko affect karta hai. python3 -m venv .venv se banao, source .venv/bin/activate se activate karo, deactivate se chhodo. pip freeze > requirements.txt se environment record karo aur pip install -r requirements.txt se restore karo.


09ollama.chat() ka message format kya hai?
Message format ek list of dictionaries hai, har ek me 'role' aur 'content' hota hai. Teen roles hain: 'system' (instructions jo model ka behaviour set karti hain), 'user' (human ka message), 'assistant' (model ke replies). Response ek dictionary hai jisme 'message' key aur 'content' key hoti hai. Model name badal kar models swap kiye ja sakte hain, aur temperature jaise options pass kiye ja sakte hain.


10LLM stateless kyun hota hai aur history kaise manage karein?
Har ollama.chat() call independent hoti hai — model kuch yaad nahi rakhta, jab tak program history na bheje. Fix hai messages naam ki list rakhna: har user message aur har assistant reply ko append karo, aur har call par poori list bhejo. Chapter ek conversation loop banata hai — while loop jo input padhta hai, append karta hai, chat call karta hai, reply print karta hai, aur reply append karta hai.


11Streaming kya hai aur stream=True se kya hota hai?
By default ollama.chat() poora jawaab aane ka wait karta hai. stream=True ke saath ye chunks ka iterator return karta hai, har chunk me content ka ek tukda hota hai, taaki program words aate hi print kar sake. Perceived speed ke liye streaming behtar lagti hai, kyunki user ko pehla word turant dikhta hai. Chapter ki streaming script har chunk ko turant print karti hai aur phir newline print karti hai.


12Streamlit kya hai aur app kaise chalate hain?
Streamlit ek Python library hai jo Python script ko web application me badal deti hai — tum Python likhte ho, Streamlit web page render karta hai, HTML/CSS/JavaScript ki zaroorat nahi. streamlit run app.py se chalao; server default port 8501 par start hota hai, Ctrl+C se rukta hai. Har interaction par poori script dobara top se run hoti hai — isiliye state session state me store karni padti hai.


13Streamlit ke core components kaun se hain?
st.title() bada heading deta hai, st.write() text ya data dikhata hai, st.text_input() ek line ka input box hai, st.text_area() multi-line input hai, st.button() click par True return karta hai, st.markdown() formatted text deta hai, st.sidebar side panel hai, aur st.columns() side-by-side layout banata hai. Chat ke liye st.chat_message() message bubbles aur st.chat_input() neeche input box deta hai.


14st.session_state kyun chahiye hota hai?
Streamlit har interaction par poori script dobara chalata hai, isliye ordinary variables reset ho jate hain — ek counter har interaction par zero par reset ho jata hai. Fix hai st.session_state, ek dictionary-jaisa object jo re-runs ke paar persist karta hai. Pattern hai: if 'messages' not in st.session_state, to use empty list se initialise karo, phir st.session_state.messages ko read aur write karo.


15Context window kya hai aur history trimming kaise karte hain?
Context window maximum tokens ki sankhya hai jo model ek saath consider kar sakta hai — Gemma 3:4b ke liye 128K tokens. Zyada hone par error ya truncated output milta hai. Teen strategies hain: saari history rakhna (simple, lekin window bhar jata hai), limited history rakhna jaise last 10 messages (simple aur safe, lekin purana context kho jata hai), ya purani history summarise karna (complex, lekin context bachta hai). Trimming function tokens count karta hai (approximately characters/4) aur sabse purane messages drop karta hai, system message ko bachate hue.


16Whisper kya hai aur MLX Whisper kyun use karte hain?
Whisper OpenAI ka open-source speech-recognition model hai. MLX Whisper Apple ke MLX framework par bana version hai, jo Apple silicon (M-series chips aur Neural Engine) ke liye optimised hai, isliye Mac par fast chalta hai. Encoder-decoder transformer pehle audio ko encode karta hai, phir text me decode karta hai; spoken language bhi detect kar sakta hai. Model used hai mlx-community/whisper-large-v3-mlx.


17Voice chat app ka pipeline kya hai?
Chaar stages hain: voice capture karo, use transcribe karo (Whisper), text ko LLM ko bhejo (Ollama), aur jawaab dikhao. Pipeline modular hai — har stage swap ho sakta hai, jaise alag Whisper model ya LLM. App ek Python file hai, voice_chat.py, jisme imports, page config, sidebar (model selector aur Clear chat button), session state, audio input (st.audio_input), transcription step, text input (st.chat_input), message handler (handle_user_message), streaming helper (stream_response), aur display loop (st.chat_message) hote hain.


18Model families me kya farak hai — Llama, Gemma, Qwen, Mistral, DeepSeek?
Llama (Meta) open weights aur widely used hai; Gemma (Google) strong multilingual hai; Qwen (Alibaba Cloud) strong coding aur Chinese me hai; Mistral (Mistral AI) European aur efficient hai; DeepSeek strong reasoning aur coding me hai, open hai. Naming me 'llama3.1:8b' ka matlab hai Llama 3.1, 8 billion parameters. Benchmarks sirf rough guide hain — models ko apne tasks par try karna behtar hai.


19Model size aur quality ka trade-off kya hai?
Quality size ke saath badhti hai lekin diminishing returns ke saath, jabki memory aur latency badhte rehte hain. 2–3B fast, low memory, basic quality; 7–8B balanced; 13–14B better quality, zyada RAM chahiye; 70B best quality, badi unified memory wala powerful Mac chahiye. RAM reality check: 7B ko lagbhag 8 GB, 14B ko lagbhag 16 GB chahiye. Chhote models zyada tokens/sec generate karte hain — Apple silicon par lagbhag 20–50 tokens/sec.


20System prompt kya hai aur ye kaise kaam karta hai?
System prompt ek message hai jiska role 'system' hota hai, jo conversation se pehle bheja jata hai; ye model ka role, tone aur rules set karta hai. Ye chat display me end user ko invisible hota hai, lekin har jawaab ko shape karta hai. Messages list ki pehli item hoti hai aur history badhne par bhi wahi rehti hai. Examples hain concise expert, patient study buddy, pirate tutor, strict coding mentor aur professional consultant — same question ke bilkul alag jawaab milte hain.


21Temperature, top_p, top_k aur num_ctx kya control karte hain?
Temperature (0.0–2.0) randomness aur creativity control karta hai — low (0.1–0.3) focused aur deterministic, medium (0.7–0.8) balanced, high (1.0–1.5) creative lekin incoherence ka risk. top_p (0.0–1.0) nucleus sampling hai, top_k (1–100) candidate tokens limit karta hai, num_ctx context window size hai (Ollama default 2048), num_predict reply length cap karta hai, aur repeat_penalty (1.0 se upar) repetition kam karta hai. Parameters ollama.chat() ke options dictionary me pass hote hain.


22Offline LLM kaise verify karein ki wo sach me offline hai?
Test simple hai: Airplane Mode on karo (ya Wi-Fi disconnect karo), phir chat app chalao aur question poochho. Agar app normally jawaab de to offline confirmed hai. Network monitor se bhi check kar sakte ho ki koi data bheja nahi jata. Ek exception hai — model download karne ke liye network ek baar chahiye hota hai. Offline aur local me farak hai: offline ka matlab koi network hi nahi, local ka matlab apni machine par chal raha hai.


23Local AI privacy ke liye kyun behtar hai?
Local me data Mac par hi rehta hai — microphone se Whisper tak, LLM tak, screen tak, sab kuch device par hota hai. Cloud me data provider ko jata hai aur unke servers par store hota hai, unki policy ke under. Regulations jaise HIPAA, GDPR, FERPA aur Japan ka APPI local processing ko attractive banate hain. Personal journal, work documents aur health information jaise sensitive data ke liye local behtar hai — lekin cloud services prompts ko training ke liye retain kar sakti hain, isliye privacy policies padhna chahiye.


24Error message ko kaise padhein aur debug karein?
Error message ke teen parts hote hain: type (jaise ConnectionError), location (file aur line number), aur message. Method hai: aakhri line pehle padho — wahi problem batati hai — phir file aur line dhoondho, phir exact message search karo. Debugging techniques hain print debugging, logging module, try/except blocks, step-by-step verification (pehle Ollama, phir script, phir Streamlit), aur community se madad. debug_test.py script Ollama connection test karke batata hai ki problem Ollama me hai ya app me.


25'connection refused' aur 'model not found' errors kaise fix karein?
'connection refused' ka matlab hai Ollama chal nahi raha — ollama serve se start karo. 'model not found' ka matlab hai model download nahi hua — ollama pull  chalao. 'address already in use' ka matlab hai ek aur Ollama ya Streamlit chal raha hai — roko ya doosra port use karo. 'out of memory' ka matlab hai model Mac ki RAM ke liye bada hai — chhota model use karo. 'command not found' ka matlab hai tool install nahi hai ya PATH par nahi hai.


26ModuleNotFoundError aaye to kya karein?
ModuleNotFoundError (jaise "No module named 'streamlit'") ka matlab hai venv active nahi hai ya package install nahi hai. Pehle check karo ki prompt me (.venv) prefix dikh raha hai ya nahi — nahi dikh raha to source .venv/bin/activate chalao, phir pip install  chalao. Python version problems ke liye python3 --version check karo aur package ki requirements dekho. 'streamlit: command not found' ka bhi wahi fix hai.


27RAG kya hai aur ye kaise kaam karta hai?
RAG (retrieval-augmented generation) wo problem solve karta hai ki LLM tumhare documents ko nahi janta. Steps hain: documents load karo, unhe chunks me todo, chunks ko embeddings (vectors jo meaning capture karte hain) me badlo, vector store me rakho, query time par sabse similar chunks retrieve karo (similarity search), aur unhe question ke saath LLM ko bhejo. Worked examples hain document Q&A system aur team knowledge base.


28RAG aur fine-tuning me kya farak hai?
RAG me koi training nahi hoti — query time par documents use hote hain, update karna aasaan hai, aur factual lookup ke liye achha hai. Fine-tuning me model ko apne data par train kiya jata hai, behaviour badalta hai, data aur time chahiye hota hai, aur style ya specialised tasks ke liye achha hai. Fine-tune tab karo jab consistent style ya specialised task chahiye aur RAG kaafi na ho; data chhota ho ya task factual lookup ho to RAG use karo.


29Open WebUI kya hai aur ise kaise chalate hain?
Open WebUI Ollama ke liye open-source web interface hai jo ChatGPT jaisa dikhta hai — multi-model chat, document upload, model management aur user management ke saath. Docker se chalate hain: docker run Ollama host flag (--add-host=host.docker.internal:host-gateway) aur port mapping ke saath, phir browser me kholo. Use case hai local model ko team ke saath share karna bina UI banaye.


30Ollama Modelfile kya hai aur custom model kaise banate hain?
Modelfile ek text file hai jo custom model define karti hai: FROM (base model), PARAMETER (jaise temperature), SYSTEM (system prompt), aur TEMPLATE (prompt format). Example: FROM gemma3:4b, SYSTEM 'You are a helpful coding assistant.', aur temperature parameter — phir ollama create mymodel -f Modelfile chalao, phir ollama run mymodel se chalao. ollama list custom models dikhata hai, ollama rm delete karta hai.


31LangChain kya hai aur Ollama ke saath kaise use hota hai?
LangChain LLM applications banane ka framework hai. Basic chain banane ke liye langchain aur langchain-ollama install karo, Ollama LLM class import karo, ek chain banao (prompt template + model), aur use invoke karo. LangChain pieces ko standardise karta hai — prompts, chains, memory, retrieval — taaki apps ek single script se aage badh sakein aur bade ho sakein.


32February 2026 me open models me kya hua tha?
February 2026 me kai powerful open models lagbhag das din ke andar release hue, jisse open aur best proprietary models ke beech ka gap bahut kam ho gaya. Headline releases hain Qwen3-Coder-Next (4 February 2026, Alibaba, Ultra-Sparse Mixture-of-Experts, coding me strong), GLM-5 (11 February 2026, Zhipu, bada MoE model, Huawei chips par train hua), aur MiniMax M2.5 (12 February 2026, SWE-bench par leading models ke saath parity, bahut kam cost par).


33Unsloth-to-Ollama pipeline kya hai?
Unsloth-to-Ollama pipeline custom model banane ka practical route hai: Unsloth se fine-tune karo, GGUF format me export karo (quantized format jo Ollama use karta hai), aur Ollama me chalao. Chapter argue karta hai ki chhote, specialised models narrow task par bade general models ko hara sakte hain. Yehi pipeline Chapter 16 me fine-tuning ke practical route ke roop me bhi batayi gayi hai.


34Local agents cloud agents se saste kyun hote hain?
Agent ek task me kai LLM calls karta hai, isliye cloud per-token pricing multiply ho jati hai. Locally marginal cost near zero hai — model ek baar download kar lo, phir har call free hai. Chapter ka worked cost analysis ek agent ko compare karta hai jo din me sau-sau calls cloud API par karta hai vs wahi agent locally chal raha ho — conclusion hai ki heavy use ke liye local agents dramatically saste hain. Isi liye agents ka future local ki taraf badh raha hai.


3590-day learning roadmap kya hai?
Month 1 (foundation) — book ke projects khatm karo aur voice app ko apna banao. Month 2 (intermediate) — apne documents par RAG app banao aur LangChain seekho. Month 3 (advanced) — agent banao aur chhota model fine-tune karo. Roadmap ke teen levels hain: Foundation (terminal, Homebrew, Ollama, Python, Streamlit), Intermediate (RAG aur document intelligence, LangChain aur frameworks, deployment), Advanced (AI agents, fine-tuning aur customization, open source aur community).


36AI ko responsibly kaise use karein?
Chaar principles hain: dhoka dene ke liye AI use mat karo; privacy ka respect karo — apni aur dusron ki; model ke jawaab check karo, kyunki ye hallucinate kar sakta hai; aur jo banate ho uske impact par socho. Local AI user ko zyada control deta hai aur isliye zyada responsibility bhi deta hai. Ye principles Chapter 18 me diye gaye hain aur har project par apply hote hain.
