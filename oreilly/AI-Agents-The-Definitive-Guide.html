Chapter 1 — LLMs Se Agents Tak: Foundational Blueprint

Agent ka blueprint hai state machine — explicit state, explicit transitions, aur ek loop jo observe, test aur stop kiya ja sake. Plain LLM call me ye kuch nahi hota; state machine me lapetne se discipline aata hai.

01.1 Finite aur hierarchical state machines — base paradigm

Finite State Machine (FSM)

FSM ek aisa system hai jisme: states ki finite list (naam wale states), ek defined start state, events/inputs se trigger hone wale transitions, aur (usually) accepting/final states hote hain.

Agents ke liye point ye hai: FSM behaviour ko explicit, testable aur auditable banata hai. Tum enumerate kar sakte ho ki agent kya kar sakta hai, kis state me kya nahi kar sakta, aur ek state se doosri me kaise pahunchta hai. Plain LLM call me ye kuch nahi hota; state machine me lapetne se discipline aata hai.

Hierarchical State Machine (HSM)

HSM me states super-states ke andar nested hote hain — poora sub-behaviour (jaise ek poora “research” sub-machine) bade machine ka ek state ban jata hai. Isse complex agent readable rehta hai: detail sub-machine me rehti hai, top level chhota rehta hai.

Transitions super-state level par define karke children inherit kar lete hain — error-handling aur cancellation logic har jagah duplicate nahi karna padta.

FSM/HSM ko agent frameworks se map karna

LangGraph book ka canonical example hai — nodes aur edges ka graph, jo effectively shared state object par ek explicit state machine hai. LangChain ke purane chain/agent abstractions, AutoGen-style multi-agent conversations, aur hand-rolled loops — sabko usi lens se padha jata hai: state kya hai, transitions kya hain, kaun decide karta hai, aur state kahan stored hai? Framework se zyada matter karta hai ki state machine explicit hai ya nahi.

01.2 Static models se dynamic agents — LLM ko state dena

Static LLM ek function hai: prompt → text. Calls ke beech koi memory nahi, koi tools nahi, apna kaam check karne ki ability nahi, duniya par action nahi. Agent teen cheezein jodta hai: state (kya hua, kya pata hai, kya baaki hai), tools (observe aur act karne ke tareeke), aur loop (plan → act → observe → re-plan).

Key move “bada model” nahi hai — model ke around persistent state wala loop hai.

Worked example — mausam wala sawaal

Book ek multi-turn exchange se samjhata hai: agent se New York ka mausam poocha jata hai. Use weather tool call karna hai, result yaad rakhna hai, aur baad ke step me use karna hai. Concrete numbers: tool 18°C return karta hai; phir agent se temperature ka square poocha jata hai — 18² = 324 — aur crucially, ye calculator/tool call karke karna hai, guess karke nahi, taaki jawab verifiable ho.

Lesson: state + tools ek one-shot jawab ko checkable computation me badal dete hain.

Tool use as state transition

Har tool call ek transition hai: agent “mujhe X lagta hai” se “maine Y observe kiya” par pahunchta hai, aur observation agle decision ke liye state ka hissa ban jata hai. Bure agents observations kho dete hain; acche agents unhe typed, inspectable state object me store karte hain.

01.3 Deus Ex Machina — abhi kya possible hai?

Example — The AI Scientist (v2): Ye project book me current frontier example ke roop me hai. Apne second version me ye end-to-end research loop kar paya — ideas generate karna, experiments chalana, results likhna — itni achhi tarah ki uska ek paper ICLR workshop me peer review se guzra.

Point ye nahi hai ki research solve ho gayi. Point ye hai ki loop (idea → experiment → observation → revision) exactly agentic loop hai, aur ye ek narrow, well-instrumented domain me pehle se kaam karta hai.

Warning: isko “agents sab kuch kar sakte hain” padhna galat hoga. System isliye kaam kiya kyunki domain, tools aur evaluation tightly scoped the.

Most production systems beech me rehte hain: bounded state machine ke andar autonomy, aur human checkpoints un transitions par jo matter karte hain.

01.4 Conclusion — state machines hi blueprint hain

State machines blueprint hain. Book me aage sab kuch — planning, multi-agent patterns, memory, evaluation, security — usi ek idea ka refinement hai: explicit state, explicit transitions, aur ek loop jo observe, test aur stop kiya ja sake.

Agar tumhe chapter 1 se sirf ek line yaad rakhni hai, to ye: agent = model + state + loop.

Chapter 2 — Architectures aur Patterns: Planning, Reactivity, Multi-Agent

Planning linear bhi ho sakti hai, tree bhi, graph bhi — aur jab duniya se facts chahiye, to ReAct loop. Multi-agent me pattern wahi chuno jo task ki structure se match kare, aur human-in-the-loop ko irreversible transitions par design karo.

02.1 Planning architectures — CoT, ToT, GoT

Chain-of-Thought (CoT)

Model se kaho jawab se pehle step by step reason kare. Multi-step arithmetic aur logic me sudhaar aata hai kyunki intermediate steps dikhte hain aur check kiye ja sakte hain. Lekin ye single linear path hai — ek galat step baaki sabko poison kar deta hai, aur backtracking nahi hai.

Tree-of-Thoughts (ToT)

Reasoning ko tree me branch karo: kai candidate next steps generate karo, unhe score karo, promising branches explore karo, baaki prune karo. Ye generation nahi, reasoning par search hai. Cost zyada hai (kai zyada model calls), lekin dead ends se recover kar leta hai jo linear chain ko maar dete hain.

Graph-of-Thoughts (GoT)

Tree ko graph me generalise karo — thoughts ko merge, reuse aur combine kiya ja sakta hai, jaise do partial solutions ko jod kar ek banana. Ye teeno me sabse expressive aur sabse expensive hai, kyunki graph ko explicit aggregation aur scoring rules chahiye.

Recurring trade-off: expressiveness vs cost aur controllability — search ko jitni freedom doge, scoring, pruning aur verification par utna zyada kharcha karna padega.

02.2 Reactive architectures — ReAct

ReAct (Reason + Act): reasoning traces ko tool actions ke saath interleave karo — socho, act karo, tool result observe karo, phir socho. Observation agle thought ko reality me ground karta hai, isliye ReAct pure CoT ko un tasks me hara deta hai jahan jawab external facts par depend karta hai (prices, availability, file contents).

Ye Chapter 1 ka FSM hi hai — LLM transition function ki tarah kaam kar raha hai.

Example — semantic search

Book ka running example: agent document set me search kar raha hai. ReAct use ye karne deta hai: pehli retrieval kuch useful nahi laayi, to query reformulate karo — khaali result se hallucinated jawab banane ke bajay.

02.3 Human-in-the-loop — automation aur oversight ka balance

HITL ka matlab ye nahi ki human toote hue agent ka fallback hai. Human state machine me ek designed transition hai. Chapter chaar forms alag karta hai:

  • (a) Approval — irreversible action (send, delete, pay) se pehle.
  • (b) Review — draft bhejne se pehle human dekhe.
  • (c) Escalation — confidence low ho ya policy trigger ho.
  • (d) Correction — human ka edit training/feedback data ban jata hai.

Code — HITL LangGraph me (Examples 2-13 se 2-21)

Short LangGraph programs step by step banate hain: human-approval wala node; pause karke input wait karne wala node; routing jo low-confidence cases human ko aur high-confidence cases seedha aage bhejti hai; aur pattern jisme human ka decision state me wapas likha jata hai, taaki agent corrected state se aage badhe, restart se nahi. Code chhote, named nodes ke roop me hai, explicit state ke saath — har example ek transition sikhata hai.

02.4 Multi-agent systems — patterns aur protocols

Patterns

  • (i) Supervisor / orchestrator — ek agent plan karta hai, specialist workers ko delegate karta hai, phir results integrate karta hai.
  • (ii) Hierarchical — supervisors ke supervisors, bade tasks ke liye.
  • (iii) Swarm / peer-to-peer — agents seedha ek doosre ko handoff karte hain, koi central controller nahi; flexible, lekin debug karna mushkil.
  • (iv) Sequential pipeline — har agent ka output agle agent ka input.

Protocols

Agents ko handoff ke liye shared contract chahiye: kya ho gaya, kya abhi khula hai, aur agle agent ko kya karne ki permission hai. Iske bina handoffs chupchaap context drop kar dete hain.

Examples — do timed case studies

Do timed case studies diye gaye hain: (1) Semiconductor whitepaper pipeline — supervisor + researcher/writer/reviewer agents — book ke run me draft whitepaper lagbhag 2 minutes me bana. (2) Fintech swarm — peer agents ne multi-step financial task specialists ke beech handoff karke lagbhag 30 seconds me poora kiya.

Numbers illustrations hain — benchmarks nahi. Chapter turant poochhta hai ki kya measure nahi hua: accuracy, cost, aur failed runs me kya hua. Speed bina accuracy ke kuch nahi batati.

02.5 Idea se deployment tak — checklist

Chapter ka closing checklist-style hai:

  • Pattern task ki structure se match karo: linear → CoT/ReAct; branching → ToT; multi-skill → supervisor; fast, loosely-coupled → swarm.
  • HITL ko irreversible transitions par rakho — baad me jodne se kaam nahi chalega.
  • Handoffs ko state me explicit banao — model choice ki chinta se pehle.

Model choice aakhir me aata hai; pehle pattern, transitions aur handoffs decide hote hain.

Chapter 3 — Advanced Planning, Reasoning, Scalable Execution

Planning search hai, learning feedback hai, aur scale ek budget hai. Accha agent test time par achhi search karta hai, deployment ke baad apni trajectories se seekhta hai, aur jaanta hai ki kitni search afford kar sakta hai.

03.1 Zero-sum games se aage — rewards se reasoning tak

Supervised fine-tuning model ko sahi jawab imitate karna sikhata hai. Reinforcement learning use poori trajectory par reward maximise karna sikhata hai — aur agent exactly wahi karta hai: ek poora trajectory chalata hai, ek jawab nahi.

Chapter classic zero-sum game idea ko reframe karta hai: game me reward jeetna hai; agent me reward hai task ko sahi, saste aur safe tareeke se poora karna — ek richer, multi-objective signal.

Do failure modes khaas taur par: reward hacking — agent task kiye bina high score paane ka rasta dhoondh leta hai; aur credit assignment — lambi trajectory me samajh nahi aata ki reward ya blame kis step ko mile.

03.2 Agents ko seekhna sikhana — PPO, GRPO, DPO

PPO (Proximal Policy Optimisation) — classic RL algorithm, ek learned value/reward model ke saath. GRPO (Group Relative Policy Optimisation) — sampled outputs ke group ko ek doosre se compare karta hai, alag value model ke bajay; training simpler hoti hai, aur ye DeepSeek-R1 family me use hua approach hai. DPO (Direct Preference Optimisation) — explicit reward modelling skip karke seedha preferred vs rejected outputs ke pairs par train karta hai.

03.3 Test-time compute — size vs thought ka balance

Inference time par tum compute ko quality se trade kar sakte ho: model ko zyada der sochne do — zyada reasoning tokens, zyada samples, self-consistency voting, ya candidate plans par search — bada model use karne ke bajay.

Chapter ka rule of thumb: reasoning-heavy agentic tasks ke liye extra test-time compute aksar modestly bade model ko hara deta hai. Lekin ye har request par pay kiya jata hai, isliye cost decision product decision hai, sirf quality decision nahi.

Sawaal hamesha ye hai: ek request par kitna sochna afford kar sakte ho? Jawab product aur budget se aata hai, benchmark se nahi.

Example — AlphaEvolve: Google DeepMind ka system jo LLM se code changes propose karwata hai aur evaluator se wahi changes rakhta hai jo kaam karte hain — real infrastructure par apply kiya gaya. Book me reported results:

  • Scheduling improvement lagbhag 17% se lagbhag 32% — recovered capacity lagbhag double.
  • GEMM kernel par 1.5× speedup.

  • Reported deployment me data-centre utilisation me lagbhag 30% improvement.

Lesson: agent ki value ek brilliant generation se nahi, evaluate-and-keep loop se aayi.

Planning search hai, learning feedback hai, aur scale ek budget hai. Chapter teeno ko jod kar khatm hota hai: accha agent test time par achhi search karta hai, deployment ke baad apni trajectories se seekhta hai, aur jaanta hai ki kitni search afford kar sakta hai.

Chapter 4 — Models Behind the Agents: Capabilities aur Optimization

Model job ke hisaab se chuno, leaderboard ke hisaab se nahi. Agents ke liye context handling, tool reliability, KV-cache efficiency aur cost per completed task — ek benchmark number se zyada matter karte hain.

04.1 Big picture — sahi architecture chunna

Chapter standard decoder-only transformer se shuru hota hai aur wo axes samjhata hai jo agents ke liye matter karte hain: context length (kitna history, tool output aur retrieved text model hold kar sakta hai), reasoning ability (kya use step by step sochne ke liye train kiya gaya), tool-use training (kya wo reliably structured calls emit karta hai), aur cost/latency.

Lusser's law — reliability ka arithmetic

Agar har agent/step p probability se succeed karta hai, to n steps ki chain pⁿ probability se succeed karti hai. Book ke worked numbers: p = 0.98 per agent aur 10 agents sequence me → end-to-end success 0.98¹⁰ ≈ 81.7% — matlab jo system per step 98% reliable dikhta hai, wo end to end lagbhag paanch me se ek baar galat hai.

Validation jodne par (book me validation success rate v = 0.9, jo effective per-step reliability ko lagbhag 0.998 tak le jata hai) 10-agent chain lagbhag 98% tak pahunch jati hai. Lesson: reliability multiplicative hai, aur har boundary par validation hi lambi chains ko viable banata hai.

Interview FAQs

AI agents par interview me sabse zyada poochhe jaane wale 36 sawaal — har jawaab is book ke content par based hai.

01Agent kya hota hai — LLM chatbot se kaise alag hai?

LLM chatbot sirf text generate karta hai; agent ke paas tools hote hain, wo state maintain karta hai, plan banata hai aur environment me actions leta hai. Book ka test: agar system tool call karke duniya badal sakta hai aur uske result se agla step decide kar sakta hai, to wo agent hai — warna sirf chatbot.

02FSM aur HSM me kya farak hai, aur agents ke liye kyun matter karta hai?

Finite State Machine (FSM) me states aur transitions pehle se tay hote hain — predictable aur testable. Hierarchical State Machine (HSM) states ko nest karta hai taaki complex behaviour manage ho. Agents FSM se shuru hote hain, lekin model-driven decisions se transitions data-driven ho jate hain — isiliye agent ka behaviour FSM se zyada flexible, lekin kam predictable hota hai.

03Static system aur agentic system me kya antar hai?

Static system me har step pehle se tay hota hai — same input, same output. Agentic system me model har step par decide karta hai ki kya karna hai — tool call, retry, ya clarify. Static systems predictable hote hain; agentic systems flexible hote hain, lekin unhe contracts, validation aur guardrails chahiye.

04Chain-of-Thought, Tree-of-Thoughts aur Graph-of-Thoughts me kya farak hai?

CoT ek linear reasoning chain hai — step by step. ToT kai branches explore karta hai, bekar ko prune karta hai aur best raasta chunta hai. GoT thoughts ko graph me jodta hai — merge, split, refine kar sakta hai. CoT simple tasks ke liye, ToT search-heavy tasks ke liye, GoT synthesis-heavy tasks ke liye.

05ReAct pattern kaise kaam karta hai?

ReAct loop hai: Thought → Action → Observation. Model sochta hai ki kya karna hai, tool call karta hai, observation padhta hai, aur phir agla thought banata hai. Ye tool use ko reasoning se jodta hai — model har observation se seekh kar agla step decide karta hai.

06Human-in-the-loop kab zaroori hota hai?

Jab action irreversible ho (payment, delete, email bhej na), jab confidence kam ho, jab policy ambiguous ho, ya jab cost high ho. HITL ek control hai, convenience nahi — aur use bypass karne ki koshish khud ek attack signal hai.

07Multi-agent systems kab use karne chahiye — aur kab nahi?

Jab task naturally decompose ho (research + writing + review), jab alag expertise chahiye, ya jab parallel kaam se speed mile. Nahi — jab ek agent kaafi ho, kyunki har extra agent coordination cost, latency aur failure modes badhata hai. Book ka rule: sabse simple architecture jo kaam kare, wahi chuno.

08PPO, GRPO aur DPO me kya farak hai?

PPO classic RL hai — value/reward model ke saath policy update. GRPO sampled outputs ke group ko compare karta hai, alag critic model ke bajay — training simpler hoti hai. DPO explicit reward modelling skip karke seedha preferred vs rejected output pairs par train karta hai. Agents ke liye GRPO aur DPO popular hain kyunki wo simpler aur stable hain.

09Reward hacking kya hai — aur use kaise rokte hain?

Reward hacking tab hota hai jab agent task kiye bina high score paane ka rasta dhoondh le — jaise test ko pass karna bina kaam kiye. Roka jata hai: process rewards se (sirf outcome nahi), held-out tests se, human review se, aur reward ko task ke asli outcome se jod kar.

10Test-time compute kya hai — bada model lena behtar hai ya zyada sochna?

Test-time compute matlab inference par zyada compute kharch karna — zyada reasoning tokens, zyada samples, self-consistency voting. Book ka rule of thumb: reasoning-heavy tasks me extra test-time compute aksar modestly bade model ko hara deta hai. Lekin ye har request par pay hota hai, isliye cost decision product decision hai.

11AlphaEvolve se kya seekha — agent ki value kahan se aati hai?

AlphaEvolve ne LLM se code changes propose karwaye aur evaluator se wahi rakhe jo kaam karte the — TPU kernel par 32.5% speedup, scheduling 17% se 32%, GEMM par 1.5×. Lesson: value ek brilliant generation se nahi, evaluate-and-keep loop se aayi.

12KV cache kya hai aur GQA use kyun kam karta hai?

KV cache pehle process kiye tokens ke keys aur values store karta hai taaki dobara compute na karna pade. GQA (Grouped-Query Attention) kai query heads ke liye ek key/value head share karta hai — Qwen2.5 me 28 query heads aur 4 KV heads (7:1) se cache lagbhag saat guna chhota ho jata hai. Lambi agentic sessions ke liye ye bada saving hai.

13Open model chunu ya closed model — decision kaise karu?

Pehle requirements decide karo: data sensitivity (VPC chahiye?), latency, cost (per-token ya infra), aur customisation (fine-tune chahiye?). Phir model chuno. Closed models shuruaat me easy aur strong hote hain; open models inspection, fine-tuning aur data control dete hain.

14vLLM kya hai aur agents ke liye kyun popular hai?

vLLM ek serving engine hai — PagedAttention se efficient KV-cache management, continuous batching, aur prefix caching. Ye lambi multi-turn agentic sessions ko efficiently serve karta hai, isiliye book bhar me use hua hai.

15Lusser's law kya hai — 98% reliable agent bhi end-to-end kyun fail hota hai?

Agar har step p probability se succeed kare, to n steps ki chain p^n probability se succeed karti hai. p = 0.98 aur n = 10 → 0.98^10 ≈ 81.7% — matlab paanch me se ek run fail. Validation (v = 0.9) effective per-step reliability ko ~0.998 tak le jata hai aur chain ~98% ho jati hai. Reliability multiplicative hai.

16MCP kya hai — aur ye agents ke liye kyun important hai?

Model Context Protocol ek standard hai jisse model tools discover karta hai, resources padhta hai aur server se prompts use karta hai — taaki ek hi tool kai agents aur kai models use kar sakein. Pattern: discover, phir call, phir result validate karo — tool ki shape kabhi hard-code mat karo.

17Deep agent kya hota hai?

Deep agent execute karne se pehle explicit plan likhta hai — sub-tasks, dependencies aur definition of done ke saath — aur observations aate hi plan revise karta hai. Plan ek first-class artefact hai jise human padh aur approve kar sakta hai. SKILL.md aur AGENTS.md files agent ko project conventions sikhati hain.

18System prompt me 'ye mat karo' likhna security kyun nahi hai?

Kyunki model ko baaton se manaya ja sakta hai, instruction ko tool output overwrite kar sakta hai, aur koi enforcement point nahi hai. Asli governance model ke bahar code me rehni chahiye — hard budgets, allow-lists aur sandboxes — jise model rewrite na kar sake.

19Deny-by-default tool gateway kya hai?

Har tool call explicit policy ke against check hoti hai, aur default answer 'no' hai. Book ke 'Monty' example ne 16 tool calls handle kiye, policy decisions ke liye model ke 0 round trips ke saath — policy code hai, model judgement nahi.

20Path traversal attack kya hai — aur use kaise rokte hain?

Attacker file path me '../' sequences daal kar allowed directory se bahar nikalne ki koshish karta hai. Defence: path canonicalise karo, check karo ki allowed directory ke andar hi rahe, absolute paths reject karo. Jo file tool paths validate nahi karta, wo remote-code-execution vulnerability hai.

21Agent deployment ke paanch maturity stages kya hain?

1. Fast MVP (Streamlit + LiteLLM), 2. Alpha (Docker + MCP + FastAPI + tracing), 3. Hardening/beta (fallback + human-in-the-loop), 4. Production (auth + tracing + logging + alerting), 5. Scale (Kubernetes/Ray + vLLM + checkpoints + autoscaling). Har stage ek operational capability jodta hai — stage skip karna hi MVPs ko production me maarta hai.

22Circuit breaker agent me kya karta hai?

Circuit breaker budget set karta hai — jaise $0.50 aur maximum 12 turns — uske baad agent loop karne ke bajay ruk jata hai. Ye runaway loops aur surprise bills rokta hai. Checkpointing ke saath mil kar ye crash ke baad resume bhi deta hai.

23Context pruning kyun zaroori hai — example kya tha?

Conversation lambi hote hi tokens aur cost badhte hain. Book ke example me pruning ne 41 messages / 2,917 tokens ko 8 messages / 432 tokens par le aaya — recent turns rakh kar, budget 4,000 tokens ke andar. Pruning cosmetic nahi hai — ye cost aur failure mode badal deta hai.

24Three-tier fallback kya hai?

Tier 1: strict structured output (JSON schema + constrained decoding). Tier 2: Instructor + Pydantic retries. Tier 3: prompt-only output + canonicalisation. Tiers order me try hote hain — sabse reliable pehle, sabse loose aakhir me. Har model par same task naapo, aur fallback tier aur consistency naapo, sirf mean score nahi.

25Cold start kya hai — scale-to-zero ka trade-off kya hai?

Model ko GPU memory me load karne me 30–120 seconds lagte hain. Scale-to-zero idle cost bachata hai lekin pehli request par ye delay deta hai. Decision hai: idle cost vs first-request latency.

26Prefix caching kaise kaam karta hai — kitna fayda mila?

Jab do requests ka lamba common prefix hota hai (same system prompt aur history), to doosri request cached KV entries reuse karti hai. Book ka measurement: request 1 me 0.321s se 0.289s (1.11×), request 2 me 1.032s se 0.840s (1.23×). Lekin cache tabhi help karta hai jab tum prune aur invalidate bhi karte ho.

27Agent evaluation me stress testing kyun zaroori hai?

Kyunki jo agent single happy-path test pass kar le, wo doosre turn par, time pressure me, ambiguous request par ya frustrated user ke saamne fail ho sakta hai. Stress dimensions: urgency, ambiguity, emotional frustration, knowledge mismatch, adversarial intent — har ek ko apne test cases chahiye.

28LLM-judge scoring me 0.4 aur 0.6 ka kya matlab hai?

Book ki scoring: final = 0.4 × deterministic score + 0.6 × LLM-judge score, teen decimals tak round. Deterministic (keyword markers) stable aur cheap hai; LLM judge nuanced hai lekin biased ho sakta hai. Dono ko combine karna balance deta hai.

29OWASP Agentic AI Top 10 (2026) me sabse important threats kaunse hain?

ASI01 goal hijacking, ASI02 tool misuse, ASI03 identity abuse, ASI04 supply-chain compromise, ASI05 unexpected code execution, ASI06 memory/context poisoning, ASI07 insecure inter-agent communication, ASI08 cascading failures, ASI09 human trust exploitation, ASI10 rogue agents. Ye agents ke liye specific failure classes hain.

30Agent memory ke three legs kya hain?

Working memory (abhi chal rahi conversation), episodic memory (pichli conversations ke episodes), semantic memory (stable facts aur preferences). Ek leg missing ho to stool gir jata hai — working ke bina turn bhool jata hai, episodic ke bina har session pehli baar lagta hai, semantic ke bina preferences bar bar puchhni padti hain.

31Memory scorer trade-off kya hai — LLM judge kab use karu?

Regex ~70% catch, 0 calls; embedding ~85%, 0 calls; classifier ~90%, 0 calls; LLM judge ~95%, 1 call per step. 5-step ReAct loop me LLM judge bill lagbhag double kar deta hai. High-stakes steps par LLM judge, baaki par cheap scorer.

32Memory poisoning kya hai — MPBench kya test karta hai?

Memory poisoning tab hota hai jab attacker agent ki memory me galat facts inject kar de — jo baad me decisions bigaadte hain. MPBench ye test karta hai. Defence: validator (SSN, card numbers, secrets reject karo), confidence threshold 0.7, aur per-user namespace isolation.

33Ek request me kitne model calls hote hain — 4.8 ka kya matlab hai?

Book ka Table 11-3: Router 1.0 + Retrieval 0.6 + Reasoning 0.7 + Reflection 0.5 + Guardrails 2.0 = lagbhag 4.8 calls per request. Isiliye per-request cost per-token price × 4.8 ke kareeb hoti hai, sirf ek call ki nahi.

34Memoisation ne kitne calls bachaye — aur 90% cache-hit kyun warning hai?

Book ke run me memoisation ne 47% LLM calls avoid kiye. Lekin 90% cache-hit rate warning sign hai — itna high hit rate matlab cache stale ho sakta hai, ya test data hi repeat ho raha hai. Cache ko prune aur invalidate karna bhi utna hi zaroori hai.

35Indirect prompt injection kya hai — travel example se samjhao?

User 5-day beach trip under $2,000 plan karwana chahta hai. Agent hotel reviews padhta hai — ek review me hidden instruction chhupi hoti hai jo agent ko 'evil.site' par bhejne ki koshish karti hai. Chaar stages: injection, retrieval, execution, exfiltration. Lesson: tool output data hai, instruction nahi.

36LlamaFirewall kaise kaam karta hai — allow, HITL, block kaise decide hota hai?

Teen layers: Prompt Guard 2 (injection detection), agent-alignment checks, CodeShield (unsafe code). Scanner lexical signals ko score karta hai — tool output ka weight sabse zyada (1.4), HITL threshold 0.40, block threshold 2.0. 11-case test set me benign allow, explicit extraction block, invisible-char HITL — thresholds tune karna hi defence ka kaam hai.
