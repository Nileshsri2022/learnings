Agent kya hai? — Thesis aur Insurance Example

Book ki thesis ek line me: agent wo system hai jo task milne par khud figure out karta hai ki kaam kaise hoga — wo plan banata hai, tools aur data use karta hai, problems se guzarta hai aur change ke saath adapt karta hai. Sirf sawaal ka jawab dena agent nahi hai.

Book ki shuruaat ek insurance claim ke example se hoti hai. Ek chatbot sirf policy ke sawaalon ka jawab de sakta hai. Ek agent ye sab karta hai:

  • Claim padhta hai aur policy data fetch karta hai.
  • Photos aur forms ko inspect karta hai aur documents ko compare karta hai.

Agent kya hai? — Chhe defining traits

Agent ek computational entity hai jiske chhe defining traits hote hain. Ye chhe traits hi agent ko simple program se alag karte hain:

TraitMatlab
AutonomyKhud se kaam karta hai — har step par human ko nahi poochta
ReactivityEnvironment me badlaav par respond karta hai
ProactivenessGoal ki taraf khud initiative leta hai — sirf react nahi karta
LearningExperience se improve hota hai
Social abilityHumans ya doosre agents se communicate aur coordinate karta hai
RationalityAise actions leta hai jinse goal achieve hone ki sabse zyada probability ho — expected utility maximise karta hai

Book ek simple program aur ek non-agent LLM wrapper se compare karti hai: sirf LLM ko call karna agent nahi banata. Reasoning layer + tools + memory + learning — ye chaaro mil kar system ko agent banate hain.

Agent vs Assistant vs Workflow

  • Workflow — fixed sequence of steps. Har baar wahi steps, wahi order.
  • Assistant — prompts ka jawab deta hai. Tum poochho, wo bataye.
  • Agent — perceive karta hai, reason karta hai, goal ki taraf act karta hai, aur plan fail ho to adapt karta hai.

Interview me ye distinction sabse zyada poochha jata hai. Yaad rakhne ka tareeka: workflow = fixed steps, assistant = reactive answers, agent = goal-directed action with adaptation.

01.1Part I · Foundations

Agent technology ka evolution

Agent technology chaar waves me aayi hai — har wave ne capabilities ko widen kiya:

  • 1950s — Symbolic AI aur expert systems: pehli wave — rules aur knowledge bases. System rules follow karta tha.
  • 1980s–90s — Reactive aur deliberative agents: subsumption architecture aur Sense-Model-Plan-Act (SMPA) loop. Robot pehle sense karta hai, phir model banata hai, phir plan karta hai, phir act karta hai.
  • 2000s–10s — Web aur cloud era: software agents as services. Agents web par services ki tarah chalne lage.
  • 2020s — LLM-driven era: language models reasoning, planning aur tool use supply karte hain. Ye wo era hai jisme hum ab hain.

Customer-support example — teeno eras ek hi kaam me

  • 2010: FAQ matching — sawaal aaya, matching FAQ ka jawab gaya.
  • 2018: ML intent classification aur routing — model samajhta hai user kya chahta hai aur sahi team ko bhejta hai.
  • 2025: book ke hisaab se leading support platforms (Zendesk, Intercom, ServiceNow) 70–85% queries autonomously resolve kar lete hain.

Ye numbers batate hain ki evolution sirf theory nahi hai — har wave ne real resolution rate badhaya hai.

01.2Part I · Foundations

Anatomy — Cognitive loop (Perceive → Learn)

Agent ka anatomy ek cognitive loop hai — paanch phases jo baar-baar chalti hain:

  • Perceive — task, environment state aur history capture karo.
  • Reason — jo perceive kiya use interpret karo.
  • Plan — actions chuno aur unhe sequence karo.
  • Act — tools se execute karo.
  • Learn — knowledge update karo aur behaviour adjust karo.

Chapter ka code isi loop ko ek class ke roop me dikhata hai — paanch methods: perceive, reason, plan, act aur learn. Khaas baat: learn method lesson tabhi append karta hai jab computed performance score 0.7 threshold se upar ho. Matlab har experience se nahi seekhte — sirf usse jo kaafi achha raha ho.

agent.py — Cognitive loop (notes ke description se reconstructed)Python
class Agent:
    def __init__(self):
        self.lessons = []

    def perceive(self, task, environment_state, history):
        # Task, environment state aur history capture karo
        return {"task": task, "state": environment_state, "history": history}

    def reason(self, perception):
        # Jo perceive kiya, use interpret karo
        return "interpreted: " + str(perception["task"])

    def plan(self, reasoning):
        # Actions chuno aur sequence karo
        return ["step-1", "step-2", "step-3"]

    def act(self, plan):
        # Tools se execute karo
        return {"done": plan}

    def learn(self, result, performance_score):
        # Sirf tabhi lesson save karo jab score threshold se upar ho
        if performance_score > 0.7:
            self.lessons.append(result)
        return self.lessons

    def run(self, task, state, history):
        perception = self.perceive(task, state, history)
        reasoning = self.reason(perception)
        plan = self.plan(reasoning)
        result = self.act(plan)
        score = 0.82  # evaluation se aata hai
        self.learn(result, score)
        return result

retry.py — Exponential backoff + circuit breaker (notes ke description se reconstructed)Python
import time

failures = 0
circuit_open = False

def call_with_retry(fn, max_retries=3):
    global failures, circuit_open
    if circuit_open:
        return "CIRCUIT OPEN — service ko call hi nahi kar rahe"
    delay = 1  # seconds, har retry par double
    for attempt in range(max_retries + 1):
        try:
            result = fn()
            failures = 0
            return result
        except Exception as e:
            failures += 1
            if failures >= 3:
                circuit_open = True
                return "CIRCUIT OPEN after 3 failures"
            time.sleep(delay)
            delay = min(delay * 2, 8)  # 1s -> 2s -> 4s -> 8s max
    return "FAILED after retries"

from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_community.vectorstores import FAISS

# 1. Chunking: 1000 tokens, 200 overlap
splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
chunks = splitter.split_documents(documents)

# 2. Embeddings + vector store
embeddings = OpenAIEmbeddings(model="text-embedding-3-large")
store = FAISS.from_documents(chunks, embeddings)

# 3. Retrieve top 3, phir generate (provenance ke saath)
retriever = store.as_retriever(search_kwargs={"k": 3})

def load_csv(path):
    # CSV file padho aur rows wapas do
    import csv
    with open(path) as f:
        return list(csv.DictReader(f))

def group_by_and_aggregate(rows, dimension, metric):
    # Dimension ke hisaab se group karo, metric ko sum karo
    totals = {}
    for r in rows:
        totals[r[dimension]] = totals.get(r[dimension], 0) + float(r[metric])
    return totals

def plot_bar(data):
    return "BAR CHART: " + str(data)

def plot_line(data):
    return "LINE CHART: " + str(data)

F1End Matter · Interview FAQs

Interview FAQs

AI agent interviews (current era) ke liye — foundations se lekar production tak, 36 sawaal-jawaab. Har jawaab isi book ke concepts par aadharit hai.

Q01Agent aur chatbot me kya farak hai?
Chatbot prompts ka jawab deta hai — tum poochho, wo bataye. Agent goal ki taraf kaam karta hai: perceive karta hai, reason karta hai, plan banata hai, tools se act karta hai aur plan fail ho to adapt karta hai. Book ka insurance-claim example yaad rakho: chatbot sirf policy ke sawaal answer karta hai, agent claim padhta hai, policy data fetch karta hai, photos inspect karta hai, anomalies detect karta hai, settlement draft karta hai aur customer ko update karta hai. Interview me ye distinction sabse pehle poochhi jati hai.
Q02Agent ke chhe defining traits kaunse hain?
Autonomy (khud se kaam), reactivity (environment par respond), proactiveness (goal ki taraf initiative), learning (experience se improve), social ability (humans ya agents se communicate aur coordinate), aur rationality (goal achieve hone ki sabse zyada probability wale actions — expected utility maximise karna). In chhe me se koi ek missing ho to system poora agent nahi kehlata — jaise sirf LLM call karna ek wrapper hai, agent nahi.
Q03Workflow, assistant aur agent me kya antar hai?
Workflow fixed sequence of steps hai — har baar wahi steps, wahi order. Assistant prompts ka jawab deta hai. Agent perceive, reason aur act karta hai goal ki taraf, aur plan fail ho to adapt karta hai. Ek tareeka yaad rakhne ka: workflow = fixed steps, assistant = reactive answers, agent = goal-directed action with adaptation. Production design discussions me ye classification sabse zyada kaam aati hai.
Q04Cognitive loop ke paanch phases kaunse hain?
Perceive (task, environment state aur history capture karo), Reason (jo perceive kiya use interpret karo), Plan (actions chuno aur sequence karo), Act (tools se execute karo), aur Learn (knowledge update karo aur behaviour adjust karo). Book ke code me learn method lesson tabhi append karta hai jab performance score 0.7 threshold se upar ho — har experience se nahi seekhte, sirf kaafi achhe experience se.
Q05Reactive, deliberative aur hybrid architecture me kya farak hai?
Reactive direct sense-to-action mappings use karti hai — fast aur robust, par long-term planning nahi hoti. Deliberative SMPA follow karti hai — pehle world ka model, phir plan, phir act — socha-samjha par slow. Hybrid layered hoti hai: neeche fast reactions, upar planning — jaise warehouse robot jo obstacle turant avoid karta hai aur route bhi plan karta hai. Robotic control ke liye 100 ms se kam latency matter karti hai, isliye reaction layer fast honi chahiye.
Q06SMPA loop kya hai aur ye kaise kaam karta hai?
Sense-Model-Plan-Act — agent pehle sense karta hai (environment ko dekhta hai), phir model banata hai (world ka internal representation), phir plan karta hai (actions choose karta hai), phir act karta hai. Ye deliberative architecture ka core hai. Book me Tokyo trip example hai: transport choose karne se pehle weather aur calendar check karta hai — pehle model, phir plan, phir action.
Q07MCP kya hai aur kyun zaroori hai?
Model Context Protocol ek standard hai agent ko tools aur data sources se connect karne ke liye. Har tool ka JSON schema hota hai — naam, description, parameters aur required fields — jaise SearchFlights tool me origin, destination, date, passengers, jisme origin aur destination required hain. Bina schema ke LLM ko pata hi nahi chalega ki tool kya karta hai aur kaunse inputs chahiye. MCP se tools plug-and-play ho jate hain.
Q08A2A protocol kya hai?
Agent-to-Agent protocol ek standard hai agents ke aapas me baat karne ke liye. A2A message me role, task status aur state fields hote hain — ek agent doosre agent ko task de sakta hai, uska status pooch sakta hai aur state share kar sakta hai. Multi-agent systems me A2A ke bina har agent ko custom integration likhni padti.
Q09Agent Development Lifecycle ke paanch phases kaunse hain?
1) Requirements aur design, 2) Architecture design, 3) Implementation aur integration, 4) Evaluation aur optimisation, 5) Governance aur lifecycle management. Sabse important baat: evaluation aur governance aakhri step nahi hain — ye continuous hain. Har phase ke baad evaluate karo, aur governance poori lifecycle me chalti rehti hai.
Q10Interaction paradigms kitne hain aur kaunse hain?
Paanch: Direct LLM interaction (single call, low autonomy — chatbot), Proxy interaction (agent user ki taraf se tools ke saath — travel booking agent), Assistant interaction (collaborative, mixed-initiative — coding assistant), Autonomous interaction (agent independently goal ki taraf — research agent), aur Multi-agent interaction (kai specialised agents collaborate — software-development team). Autonomy upar se neeche badhti hai.
Q11Agentic AI Progression Framework ke levels kya hain?
Level 0 static rules, Level 1 LLM-assisted (model draft karta hai, human decide karta hai), Level 2 tool-using (agent khud tools call karta hai), Level 3 planning (agent goals decompose karta hai aur plans adapt karta hai), Level 4 multi-agent aur learning systems. Apne system ko is scale par rakho, phir decide karo ki agla level chahiye ya current hi kaafi hai — har level par cost, complexity aur risk badhta hai.
Q12LangChain vs LangGraph kab chunna chahiye?
LangChain modular hai, extensive integrations hain — general agent applications ke liye. LangGraph graph-based hai, explicit state aur control flow deta hai — complex workflows ke liye jahan state machine jaisi control chahiye. Simple agent ho to LangChain, complex multi-step workflow with branching aur state ho to LangGraph. Chapter ki advice: popularity se nahi, use case ki state aur orchestration needs se match karo.
Q13Framework use karna chahiye ya custom orchestration banana chahiye?
Framework use karo jab speed chahiye aur standard patterns kaafi hain. Custom orchestration tabhi banao jab control, latency ya koi unusual state model chahiye jo framework me fit nahi hota. Rule of thumb: pehle framework se shuru karo; jab framework rokne lage tabhi custom banao. Aksar teams ulta karti hain — pehle custom banati hain, phir framework ki kami me phas jaati hain.
Q14Hybrid LLM routing kya hai?
Har query ko us model par bhejna jo uske liye best suited hai — factual queries chhote model (jaise Mistral 7B) ko, creative kaam doosre model ko, analytical kaam strong reasoning model (jaise GPT-4o) ko, aur ek fallback default. Fayda: har query par sabse mehenga model use nahi hota — cost girti hai aur latency bhi, quality bina giraye.
Q15Context window manage karne ka best tareeka kya hai?
Context windows chhote models me lagbhag 8,000 tokens se lekar bade models me 1 million tokens tak hote hain. Practical advice: window ko bharne ke bajaye summarisation aur retrieval se manage karo. Sirf relevant cheezein window me rakho — poora context bharna mehenga bhi hai aur model ko confuse bhi karta hai.
Q16Embeddings kitne dimensions ke hote hain?
Base model 768 dimensions, large model 1,024 dimensions, aur OpenAI text-embedding-3-small 1,536 dimensions. Similarity cosine distance ya Euclidean distance se measure hoti hai. Retrieval ke liye chunks aam taur par 500–1,000 tokens ke hote hain, overlap ke saath. Approximate nearest neighbour search (HNSW, IVF) thodi recall kam karke badi speed gain deta hai.
Q17RAG me chunk size kaise choose karein?
Chunking strategies teen hain: fixed-size, recursive (headings aur paragraphs par split), aur semantic (meaning ke hisaab se split). Precise retrieval ke liye 200–500 tokens ke chhote chunks recommend kiye gaye hain. Book ke example me 1,000 tokens ke chunks with 200 tokens overlap use hue hain, top 3 chunks retrieve karke. Chunks bahut bade hon to similarity scores low aate hain; bahut chhote hon to context toot jata hai.
Q18PTCF kya hai aur system prompt me iska kya role hai?
PTCF system prompt ka blueprint hai: Persona (agent kaun hai), Task (use kya karna hai), Context (background aur constraints), Format (jawab kis shape me ho). Chaaro parts hone chahiye — koi ek missing ho to output unpredictable ho jata hai. Example: Persona — senior financial analyst, Task — quarterly report summarise karo, Context — sirf audited figures use karo, Format — bullet points me, har point ke saath source.
Q19System prompt aur user prompt alag kyun rakhne chahiye?
System prompt identity, rules aur output format set karta hai; user prompt specific request carry karta hai. Inhe alag rakhna zaroori hai — warna user input agent ka role overwrite kar dega. System prompt immutable rules hain, user prompt har baar badalta hai. Ye separation prompt injection se bhi bachata hai.
Q20Chain-of-Thought aur Tree-of-Thought me kya farak hai?
Chain-of-Thought linear hai — model ek path par step-by-step reason karta hai, arithmetic aur multi-step reasoning ke liye achha hai. Tree-of-Thought branching hai — model kai reasoning branches parallel explore karta hai aur evaluate karta hai, creative aur planning problems ke liye achha hai. CoT ek line hai, ToT ek search tree hai.
Q21Few-shot prompting aur RAG me kab kya use karein?
Few-shot examples se pattern sikhata hai — style aur format ke liye use karo. RAG documents se facts deta hai — knowledge ke liye use karo. Dono ka kaam alag hai: few-shot batata hai jawab kaisa dikhna chahiye, RAG batata hai jawab me kya facts hone chahiye. Confuse karne par ya to style sahi facts galat honge, ya facts sahi style galat.
Q22Prompt testing kaise karte hain?
A/B testing se do prompts compare karo, regression testing se har change ke baad purane tests chalao (chapter me 20 me se 20 regression tests pass hone ka case hai), aur four-step loop follow karo: baseline establish karo, evaluate karo, weaknesses identify karo, revise karo. Prompts ko version bhi do (jaise v1.2.0) — bina version ke pata hi nahi chalega ki production me kaunsa prompt chal raha hai.
Q23Circuit breaker pattern kya hai?
Circuit breaker failing service ko call karna band kar deta hai. Book ke example me 3 failures ke baad circuit open ho jata hai — uske baad service ko call hi nahi kiya jata, turant fallback milta hai. Isse cascading failures rukte hain: ek slow service poora system slow nahi karti. Tools: Hystrix, Istio, Sentinel. Retry ke saath combine karo: 3 retries, delay 1 second se badh kar 8 seconds tak.
Q24Exponential backoff kya hai aur kyun use karte hain?
Fail hone par turant retry karne ke bajaye badhte delay se retry karo — jaise 1 second, phir 2, phir 4, phir 8 seconds. Isse failing service ko recover karne ka time milta hai aur retry storm nahi banta. Book ke code example me 3 retries hain, delay 1 se 8 seconds tak badhta hai, aur 3 failures ke baad circuit open ho jata hai. Claimed effect: load ke neeche P99 latency 40–60% kam.
Q25Zero-trust security kya hai?
Zero-trust ka matlab hai har request verify karo — location par kabhi trust mat karo. Agent systems me ye khaas zaroori hai kyunki agents tools call karte hain aur data access karte hain. Controls: authentication aur authorisation, encryption in transit aur at rest, data minimisation, anonymisation, aur audit logs 90–180 days tak retain karna.
Q26NIST AI Risk Management Framework ke chaar functions kaunse hain?
Govern, Map, Measure, Manage. Govern — policies aur accountability set karo. Map — risks aur context identify karo. Measure — risks ko analyse aur track karo. Manage — risks ko mitigate karo. Ye framework Chapter 4 me compliance ke context me cover kiya gaya hai, US Executive Order 14110 aur IEEE standards ke saath.
Q27Memory-Augmented agent me teen memory types kaunse hain?
Working memory (current conversation), episodic memory (specific past events), aur semantic memory (general knowledge). Figure 5.3 ke hisaab se memory architecture ke aath components hain: ingestion, encoding, storage, retrieval, consolidation, decay, summarisation aur query interface. Galat memory type chunne par agent ya to context bhool jayega ya irrelevant purani baatein le aayega.
Q28RAG pipeline ke steps kaunse hain?
Query understanding (user asal me kya poochh raha hai), retrieval (relevant chunks dhoondhna), reranking (relevance ke hisaab se order karna), aur generation with provenance (source cite karke jawab dena). Book ke example me LangChain, text-embedding-3-large, FAISS, 1,000-token chunks with 200 overlap, top 3 chunks, aur GPT-4o-mini se generation. Failure diagnosis: refund ke sawaal par subscription-policy document aaye to usually metadata filter missing hai.
Q29Tool selection funnel kaise kaam karta hai?
Teen stages: intent classification (user kya chahta hai), semantic search (tool descriptions par embedding search), constraint filtering, phir dynamic reranking. Strategies: template matching, embedding search, constraint filtering, plan-driven selection, aur dynamic reranking. Funnel ka fayda hai ki 100 tools me se agent ko sirf relevant 2–3 tools dikhte hain — LLM confuse nahi hota.
Q30Chain-of-agents orchestrator ke chaar pillars kaunse hain?
Clear roles, common infrastructure, shared memory, aur orchestration. Table 7.1 ke hisaab se agent-to-agent messages me message format, role declaration, task delegation aur status signalling hone chahiye. Market-intelligence example me News, Financial aur Sentiment agents ek LLM analyst ko feed karte hain — har agent apna kaam karta hai, shared memory se sabko context milta hai.
Q31Insurance-claims workflow me confidence threshold kya hai?
Claim CLM-4821 ($8,400, policy POL-992317) confidence 0.91 aur low risk ke saath pay hua. Contrasting case confidence 0.79 aur high risk ke saath human ke paas gaya. Table 7.2 ke guards: amount threshold se upar ho to human review, validation failure ho to claim Rejected, aur confidence 0.85 se kam ho to human ko escalate karo. State machine: Intake → Validating → Assessing Risk → Processing Payout → Closed (Approved), ek branch Pending Human Review ki taraf.
Q32Test-Driven Generation (TDG) kya hai?
Pehle tests likho, phir code generate karo jo tests pass kare. Six stages: task padho, pehle tests likho (red phase), tests pass karne ke liye code generate karo (green phase), tests chalao, failures fix karo, refactor karo. Teen roles: Tester, Developer, Refactorer. Shipping calculator example me pehli attempt me 5 me se 4 tests pass hue. Full-stack example me Project Manager, Backend (Flask), Frontend (React) aur Tester agents parallel chalte hain — maximum 3 iterations, average 1.4 per task.
Q33Self-Improving agent ka loop kya hai?
Execute → Observe → Learn → Adapt. Figure 9.5 me sensing, coder, critic, planner, human-in-the-loop, learning store aur deployment hain. Metrics: task completion, error recovery, latency, user satisfaction aur improvement velocity. Example: async rejections 31 failures me se 23 ke liye zimmedar the — hypothesis bani aur test hui. Support agent case study me do quarters me first-contact resolution 18% badha, resolution time 23% kam hua, satisfaction 3.8 se 4.2 hui.
Q34Conversational agent me Safety Layer kyun pehle aata hai?
SafetyLayer entry par crisis triggers screen karta hai — 'hurt myself', 'suicide', 'end my life', 'harm' jaise triggers par predefined protocol response deta hai, saari generation bypass karke. Safety deterministic circuit breaker hai; generation policy ke downstream hai. Iska matlab: unsafe input par model kuch generate hi nahi karta — pehle safety, phir baat. Turn loop hai: safety check → working context retrieve → persona constraints ke under generate → memory me wapas likho.
Q35Brand consistency ko CSP ke roop me kaise model karte hain?
Brand consistency ko Constraint Satisfaction Problem mana jata hai: tonal requirements (authoritative but friendly — token weighting se), forbidden terminology (luxury context me 'cheap' word kabhi nahi), aur formatting rules (SEO ya regulatory templates). Consistency score ka formula hai C = 1/n × Σ φ(Ai, G), jahan n brand parameters ki sankhya hai. Researcher-Writer-Editor roles me Editor quality control karta hai — uske bina example draft teen forbidden terms ke saath publish ho jata.
Q36Multi-agent pipeline kab use karna chahiye aur kab nahi?
Tabhi jab teen conditions hon: ek se zyada output types par brand-constraint enforcement, teen ya zyada distinct roles coordinate karne hon, aur analytics-driven feedback future generation ko update karta ho. Warna single LLM call kaafi hai. Chapter ki advice: complexity tabhi add karo jab zaroorat pakki ho — har problem multi-agent nahi hoti.
