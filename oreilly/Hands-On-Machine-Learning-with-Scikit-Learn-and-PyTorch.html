Preface — Kitab kis liye hai, kin ke liye hai

Ye kitab machine learning ko haath se bana kar seekhne ki kitab hai — sirf theory padhne ki nahi, asli systems banane, tune karne aur deploy karne ki. Har concept ke saath code chalta hai, output dekha jata hai, phir agla kadam aata hai.

Kin ke liye hai?

  • Working practitioners aur developers — jo model ko ek baar chala kar bhoolna nahi chahte, balki use build, tune aur deploy karna chahte hain.
  • Jo reader Python reasonably achhe se jaanta ho aur Jupyter me kaam kar sakta ho.
  • Jo NumPy, pandas aur Matplotlib ki basic pehchan rakhta ho.

Prerequisites — pehle se kya aana chahiye

  • Linear algebra — vectors, matrices, dot product, transpose, inverse.
  • Calculus — gradient aur Hessian ki samajh.
  • Probability aur statistics — Gaussian aur binomial distribution, expectation, variance, median, Bayes' rule.

Ye prerequisites isliye zaroori hain kyunki kitab formulas ko black box nahi chhodti — wo batati hai ki gradient kyun waisa hai, aur regularisation weights ko kyun shrink karta hai.

TIP

Agar linear algebra ya probability thodi kamzor hai to ghabrao mat — kitab har jagah intuition pehle deti hai, formula baad me. Lekin Python aur Jupyter aana zaroori hai, kyunki har chapter me code chalana padega.

1.1Ch 1 — ML Landscape

Machine learning kya hai?

Machine learning ka matlab hai: program ko har case ke liye explicit rules likh kar nahi dena, balki examples dikha kar use seekhne dena — aur uski performance, kisi defined measure par, experience ke saath behtar hoti jaye.

Simple shabdon me: rule likhne ki jagah, data dikhao. Program khud pattern nikaal lega.

Spam filter — sabse saaf example

Spam filter ko labelled mail dikhaye jate hain — ye spam hai, ye nahi hai. Jitne zyada examples dekhta hai, utna behtar naye mail ko classify karta hai. Kisi ne use ye rule nahi likha ki "agar mail me 'lottery' likha ho to spam hai" — usne khud examples se seekha.

Do aur examples

  • Housing-price prediction — features jaise median income aur latitude/longitude dekar price (value) predict karna. Ye regression hai.
  • Music recommendation — features jaise age, sex, location aur listening history dekar ye batana ki user ko kaunsa gaana pasand aayega.

Har example me teen cheezein hoti hain: training set (examples jinse seekha jata hai), features (inputs), aur labels/target (wo output jo predict karna hai).

1.2Ch 1 — ML Landscape

ML kyun use karein?

Har problem ke liye ML nahi chahiye — lekin kuch problems aisi hain jahan rules likhna ya to namumkin hai, ya bekaar hai.

  • Koi tractable rule-based solution nahi — speech recognition, image recognition, natural language. Inme rules likhne baitho to kabhi khatm nahi honge — "ye awaaz 'a' hai" ka rule kya likhoge?
  • Data badalta rehta hai — spam karne wale apni tactics badalte hain, users ka behaviour badalta hai. Rule-based system ko baar-baar haath se update karna padega; ML system naye data se khud adapt kar leta hai.
  • Bade data me structure chhupa hai — itna data hai ki insaan use dekh kar pattern nahi nikaal sakta. ML use mine karke wo structure nikaal leta hai jo aankhon se dikhta hi nahi.

Short me: jahan rules likhna mushkil ho, data badalta ho, ya data itna bada ho ki insaan na samajh sake — wahan ML kaam aata hai.

1.3Ch 1 — ML Landscape

ML systems ke types — supervision, mode, generalisation

ML systems ko teen tareekon se classify kiya jata hai — supervision ke hisab se, seekhne ke mode ke hisab se, aur generalisation ke tareeke ke hisab se.

(a) Supervision ke hisab se

  • Supervised — labels diye jate hain. Classification (spam / not spam) aur regression (price predict karna) dono supervised hain.
  • Unsupervised — koi labels nahi. Clustering (similar cheezein group karna), visualisation, dimensionality reduction, anomaly detection, association rules.
  • Semi-supervised — thode se labelled examples + bahut saare unlabelled. Example: photo app me ek person ko kuch photos me tag karo, wo baaki photos me use pehchan leta hai.
  • Self-supervised — labels data se hi derive hote hain. Example: ek masked word ko predict karna — isi tareeke se LLMs pretrain hote hain.
  • Reinforcement learning — ek agent environment me reward/penalty se seekhta hai. Example: board games khelna seekhna.

(b) Seekhne ke mode ke hisab se

  • Batch / offline — saare data par ek baar train karo, phir deploy karo. Data badle to dobara train karna padega.
  • Online / incremental — data ki stream se lagatar seekhta rehta hai. Learning rate control karta hai ki kitni tezi se adapt kare — zyada rate par purana data bhool bhi sakta hai.

(c) Generalisation ke hisab se

  • Instance-based — examples ko yaad rakho, naye input ko unse compare karo. Example: k-nearest neighbours — naye point ke sabse kareeb ke 3 neighbours dekho.
  • Model-based — ek function ke parameters fit karo, phir us function se predict karo. Example: linear regression.

Linear regression ka equation (Eq. 1-1): predicted value = θ0 + θ1x1 + ... + θnxn — matlab features ka weighted sum plus ek bias term. Ise parameter vector θ aur feature vector x ka dot product bhi likha ja sakta hai.

1.4Ch 1 — ML Landscape

Main challenges — overfitting, underfitting aur baaki

ML me sabse badi galti ye hoti hai ki model training data par achha, naye data par bekaar ho. Isi ke aas-paas saari challenges ghumti hain.

Overfitting vs underfitting

  • Overfitting — model training data ke noise ko bhi fit kar leta hai. Training error kam, lekin naye data par error zyada. Jaise exam ke saare sawaal ratt lena, concept samjhe bina.
  • Underfitting — model itna simple hai ki pattern hi nahi pakad pata. Training error bhi zyada, test error bhi zyada. Jaise quadratic data par seedhi line fit karna — x = 100 ke aas-paas decision boundary galat ho jata hai, upar bhi aur neeche bhi.

Aur challenges

  • Generalisation error — model naye data par kitna achha karega, yehi asli measure hai; training error nahi.
  • Hyperparameters vs parameters — parameters training me seekhe jate hain (jaise θ), hyperparameters training se pehle set kiye jate hain (jaise polynomial degree ya regularisation strength).
  • Data mismatch — training data ka distribution production data se alag ho. Model lab me achha, real duniya me bekaar.
  • No free lunch — koi ek algorithm har problem ke liye best nahi hota. Har problem me try aur compare karna padta hai.
  • Regularisation — fitted line ko shrink karke training accuracy thodi kam karo, generalisation behtar karo. Overfitting ka ilaaj hai.

1.5Ch 1 — ML Landscape

Testing aur validating — model par bharosa kaise karein

Model ko sirf training data par achha dekh kar chunna misleading hai — wo to ratt kar bhi achha lag sakta hai. Bharosa tab banta hai jab model kabhi na dekhe hue data par achha kare.

  • Test set hold out karo — data ka ek hissa alag rakho, training me use mat karo. End me us par check karo ki model naye data par kaisa karega.
  • Cross-validation — data ko kai hisson me baanto, har baar ek hissa test banao aur baaki se train karo. Ek hi split par bharosa karne se behtar estimate milta hai.
  • Train / validation / test split — validation set se model chunno aur hyperparameters tune karo, test set se final check karo. Test set ko baar-baar dekh kar tune karna cheating jaisa hai — wo phir test nahi rehta.

Performance measures — confusion matrix, precision, recall, F1

Accuracy kaafi nahi hai — khaas taur par jab classes imbalanced hon. Isliye confusion matrix aur usse nikle metrics use hote hain.

Confusion matrix — chaar hisse

  • True positives (TP) — 5 tha, aur 5 hi bola.
  • False positives (FP) — 5 nahi tha, phir bhi 5 bola.
  • True negatives (TN) — 5 nahi tha, aur nahi bola.
  • False negatives (FN) — 5 tha, lekin miss kar diya.

Precision aur recall

  • Precision = TP / (TP + FP) — jin items ko positive flag kiya, unme se kitne asal me positive the. Matlab: "jab model 5 kehta hai, to kitni baar sahi hota hai?"
  • Recall = TP / (TP + FN) — asal positives me se kitne pakde gaye. Matlab: "kul 5s me se kitne dhoondh liye?"
  • F1 score — precision aur recall ka harmonic mean. Ek hi number me dono ka balance.

Precision/recall tradeoff

Decision threshold badhao to precision badhti hai aur recall girta hai — aur ulta bhi. Threshold ek knob hai jise apni zaroorat ke hisab se ghumate ho.

  • Precision-recall curve aur ROC curve (true positive rate vs false positive rate) — dono tradeoff dikhate hain. ROC ke neeche ka area AUC kehlata hai.
  • Precision-recall curve se threshold chuna jata hai — jaise 90% precision ke liye lagbhag 55% recall milta hai.
  • Precision aur recall ko threshold ke against plot karo to dono lagbhag 0.5 threshold par cross karte hain — wahan dono lagbhag 0.75 hote hain.

Linear regression ko train karne ke do tareeke hain — ek closed-form solution, aur ek iterative solution. Dono ko samajhna zaroori hai kyunki aage ke saare models dusre tareeke par hi khade hain.

(a) Normal Equation — seedha formula

Gradient descent ka idea simple hai: cost function ki slope dekho, aur uske ulta direction me ek chhota step lo. Baar-baar karo, aur tum minimum par pahunch jaoge.

Teen variants

  • Batch GD — har step me poora training set use karta hai. Stable hai, lekin bada dataset ho to ek step bhi slow hai.
  • Stochastic GD (SGD) — har step me sirf ek random instance use karta hai. Fast hai, noisy hai, aur noise ki wajah se local minima se nikal bhi sakta hai.
  • Mini-batch GD — har step me chhota random batch (jaise 50 examples). Dono ka beech ka rasta — yehi aam taur par use hota hai.

Learning rate — sabse important knob

  • Bahut chhota — converge hoga, lekin bahut slow.
  • Bahut bada — minimum ke aas-paas oscillate karega ya diverge kar jayega (cost badhne lagegi).
  • Learning-rate schedules — rate ko samay ke saath kam karo, jaise ηt = t0 / (t + t1). SGDClassifier/SGDRegressor me schedule eta0 aur power_t se control hota hai.
TIP

Learning rate ko tune karna gradient descent ki sabse badi kala hai. Cost badh rahi hai to rate bahut bada hai; cost bahut slow gir rahi hai to rate bahut chhota hai.

CART training algorithm — greedy split

CART woh algorithm hai jo decision tree ko train karta hai. Uska tareeka greedy hai — matlab wo har kadam par wahi split chunta hai jo us waqt sabse behtar lage, aage ka soch kar nahi.

  • Har feature, har threshold: algorithm har node par har feature ke har possible threshold ko aazma kar dekhta hai.
  • Weighted impurity: split ke baad dono bachcho ki impurity ko unke size ke hisab se weight dekar joda jata hai; jis split ki weighted impurity sabse kam ho, wahi chuni jati hai.

Gini impurity ya entropy?

Split kitna achha hai, ye naapne ke liye impurity ka ek measure chahiye. Do mashhoor measures hain — Gini impurity aur entropy — aur dono ka kaam ek hi hai: node kitna mila-jula hai, ye batana.

Formulas

  • Gini impurity = 1 − ∑(pi²) — jahan pi class i ka fraction hai. Node pure ho (ek hi class) to Gini 0; do classes barabar hon to Gini 0.5.
  • Entropy = −∑(pi × log2(pi)) — node pure ho to entropy 0; do classes barabar hon to entropy 1.

Kaun sa chunein?

  • Gini default hai — kyunki ye tez hai (log nahi nikalna padta) aur aam taur par entropy jaisi hi tree deta hai.
  • Entropy kabhi-kabhi thoda alag, thoda zyada balanced tree de sakti hai, lekin farak aam taur par chhota hota hai.
  • Agar tumhe khaas wajah na ho, to default Gini par hi raho — criterion badalne se pehle depth aur leaf size jaise hyperparameters par dhyaan do, wahi zyada farak dalte hain.
tree_gini = DecisionTreeClassifier(criterion='gini')      # default, tez
tree_ent = DecisionTreeClassifier(criterion='entropy')   # log wala measure

Voting classifier ka idea seedha hai: ek model ki jagah kai alag-alag classifiers train karo, aur unhe vote karne do. Akele model se galti ho sakti hai, lekin bahut se alag models ki galtiyan aksar ek dusre ko kaat deti hain.

Bagging aur pasting — alag data, wahi algorithm

Bagging me wahi algorithm alag-alag random subsets par train hota hai, phir unki predictions ko mila diya jata hai — classification me vote se, regression me average se. Pasting bhi wahi hai, bas ek farak ke saath.

  • Bagging (bootstrap aggregating): har subset training data se replacement ke saath sample kiya jata hai — matlab ek hi example ek subset me kai baar aa sakta hai.
  • Pasting: subset bina replacement ke sample kiya jata hai — har example ek subset me zyada se zyada ek baar.
  • Fayda: bagging variance kam karta hai aur overfitting se bachata hai. Ek tree unstable hota hai, lekin 500 tree ka average stable hota hai.

Out-of-bag (OOB) evaluation

Bagging ki ek khaas baat: har model ko train karte waqt kuch examples chhoot jate hain (bootstrap me har baar lagbhag ek-tihaai data chhoot jata hai). Un chhoote hue examples par model ko test kiya ja sakta hai — ise OOB evaluation kehte hain, aur iske liye alag validation set ki zaroorat nahi hoti.

Curse of dimensionality — zyada dimensions, zyada musibat

Jaise-jaise features (dimensions) badhte hain, data khali jagah me phail jata hai — points ek dusre se door ho jate hain, zyada tar space khaali rehta hai, aur model ko seekhne ke liye exponentially zyada data chahiye hota hai. Isi ko curse of dimensionality kehte hain.

PCA — principal component analysis

PCA woh directions dhoondhta hai jinme data ki variance sabse zyada ho — inhe principal components kehte hain. Data ko pehle kuch components par project kar do, to zyada tar jaankari bach jati hai, dimensions kam ho jate hain.

Mathematically, PCA covariance matrix ki eigendecomposition se ye directions nikaalta hai. Tumhe maths ka har step yaad rakhne ki zaroorat nahi — ye samajhna kaafi hai ki pehla component sabse zyada variance pakadta hai, dusra usse kam, aur aise aage.

Explained variance ratio

Har component kitni variance capture karta hai, ye explained variance ratio batata hai. Notes me MNIST par pehle do components lagbhag 82.3% aur 10.8% variance samjhate hain — pehla component akela hi zyada tar variance le leta hai, kyunki MNIST data bahut correlated hai.

Kitne components chahiye?

  • MNIST par 95% variance bachane ke liye 154 components chahiye hote hain — 784 se kam, lekin 2 se bahut zyada. Matlab 2D visualisation ke liye 2 components kaafi hain, lekin model ke liye 154 chahiye.

  • Bade datasets ke liye RandomizedPCA / SVD tez tareeka hai, aur IncrementalPCA data ko batches me process karta hai — poora data memory me lane ki zaroorat nahi.
  • KernelPCA kernel ka use karke non-linear PCA karta hai — is par alag section 7.5 me hai.

Johnson-Lindenstrauss lemma — random projection

Johnson-Lindenstrauss lemma kehta hai: random projection se distances lagbhag bachayi ja sakti hain — agar target dimension kaafi bada ho. Ye hairan karne wali baat hai, kyunki random projection me koi seekhna nahi hota, phir bhi distances bach jati hain.

Formula

Target dimension kam se kam lagbhag 8 × log(m) / ε² hona chahiye — jahan m examples ki sankhya hai aur ε distortion (kitni galti chalegi) hai.

  • m = 5,000 aur ε = 0.1 ke liye minimum dimension lagbhag 7,300 nikalta hai.
  • Matlab: 5,000 examples ke distances ko 10% galti ke andar bachane ke liye 7,300 dimensions chahiye — ye bahut zyada lag sakta hai, lekin agar original dimensions isse bhi zyada hon, to bhi fayda hai.
  • Epsilon chhota karo (kam galti chaho) to dimension bahut tezi se badhta hai — kyunki formula me epsilon ka square denominator me hai.

Is lemma ka practical matlab: jab data bahut high-dimensional ho aur PCA mehenga ho, to random projection ek sasta aur tez shortcut ho sakta hai — distances lagbhag waisi hi rahengi, aur aage ka model chal jayega.

K-means sabse seedha clustering algorithm hai: k centroids chuno, har example ko sabse nazdeek wale centroid se jodo, phir har centroid ko uske examples ke mean par le jao — aur ye tab tak repeat karo jab tak centroids hilna band na kar dein.

DBSCAN — density se cluster, bina k ke

DBSCAN (Density-Based Spatial Clustering of Applications with Noise) clusters ko density se dhoondhta hai, k se nahi. Tumhe ye nahi batana padta ki kitne clusters hain — algorithm khud gin leta hai, aur outliers ko alag se noise keh deta hai.

Core, border, noise

  • Core point: jis point ke eps distance ke andar kam se kam min_samples neighbours hon.
  • Border point: core point nahi hai, lekin kisi core point ke nazdeek hai — cluster ka kinara.
  • Noise: na core, na border — kisi cluster me nahi aata. Ye outliers ko alag karne ka natural tareeka hai.
  • Paas wale core points ek hi cluster me aate hain.

Notes me moons data par eps=0.2 aur min_samples=5 se DBSCAN 2 clusters dhoondhta hai aur noise ko alag karta hai — moons ki aadhi-chand (crescent) shape ko K-means nahi pakad sakta, lekin DBSCAN pakad leta hai.

  • Taakat: kisi bhi shape ke clusters dhoondh sakta hai, k batane ki zaroorat nahi, outliers pehchan leta hai.
  • Kamzori: eps aur min_samples par sensitive hai — galat eps chuno to ya to sab ek cluster ban jayega, ya sab noise.

dbscan = DBSCAN(eps=0.2, min_samples=5)

Gaussian mixtures — soft clustering

Gaussian mixture data ko kai Gaussian distributions ke mixture ke roop me model karta hai — har component ka apna mean, covariance aur weight hota hai. K-means se farak ye hai ki yahan har example kisi ek cluster ka nahi hota, balki har cluster ki ek probability rakhta hai — soft clustering.

Poora dataset ek saath train karna (batch GD) dheere hota hai, aur ek-ek example (stochastic GD) noisy hota hai. Beech ka raasta hai mini-batch GD — chhote batches me train karo. PyTorch me ye kaam DataLoader karta hai.

for epoch in range(100):

        loss = loss_fn(model(X_batch), y_batch)
        loss.backward()

    val_loss = loss_fn(model(X_val_t), y_val_t)

Vanishing aur exploding gradients — gehri network ki sabse badi mushkil

Gehri network me gradient peechhe ki layers tak pahunchte-pahunchte ya to lagbhag zero ho jata hai, ya bahut bada ho jata hai. Isi ko vanishing / exploding gradients kehte hain. Neeche wali layers phir bahut dheere seekhti hain, ya training diverge kar jati hai.

Kyun hota hai?

  • Backpropagation me gradient har layer se guzarte hue multiply hota hai. Agar har step par factor 1 se chhota hai, to product tezi se zero ki taraf jata hai; agar 1 se bada hai, to tezi se bada hota hai.
  • Sigmoid jaise activation ka derivative chhota hota hai — zyada tar jagah 0.25 se kam — isliye sigmoid wali gehri network me gradient peeche jaate-jaate ghis jata hai.
  • Bade weights bhi gradient ko bada kar dete hain — wahi exploding gradient hai.
  • Asar: upar wali layers seekh leti hain, neeche wali layers lagbhag wahi ki wahi rehti hain — network gehri hone ka fayda hi nahi milta.

Activation functions — ReLU, ELU, GELU kyun behtar hain

Activation function hi tay karta hai ki gradient kitna bachega. Sigmoid aur tanh saturate hote hain — bade input par unka derivative lagbhag zero ho jata hai. Isi liye gehri network me inki jagah ReLU family use hoti hai.

  • ReLU — positive input ko waisa ka waisa, negative ko zero. Derivative positive side par 1 hota hai, isliye gradient peeche tak bachta hai. Simple aur tez hai — hidden layers ke liye default pasand.
  • ELU — negative side par bhi thoda output deta hai, isliye dead units kam hote hain; lekin thoda mehenga padta hai.
  • GELU — smooth version hai, transformer wale models me bahut use hota hai.
  • Sigmoid — output 0 se 1 ke beech; binary output layer ke liye theek hai, hidden layers ke liye nahi, kyunki derivative chhota hota hai.
  • Tanh — output -1 se 1 ke beech, sigmoid se behtar centre hota hai, lekin phir bhi saturate hota hai.

Weight initialisation aur batch normalisation

Weights ko kaise shuru kiya jaye, ye bhi gradient ko tay karta hai. Galat initialisation se signal aage jaate-jaate ya to dab jata hai ya phat jata hai — aur batch normalisation har layer ke input ko stable rakhti hai.

Initialisation — activation ke hisab se chuno

  • He initialisation — ReLU ke liye. Variance ko is hisab se set karta hai ki ReLU ke baad signal ka scale bana rahe.
  • Xavier / Glorot initialisation — tanh aur sigmoid ke liye. Aage aur peeche dono taraf signal ka variance barabar rakhne ki koshish karta hai.
  • Galat pairing (jaise sigmoid ke liye He, ya ReLU ke liye bahut chhota scale) se training shuru se hi dheemi ya unstable ho jati hai.
  • PyTorch me ye initialisation layers ke default me ya explicit init functions se milti hai — activation dekh kar chuno, yaad se nahi.

Batch normalisation

  • Har layer ke input ko mini-batch ke mean aur variance se normalise karta hai — phir seekhe hue scale aur shift se wapas dhalta hai.
  • Isse training tez aur stable hoti hai: bada learning rate use kar sakte ho, aur initialisation ki galti ka asar kam hota hai.
  • Original paper ke hisab se batch normalisation se same accuracy tak pahunchne me 14 guna kam steps lage — ye iska sabse mashhoor number hai.
  • Side effect: ye regulariser jaisa bhi kaam karta hai, kyunki har batch ka noise thoda alag hota hai.

Faster optimisers — momentum se AdamW tak

Plain gradient descent dheera aur bhatakta hua hota hai. Optimiser ka kaam hai gradient ko samajhdaari se use karna — past steps ki direction yaad rakhna, aur har parameter ke liye alag step size tay karna.

  • Momentum — pichhle update ka ek hissa (fraction) naye update me jod do. Isse seedhi disha me raftaar badhti hai aur idhar-udhar ka oscillation kam hota hai — jaise bhaari gend dheere-dheere seedhi chalti hai.
  • Nesterov accelerated gradient — momentum ko thoda aage dekh kar lagata hai: pehle momentum step se aage badho, phir wahan gradient napo. Overshoot kam hota hai.
  • AdaGrad — har parameter ka step uske past gradients ke hisab se adjust karta hai; kam aane wale features ko bada step milta hai. Masla: step size samay ke saath bahut chhota ho jata hai.
  • RMSProp — AdaGrad ka sudhaar: past gradients ka recent average use karta hai, isliye step size mar nahi jata.
  • Adam — momentum + RMSProp dono ka combination (adaptive moment estimation). Sabse zyada use hone wala optimiser hai.
  • AdamW — Adam ka version jisme weight decay sahi tareeke se alag se lagta hai; aaj ke samay me ye aksar behtar pasand hai.

Learning rate scheduling — 1cycle ka kamaal

Ek hi learning rate poori training ke liye sahi nahi hota. Shuru me bada, baad me chhota — yehi scheduling ka idea hai. Sahi schedule se kam epochs me behtar accuracy milti hai.

  • Exponential decay — learning rate har step/epoch par ek fixed factor se ghat-ta jata hai.

Convolutional layers — filter, stride, padding

Convolutional layer me ek chhota filter (kernel) — jaise 3x3 ya 5x5 — image ke upar slide karta hai aur har jagah dot product nikaalta hai. Jahan filter jaisi cheez milegi, wahan feature map me bada value aayega.

  • Filter / kernel — seekha hua chhota weight matrix; har filter ek feature dhoondhta hai (jaise vertical edge).
  • Feature map — filter ke slide karne se bana output; har filter ki apni feature map hoti hai.
  • Stride — filter har step me kitna aage badhega. Stride 1 matlab har pixel, stride 2 matlab har dusra pixel — output chhota hota hai.

    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(1, 32, 3)
        self.pool = nn.MaxPool2d(2)
        self.conv2 = nn.Conv2d(32, 64, 3)
        self.fc = nn.Linear(64 * 5 * 5, 10)
    def forward(self, x):
        x = self.pool(F.relu(self.conv1(x)))
        x = self.pool(F.relu(self.conv2(x)))
        x = torch.flatten(x, 1)
        return self.fc(x)
  • Conv2d — in-channels, out-channels, kernel size. Pehli layer me in-channels = image channels (grayscale ke liye 1).
  • ReLU — har convolution ke baad activation lagana mat bhoolo.
  • MaxPool2d(2) — har pooling se height/width aadhi ho jati hai.
  • Flatten — 2D feature maps ko 1D vector banao, phir Linear layer classifier ka kaam kare.
  • Training loop wahi hai jo Chapter 10 me tha: DataLoader se mini-batches, Adam optimiser, loss backward, step.

Implementing ResNet-34 — residual blocks se 34 layers

ResNet-34 me 34 layers hain aur lagbhag 21 million parameters. Iska building block residual block hai — do 3x3 convolutions, batch normalisation, ReLU, aur ek skip connection jo input ko output me jod deti hai.

  • Residual block: do 3x3 convolutions, har ek ke baad batch normalisation, beech me ReLU; ant me input x ko output me jod kar phir ReLU.
  • 34 layers isi block ko baar-baar stack karke banti hain — blocks ke groups me feature maps ki sankhya badhti hai aur size kam hota hai.
  • Lagbhag 21 million parameters — VGG se kam, accuracy zyada — kyunki residual se gehri network train ho pati hai.
  • Figure 12-18 aur 12-19 me ResNet aur uske residual blocks dikhaye gaye hain.
class ResidualBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1)
        self.bn1 = nn.BatchNorm2d(channels)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1)
        self.bn2 = nn.BatchNorm2d(channels)
    def forward(self, x):
        out = F.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        return F.relu(out + x)  # skip connection

Training RNNs — BPTT aur vanishing gradients

RNN ko train karne ke liye use time me unroll karke backpropagation through time (BPTT) chalaya jata hai. Lekin lambi sequence par wahi purani mushkil wapas aati hai — gradient ya to ghis jata hai ya phat jata hai.

  • BPTT: network ko time steps me unroll karo, phir peeche se gradient bhejo — jaise gehri network me, bas yahan "gehrai" time hai.

  • Vanishing gradients: lambi sequence par pehle wale steps ka gradient lagbhag zero ho jata hai — model door ki baat bhool jata hai.

13.3Ch 13 — RNNs

LSTM aur GRU — gates se lambi yaad

LSTM aur GRU me gates hote hain — chhote switch jo tay karte hain ki kya yaad rakho, kya bhoolo, kya bahar bhejo. Isi se lambi sequence ki yaad bachti hai.

LSTM — teen gates

  • Forget gate — purani yaad me se kya bhoolna hai, ye tay karta hai.
  • Input gate — nayi jaankari me se kya store karna hai, ye tay karta hai.
  • Output gate — yaad me se kya bahar bhejna hai, ye tay karta hai.
  • Ek alag cell state hoti hai — lambi yaad ka rasta, jisme gradient aasani se beh sakta hai.

GRU — do gates, tez

  • Reset gate — purani hidden state ko kitna bhoolna hai.
  • Update gate — nayi jaankari ko kitna apnana hai, purani ko kitna rakhna hai.
  • GRU me alag cell state nahi hoti — isliye ye LSTM se tez hota hai, aur aksar lagbhag utna hi achha karta hai.

Attention mechanisms — decoder kis shabd par dhyaan de

Attention ka idea hai: decoder har step par source sentence ke relevant hisse par dhyaan de, ek hi context vector par nirbhar rehne ki jagah. Attention weights batate hain ki har target word ke liye kaunsa source word sabse relevant tha.

  • Masla jo hal hota hai: ek context vector me poori lambi sentence dabani padti thi — jaankari kho jati thi. Attention se decoder har step par source ke saare words ko dekh sakta hai.
  • Attention weights: har target word ke liye source words par weights — zyada weight matlab zyada relevant. In weights ko dekh kar samajh aata hai ki model ne kya dekha.
  • Pehla attention tareeka (multiplicative): notes me bataya gaya attention ka ek tareeka — decoder ki hidden state se source ke hidden states se score nikaal kar weights banaye jate hain.
  • Doosra attention tareeka (additive): notes me bataya gaya doosra tareeka — ek chhota network score nikaalta hai, phir weights bante hain. Dono ka maksad ek hi: relevant source words ko zyada weight do.
  • Asar: lambi sentences par translation behtar hoti hai, aur model interpretable banta hai — weights dekh kar pata chalta hai ki kis word ka translation kahan se aaya.

15.1Ch 15 — Transformers

Attention Is All You Need — transformer kya hai?

Transformer ki sabse badi baat ye hai ki ye sirf attention par based hai — na recurrence (RNN jaisa step-by-step), na convolution. Poori sequence ko ek saath dekhta hai, aur har token dusre tokens se rishta attention se seekhta hai.

Transformer ke do hisse hote hain:

  • Encoder — input sequence ko samajhta hai aur uska rich representation banata hai.
  • Decoder — us representation se output sequence banata hai, ek token at a time.

Har block ke andar kya hota hai?

  • Self-attention — har token sequence ke baaki tokens ko dekh kar apna matlab refine karta hai.
  • Feed-forward network — har position par alag se lagta hai, representation ko transform karta hai.
  • Residual connections — input ko block ke output me jod dete hain, taaki gradient deep network me bhi beh sake.
  • Layer normalisation — har layer ke activations ko normalise karke training ko stable rakhti hai.

Decoder me ek extra cheez hoti hai: masked self-attention — decoder output banate waqt aage ke tokens ko dekh nahi sakta, sirf pehle wale tokens ko. Uske baad encoder-decoder attention hoti hai, jisme decoder encoder ki taraf dekhta hai.

Yehi architecture aaj ke lagbhag saare bade language models ki neev hai — encoder-only, decoder-only ya encoder-decoder, sab isi ke roop hain.

Scaled dot-product attention aur multi-head attention

Attention ka core formula ye hai:

Attention(Q, K, V) = softmax(QKT / √(dk)) V

Teeno matrices ka matlab samjho:

  • Q — Query: har token poochhta hai, "mujhe kis se matlab hai?"
  • K — Key: har token batata hai, "main kis baare me hoon?" Query aur key ka dot product batata hai ki dono kitne relevant hain.
  • V — Value: asal information jo aage badhani hai — relevance ke hisab se weighted sum banta hai.

sqrt(dk) se divide kyun?

Jab key vectors bade hote hain (dk bada), to dot products bhi bade ho jate hain. Bade dot products softmax ko bahut sharp bana dete hain — gradients chhote ho jate hain aur training mushkil ho jata hai. √(dk) se divide karne se scores sane range me rehte hain aur gradients behtar bechte hain. Ye chhota sa scaling hi "scaled" dot-product attention ko stable banata hai.

Multi-head attention

Ek hi attention head se kaam nahi chalta — alag-alag rishte alag tareeke se dekhne hote hain. Multi-head attention me kai attention heads parallel me chalte hain, har head Q, K, V ko apne alag projection se dekhta hai, phir sab heads ke outputs ko concatenate karke ek final projection se joda jata hai.

  • Ek head shayad grammar (subject-verb) dekhe, dusra head meaning ya long-range rishta dekhe.
  • Har head alag subspace me attention seekhta hai, isliye model zyada rich representation banata hai.

Short me: attention ek weighted average hai — kaunsi value kitni leni hai, ye query-key similarity tay karti hai.

Positional encoding — position ka pata kaise chale?

RNN me sequence ka order apne aap milta tha — ek token ke baad dusra aata tha. Transformer me aisa kuch nahi hai: wo poori sequence ko parallel me process karta hai. Bina position ke, "ram ne shyam ko mara" aur "shyam ne ram ko mara" ek jaise lagenge.

Isiliye transformer token embeddings me positional encoding jodta hai — har position ke liye ek extra vector, jo batata hai ki token sequence me kahan hai.

  • Sinusoidal positional encoding — sine aur cosine functions se bani fixed encoding. Alag-alag frequencies se har position ka unique pattern banta hai, aur model relative distances bhi seekh sakta hai.
  • Learned positional embeddings — position ke liye bhi embedding seekhi jati hai, jaise word embeddings seekhe jate hain. Training ke dauraan model khud seekhta hai ki position 1, 2, 3 ka kya matlab hai.

Dono tareekon ka maksad ek hi hai: order ki jaankari token ke representation me ghusa dena, taaki attention sirf "kya" nahi, "kahan" bhi samjhe. Positional encoding ke bina transformer bag-of-words jaisa ho jata — saare tokens honge, order gayab.

TIP

Yaad rakho: transformer me recurrence nahi hai, isliye position alag se deni padti hai. Yehi wajah hai ki lambi sequences par positional encoding aur attention cost dono important ho jate hain.

Encoder-only models — BERT, RoBERTa, DistilBERT

Encoder-only models sirf transformer ke encoder hisse ko use karte hain. Ye text generate nahi karte — ye text ko samajhte hain: classify karna, sawal ka jawab nikaalna, naam pehchanna, aur aise tasks jahan poora input ek saath dekhna ho.

BERT

BERT (Bidirectional Encoder Representations from Transformers) dono taraf ka context dekhta hai — token ke pehle aur baad wale dono taraf ke words. Isiliye iska naam "bidirectional" hai. BERT do tasks par pretrain hota hai:

  • Masked language modelling (masked LM) — sentence ke kuch words ko chhupa (mask) kar do, model ko unhe guess karna hai. Isse model ko dono taraf ka context use karna padta hai.
  • Next-sentence prediction — do sentences diye jate hain, model batata hai ki dusra sentence pehle ke baad aata hai ya nahi. Isse model ko sentences ke beech ka rishta seekhne me madad milti hai.

RoBERTa aur DistilBERT

  • RoBERTa — BERT ka hi improved version: zyada data, zyada training, aur training ke kuch details badal kar behtar performance.
  • DistilBERT — BERT ka chhota, tez version, distillation se banaya gaya: bada BERT teacher banta hai, chhota model usse seekhta hai. Size aur speed ka fayda, performance me chhota sa nuksaan.

Encoder-only models ko fine-tune kiya jata hai: pretrained BERT lo, uske upar apne task ke liye ek chhota classification head lagao, aur apne labelled data par thoda train karo — classification, question answering, aur aise hi understanding tasks ke liye.

Kadam 1 — Supervised Fine-Tuning (SFT)

Vision Transformer (ViT) — image ko patches me baanto

Transformer sirf text ke liye nahi hai. Vision Transformer (ViT) image ko bhi sequence bana kar transformer ko deta hai — aur kaafi data milne par CNNs ko hara bhi deta hai.

ViT image ko kaise dekhta hai:

  • Image ko patches me baanto — jaise 16×16 pixels ke chhote tukde. Har patch ek "token" ban jata hai, bilkul text ke word ki tarah.
  • Har patch ko flatten karo — 16×16×3 (RGB) patch ek lamba vector ban jata hai, phir use linear projection se embedding me badlo.
  • Positional embedding jodo — taaki model ko pata chale ki kaunsa patch image me kahan tha.
  • [CLS] token jodo — ek khaas classification token sequence ke shuru me lagaya jata hai; aakhir me usi token ka representation final prediction ke liye use hota hai.
  • Transformer encoder se guzaro — wahi self-attention, feed-forward, residual aur layer norm, jo text me use hote the.

ViT ki kamzori — bahut data chahiye

ViT ko achha train karne ke liye bahut saara data chahiye. CNNs me convolution ki wajah se built-in bias hota hai — wo pehle se jaante hain ki paas wale pixels ka rishta hota hai, translation se farak nahi padta. ViT me ye bias nahi hai — use sab kuch data se seekhna padta hai. Data kam ho to ViT CNN se peeche reh jata hai; data bahut ho to ViT CNN ko peeche chhod deta hai.

DeiT, PVT aur Swin — ViT ki kamiyon ke jawab

ViT achha hai, lekin uski do kamiyan saaf hain: data ki bhookh, aur har image size par ek jaisa treatment. Teen models inka jawab dete hain.

  • DeiT (Data-efficient Image Transformer) — knowledge distillation se ViT ko kam data par train karta hai. Ek CNN teacher hota hai — bada, pehle se train kiya hua model — jo chhote ViT student ko sikhata hai. Teacher ki soft predictions se student kam examples me bhi behtar seekhta hai.
  • PVT (Pyramid Vision Transformer) — hierarchical structure banata hai: jaise-jaise network gehra hota hai, feature maps chhote aur rich hote jate hain — bilkul CNN ke pyramid jaisa. Isse alag-alag size ki images aur dense tasks (detection, segmentation) behtar handle hote hain.
  • Swin Transformer — shifted windows ka idea: poori image par ek saath attention lagane ke bajay, image ko windows me baanto aur har window ke andar attention lagao, phir windows ko shift karke dobara lagao. Isse computation kam hota hai aur model alag sizes ki images par achha kaam karta hai.

Efficient data representations — autoencoder kya hai?

Autoencoder ek neural network hai jo apne input ko copy karke output me laane ki koshish karta hai — lekin beech me ek bottleneck (chhoti hidden layer) se guzar kar. Bottleneck ki wajah se network ko input ka compressed representation seekhna padta hai — sirf zaroori jaankari bachti hai, baaki chhoot jati hai.

Autoencoder ka maksad output ko input jaisa banana hai — lekin bottleneck ke through. Agar bottleneck na ho, to network sirf copy karna seekh lega aur kuch useful nahi seekhega. Bottleneck hi use seekhne par majboor karta hai ki data me asal me kya structure hai.

Is compressed representation ke kai fayde hain: dimensionality reduction, denoising, aur aage generative models (VAE, GAN, diffusion) ki neev.

Variational autoencoders (VAE) — latent space se sampling

Variational autoencoder (VAE) normal autoencoder se ek kadam aage hai: ye har input ke liye ek fixed encoding nahi, ek distribution seekhta hai — har input ke liye mean aur standard deviation.

  • Encoder har input ko ek distribution (mean + std) me badalta hai, phir us distribution se sample karke ek latent vector banaya jata hai, aur decoder usse image banata hai.
  • Loss ke do hisse hote hain: reconstruction error (image kitni sahi bani) + KL divergence (seekhi hui distribution standard normal distribution se kitni door hai). KL divergence latent space ko smooth aur regular rakhta hai.
  • KL divergence ki wajah se latent space me paas wale points paas wali images banate hain — space me koi bada khaali ya toota hissa nahi rehta.

VAE ki sabse badi taakat: ye generate kar sakta hai. Latent space se koi bhi point sample karo, decoder ko do, aur ek nayi image milegi — jo training data jaisi hogi, lekin uski copy nahi hogi.

Learning to optimize rewards — agent-environment loop

Reinforcement Learning (RL) me koi labelled dataset nahi hota. Ek agent ek environment me kaam karta hai: wo state dekhta hai, action leta hai, reward pata hai, aur nayi state milti hai — phir dobara. Agent ka maksad hai cumulative discounted reward ko maximize karna.

  • State — environment ki current halat (jaise cart ki position aur pole ka angle).
  • Action — agent kya karta hai (jaise cart ko left ya right dhakelo).
  • Reward — har step par milne wala signal — achha kaam to positive reward, galat kaam to negative ya zero.
  • Cumulative discounted reward — sirf aaj ka reward nahi, aane wale saare rewards ka total, jisme aage ke rewards ko discount kiya jata hai.

Discount factor gamma = 0.95

Chapter ke example me gamma 0.95 hai. Iska matlab: agle step ka reward aaj ke reward ka 95% ke barabar mana jata hai, uske agle step ka 0.95×0.95, aur aise hi aage. Gamma batata hai ki agent ko aane wale rewards ki kitni parwah hai — gamma 0 ho to sirf immediate reward matter kare, gamma 1 ke kareeb ho to door ke rewards bhi utne hi important hon.

Supervised learning se farak: wahan sahi jawab pehle se pata hota hai; yahan agent ko try karke seekhna padta hai ki kaunsa action aage chal kar zyada reward dega.

Credit assignment problem — kis action ko credit mile?

Credit assignment problem RL ki sabse mushkil samasyaon me se ek hai: ek lambi trajectory ke end me reward mila — to kis action ko uska credit mile? Pehle wala action achha tha, ya beech wala, ya aakhri wala?

Q-learning — grid world, Q-values aur optimal policy

Q-learning me hum Q-function seekhte hain: Q(s, a) matlab state s me action a lene aur phir optimal policy follow karne par kitna return milega. Q-function seekh li, to policy simple hai — har state me wohi action lo jiska Q sabse zyada ho.

Q-learning update

Update formula:

Q(s,a) ← Q(s,a) + α (r + γ · maxa′ Q(s′,a′) − Q(s,a))

  • α — learning rate; r — mila hua reward; γ — discount factor; s′ — nayi state.
  • r + γ · max Q(s′,a′) — target: abhi ka reward + aage ka best possible return.
  • Bracket ke andar ka farak (target − current Q) TD error hai — usi se Q ko sudhara jata hai.

Mixed-precision training (MPT) — FP32 weights, FP16 compute

Mixed-precision training (MPT) standard approach hai: weights aur weight updates FP32 me rakho, baaki computations FP16 me karo. Training ke baad weights ko FP16 me shrink kar do.

  • Weights FP32 me kyun? Kyunki weight updates bahut chhote hote hain — FP16 me wo round hokar zero ho sakte hain, aur training ruk jayegi. FP32 me updates safe rehte hain.
  • Compute FP16 me kyun? Kyunki forward aur backward ka zyada hissa FP16 me tez aur kam memory me hota hai.
  • Loss scaler kya hai? Loss ko ek bade factor se multiply karke gradients ko bada kiya jata hai, taaki chhote gradients FP16 me kho na jayein, phir update se pehle wapas divide kar diya jata hai.

Yehi combination — FP32 stability + FP16 speed — mixed-precision training ko standard banata hai.

FInterview FAQs

Interview FAQs — Hands-On ML

36 sawal-jawab jo aaj ke interviews me is kitab ke topics par poochhe jate hain. Har jawab kitab ke content par based hai.

Q1Supervised, unsupervised aur reinforcement learning me kya farq hai?

Supervised learning me labels diye jate hain — classification jaise spam ya not spam, aur regression jaise ghar ki keemat. Unsupervised learning me koi label nahi hota — clustering, visualisation, dimensionality reduction aur anomaly detection isme aate hain. Reinforcement learning me agent environment me reward aur penalty se seekhta hai, jaise game khelna. Semi-supervised me kuch labelled aur bahut se unlabelled examples hote hain, aur self-supervised me labels data se hi bante hain, jaise masked word predict karna.

Q2Overfitting aur underfitting kya hain, aur regularisation kaise madad karta hai?

Underfitting tab hota hai jab model bahut simple ho aur pattern hi na pakde — training aur validation dono errors zyada hote hain, jaise degree-1 polynomial quadratic data par. Overfitting tab hota hai jab model training data ka noise bhi yaad kar le — training error kam, validation error zyada, jaise degree-10 polynomial. Regularisation weights par penalty lagakar model ko simple rakhta hai, aur early stopping validation error badhne par training rok deta hai.

Q3California housing project ka end-to-end pipeline kya tha aur RMSE kitna aaya?

Project me California districts ki median house value predict karni thi — dataset me 20,640 rows aur 10 columns hain, jisme median_income, latitude, longitude aur ocean_proximity shamil hain. Pipeline me missing values ke liye median imputer, scaling ke liye StandardScaler aur ocean_proximity ke liye OneHotEncoder use hua. LinearRegression ka RMSE lagbhag $68,973, DecisionTree ka lagbhag $70,060, RandomForest ka lagbhag $47,038, tuned forest ka lagbhag $44,500 aur final test RMSE $41,446 aaya, jiska 95% confidence interval lagbhag $39,980 se $42,912 hai.

Q4Precision, recall aur F1 kya hain, aur accuracy kyun dhokha deti hai?

Precision batata hai ki positive flag kiye gaye items me se kitne asli positive the — TP/(TP+FP). Recall batata hai ki asli positives me se kitne mil gaye — TP/(TP+FN). F1 in dono ka harmonic mean hai. MNIST par 5-detector ki accuracy 95.3% hai, lekin ye dhokha deti hai kyunki hamesha 'not 5' bolne wala classifier bhi 90.1% accuracy deta hai — sirf lagbhag 9.1% digits 5 hain. Isliye imbalanced data par precision, recall aur F1 dekho, sirf accuracy nahi.

Q5Gradient descent ke variants kya hain aur learning rate kyun matter karta hai?

Batch gradient descent har step me poora training set use karta hai — stable lekin slow. Stochastic gradient descent ek random instance use karta hai — fast aur noisy, aur local minima se nikal sakta hai. Mini-batch gradient descent chhota batch, jaise 50 examples, use karta hai — beech ka achha compromise. Learning rate bahut chhota ho to training bahut slow hoti hai, bahut bada ho to cost diverge kar jata hai. Learning-rate schedule, jaise eta_t = t0/(t+t1), training ke dauraan rate kam karta hai.

Q6Ridge, Lasso aur Elastic Net me kya farq hai?

Ridge L2 penalty lagata hai — alpha guna weights ke squares ka sum — jo weights ko shrink karta hai lekin kisi ko zero nahi karta. Lasso L1 penalty lagata hai — jo kuch weights ko bilkul zero kar deta hai, isliye woh feature selection bhi karta hai. Elastic Net dono ko combine karta hai aur L1 ratio se mix control hota hai. Kitab me degree-10 polynomial par Ridge alpha=0.1 unregularised model se bahut behtar test error deta hai.

Q7Decision tree me Gini aur entropy me kya farq hai, aur tree unstable kyun hota hai?

Gini impurity 1 minus sum of squared class probabilities hoti hai — pure node par 0, do classes barabar hon par 0.5. Entropy minus sum of p log2(p) hoti hai — pure node par 0, barabar split par 1. Dono milte-julte tree dete hain, lekin Gini fast hai isliye default hai. Tree unstable isliye hota hai kyunki training data me chhota sa badlaav pehla split badal sakta hai aur poora tree alag ho sakta hai — isiliye ensemble methods use hote hain. Max_depth, min_samples_split aur min_samples_leaf se overfitting roka jata hai.

Q8Voting, bagging, random forest, boosting aur stacking me kya farq hai?

Voting me alag-alag classifiers vote karte hain — hard voting majority leta hai, soft voting probabilities average karta hai. Bagging me ek hi algorithm alag random subsets par train hota hai aur predictions average hote hain, jisse variance kam hota hai. Random forest bagging plus har split par random feature subset hai. Boosting me models sequentially train hote hain aur har naya model pichhle ki galtiyan sudharta hai. Stacking me base models ki predictions par ek meta-model train hota hai — moons dataset par stacking 92.8% accuracy ke saath sabse behtar tha.

Q9PCA kya hai aur curse of dimensionality kya hoti hai?

PCA woh directions dhoondhta hai jahan data ki variance sabse zyada hoti hai — principal components — aur data ko pehle k components par project kar deta hai. MNIST par pehla component lagbhag 82.3% aur doosra lagbhag 10.8% variance samjhata hai, aur 95% variance ke liye 154 components chahiye. Curse of dimensionality ka matlab hai ki high dimensions me data points door-door ho jate hain, zyada jagah khaali rehti hai, distances ka matlab kam ho jata hai aur overfitting ka risk badh jata hai.

Q10K-means, DBSCAN aur Gaussian mixtures me kya farq hai?

K-means k centroids chunta hai, har example ko nearest centroid deta hai aur centroid ko mean par le jata hai — fast hai lekin spherical clusters maanta hai aur initial centroids par depend karta hai. Blob data par k=5 par inertia lagbhag 211.6 aur silhouette lagbhag 0.656 aaya. DBSCAN ko k nahi chahiye — woh density se arbitrary shape ke clusters aur outliers dhoondhta hai, lekin eps aur min_samples par sensitive hai. Gaussian mixtures data ko Gaussian distributions ka mixture maankar Expectation-Maximisation se fit karta hai, aur BIC/AIC se components ki sankhya chuni jati hai.

Q11Perceptron aur MLP kya hain aur ye kaise seekhte hain?

Perceptron ek artificial neuron hai jo inputs ka weighted sum plus bias lekar activation function lagata hai — single unit sirf linearly separable problems solve kar sakta hai. MLP kai layers ko stack karta hai aur non-linear problems solve kar sakta hai. California housing par 50-50-50 hidden units wala MLP regressor ka training loss 0.852 se 0.130 tak gira, aur Fashion MNIST par 300-100 units wala MLP classifier lagbhag 89.7% validation accuracy aur 89.2% test accuracy par pahuncha.

Q12PyTorch me tensors aur autograd kaise kaam karte hain?

Tensor multi-dimensional array hota hai — torch.tensor, zeros, ones, rand se banta hai — aur NumPy jaisi operations, matmul, reshape aur slicing support karta hai. Tensors CPU ya GPU par reh sakte hain aur .to(device) se move hote hain. Autograd me requires_grad=True set karke function compute karo, .backward() call karo aur gradients .grad me mil jate hain. Example: f(x)=x squared par f(5)=25 aur f prime(5)=10 hota hai. PyTorch me model nn.Module ka subclass hota hai, loss MSELoss aur optimiser SGD ya Adam hota hai.

Q13Vanishing gradients kya hain aur batch normalisation kaise madad karta hai?

Deep network me gradients ya to zero ki taraf shrink ho jate hain — jaise sigmoid ki derivative chhoti hoti hai — ya exponentially badh jate hain, jisse neeche ki layers bahut slow seekhti hain ya diverge karti hain. Fixes hain ReLU ya GELU activations, sahi initialisation (ReLU ke liye He, tanh ya sigmoid ke liye Xavier/Glorot), batch normalisation aur residual connections. Batch normalisation har layer ke inputs ko normalise karta hai, training tez karta hai — original paper ke hisab se same accuracy tak pahunchne me 14 guna kam steps — aur regulariser ki tarah bhi kaam karta hai.

Q14CNN me convolution aur pooling kya karte hain, aur ResNet ke skip connections kyun hain?

Convolution me chhota filter, jaise 3x3, input par slide karke dot product karta hai aur feature map banata hai — pehli layers edges aur textures, beech ki layers parts aur aakhri layers objects seekhti hain. Pooling, jaise 2x2 max pooling, feature maps ko chhota karta hai aur chhoti translation se invariant banata hai. ResNet me skip connection input ko output me jod deta hai, jisse gradient seedha behta hai aur 152 layers tak ke deep network train ho pate hain — ResNet ne ImageNet par 3.6% top-5 error ke saath jeeta tha.

Q15RNN, LSTM aur GRU me kya farq hai?

RNN me neuron ka output agle time step me input ki tarah wapas aata hai, isliye use past ki memory rehti hai — lekin lambi sequences par vanishing gradients hote hain. LSTM ke teen gates hote hain: forget gate kya bhoolna hai, input gate kya store karna hai aur output gate kya output karna hai — isse lambi dependency yaad rehti hai. GRU ke sirf do gates hote hain, reset aur update, aur woh fast hota hai. Time-series forecasting me 1D CNN ka MAE 29,273 aur multivariate RNN ka MAE 23,227 aaya, jo naive baseline ke 43,916 se bahut behtar hai.

Q16Attention aur transformer architecture kaise kaam karte hain?

Transformer sirf attention par based hai — na recurrence, na convolution. Scaled dot-product attention ka formula hai softmax(Q K transpose / sqrt(d_k)) V, jahan Q, K, V query, key aur value matrices hain. Multi-head attention kai heads ko parallel chalakar unke outputs ko jodta hai. Kyunki transformer me recurrence nahi hai, token ki position ke liye sinusoidal positional encoding add ki jati hai. English-to-Spanish transformer 6 layers, 8 heads aur 512 model dimension ke saath lagbhag 25 BLEU score par pahuncha.

Q17BERT aur GPT me kya farq hai?

BERT encoder-only model hai — bidirectional hai, masked language modelling aur next-sentence prediction par pretrain hota hai, aur classification ya question answering ke liye fine-tune kiya jata hai. GPT decoder-only model hai — next-token prediction par pretrain hota hai aur text generate karta hai, sawal-jawab karta hai aur code likhta hai. Dono hi transformer par based hain, lekin BERT context ko dono taraf se dekhta hai jabki GPT sirf pehle ke tokens ko dekhta hai.

Q18Vision Transformer aur CLIP kya hain?

Vision Transformer image ko patches, jaise 16x16 pixels, me todta hai, har patch ko flatten karke positional embedding jodta hai aur sequence ko transformer encoder me daalta hai — classification ke liye ek [CLS] token use hota hai. ViT ko bahut data chahiye, lekin kaafi data par woh CNN se behtar hota hai. CLIP images aur text ko ek joint embedding space me seekhta hai, isliye woh images ko text descriptions se compare karke zero-shot classification kar sakta hai — bina us class par train hue.

Q19Autoencoder, VAE, GAN aur diffusion model me kya farq hai?

Autoencoder input ko bottleneck se copy karna seekhta hai aur compressed representation banata hai — linear undercomplete autoencoder PCA ke barabar hota hai. VAE fixed encoding ke bajay har input ke liye distribution seekhta hai aur latent space se sample karke nayi images generate karta hai. GAN me generator fake images banata hai aur discriminator asli-nakli pehchanta hai — competition se generator behtar hota jata hai. Diffusion model image me step by step noise jodta hai, phir noise hatana seekhta hai aur noise se shuru karke nayi images generate karta hai, jaise Stable Diffusion.

Q20Q-learning, DQN aur PPO kya hain?

Q-learning Q-function seekhta hai — state me action lene aur phir optimal policy follow karne ka expected return. Update hai Q(s,a) += alpha (r + gamma max Q(s prime,a prime) - Q(s,a)). Grid-world me alpha=0.05 aur gamma=0.95 par lagbhag 10,000 iterations me optimal Q-values mile: s0 [18.92, 17.03, 13.62], s1 [0, -inf, -4.88], s2 [-inf, 50.13, -inf], aur optimal policy [0, 0, 1]. DQN Q-function ko neural network se approximate karta hai aur experience replay plus target network se stable karta hai — CartPole par lagbhag 500 reward. PPO policy update ko clip karta hai taaki bada badlaav na ho.

Q21Autodiff me forward-mode aur reverse-mode me kya farq hai?

Autodiff automatic differentiation hai — backpropagation ki neev. Example f(x,y) = x squared y + y + 2 par x=3, y=4 par f=42, df/dx=24 aur df/dy=10 hote hain. Forward-mode derivative ko function value ke saath aage propagate karta hai aur tab efficient hota hai jab inputs kam aur outputs zyada hon. Reverse-mode pehle function value forward compute karta hai phir gradients ko peeche propagate karta hai — jab inputs bahut zyada aur output ek ho, jaise machine learning me, tab yahi efficient hai aur PyTorch ka autograd yahi karta hai.

Q22Mixed precision aur quantization se memory kitni bachti hai?

PyTorch default 32-bit floats use karta hai — 4 bytes per parameter — isliye 1 billion parameters wala model sirf hold karne me kam se kam 4 GB RAM leta hai. Training me Adam optimiser ko har parameter ke liye do extra values chahiye, yani 1-billion-parameter model ke liye extra 8 GB. Mixed-precision training me weights 32-bit me rehte hain lekin computations 16-bit me hote hain, aur baad me weights 16-bit me shrink karne se size aadha ho jata hai. Quantization parameters ko 8-bit ya 4-bit integers me badal kar model ko aur chhota karta hai.

Q23Chapter 17 ke baare me kya khaas baat hai — woh kitab me kyun nahi hai?

Chapter 17, Speeding Up Transformers, is edition me online-only hai — O'Reilly reader me sirf uska introduction aur ek tip hai, poora chapter nahi. Introduction ke hisab se woh chaar areas cover karta hai: training tez karna, inference tez karna, model chhota karna aur efficient attention mechanisms. Tip me kaha gaya hai ki mixed-precision training aur quantization ke details ke liye Appendix B padho, jo printed kitab me hai. Isliye is chapter ke figures, tables aur code notes me nahi hain.

Q24Optuna se hyperparameter tuning kaise hoti hai?

Optuna me ek objective function define karte ho jo hyperparameters suggest karta hai, model train karta hai aur validation accuracy return karta hai. Kitab ke example me learning rate 1e-4 se 1e-1 tak log-uniform, hidden units 16 se 128 tak aur dropout 0 se 0.5 tak suggest kiye gaye. 20 trials ke baad best hyperparameters mile: learning rate lagbhag 0.0853, 116 hidden units aur dropout lagbhag 0.25, jinki validation accuracy lagbhag 88.68% thi.

Q25Transfer learning kya hai aur ye kab kaam aata hai?

Transfer learning me bade dataset par train kiya model lekar uski neeche ki layers ko naye task ke liye reuse karte ho aur sirf upar ki layers train karte ho — ya chhoti learning rate se poora model fine-tune karte ho. Chhote dataset par, har class ke sirf 20 images par, transfer learning ne accuracy lagbhag 71.6% se badhakar lagbhag 92.5% kar di. TorchVision se pretrained ResNet lekar Flowers102 dataset par sirf naya head train karne se lagbhag 90% accuracy mili, aur poora fine-tune karne se usse bhi zyada.

Q26MNIST par multiclass classification me kaunsi galtiyan hoti hain?

MNIST me 70,000 handwritten digits hain, har ek 28x28 pixels ya 784 features — 60,000 training aur 10,000 testing. RandomForestClassifier ko lagbhag 97.4% cross-validated accuracy mili, jabki SGD classifier ko 10 classes par lagbhag 89.1% mili. Confusion matrix dikhata hai ki 3 aur 5 aksar 8 se confuse hote hain, aur 4 aksar 9 se. Bahut si misclassified images asal me ambiguous hoti hain — jaise 5 jo 3 jaisa dikhta hai — isliye confused pairs ke liye zyada training data ya naye features madad karte hain.

Q27Logistic regression aur softmax regression kya karte hain?

Logistic regression binary classification ke liye sigmoid function se probability predict karta hai — 1/(1+exp(-z)). Iris dataset par iski accuracy lagbhag 95% aayi. Softmax regression iska multiclass version hai — har class ke liye score nikalta hai, softmax unhe probabilities me badalta hai aur sabse zyada probability wali class predict hoti hai. Iris par softmax regression ki accuracy lagbhag 96% aayi.

Q28Learning curves aur early stopping kya batate hain?

Learning curves training aur validation error ko training set ke size ya epochs ke saath plot karte hain. Dono errors zyada hon to underfitting hai, training error kam aur validation error zyada ho to overfitting hai, aur dono kam aur paas-paas hon to achha fit hai. Early stopping me validation error badhne lagte hi training rok dete hain, taaki model overfit na ho. MLP regressor par training loss 0.852 se 0.130 tak gira, lekin validation RMSE badhne par rukna sahi hota hai.

Q29California housing me feature engineering se kya fayda hua?

Naye features banaye gaye: rooms_per_household = total_rooms / households, bedrooms_per_room = total_bedrooms / total_rooms aur population_per_household = population / households. Upar ke 0.5% rooms-per-household values hatane ke baad rooms_per_household aur house value ka correlation dikhne laga, aur bedrooms_per_room price se negatively correlated nikla. Random forest ki feature importances me median_income sabse upar tha, phir latitude/longitude aur housing_median_age aaye.

Q30Cross-validation aur GridSearchCV kaise kaam karte hain?

Cross-validation me data ko folds me baant kar har fold ko baari-baari validation banakar model ki error estimate ki jati hai — kitab me 5-fold aur 10-fold dono use hue. GridSearchCV hyperparameters ke grid ke har combination ko cross-validation se try karta hai — random forest ke liye n_estimators 10, 50, 100, 200, 300 aur max_features 2, 4, 6, 8, 10, 12 try kiye gaye, aur best combination 200 trees aur max_features 6 nikla. RandomizedSearchCV grid ke bajay random combinations try karta hai aur bade search space me fast hota hai.

Q31Time-series forecasting me kaunsa model sabse behtar raha?

Bus aur train ke passengers ko 14 din aage forecast karna tha. Naive baseline ka MAE bus par 43,916 aur rail par 42,143 tha, SARIMA ka 32,041, linear regression ka 37,726, RNN ka 30,659 aur 1D CNN ka 29,273 tha. Dono series ko saath me use karne wala multivariate RNN sabse behtar raha — MAE 23,227. Sequence-to-sequence model ka MAE t+1 par 23,350 aur t+14 par 35,315 tha — jitna door forecast, utni zyada galti.

Q32Encoder-decoder translation aur beam search kaise kaam karte hain?

Encoder-decoder me encoder source sentence padhkar context vector banata hai aur decoder usse target sentence word by word generate karta hai. Portuguese-English dataset par 60,000 sentence pairs aur 10,000 words ki vocabulary ke saath BLEU score lagbhag 20 aaya. Beam search greedy ke bajay k sabse likely sequences, jaise beam width 5, ko saath rakhkar expand karta hai, jisse behtar translation milta hai. Attention se decoder har step par source ke alag-alag words par dhyaan de sakta hai, ek hi context vector ke bajay.

Q33Chatbot banane ke liye LLM ko kaise train karte hain?

Pehle base model ko instruction-following data par supervised fine-tuning (SFT) se train karte hain, phir human preferences se align karte hain — reinforcement learning from human feedback (RLHF) ya direct preference optimisation (DPO) se. Kitab me chhota model, jaise 0.5B parameters wala, chatbot dataset par fine-tune karke chat template ke saath use kiya gaya. RLHF me pehle reward model train hota hai phir policy optimize hoti hai, jabki DPO reward model ko skip karke preferences se direct policy optimize karta hai.

Q34Semi-supervised learning se MNIST accuracy kitni badhi?

Semi-supervised learning me chhote labelled set par classifier train karke unlabelled data ko pseudo-labels dete hain aur phir combined data par retrain karte hain. MNIST par har class ke sirf 50 labelled examples se accuracy lagbhag 75.8% mili, aur unlabelled data ke pseudo-labels jodne se woh badhkar lagbhag 88.4% ho gayi. Ye tab useful hai jab labels mehenga hon aur unlabelled data bahut ho.

Q35Object detection aur semantic segmentation me kya farq hai?

Object detection image me objects ke bounding boxes aur unki class predict karta hai — YOLO ek hi forward pass me boxes aur probabilities deta hai aur tiny version GPU par 1,000 frames per second se zyada chal sakta hai. Semantic segmentation har pixel ko class deti hai, jaise U-Net. Object tracking video ke frames me object ko follow karta hai, jaise DeepSORT. Classification aur localization me object ki class ke saath uski location bhi batayi jati hai.

Q36PyTorch model ko save, load aur fast kaise karte hain?

Model ka state_dict torch.save se save karte hain aur torch.load plus load_state_dict se load karte hain — poora model bhi torch.save(model) se save ho sakta hai. torch.compile(model) operations ko fuse karke training aur inference tez karta hai. GPU par wahi matrix multiplication jo CPU par 16.1 ms leta hai, sirf 549 microseconds leta hai — lagbhag 29 guna fast. DataLoaders mini-batches dete hain aur validation loop me torch.no_grad() use hota hai.
