Kitaab ek vignette se shuru hoti hai: ek data scientist jo LLMs se pehli baar 2019–2020 me research curiosity ke roop me milta hai, phir ChatGPT ke public launch ke baad wapas aata hai aur field ko poori tarah badla hua pata hai. Timeline yeh hai:

Core problem jo chapter set karta hai: model akela product nahi banata. Ek fictional company — ek chhoti online travel agency, jiski site hotels, flights aur reviews ke database par bani hai — dikhati hai ki ek single prompt travel questions ka sahi jawab dene ke liye kaafi nahi hai; jawab model ke aas-paas ek system design karne me hai.

Ek central distinction: generative model content create karta hai, jabki discriminative model sirf classify ya score karta hai. Example: travel blog ka generated summary vs ek classifier jo use sirf label karta hai.

1.2 The Foundation Model Stack — paanch layers

Kitaab modern GenAI stack ko paanch layers me present karti hai: (1) data — documents, images, structured data aur woh saare sources jinhe application ko handle karna hai; (2) foundation models — bade pretrained models, broad abilities ke saath, proprietary aur open-weight dono; (3) orchestration aur workflows — woh logic jo tools, memory aur reasoning steps ko jodti hai; (4) applications — user-facing product, jaise chatbots aur assistants; (5) evaluation aur observability — logging, metrics aur tracing, jo ek nondeterministic system ko control me rakhne ke liye chahiye.

Stack ko internet stack ke analogy se samjhaya gaya hai: application, model aur orchestration layers ek data layer aur infrastructure par rest karte hain, aur bottom layer application-data layer hai (application aur uske use ke baare me data), jabki ek infrastructure layer poore stack ko support karta hai.

1.3 Scale ke numbers — parameters, tokens, compute

Foundation-model history numbers me: models GPT-2 ke hundreds of millions parameters se GPT-3 ke 175 billion tak gaye, phir trillion-parameter-scale frontier systems tak (GPT-4 ko lagbhag 1.8 trillion parameters ke mixture-of-experts form me present kiya gaya hai). Training data early models ke tens of billions tokens se badhkar baad ke models ke liye lagbhag 13 trillion tokens tak pahunchi; compute thousands of GPU-hours se tens of millions tak badha.

1.4 Transformer step by step aur Mixture of Experts

Transformer architecture step by step samjhaya gaya hai — tokenization text ko tokens me badalti hai; embedding har token ko ek vector me badalta hai; positional encoding token ki position ki information add karta hai; stacked self-attention layers har token ko sequence ke doosre tokens ko attend karne deti hain; feed-forward networks har token ki representation ko transform karte hain; aur final layer representation ko vocabulary par probability distribution me convert karta hai. Attention ka matlab hai: har token aur har doosre token ke beech scores compute karna, phir weighted sum lena, taaki ek word ki representation uske aas-paas ke words ko reflect kare.

Mixture of Experts (MoE): model me kai specialist sub-networks ('experts') hote hain, plus ek router jo har token ko sirf kuch experts ko bhejta hai, taaki kisi ek token ke liye total parameters ka sirf ek fraction active ho. Worked example DeepSeek-V3 hai: 671 billion total parameters, per token sirf lagbhag 37 billion active, 14.8 trillion tokens par trained — concrete demonstration ki scale ko saste me khareeda ja sakta hai, model ka ek subset activate karke.

1.5 Prompting — naya interface, lekin program nahi

Prompting ko naya interface ke roop me introduce kiya gaya hai: prompt woh input hai jo model ko batata hai kya karna hai, aur model use complete karta hai. Chapter samjhata hai ki prompt ek program kyun nahi hai: wahi prompt alag outputs de sakta hai, model hallucinate kar sakta hai, aur exact behaviour ki koi guarantee nahi hai. Yahi nondeterminism wajah hai ki baaki kitaab ke patterns exist karte hain.

1.6 Decoding / sampling — temperature aur top-p

Temperature aur top-p randomness ke do main controls hain. Temperature probability distribution ko reshape karta hai — low temperature sabse likely token ko dominate karwata hai, high temperature distribution ko flat karta hai taaki rare tokens bhi likely ho jayein; top-p (nucleus sampling) sirf woh smallest set of tokens rakhta hai jinki cumulative probability p tak pahunche. Chapter ki guidance: factual kaam ke liye low temperature, creative kaam ke liye high temperature.

2. Controlling Content Style


2.1 Opening problem — RPG wala NPC


Generative model kisi bhi style, length ya tone me text produce kar dega — aur woh text bhi jo aap nahi chahte: off-brand, off-topic, bahut lamba, ya unsafe. Chapter ka running example ek role-playing game (RPG) hai, jisme ek non-player character (NPC) ko character me bolna hai, sahi voice me, aur game ki duniya ko tode bina.


2.2 Pattern 1: Content Filter


Context: model se generated content user tak pahunchta hai, aur model par bharosa nahi kiya ja sakta ki woh khud refuse karega. Problem: generated content off-brand, off-topic, irrelevant ya unsafe ho sakta hai. Solution: model aur user ke beech (ya user aur model ke beech) ek filter rakho jo content ko rules ke set ke against check kare aur jo fail ho use block, rewrite ya replace kare. Filter ek doosra model, ek classifier, rules ka set, ya inka combination ho sakta hai.


Pattern 1 — Content Filter (reconstructed from notes)reconstructed from notes
def generate_in_character(prompt):
    draft = model.generate(prompt)
    verdict = filter_model.check(draft, rules=["game world ke andar raho",
                                               "brand voice me bolo",
                                               "unsafe content nahi"])
    if verdict == "pass":
        return draft
    return filter_model.rewrite(draft)   # ya: block karke safe reply do


Chapter ki guidance: inputs aur outputs dono ko filter karo, aur filter ke decision ko auditable banao.



2.3 Pattern 2: Content Expansion


Context: application ko lamba, rich answer chahiye. Problem: model chhota, generic answer deta hai jab application ko zyada detail chahiye — jaise ek NPC jo ek location ka vivid description de. Solution: model ke chhote answer ko doosre prompt me wapas feed karo jo model se kahe use expand kare — detail, sensory language aur world-specific flavour add karte hue, facts consistent rakhte hue.


Pattern 2 — Content Expansion (reconstructed from notes)reconstructed from notes
short = model.generate("Tavern ka ek sentence me description do")
rich = model.generate(
    "Is description ko expand karo — smells, sounds, regulars ke naam: "
    + short + "  Key facts preserve karo: " + KEY_FACTS)


Warning: expansion facts se drift kar sakta hai, isliye expansion prompt me woh key facts repeat karne chahiye jo preserve karne hain. Code example: pehli call ek tavern ka one-sentence description generate karti hai, doosri call use smells, sounds aur regulars ke naamon ke saath poora paragraph bana deti hai.



2.4 Pattern 3: Content Regeneration


Context: pehli generation kaafi achhi nahi hoti. Problem: pehli generation galat tone, galat length, ya factual slip ke saath aati hai — aur user ko use accept nahi karna chahiye. Solution: content ko regenerate karo, optionally alag prompt, temperature ya model ke saath, aur attempts me se best ko rakho.

best, best_score = None, -1

3. Adding Knowledge: Bass


3.1 Opening problem — jazz bass analogy


Foundation model sirf wahi janta hai jo uski training data me tha, ek cutoff date tak, aur woh application ke private documents, products ya data ko nahi janta. Chapter ki analogy jazz bass line hai: bass woh foundation deta hai jis par baaki music khada hota hai, aur retrieval woh factual foundation deta hai jis par generation khada hota hai. Running example travel agency ke documents par question-answering system hai.


3.2 Pattern 4: Basic RAG


Context: model ko woh info chahiye jo uski training me nahi thi. Problem: model hallucinate karta hai ya outdated jawab deta hai jab usse aisi information ke baare me poochha jaye jisme woh trained nahi tha. Solution: knowledge base se relevant documents (ya passages) retrieve karo aur unhe question ke saath prompt me daalo, taaki model memory se nahi, retrieved text se jawab de.


Pattern 4 — Basic RAG, step by step (reconstructed from notes)reconstructed from notes
# 1. documents load karo
docs = load(travel_documents)
# 2. chunks me split karo
chunks = split(docs, size=500, overlap=50)
# 3. embed karo, 4. vector store me daalo
store.add(embed(chunk) for chunk in chunks)
# 5. query time: question embed karo, nearest chunks retrieve karo
context = store.search(embed(question), k=5)
# 6. prompt = question + retrieved context, phir model call karo
answer = model.generate(prompt(question, context))


Chapter ka example: chhote set of travel documents use karke model hotel ki cancellation policy ke baare me tabhi sahi jawab deta hai jab policy text retrieve ho jaye. Chapter stress karta hai ki RAG kitaab ka single sabse important pattern hai, aur uski quality retrieval step ki quality se limited hai.



3.3 Pattern 5: Semantic Indexing


Context: documents me structure hai — headings, sections, tables. Problem: keyword search woh documents miss kar deta hai jo same idea ke liye alag words use karte hain, aur chunks ki flat list source ki structure kho deti hai. Solution: aisa index banao jo meaning aur structure dono capture kare — chunks ko embed karo, metadata (source, section, page) ke saath store karo, aur semantic similarity se retrieve karo, optional re-ranking ke saath.


Pattern 5 — Semantic Indexing (reconstructed from notes)reconstructed from notes

Chapter chunking strategy bhi cover karta hai (size, overlap, section boundaries respect karna) aur metadata filtering (jaise sirf ek product line ke documents retrieve karna).



3.4 Pattern 6: Recursive Language Model (RLM)


Context: kuch sawaal kuch retrieved passages se answer nahi hote. Problem: jawab kai documents me bikhra hai, ya task ko poore corpus par reasoning chahiye — jaise 'Alexander the Great ne kaunsi battles ladi, order me, aur har ek me kya hua?' Solution: model ko ek tareeqa do jisse woh corpus par khud ko recursively call kar sake: model ek chhota program (ya sub-queries ka set) likhta hai jo documents ko padhta hai, relevant facts nikalta hai, aur answer assemble karta hai, intermediate results par model ko dobara call karte hue.


Pattern 6 — Recursive Language Model (reconstructed from notes)reconstructed from notes
def answer_distributed_question(question, corpus):
    sub_questions = model.decompose(question)   # "kaunsi battles, order me?"
    facts = []
    for sq in sub_questions:
        facts += model.search_and_extract(corpus, sq)  # recursive calls
    return model.synthesise(facts)   # 62 battles, chronological order

4. Adding Knowledge: Syncopation


4.1 Opening problem — syncopation


Ek type ke sawaal par kaam karne wala retrieval doosre type par fail ho jata hai — keyword query, conceptual query aur entities ke beech relationships ke baare me sawaal, teeno ko alag retrieval chahiye. Jazz analogy syncopation hai: interesting notes beat se hatkar aate hain, aur interesting answers obvious retrieval se bahar milte hain. Running example ek bade, changing document collection par question-answering system hai, jisme documents me text, tables aur structured records hain.


4.2 Pattern 7: Hybrid Search


Context: queries alag-alag type ki hoti hain. Problem: pure keyword search paraphrases miss kar deta hai, aur pure vector search exact terms (product codes, names, numbers) miss kar deta hai. Solution: dono chalao, aur results ko combine karo.


Chapter dono retrieval families ko detail me samjhata hai: lexical (BM25) retrieval, jo documents ko term frequency aur inverse document frequency se score karta hai, aur dense vector retrieval, jo embedding similarity se score karta hai; phir batata hai ki dono ranked lists ko kaise merge karein (reciprocal rank fusion woh method hai jo dikhaya gaya hai).


Pattern 7 — Hybrid Search, RRF fusion (reconstructed from notes)reconstructed from notes

Interview FAQs
Interview FAQs — 36 sawaal
Har pattern par interview me poochhe jaane wale sawaal, Hinglish me jawab ke saath.
Q1 RAG kya hai aur yeh hallucination ko kaise kam karta hai?
RAG — Retrieval-Augmented Generation — woh pattern hai jisme model ko jawab dene se pehle relevant documents retrieve karke prompt me diye jate hain, taaki model memory se nahi, retrieved text se jawab de. Isse hallucination kam hoti hai kyunki model ke paas ground truth hota hai, lekin retrieval galat ho to jawab bhi galat ho sakta hai — isliye retrieval quality hi RAG ki quality hai.
Q2 Basic RAG aur Recursive Language Model (RLM) me kya farq hai?
Basic RAG ek sawaal ke liye kuch most similar passages retrieve karta hai — yeh fact-based sawaalon ke liye achha hai. RLM model ko corpus par recursively kaam karne deta hai: woh task decompose karta hai, sub-questions par corpus search karta hai, aur answer synthesise karta hai. RLM tab use karo jab jawab poore corpus me distributed ho, jaise 62 battles ki chronological list.
Q3 Hybrid search kyun zaroori hai — sirf vector search kaafi kyun nahi?
Vector search meaning ke hisaab se retrieve karta hai lekin exact terms (product codes, names, numbers) miss kar deta hai. BM25 keyword search exact terms dhoondhta hai lekin paraphrases miss karta hai. Hybrid search dono chalakar reciprocal rank fusion se merge karta hai, aur fused ranking dono me se kisi ek se behtar hoti hai.
Q4 Graph indexing kab use karna chahiye aur kab nahi?
Graph indexing tab use karo jab sawaal relationships ke baare me hon — 'kaunse suppliers woh parts supply karte hain jo is product me use hote hain?' Simple fact lookup ke liye graph extra cost ke layak nahi hai; wahan basic RAG ya hybrid search kaafi hai.
Q5 Index maintenance kyun zaroori hai?
Documents badalte rehte hain — add, update, delete hote hain. Stale index galat jawab deta hai. Index ko living system ki tarah treat karo: documents version karo, sirf changed parts re-index karo, aur deleted documents ke chunks hatao.
Q6 LLM as Judge kaise kaam karta hai aur us par kitna bharosa karein?
Ek doosra model (aam taur par stronger) clear rubric ke saath pehle model ke output ko score karta hai — correctness, completeness, clarity par 0 se 1 tak. Judge ko human scores ke against calibrate karo, aur scores ko relative treat karo, absolute nahi — judge prompt variants compare karne ke liye useful hai, final truth ke liye nahi.
Q7 Reflection se answer kharab bhi ho sakta hai — phir use kyun karein?
Haan, reflection achhe answer ko bhi kharab kar sakta hai. Isliye original draft ko rakho aur best version chuno — reflection loop me har round ke baad score karo, aur maximum 3 rounds ke baad best version return karo.
Q8 DSPy prompt optimization me 0.63 se 0.74 ka matlab kya hai?
Yeh judge score hai — travel review ko short blurb me summarise karne wale task par. Initial blurb ne 0.63 score kiya, aur optimisation ke baad best blurb ne 0.74. Improvement optimisation process ka result tha, ek single hand edit ka nahi — aur optimisation held-out evaluation set par karni chahiye.
Q9 Harness engineering kya hai?
Harness model ke aas-paas ek deterministic loop hai jo steps ko control karta hai, state rakhta hai, budget enforce karta hai (maximum steps, tokens, time), aur run ko rok deta hai jab goal meet ho ya budget khatm ho. Bina harness ke multi-step agent bhatak sakta hai ya atak sakta hai.
Q10 Function calling me validation kyun zaroori hai?
Model ka tool-call output galat arguments ya missing fields ke saath aa sakta hai. Execute karne se pehle code me validate karo — galat ho to retry karo, blindly execute mat karo. Yeh security aur reliability dono ke liye zaroori hai.
Q11 Autonomous agent ko safely kaise bound karein?
Tools limited rakho, budget cap karo (maximum steps, tokens, time), aur risky actions ke liye human approval required rakho. Supervisor pattern bhi use kar sakte ho jo worker actions ko monitor aur approve kare.
Q12 Small language model kab use karein, bada model kab?
Routine tasks — classification, extraction, simple rewriting — chhote, fast, cheap models se ho jate hain. Hard reasoning, complex planning aur creative writing ke liye bade models chahiye. Task ke size ke hisaab se route karo.
Q13 Prompt caching se kitna fayda hota hai?
Jab prompts me repeated parts hote hain — lamba system prompt ya context — to caching se har request me woh dobara process nahi hota. Cost aur latency dono kam hote hain, khaas taur par jab same prefix ke saath kai requests aate hon.
Q14 Continuous batching se throughput 20× kaise badha?
Requests ek-ek karke process hone par GPU idle rehta hai. Continuous batching incoming requests ko ek saath batch karta hai taaki GPU busy rahe. Kitaab ka worked example: baseline 106.11 seconds me 0.94 samples/second thi, batching ke baad throughput 20× badhi — lekin batching latency badha sakta hai, isliye trade-off measure karo.
Q15 Degradation testing kya hai aur 2,499/2,500 ka matlab kya hai?
Degradation testing me load badha-badha kar measure karte hain ki system kab degrade hota hai. Kitaab ka worked example: 100 concurrent users par 2,499 out of 2,500 requests successful rahe, total 190.57 seconds, mean latency lagbhag 7.6 seconds. Isse pata chalta hai ki system kab aur kaise fail hota hai.
Q16 Self-check se hallucination kitni kam hoti hai?
Vectara leaderboard ke numbers: best case me hallucination rate 1.3% se 0.7% hui, aur 25th-ranked case me 4.1% se 2.4%. Self-check hallucination kam karta hai, khatm nahi karta — isliye self-check ko guardrails aur RAG ke saath combine karo.
Q17 Guardrails kitni layers me lagane chahiye?
Teen layers par: input par (user prompt check karo), output par (generated content check karo), aur tool calls par (risky actions se pehle approval). Ek layer fail ho to doosri pakde — single layer kaafi nahi hoti.
Q18 Content Filter aur Guardrails me kya farq hai?
Content Filter ek specific pattern hai — generated content ko brand, safety aur relevance ke liye filter karna. Guardrails poora defence-in-depth approach hai — input, output aur tool calls par layers. Content Filter guardrail system ka ek hissa ho sakta hai.
Q19 Content Expansion me facts drift kyun hota hai aur use kaise rokein?
Expansion karte waqt model naye details invent kar sakta hai. Roko is tarah: expansion prompt me woh key facts repeat karo jo preserve karne hain, aur expanded output ko original facts ke against check karo.
Q20 Decomposition aur Prompt Chaining me kya farq hai?
Decomposition task ko sub-tasks me split karta hai — har sub-task alag model call se solve hota hai, aur results combine hote hain. Prompt Chaining calls ko sequence me connect karta hai — ek call ka output agli call ka input banta hai. Dono ko combine bhi kar sakte ho.
Q21 Programmatic Logic kab use karna chahiye?
Jab jawab bilkul exact hona chahiye — arithmetic, totals, taxes, discounts. Model ko code likhne do jise deterministic interpreter execute kare, model se calculation karwane ke bajay. Code hi audit trail banta hai.
Q22 Structured Input me schema-first design kya hai?
Prompt likhne se pehle schema define karo — fields, types, constraints — aur model se schema fill karwao. Output ko use karne se pehle code me validate karo; validation fail ho to retry karo.
Q23 Multi-agent collaboration me roles kaise divide karein?
Har agent ko ek clear role do — researcher (facts gather kare), writer (draft likhe), critic (review kare). Shared context ke saath collaborate karwao, aur orchestrator se sequence control karo.
Q24 Agent Orchestration aur Agent Supervision me kya farq hai?
Orchestration agents ko schedule aur route karta hai — kaun kab chalega, outputs kahan jayenge. Supervision worker agents ke actions ko monitor karta hai — approve ya reject karta hai, aur galat hone par redirect karta hai. Dono ko ek saath use kar sakte ho.
Q25 Long-term memory me kya store karna chahiye aur kya nahi?
Important facts store karo — user preferences, past decisions, ongoing work. Har cheez store mat karo — sirf woh jo future sessions me relevant hoga. Memory ko retrieve karte waqt relevance ke hisaab se filter karo.
Q26 Composable workflows ki chaar properties kya hain?
Har pattern ka clear input aur output ho, patterns independently testable hon, patterns replaceable hon, aur failure ek stage tak limited rahe. In chaar properties se workflows maintainable aur testable bante hain.
Q27 Pattern language ka idea kahan se aaya hai?
Pattern language woh idea hai ki design problems ke reusable solutions ko named patterns ke roop me capture kiya jaye, jo ek doosre se judte hain. Yeh idea architecture se aaya hai, jahan patterns buildings ke liye use hote the — kitaab use generative AI applications par apply karti hai.
Q28 Har pattern ka Context-Problem-Solution-Code template kyun hai?
Template har pattern ko ek hi structure me present karta hai: kab use karein (Context), kya problem solve karta hai (Problem), solution kya hai (Solution), aur code kaisa dikhta hai (Code). Isse patterns ko compare karna aur choose karna aasan ho jata hai.
Q29 Temperature aur top-p sampling kya hai?
Yeh decoding parameters hain jo model ke output ki randomness control karte hain. Temperature zyada ho to output zyada varied aur creative hota hai; kam ho to zyada predictable. Top-p (nucleus sampling) sirf sabse likely tokens me se choose karta hai. Lab 4 me dono ko try karke dekho.
Q30 Context window kya hai aur yeh RAG ko kaise affect karti hai?
Context window woh maximum text hai jo model ek baar me dekh sakta hai. RAG me retrieved chunks ko context window me fit karna hota hai — zyada chunks daalo to window overflow ho jati hai, kam daalo to relevant info miss ho sakti hai. Isliye chunk size aur top-k ka balance zaroori hai.
Q31 LMArena leaderboard kya hai aur kitaab me iska kya use hai?
LMArena ek public leaderboard hai jahan models ko human votes se rank kiya jata hai. Kitaab me 6 April 2025 ki table di gayi hai jo dikhati hai ki us waqt kaunse models top par the — yeh model selection ke liye ek reference hai, lekin leaderboard badalta rehta hai.
Q32 MoE (Mixture of Experts) kya hai?
MoE woh architecture hai jisme model ke kai expert sub-networks hote hain, aur har token ke liye sirf kuch experts activate hote hain. DeepSeek-V3 ka example: 671 billion total parameters, lekin har token ke liye sirf 37 billion active hote hain — isse bada model efficiently chal sakta hai.
Q33 RPG example kitaab me kyun use hua hai?
RPG (role-playing game) ek running example hai jo Chapter 2 se shuru hota hai — ek NPC jo character me bolta hai, sahi voice me, aur game ki duniya ko tode bina. Yeh example content patterns (filter, expansion, regeneration) ko concrete banata hai.
Q34 Kitaab ke code repos kaun se hain?
Do repos hain: generative-ai-design-patterns (saare patterns ke code examples) aur rpg-gpt (RPG example). Dono ke links Home section ke Sources me diye gaye hain.
Q35 32 patterns ko yaad rakhne ka sabse achha tareeqa kya hai?
Patterns ko chapter-wise groups me yaad rakho — content (Ch 2), knowledge (Ch 3-4), reasoning (Ch 5), evaluation (Ch 6), tools (Ch 7), production (Ch 8), output (Ch 9), composition (Ch 10). Har pattern ka ek-line solution summary tables me diya gaya hai — unhe revise karo.
Q36 Kitaab ki sabse important baat ek line me kya hai?
Generative AI applications ko reliable banane ke liye patterns chahiye — model ki capabilities ke aas-paas engineering karo, model se perfection ki ummeed mat karo. Har pattern ek specific problem ka reusable solution hai.
