Data — Wikidata aur RDF triples

Wikidata ek Resource Description Framework (RDF) knowledge graph hai, jo Wikimedia Foundation support karta hai — Wikipedia ki tarah.

RDF format kaise kaam karta hai

Data semantic triples me hota hai — teen hisse: subject, predicate, object. Har entity ko ek Uniform Resource Identifier (URI) se represent karte hain. Predicates bhi URI hote hain jo relationships batate hain. Values ke liye literals use hote hain.

Do tarah ke triples

  • Truthy triples (entity–predicate–entity): jaise — koi film, uska director, koi vyakti.
  • Properties (entity–predicate–value): jaise — koi film, uski release date, koi tareekh.

Wikidata kyun useful hai

Information extraction kiye bina hi bahut tarah ki entities ke relationships aur properties mil jati hain — movies se lekar genetic sequence variants tak. Aage hum SPARQL (RDF query language) se Wikidata query karna dekhenge. Wikidata Query Service par try kar sakte ho.

Wikidata query — get_director aur galat SPARQL se seekh

Ab director dhoondhne wala function banate hain. Ye section book ka sabse important early lesson hai: SLM ko aisi language me query likhne ko bologe jo usne zyada dekhi hi nahi, to galat jawab milega — aur wahi measurement ki zaroorat ko samjhata hai.

Function

python
def get_director(movie):
    # first we create the prompt
    prompt = """
Please write a Wikidata query to find who is the director of "{movie}".
Return only the query, not explanation.
    """.format(movie=movie).strip()

    print("Prompt:")
    print(prompt)
    print()

    # we will use the same call from above. The temperature is set to 0.1,
    # If you want to experiment with trying to get better results,
    # add a function argument for temperature.
    response = completion(
        model="ollama_chat/llama3",
        messages=[{
            "content": prompt,
            "role": "user"
        }],
        temperature=0.1,
        api_base="http://localhost:11434"
    )

    # This query often return markdown ticks, so we remove that.
    print("Query:")
    return response.choices[0]["message"].content.strip("`").strip()

"John Carter" par kya hua

print(get_director("John Carter")) chalane par model ne ye query di:

sparql (galat output)
PREFIX wdt: <http://www.wikidata.org/prop/direct/>
SELECT ?director WHERE {
  wd:Q113745 (film) .
  film wdt:director ?director .
}

Ye valid SPARQL hai hi nahi! Lab 6 me is query ke bugs dhoondne ki practice hai.

Aisa kyun hua

  • Zyada tar models general internet par train hote hain, aur SPARQL utna popular topic nahi hai — model ne ye language zyada dekhi hi nahi hogi.
  • Wikidata ke apne idiosyncratic patterns hain (jaise director ke liye wdt:P57 property) — model unhe guess nahi kar sakta.
  • Isliye: model ko sahi tool, sahi prompt aur sahi measurement do — bina measurement ke "kaam kar gaya" kehna galat hai.

Measurement kyun zaroori hai

Jaise har machine learning kaam me, yahan bhi shuruaat measurement se hoti hai. Model chunne se pehle ye tay karna hoga ki "achha" ka matlab kya hai — aur use kaise naapa jayega.

General quality kaafi kyun nahi

Language model ki general quality — matlab sahi sequences banane ki ability — sirf ek had tak kaam aati hai. SLMs khaas isliye hote hain kyunki wo specialized hote hain — sirf domain/topic me nahi, functionality me bhi. General "bhasha" banana unke liye utna important nahi, jitna apna khaas kaam sahi karna hai.

Iska matlab kya hai

  • SLMs ke liye task-specific metrics chahiye — ye classic machine learning measurement jaisa hoga.
  • Achhi baat: aise measurements zyada seedhe aur samajhne me aasan hote hain.
  • Buri baat: task jitna novel hoga, utna hi kam chance hai ki uske liye ready dataset mile.

Classic ML metrics — Regression

Classic machine learning me metric is baat par depend karti thi ki model kis category me hai. Pehli category: regression — jab model ek floating point number predict karta hai.

Error term

Sab regression metrics error term par based hain:

formula
err_i = y_i - ŷ_i
(asli value - predicted value)

Chaar metrics

  • MAE (Mean Absolute Error): error term ke absolute value ka mean. Bade aur chhote errors ko barabar weight deta hai.
  • MSE (Mean Squared Error): error term ke square ka mean. Bade errors ko zyada saza deta hai (square hone se).
  • RMSE (Root Mean Squared Error): MSE ka square root — isse metric wapas original unit me aa jati hai, samajhna aasan hota hai.
  • R² (R-squared): R² = 1 - MSE / VAR[Y] — model target variable ki variance ka kitna hissa samjha paya. 1 ke kareeb = behtar.

Classic ML metrics — Classification

Doosri category: classification — jab model ek categorical value predict karta hai. Iske metrics confusion matrix par based hote hain.

Confusion matrix (binary classification)

Actual: PositiveActual: Negative
Predicted: PositiveTrue Positive (TP)False Positive (FP)
Predicted: NegativeFalse Negative (FN)True Negative (TN)

Book me is jagah ek confusion matrix image ka placeholder hai — asal image PDF me nahi thi, isliye upar wali table hi uska kaam karti hai.

Precision aur Recall

  • Precision = TP / (TP + FP) — model ne jitni positive predictions ki, unme se kitni asal me positive thi. Ye batata hai ki positive prediction kitni reliable hai. Range 0–1.
  • Recall = TP / (TP + FN) — asal positives me se kitne pakde gaye. Ye batata hai ki positive dhoondhne ki kitni likelihood hai. Range 0–1.
  • F-score = precision aur recall ka harmonic mean — jab ek hi metric chahiye ho to ye use karo.

AUC / ROC curve

Binary classification ke liye ek aur common metric: Area Under the ROC Curve (AUC). Pseudo-probability wale models ki predictions ko sort karo, har threshold par recall aur false positive rate nikalo, curve banao, uske neeche ka area nikalo. Range 0–1. Coin flip se decide karoge to AUC 0.5 milega — isliye 0.5 se upar hona hi predictive power ki pehli nishani hai.

Ranking

Ranking category ke metrics bhi aam taur par precision aur recall par based hote hain, halanki aur popular metrics bhi hain. Jaise-jaise naye tasks aayenge, waise-waise best metric tay karenge.

SLMs ka sabse bada developer fayda yahi hai: unke toote hue tasks seedhe measurable hote hain. LLM ka purpose general aur broad hota hai, isliye unki measurement bahut alag tareeke se hoti hai.

Pre-training measurement — cross-entropy

Large aur small language models teen parts me train hote hain: pre-training, supervised fine-tuning (SFT), aur alignment. Pehla part dekhte hain.

Pre-training kya hai

Is phase me model seekhta hai ki diye gaye input sequence ke baad sahi sequence kaise banaye. Ye phase aam taur par cross-entropy use karta hai.

Cross-entropy ka matlab

Cross-entropy ek distribution ka doosri distribution se "surprise" hai. Model ne kisi context ke liye tokens ki ek distribution seekh li hai, par asli distribution alag hai. Loss function ke roop me ye metric minimize karti hai ki model asal token se kitna surprised hota hai:

formula
H(p, q) = Σ p_i log q_i
(p = asli distribution, q = model ki distribution)

Kyunki hum scratch se koi model nahi banayenge, humein pre-training karne ki zaroorat nahi hai. Humari dilchaspi doosre part — alignment — me zyada hai. Lekin cross-entropy samajhna isliye zaroori hai kyunki SFT me bhi wahi loss use hota hai.

Lab 4 me cross-entropy ko haath se chalao: model jab sahi token ko 90% probability de to surprise kam hota hai, aur 1% de to surprise bahut zyada.

LLM-as-a-Judge

LLMs se nikli sabse surprising cheezon me se ek: LLMs ek doosre ko judge kar sakte hain — aur carefully kiya jaye to khud ko bhi. Matlab bahut si situations me human labels bahut kam ya bilkul nahi chahiye.

Validate karna zaroori hai

Ye concept abhi naya hai, isliye apni measuring methodology ko validate karna chahiye. Check karo ki tumhara LLM-as-a-Judge asal me kitna reliable hai. Iske liye aisa data chahiye jisme inputs, outputs aur outputs ke labels hon — hamare case me synopses + genres (inputs), subgenres (outputs), aur subgenres sahi hain ya nahi (labels).

Golden labels kaise laayein

  • Human labeling: baseline ke hisaab se labels aur kam kar sakte ho. Meta-measurement ke liye har subgenre ke sau examples nahi chahiye — kuch examples per subgenre kaafi hain, labeling ek order of magnitude kam ho jati hai. Caveat: baseline 90%+ cases me sahi ho to few hundred examples me negative examples kaafi nahi milenge.
  • Sample check: judge ke judgments ka ek sample (positives aur negatives me balanced) human se check karwao — isse pata chalega ki judgment system kaisa kaam kar raha hai.

Judge SLM bhi ho sakta hai

"LLM-as-a-Judge" kehte hain, par judge koi SLM bhi ho sakta hai — judgment task ke liye specialized. Wahi model judge bhi ho to dhyaan rakhna: judging task ko actual task se clearly alag rakho, warna model apna hi kaam repeat karke khud ko affirm kar dega.

Do prompts ka farak

Subgenre assignment prompt: "Please identify if the given movie belongs to one of the given subgenre. Genre, possible subgenres, title, synopsis — Subgenre(s):"

Subgenre judgment prompt: "Please rate, 1–5, how well the given movie fits within the subgenre description. Title, synopsis, genre, subgenre, subgenre description — Rating (1–5):"

Doosre prompt me subgenre description judne se input data kaafi badal jata hai — model wahi kaam repeat nahi karta. LLM-as-a-Judge karne ke use-case aur resources ke hisaab se bahut tareeke hain.

SLM (Small Language Model) chhota aur focused hota hai — ek khaas kaam, jaise query likhna ya classify karna, ke liye banta hai. LLM general hota hai — open-ended chatbot jaise kaam ke liye. SLM commodity machine par chalta hai, sasta hai, aur uske chhote tasks ko seedha measure kiya ja sakta hai. LLM zyada capable hai par mehenga aur bhaari hai.


Q02 SLM kab use karna chahiye, LLM kab?
Jab kaam well-defined aur constrained ho — jaise ek tool call karna, text ko query me badalna, ya classification — to SLM behtar hai: sasta, tez, local chal sakta hai. Jab kaam open-ended ho, jaise lambi creative writing ya broad reasoning, to LLM chahiye. Book ka usool: pehle task define karo, phir decide karo ki SLM kaafi hai ya LLM chahiye.


Q03 Theoros project kya hai?
Theoros poori book ka throughline project hai — movies dhoondhne, movies ke baare me seekhne aur movie-related tools chalane wala ek agentic system. Naam Greek shabd theoros se aaya hai (spectator/envoy). Movies isliye chune gaye kyunki data public hai, domain knowledge nahi chahiye, aur data ka mix milta hai — structured, free-text, aur aage non-text bhi.


Q04 Miniconda kyun chahiye? pip se kaam nahi chalega?
Miniconda sirf Python packages nahi, poora environment manage karta hai — Python version samet. Is book me Python 3.12 ka alag environment (slmbook) banta hai taaki project ki dependencies system Python se takraayein nahi. pip packages install karta hai, par environment isolation aur non-Python dependencies ke liye conda behtar hai. Sirf Google Colab use karne walon ko Miniconda nahi chahiye.


Q05 conda environment alag kyun banate hain?
Alag environment se har project ki dependencies alag rehti hain — ek project ka numpy version doosre ko todta nahi. Book me `conda create --name slmbook python=3.12` se environment banta hai aur `conda activate slmbook` se use karte hain. Book ke repo me YAML file bhi hai jisse environment ek command me setup ho jata hai.


Q06 Python Data Science Stack me kaunsi libraries hain aur kyun?
NumPy (arrays/matrices), SciPy (scientific algorithms), pandas (data frame/series), Matplotlib (plotting), scikit-learn (ML algorithms aur metrics), Jupyter (notebooks). Inke alawa NLTK (NLP algorithms) aur NetworkX (graphs) bhi use hongi. Ye stack isliye kyunki data ko load, analyze aur measure karne ke liye yahi neev hai — SLM ke aas-paas ka saara kaam inhi se hota hai.


Q07 MCP kya hai? Ye framework hai ya protocol?
Dono. MCP (Model Context Protocol) ek open-source standard hai jo AI applications ko external systems se jodta hai — ye protocol hai. Saath me MCP servers aur clients banane wali library ko bhi MCP kehte hain. Isse prompts, tools aur data organize karne ka standard tareeka milta hai aur boilerplate kam ho jata hai.


Q08 MCP aur normal API call me kya farak hai?
Normal API call me tum har tool ke liye alag code likhte ho. MCP me tools, prompts aur data ek standard structure me organize hote hain — ek baar MCP server ban gaya to koi bhi MCP-compatible application use istemal kar sakti hai. Matlab integration ka kaam ek baar, fayda har jagah. Isi liye Theoros pehle simple MCP client se test hoga.


Q09 LiteLLM kyun use karte hain?
LiteLLM alag-alag providers ke models ko ek hi interface se call karne deta hai — model badlo, code wahi rahe. Kuch models ke paas OpenAI-compatible API nahi hoti, LiteLLM un tak bhi pahuncha deta hai. Iska Proxy Server deployment me custom behavior aur secrets management bhi sambhalta hai. Install `pip install litellm` se hoti hai kyunki ye mainline conda repo me nahi hai.


Q10 OpenRouter kya hai aur kab use karein?
OpenRouter ek platform hai jahan ek hi API key se bahut saare hosted models milte hain. Is book me iska use local models ko hosted models se compare karne ke liye hai. Agar security ya privacy ki chinta nahi hai aur local run nahi kar sakte, to OpenRouter ek viable option hai — aur LiteLLM se local se hosted par switch karna sirf ek chhota config change hai.


Q11 Docker kyun chahiye? Bina Docker ke nahi chalega?
Docker containers me Ollama ya vector database jaise servers bina system par install kiye chalaye ja sakte hain — environment clean rehta hai aur setup repeatable hota hai. Bina Docker bhi chal sakta hai (Ollama seedha install karke), par book ka setup Docker par hai. Sirf Google Colab use karne walon ko Docker install nahi karna hai.


Q12 LibreChat kya hai? Claude Desktop se behtar kyun?
LibreChat ek open-source chat application hai jisse apni application ko asli chat scenario me test kar sakte ho. Claude Desktop me MCP integration hai, par wo Anthropic models ke liye bana hai. LibreChat kisi ek model family se bandha nahi hai aur isme bhi MCP integration hai — isliye is book me yahi chuna gaya. Ye localhost:3080 par chalta hai.


Q13 Ollama kya karta hai?
Ollama language models ko locally chalane ka framework hai aur unhe OpenAI-compatible API ke through available karata hai. Is book me Ollama Docker container me chalta hai (port 11434). LiteLLM se `api_base="http://localhost:11434"` aur `model="ollama_chat/llama3"` likh kar local model ko call karte hain — bina kisi hosted API ke.


Q14 Ollama aur OpenRouter me kya farak hai?
Ollama models ko tumhari apni machine par chalata hai — data bahar nahi jata, cost nahi hai, par GPU/hardware chahiye. OpenRouter hosted models deta hai — hardware nahi chahiye, par data bahar jata hai aur API cost lagti hai. Book me dono hain: local kaam Ollama se, comparison ke liye hosted OpenRouter se.


Q15 Wikipedia data RAG ke liye kaise use hota hai?
Wikipedia articles ko RAG (Retrieval Augmented Generation) system ke context ke roop me use karte hain — model sawaal ka jawab dene se pehle relevant articles padhta hai. Theoros me Wikipedia se movie attributes aur relationships bhi nikaale jayenge. Individual articles ke liye Wikipedia search wala MCP agent use hoga; poora dump dumps.wikimedia.org se milta hai.


Q16 Wikidata kya hai? RDF triple kya hota hai?
Wikidata ek RDF knowledge graph hai. Data semantic triples me hota hai: subject–predicate–object. Har entity ek URI hoti hai, predicate bhi URI hota hai (relationship batata hai), aur values ke liye literals hote hain. Do tarah: truthy triples (entity–predicate–entity) aur properties (entity–predicate–value). Isse bina information extraction ke relationships aur properties mil jati hain.


Q17 SPARQL kya hai aur Wikidata par query kaise likhte hain?
SPARQL RDF data ko query karne ki language hai — jaise SQL relational data ke liye hota hai, waise SPARQL knowledge graphs ke liye. Theoros me director dhoondhne ke liye SPARQL query chahiye thi, aur book ke example me model ne galat SPARQL likha — kyunki SPARQL internet par kam hai aur model ne use zyada dekha nahi. Isi liye measurement zaroori hai.


Q18 Hugging Face se dataset kaise download karte hain?
Hugging Face client library se: `conda install -c huggingface -c conda-forge datasets` aur `huggingface_hub[cli]` install karo, account setup karo, phir datasets search karke download karo. Hugging Face par models ka version control, dataset leaderboards aur model hosting bhi milta hai — task-specific datasets measure karne ke liye ye sabse achha source hai.


Q19 Kaggle datasets ko API se kyun nahi download karte?
Kaggle par har dataset ki licensing aur access requirements alag ho sakti hain — kuch datasets ke liye alag terms accept karne hote hain. Isliye book me API ke bajaye manually download karne ki salah di gayi hai. Kaggle account setup chahiye, aur platform par datasets, models aur notebook-based development sab milta hai.


Q20 MAE, MSE, RMSE me kya farak hai? Kab kaunsa?
Teeno regression metrics error term par based hain. MAE error ke absolute value ka mean hai — bade aur chhote errors ko barabar tolta hai. MSE error ke square ka mean hai — bade errors ko zyada saza deta hai. RMSE MSE ka square root hai — metric wapas original unit me aa jati hai, isliye samajhna aasan hota hai. Outliers se bachna ho to MAE, bade errors par sakhti chahiye to MSE/RMSE.


Q21 R² kya batata hai?
R² = 1 − MSE / VAR[Y]. Ye batata hai ki model target variable ki variance ka kitna hissa samjha paya. R² = 1 matlab perfect fit, 0 matlab model sirf mean predict karne jitna achha hai. Negative R² ka matlab model mean se bhi bura hai. Ye ek relative metric hai — do models ko compare karne me kaam aata hai.


Q22 Precision aur recall me kya farak hai? Dono kab matter karte hain?
Precision = TP / (TP + FP): positive predictions me se kitni sahi thi — prediction ki reliability. Recall = TP / (TP + FN): asal positives me se kitne pakde gaye — pakadne ki likelihood. Spam filter me precision matter karta hai (galat spam tag mehenga hai), aur cancer detection me recall (miss karna mehenga hai). Dono ke beech trade-off hota hai.


Q23 F-score kya hai? Harmonic mean hi kyun?
F-score precision aur recall ka harmonic mean hai. Harmonic mean isliye kyunki ye chhoti value ko zyada saza deta hai — agar precision 0.9 aur recall 0.1 hai, to simple average 0.5 hota, par harmonic mean ~0.18 hota hai, jo sahi tasveer deta hai. Jab ek hi number se model judge karna ho to F-score use karte hain.


Q24 AUC 0.5 ka matlab kya hai?
AUC ROC curve ke neeche ka area hai. Coin flip karke decide karoge to AUC 0.5 milega — matlab model me koi predictive power nahi hai. 0.5 se upar hona predictive power ki pehli nishani hai, aur 1.0 perfect hai. AUC threshold-independent metric hai, isliye alag-alag thresholds par compare karne me useful hai.


Q25 Cross-entropy kya hai? 'Surprise' se kya matlab?
Cross-entropy ek distribution ka doosri distribution se surprise hai: H(p, q) = Σ p_i log q_i. Model ne kisi context ke liye tokens ki distribution seekhi hai; asli token aane par model kitna surprised hota hai, wahi loss hai. Sahi token ko 90% probability de to surprise kam, 1% de to surprise bahut zyada. Training me isi loss ko minimize karte hain.


Q26 SFT kya hai? Pre-training se kaise alag hai?
Pre-training me model sirf sahi sequence banana seekhta hai. SFT (Supervised Fine-Tuning) me model labeled sequences se behtar aur useful sequences banana seekhta hai — jaise instruction follow karna. Dono me cross-entropy loss hi use hota hai kyunki dono wahi network update karte hain. SFT kamzor ho to outputs ki quality girti hai aur har task kharab hota hai.


Q27 RLHF aur DPO me kya farak hai?
RLHF me pehle human feedback se reward model seekhte hain, phir reinforcement learning se model optimize karte hain. DPO (Direct Preference Optimization) reinforcement learning ke bajaye supervised learning use karta hai — reward model seekhne ki zaroorat hi nahi padti, isliye zyada efficient aur simple hai. Dono ka goal ek hi hai: model ko human preferences aur safety rules se align karna.


Q28 Task-specific metric kyun zaroori hai? General benchmark kaafi kyun nahi?
General benchmarks jaise MMLU-Pro model ki baseline quality batate hain, par tumhara use-case usse alag ho sakta hai. Theoros me movie subgenre assign karna hai — iske liye per-label F-score chahiye, MMLU-Pro nahi. SLMs ke tasks chhote aur focused hote hain, isliye unhe classic ML metrics se seedha measure karna behtar hai.


Q29 MMLU-Pro kya hai? MMLU se kaise alag hai?
MMLU-Pro Massive Multitask Language Understanding ka augmented version hai. MMLU alag domains ke multiple-choice questions ka set hai. MMLU-Pro is dataset ko 12,000 questions aur 10 answer choices tak badhata hai, aur zyada reasoning-mangne wale questions rakhta hai. Ye model ki general reasoning aur Q&A capability test karta hai.


Q30 GPQA kya test karta hai?
GPQA physics, chemistry aur biology me 448 multiple-choice questions ka benchmark hai. Questions is tarah design kiye gaye hain ki experts (PhD students) ke liye bhi mushkil hon. Ye model ki scientific reasoning dikhata hai. Theoros jaise movie use-case ke liye ye seedha relevant nahi hai, par baseline ke roop me useful hai.


Q31 HELM kya hai aur ye doosre benchmarks se kaise alag hai?
HELM Stanford CRFM ka project hai jo foundational models ko evaluate karta hai. Inki website par leaderboards hain jinme MMLU-Pro aur GPQA bhi shamil hain. HELM me multi-modal models aur domain-specific models ke benchmarks bhi hain — isliye ek hi jagah kai benchmarks ka comparison mil jata hai.


Q32 Custom dataset banate waqt pehla step kya hota hai?
Pehla step hai task ko clearly define karna — kya predict karna hai, label set kya hai, metric kya hogi, columns kya chahiye, aur kitna data chahiye. Theoros ke example me: subgenre classification, label set film academy article se, genres Wikidata se, synopses Wikipedia se, metric per-label F-score aur macro-average F-score, ideal size 3,000–6,000.


Q33 Human labeling itni mehengi kyun hai? Cost kaise kam karein?
Har task me 10–15 seconds lagte hain — poora dataset label karne me 100–140 hours. Cost kam karne ke tareeke: task ko confirmation task banao (prediction confirm karna), preference dataset banao, sirf few thousand examples label karo (10–14 hours), aur sample ko genre ke hisaab se stratify karo taaki bias na aaye. Har nayi functionality par ye cost phir se lagti hai.


Q34 LLM-as-a-Judge kya hai? Is par bharosa kaise karein?
LLM-as-a-Judge me ek language model doosre model ke outputs ko judge karta hai — isse human labels kam ya zero ho jate hain. Bharosa karne ke liye methodology validate karni hoti hai: golden labels wala data chahiye, ya judge ke judgments ka balanced sample human se check karwana hota hai. Judge SLM bhi ho sakta hai, bas judging task ko actual task se clearly alag rakho.


Q35 Qwen3-4B, Llama-3.2-3B aur Phi-4-mini me se kaunsa chunoon?
Tool use aur agentic kaam (Theoros) ke liye Qwen3-4B — 262K context aur sabse strong scores (MMLU-Pro 69.6, GPQA 62.0). Chat aur summarization ke liye Llama-3.2-3B — isi ke liye design hua hai. Phi-4-mini synthetic-data experiment aur building-block ke liye achha hai. Aakhir me apne task ka apna dataset aur metric hi faisla karega — benchmark sirf baseline hai.


Q36 gpt-oss-20b ke 21B parameters hone ke bawjood 3.6B active ka matlab kya hai?
gpt-oss-20b Mixture-of-Experts (MoE) model hai: total 21B parameters hain, par har token ke liye router 32 experts me se sirf top-4 select karta hai — isliye har token par sirf 3.6B parameters active hote hain. Fayda: zyada learned parameters ka gyaan, bina zyada compute cost ke. Isi liye MoE models bade hokar bhi efficiently chalte hain.
