Preface — Ye kitab kis liye hai

ChatGPT ke launch se lekar LangChain tak — build karna hi seekhne ka tareeka hai.

Shuruaat — November 2022 se

Kitab November 2022 me ChatGPT ke launch se shuru hoti hai — paanch din me ek million users, aur 2024 tak LLM par bane chatbots ko hundreds of millions log istemal kar rahe the. Lekhakon ka kehna hai ki us point ke baad koi bhi software project language models ko ignore nahi kar sakta. Usse do saal pehle, October 2022 me LangChain aaya — tab in models par applications banana abhi bhi mushkil tha; LangChain ne use aasan banaya.

Timeline ka point ye hai: koi ek dominant design nahi hai — isliye practical tareeka ye hai ki build karo, dekhna seekho, aur iterate karo.

LLM kya hai — do tarah ke models

Large language model ek aisi application hai jo natural-language input leti hai aur natural-language output deti hai. Do tarah bataye gaye hain: general-purpose (chat) models — wide usefulness ke liye; aur reasoning models — careful, multi-step kaam ke liye. Dono text lete hain, aur aaj kal kai models images aur audio bhi lete hain.

Central idea — prompt template

Kitab ka central building idea hai prompt template — variables ke liye placeholders wala reusable prompt. Example: English-to-French translation ka instruction, jisme source language aur target language ke liye placeholders hain — har sentence ke liye fill karo. Prompt templates prompts ko repeatable aur testable banate hain.

Nau prompting techniques — ek jhalak

  • Zero-shot prompting — bina worked examples ke task do, jaise sentence ko French me translate karo ya names ki list ko do groups me sort karo.
  • Few-shot prompting — pehle worked examples do, jaise English-to-French ki do lines, phir teesri maango.
  • Chain-of-thought — model se step by step reasoning dikhane ko kaho, jaise "Let's think step by step."
  • Self-consistency — kai baar reasoning karke kai answers generate karo, aur jo answer sabse zyada baar aaye use lo — accuracy badhane ke liye.
  • ReAct (Reason + Act) — model reason karta hai, phir tool call karke act karta hai, result observe karta hai, phir dobaara reason karta hai — jab tak jawab ke liye kaafi na ho.
  • Tool calling / function calling — model khud choose karta hai ki kaunsa external function invoke karna hai, aur uske arguments deta hai.
  • Structured outputs — model ko ek defined structure me jawab dene par majboor karo, taaki output ko program seedha istemal kar sake.
  • Prompt engineering aur system prompts — system prompts role aur tone set karte hain, user prompts task dete hain, assistant prompts conversation continue karte hain; clarity aur specificity par zor hai.
  • Retrieval-augmented generation (RAG) — pehle relevant information retrieve karo aur prompt me daalo, taaki model apne documents se jawab de, sirf training data se nahi.

Kis ke liye hai, aur kaise padhein

Kitab data engineers, ML engineers, data scientists, software developers aur product managers ke liye hai, aur Python aur basic ML knowledge assume karti hai. Poori kitab ek hi product par bani hai — ek personal product-knowledge chatbot, ek "digital brain", jo aage chalkar "Ask Your Books" naam ki ek working storefront application ban jata hai. Ch 1 — LLM Fundamentals with LangChain

Agla token predict karna, embeddings, LangChain ke teen layers, aur pehla chatbot.

LLM kaise kaam karta hai — agla token predict karna

Language model pehle ke tokens ko dekhkar agla token predict karta hai. Token woh unit hai jise model padhta hai. Kitab English alphabet se samjhati hai: sirf 26 letters hain, to 26³ = 17,576 possible three-letter sequences hain — lekin words random strings se bahut kam hote hain, isliye model har possibility ko yaad karne ke bajay training data se patterns seekhta hai. Words aur sentences ke liye wahi reasoning, bahut bade scale par.

Training ke teen stages

1 · PretrainingBahut zyada text se general patterns seekhna
→
2 · Supervised fine-tuningLabelled examples (jaise Q&A form) par training
→
3 · AlignmentRLHF jaise techniques se helpful aur appropriate responses sikhana

Har step par output agle token par ek probability distribution hota hai; model usme se sample karta hai — isliye sampling settings badalne se result ki randomness badalti hai.

Embeddings — matlab ko vector me badalna

Embeddings text ki vector representations hain jo meaning preserve karti hain. Semantically similar texts ke similar vectors hote hain, aur similarity cosine measure se measure hoti hai — kitab me likha formula: cos(θ) = (A · B) / (||A|| ||B||), jisme similar texts ka score 1 ke paas hota hai.

Model landscape — open-weight vs closed-weight

Models ko do tarah se baanta gaya hai: open-weight models aur closed-weight (proprietary) models — aur context window, capabilities aur price ke hisaab se bhi. Kitab GPT-4, GPT-4o, Claude, Mistral aur Llama ko compare karti hai, aur batati hai ki kuch evaluations me Llama 3.1 70B ne GPT-4o ke barabar score kiya — jo cost ke liye matter karta hai. Salah: jab chhota, sasta model kaafi ho, use wahi chuno; context length check karo; aur yaad rakho ki landscape tezi se badalta hai.

LayerKya hai
LangChain Core (base)Abstractions, LCEL, runnable interface, output parsing aur callbacks ke tools
Integrations (beech me)Jaise OpenAI aur Anthropic ke saath integrations
Application layers (upar)LangGraph, LangGraph Platform, LangSmith aur LangChain Hub

Kitab ka code LangChain 0.3 aur LangGraph 0.2 istemal karta hai, aur chetavni deta hai ki APIs badal sakte hain.

Development environment setup

Python virtual environment banao, packages install karo, aur keys ko ".env" file me store karo. Keys jo naam liye gaye hain: OPENAI_API_KEY, ANTHROPIC_API_KEY, TAVILY_API_KEY, LANGSMITH_API_KEY aur LANGSMITH_TRACING. Examples Python 3.11, ek "llm_app" folder, ek requirements file aur ek notebook istemal karte hain.

Prompt engineering — prompts brittle hote hain

System prompt model ka role aur tone set karta hai. Kitab chetavni deti hai ki prompts brittle hote hain — wording me chhota sa badlav result badal sakta hai — isliye prompts ko test aur version karna chahiye.

Pehla chatbot banana

Code pehle chat model banata hai — ChatOpenAI(model="gpt-4o-mini", temperature=0) — phir ChatPromptTemplate.from_messages se prompt banata hai: ek system message jaise "You are a helpful assistant" aur placeholder wala human message — phir chain karta hai: prompt | model | StrOutputParser(). Example prompt "Hello, how are you?" hai aur kitab me diya gaya jawab hai: "I'm just a computer program, so I don't have feelings, but I'm here and ready to help you with whatever you need! How can I assist you today?" Point ye hai ki wahi chain alag-alag inputs ke saath dobaara istemal ho sakti hai.

Pehla chatbot — chain (notes se banaya gaya)Python — notes se banaya gaya, verbatim nahi
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant"),
    ("human", "{question}"),
])
chain = prompt | model | StrOutputParser()
print(chain.invoke({"question": "Hello, how are you?"}))

Chatbot me intelligence add karna

Wahi chain ek specific sawal par chalayi jati hai — is kitab ke baare me: "Is kitab ka title kya hai?" — jawab milta hai "Learning LangChain". Ek aur detailed example kitab ke baare me poochhta hai aur jawab me kitab ka naam aata hai. Kitab inhe isliye dikhati hai ki model apni training knowledge se jawab de sakta hai — lekin ye apne documents se jawab dene jaisa nahi hai — aur isiliye aage RAG ki zaroorat padegi.

LCEL ke fundamentals

Pipe operator "|" runnables ko jodta hai. Runnable interface: invoke ek input ke liye, batch kai inputs ke liye, stream token-by-token output ke liye, aur ainvoke / abatch / astream unke asynchronous versions.

Ch 2 — RAG Part I: Indexing Your Data

Load → split → embed → store — indexing hi RAG ki neev hai.

RAG kya hai — aur kyun chahiye

RAG (retrieval-augmented generation): pehle apne data se relevant information retrieve karo, phir use model ko do taaki woh us data par grounded jawab generate kar sake. Zaroorat isliye hai kyunki model ki training knowledge ek cutoff date par fixed hoti hai, usme private ya recent data nahi hota, aur woh hallucinate kar sakta hai. RAG grounding se hallucination kam karta hai — lekin khatm nahi karta.

RAG system design karna

User ke sawal se shuru karo: kaunsa data chahiye, use kaise index karenge, kaise retrieve karenge, aur jawab kaise generate hoga. Kitab zor deti hai ki jawab ki quality retrieval ki quality par depend karti hai.

Document loaders

Examples kitab ka apna text PyPDFLoader se PDF se load karte hain, aur web pages WebBaseLoader se. Loader Document objects deta hai — har ek me page_content aur metadata jaise source aur page number.

Text splitters — chunking

Code RecursiveCharacterTextSplitter istemal karta hai — chunk_size=1000, chunk_overlap=200. Trade-off samjho: chunks bahut bade hon to relevance dilute ho jati hai; bahut chhote hon to context kho jata hai; aur overlap boundaries ke across continuity preserve karta hai.

Indexing pipeline — chunk + embed (notes se banaya gaya)Python — notes se banaya gaya, verbatim nahi
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)
chunks = splitter.split_documents(docs)

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
store = Chroma.from_documents(chunks, embeddings, persist_directory="./chroma")
retriever = store.as_retriever()

Embeddings models

Kitab OpenAIEmbeddings (model text-embedding-3-small) istemal karti hai. Embeddings semantic similarity capture karte hain — "LangChain" ke baare me query ka matlab alag wording wale text se bhi match karega.

Vector stores

Code documents aur embeddings se Chroma store banata hai (persist_directory ke saath), phir usse retriever banata hai. Similarity search "What is LangChain?" par chalayi jati hai aur sabse relevant chunks milte hain.

Ch 3 — RAG Part II: Chatting with Your Data

Retriever + prompt + model — aur RAGAS scores jo batate hain ki system kitna bharosemand hai.

RAG chain banana

RAG chain banti hai retriever + prompt template + model se. Prompt model ko instruct karta hai ki woh sirf retrieved context se jawab de, aur jab context me jawab na ho to keh de ki use nahi pata. Chain: relevant documents retrieve karo → unhe context ke roop me daalo → jawab generate karo.

Jawab generate karna

Kitab chain ko "What is LangChain?" aur is kitab ke baare me sawalon par chalakar dikhati hai — jawab retrieved text se aate hain. Zor is par hai ki retrieved source ko cite karo aur usse aage ki information add mat karo.

Testing — jawab dena chahiye ya mana karna chahiye

Examples chain ko un sawalon par test karte hain jinke jawab use dene chahiye, aur un par bhi jinke jawab use mana karna chahiye — jaise documents me na ho aisa topic. Expected behaviour hai refusal ya "I don't know" — hallucinated jawab nahi.

Retrieval ko behtar karna — paanch tareeke

  • Hybrid search — keyword (BM25) aur vector search combine karo, taaki exact terms aur meaning dono matter karein.
  • Query rewriting / expansion — user ke sawal ko dobaara likho taaki matching behtar ho.
  • Reranking — cross-encoder se retrieved documents ko relevance ke hisaab se dobaara order karo.
  • Metadata filtering — jaise source ya date ke hisaab se filter karo.
  • Multi-query retrieval — sawal ke kai versions generate karo aur results combine karo.

Generation ko behtar karna

Behtar prompt istemal karo, few-shot examples add karo, factual jawabon ke liye temperature low rakho, aur jahan answer format matter karta ho wahan structured outputs istemal karo. Model ko ye bhi batana chahiye ki woh sirf context istemal kare.

Deploy karna

RAG application ek simple web interface me wrap ki jati hai — sawal ke liye text input, aur jawab aur uske sources ke liye display area. Kitab batati hai ki wahi chain API ke through bhi serve ki ja sakti hai.

Ch 4 — LangGraph se Chatbot me Memory

StateGraph + MemorySaver + thread_id — chatbot jo naam yaad rakhta hai.

Chatbot me memory kya hai

Memory chatbot ki woh ability hai jo conversation ke pehle ke turns ko yaad rakhti hai. Bina iske har message ko naya samjha jata hai; iske saath model pehle kahi gayi baat — jaise naam ya preference — ka reference de sakta hai.

Table 4-1 — Types of memoryKya hai
Short-term memoryCurrent conversation, message history me rakhi hui
Long-term memorySessions ke across persist karne wali jaankari, jaise user preferences aur facts

Kitab working memory, episodic memory aur semantic memory me bhi farak batati hai, aur kehti hai ki LangGraph ki checkpointing persistence layer deti hai.

Ek stateless model call ki koi memory nahi hoti — isliye application ko history store karke dobaara supply karni padti hai.

Memory wala chatbot banana

Code ek stateful graph banata hai — ek node jo model ko call karta hai, aur ek checkpointer jo har step ke baad state save karta hai. State messages ki list hai, aur har naya user message model ko call karne se pehle usme append hota hai — taaki model poori history dekhe.

LangGraph — nodes, edges, checkpointers

Key concepts: state (nodes ke beech pass hone wala data), nodes (kaam karne wale steps), edges (steps ke beech transitions), aur checkpointers (storage jo state ko persist karta hai).

Implementation

Code ek StateGraph define karta hai — messages state ke saath — ek node add karta hai jiska naam "chatbot" hai jo messages par model invoke karta hai, start se us node tak aur us node se end tak edge add karta hai, graph ko MemorySaver checkpointer ke saath compile karta hai, aur phir use config me thread_id ke saath invoke karta hai, jaise {"configurable": {"thread_id": "1"}}. Wahi thread_id follow-up messages ke liye reuse hota hai — history preserve rehti hai; alag thread_id nayi conversation shuru karta hai.

Memory wala chatbot — StateGraph + checkpointer (notes se banaya gaya)Python — notes se banaya gaya, verbatim nahi
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver

graph = StateGraph(MessagesState)
graph.add_node("chatbot", lambda state: {"messages": [model.invoke(state["messages"])]})
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)

app = graph.compile(checkpointer=MemorySaver())
config = {"configurable": {"thread_id": "1"}}
app.invoke({"messages": [("user", "Hi, my name is Rahul.")]}, config)

Memory test karna

Example conversation: user kehta hai "Hi, my name is Rahul." Assistant greeting ke saath jawab deta hai. User phir poochhta hai "What is my name?" aur assistant jawab deta hai "Rahul" — dikhata hai ki naam retain hua. Doosra test alag thread istemal karta hai aur dikhata hai ki wahan naam yaad nahi hai — isse confirm hota hai ki memory thread se scoped hoti hai.

Ch 4 ka saar: LangGraph stateless chain ko stateful application bana deta hai; checkpointing + thread_id per-conversation short-term memory dete hain — aur wahi mechanism aage ke chapters ki long-term memory aur complex graphs ki neev hai. Chapter ka summary chat messages ko summarise karne ka bhi zikr karta hai (lambi histories ko context limits me rakhne ke liye), halanki detailed summarisation code ek alag section ke roop me notes me nahi diya gaya.

Ch 5 — Cognitive Architectures with LangGraph

Single-agent, multi-agent, aur human-in-the-loop — LangGraph ke primitives.

Cognitive architecture kya hai

Cognitive architecture woh design hai jo batata hai ki agent kaise sochta aur act karta hai — kaunse steps, kis order me, kya yaad rakhta hai, aur kab human intervene karta hai. Kitab simple chain se compare karti hai — jo steps ko fixed order me chalati hai — aur agent se, jo apne steps khud decide karta hai.

Single-agent system

Code ek graph banata hai — ek node jo model ko call karta hai, ek node jo tools ko call karta hai, aur ek conditional edge jo tool call chahiye hone par model par wapas route karta hai aur na chahiye hone par end par. Agent tab tak loop karta hai jab tak uske paas jawab ke liye kaafi information na ho.

Multi-agent system

Example me ek supervisor, ek researcher aur ek coder hain. Supervisor decide karta hai ki kis worker ko call karna hai, worker apna task karke report karta hai, aur supervisor ya to dobaara delegate karta hai ya final jawab deta hai.

Human-in-the-loop

Graph sensitive action se pehle rukta hai — jaise tool execute karne se pehle — aur human ke approve ya reject karne ka wait karta hai. Ye control rakhne ka tareeka hai jab agent asli actions le sakta hai.

Ch 5 ka saar: LangGraph primitives deta hai — nodes, edges, conditional edges, parallel branches, subgraphs aur human-in-the-loop interrupts — jinse single-agent aur multi-agent cognitive architectures bante hain.

Ch 6 — Agent Architecture

ReAct loop aur tool calling — aur kyun tool ke output ko blindly trust nahi karna chahiye.

Agent kya hai

Agent ek aisa system hai jo language model ko istemal karke decide karta hai ki aage kya karna hai — fixed sequence follow karne ke bajay. Uske paas model, tools, memory aur ek loop hota hai: plan, act, observe, repeat.

ReAct framework

Kitab ek worked example se samjhati hai: ek prasiddh vyakti ki mrityu ke samay umar kitni thi? Agent pehle sochta hai ki use janm aur mrityu ki dates chahiye, phir search karke act karta hai, observe karta hai ki vyakti ka janm 4 July 1872 ko hua aur mrityu 5 January 1933 ko hui, phir sochta hai ki use umar calculate karni hai, phir calculator call karke act karta hai, aur result observe karta hai.

Kitab ka key numerical example — dhyaan se padho: Sirf saal ghata dena — 1933 − 1872 = 61 — GALAT hai, kyunki mrityu 5 January ko hui thi, janmdin 4 July se pehle — isliye vyakti ne abhi 61 saal poore nahi kiye the. Sahi umar 60 hai. Chaining

FAQs — Interview Sawal-Jawab

Current-era interviews ke liye 36 sawal-jawab — har chapter se, kitab ke concepts, numbers aur examples par based. Har jawab khud me poora hai.

Q1LLM kaise kaam karta hai? Token kya hai?
LLM pehle ke tokens ko dekhkar agla token predict karta hai. Token text ka ek tukda hai — ek word, word ka hissa, ya punctuation. Kitab ka example: 26 letters se 26³ = 17,576 possible three-letter sequences bante hain, lekin words random strings se kam hote hain — isliye model patterns seekhta hai, har possibility yaad nahi karta.
Q2Pretraining, fine-tuning aur alignment me kya farak hai?
Pretraining me model bahut zyada text se general patterns seekhta hai. Supervised fine-tuning me use labelled examples (jaise Q&A form) par train karte hain. Alignment me RLHF jaise techniques se use helpful aur appropriate responses sikhate hain. Har step par output agle token par ek probability distribution hota hai.
Q3Embeddings kya hain? Cosine similarity ka formula kya hai?
Embeddings text ki vector representations hain jo meaning preserve karti hain — similar texts ke similar vectors hote hain. Cosine measure: cos(θ) = (A · B) / (||A|| ||B||) — similar texts ka score 1 ke paas hota hai. Lab 1 me token aur context-window ka hisaab karke dekho.
Q4Open-weight aur closed-weight models me kya farak hai?
Open-weight models ke weights openly available hote hain (jaise Llama), closed-weight proprietary hote hain (jaise GPT-4, Claude). Kitab batati hai ki kuch evaluations me Llama 3.1 70B ne GPT-4o ke barabar score kiya — jo cost ke liye matter karta hai. Salah: jab chhota sasta model kaafi ho, use wahi chuno; context length check karo.
Q5LangChain ke teen layers kaunse hain?
Base layer LangChain Core hai — abstractions, LCEL, runnable interface, output parsing aur callbacks. Beech me integrations hain — jaise OpenAI aur Anthropic. Upar application layers hain — LangGraph, LangGraph Platform, LangSmith aur LangChain Hub. Kitab ka code LangChain 0.3 aur LangGraph 0.2 par hai.
Q6LCEL kya hai? Pipe operator kaise kaam karta hai?
LCEL (LangChain Expression Language) components ko pipe operator | se chain karta hai — prompt | model | output_parser. Example: ChatPromptTemplate → ChatOpenAI (gpt-4o-mini, temperature=0) → StrOutputParser. Runnable interface: invoke ek input ke liye, batch kai ke liye, stream token-by-token ke liye, aur ainvoke / abatch / astream async versions.
Q7Pehla chatbot kaise banta hai? 'Hello, how are you?' ka jawab kya aaya?
ChatOpenAI(model='gpt-4o-mini', temperature=0) banao, ChatPromptTemplate.from_messages se prompt banao (system: 'You are a helpful assistant', human: placeholder), phir chain karo: prompt | model | StrOutputParser(). 'Hello, how are you?' par kitab me diya gaya jawab hai: 'I'm just a computer program, so I don't have feelings, but I'm here and ready to help you...' Wahi chain alag inputs se dobaara chal sakti hai.
Q8RAG kya hai aur ye hallucination kyun kam karta hai?
RAG (retrieval-augmented generation): pehle apne data se relevant information retrieve karo, phir use model ko do taaki woh grounded jawab de. Zaroorat isliye hai kyunki model ki knowledge cutoff date par fixed hoti hai, usme private/recent data nahi hota, aur woh hallucinate kar sakta hai. Grounding se hallucination kam hota hai — khatm nahi hota.
Q9RAG indexing pipeline ke chaar steps kaunse hain?
Load → split → embed → store. Load: PyPDFLoader se PDF, WebBaseLoader se web pages — Document objects (page_content + metadata). Split: RecursiveCharacterTextSplitter, chunk_size=1000, chunk_overlap=200. Embed: OpenAIEmbeddings, text-embedding-3-small. Store: Chroma, persist_directory ke saath, phir retriever banao.
Q10Chunk size 1000 aur overlap 200 kyun? Trade-off kya hai?
Chunks bahut bade hon to relevance dilute ho jati hai; bahut chhote hon to context kho jata hai; overlap boundaries ke across continuity preserve karta hai. Lab 2 me chunk size aur overlap badalkar dekho — kitne chunks bante hain aur har chunk me kya hai.
Q11Token limits kya hain? GPT-4o, Claude 3.5 Sonnet aur Llama 3.1 ke kitne hain?
Table 2-2 ke hisaab se: GPT-4o — 128,000 tokens; Claude 3.5 Sonnet — 200,000 tokens; Llama 3.1 — 128,000 tokens. Lab 1 me apne text ka token estimate aur context-window usage dekho. Rule of thumb: 1,000 tokens ≈ 750 words.
Q12RAG chain kaise banti hai? 'I don't know' kab kehna chahiye?
Retriever + prompt template + model. Prompt model ko instruct karta hai ki woh sirf retrieved context se jawab de, aur jab context me jawab na ho to keh de ki use nahi pata. Testing me chain ko un sawalon par bhi test karo jinke jawab use mana karna chahiye — expected behaviour refusal ya 'I don't know' hai, hallucinated jawab nahi.
Q13Retrieval behtar karne ke paanch tareeke kaunse hain?
Hybrid search (BM25 keyword + vector), query rewriting/expansion, reranking (cross-encoder se reorder), metadata filtering (source/date ke hisaab se), aur multi-query retrieval (sawal ke kai versions, results combine karo). Generation behtar karne ke liye: behtar prompt, few-shot examples, factual jawabon ke liye low temperature, aur structured outputs.
Q14RAGAS metrics kya hain? Kitab ke example scores kya hain?
Paanch metrics: faithfulness, answer relevancy, context precision, context recall, answer correctness. Kitab ke example scores (Table 3-3, Ch 10 me dobaara): faithfulness 0.85, answer relevancy 0.92, context precision 0.78, context recall 0.88, answer correctness 0.81. Lab 5 me in sliders se average aur verdict nikalo.
Q15Chatbot me memory kya hai? Short-term aur long-term memory me farak?
Memory chatbot ki ability hai jo pehle ke turns ko yaad rakhti hai. Short-term memory current conversation hai (message history me); long-term memory sessions ke across persist karti hai (preferences, facts). Kitab working, episodic aur semantic memory me bhi farak batati hai; LangGraph ki checkpointing persistence layer deti hai.
Q16LangGraph me StateGraph, checkpointer aur thread_id kaise kaam karte hain?
StateGraph messages state ke saath banta hai; ek 'chatbot' node messages par model invoke karta hai; START → chatbot → END edges hote hain; graph MemorySaver checkpointer ke saath compile hota hai. Invoke config me thread_id dete hain, jaise {'configurable': {'thread_id': '1'}}. Wahi thread_id reuse karo to history preserve rehti hai; alag thread_id nayi conversation shuru karta hai. Lab 7 me dono threads try karo.
Q17Memory test ka example kya tha? Naam kaise yaad raha?
User kehta hai 'Hi, my name is Rahul.' Assistant greeting deta hai. User poochhta hai 'What is my name?' — assistant jawab deta hai 'Rahul'. Doosra test alag thread me dikhata hai ki wahan naam yaad nahi hai — memory thread se scoped hoti hai. MemorySaver in-memory hai — process restart hote hi history gayab; production ke liye persistent checkpointer chahiye.
Q18Cognitive architecture kya hai? Chain aur agent me farak?
Cognitive architecture design hai ki agent kaise sochta aur act karta hai — kaunse steps, kis order me, kya yaad rakhta hai, kab human intervene kare. Simple chain steps ko fixed order me chalati hai; agent apne steps khud decide karta hai. LangGraph primitives: nodes, edges, conditional edges, parallel branches, subgraphs, human-in-the-loop interrupts.
Q19Single-agent aur multi-agent system me kya farak hai?
Single-agent me ek agent tools ke saath loop karta hai — model node, tools node, conditional edge. Multi-agent me supervisor agent workers (researcher, coder) ko delegate karta hai — supervisor decide karta hai kis ko call karna hai, worker report karta hai, supervisor dobaara delegate karta hai ya final jawab deta hai.
Q20Human-in-the-loop kyun zaroori hai?
Graph sensitive action se pehle rukta hai — jaise tool execute karne se pehle — aur human ke approve ya reject ka wait karta hai. Ye control rakhne ka tareeka hai jab agent asli actions le sakta hai. System prompt me 'stop and ask' rule bhi isi liye hota hai.
Q21Agent kya hai? Plan-act-observe loop samjhao.
Agent ek system hai jo LLM ko istemal karke decide karta hai ki aage kya karna hai — fixed sequence ke bajay. Uske paas model, tools, memory aur loop hota hai: plan, act, observe, repeat. ReAct cycle hai: Thought → Action → Observation → Thought, aur aise hi chalta hai jab tak jawab ke liye kaafi na ho.
Q22Umar wala example samjhao — 60 sahi hai ya 61?
Vyakti ka janm 4 July 1872 ko hua, mrityu 5 January 1933 ko hui. Sirf saal ghatao to 1933 − 1872 = 61 milta hai — lekin ye GALAT hai, kyunki mrityu janmdin (4 July) se pehle hui thi, isliye 61 saal poore nahi hue the. Sahi umar 60 hai. Model pehle 60 deta hai; calculator jo sirf saal ghata-ta hai, 61 deta hai — isiliye tool ke output ko interpret karo, blindly trust mat karo. Lab 4 me khud hisaab karke dekho.
Q23Tool calling kaise kaam karta hai? bind_tools kya hai?
Tools @tool decorator se Python functions se bante hain; model se bind_tools se bind karte hain. Model structured tool call deta hai (naam + arguments), application tool chalati hai, aur result ToolMessage ke roop me model ko wapas milta hai. LangGraph me model node aur tools node conditional edge se jude hote hain.
Q24Tool call fail ho to kya karna chahiye?
Error catch karo, model ko batao ki kya galat hua, aur use retry karne ya doosra tool chunne do — crash mat karo. Example: search kuch na de, ya calculator ko invalid input mile. Error handling hi loop ko robust banati hai.
Q25Reflection kya hai? 'The Little Prince' wala example samjhao.
Reflection me agent draft banata hai, phir critic node use accuracy aur style ke liye review karta hai, phir writer revise karta hai — loop tab tak jab tak draft kaafi achha na ho ya limit na aa jaye. Example: 'The Little Prince' par essay. Ye bina bada model liye quality behtar karne ka tareeka hai.
Q26Planning aur ReAct me kya farak hai?
Planning me planner pehle task ko steps me todta hai, executor har step karta hai, aur step fail ho to planner plan revise karta hai. ReAct ek-ek step plan karta hai — pehle se poora plan nahi banata. Research task planning ka example hai; umar wala sawal ReAct ka.
Q27Multi-agent patterns kaunse hain? Supervisor pattern kya hai?
Table 7-1 ke hisaab se: supervisor (ek central coordinator), hierarchical (levels me delegation), peer-to-peer (agents seedha baat karte hain), aur doosre patterns. Supervisor pattern me researcher jaankari gather karta hai, coder/writer output banata hai, supervisor coordinate karta hai; agents shared state se communicate karte hain.
Q28Chaining, parallelization aur routing me kya farak hai?
Chaining: steps sequence me, har ek agle ko feed karta hai — jab har step pehle wale par depend kare. Parallelization: independent steps ek saath — latency kam hoti hai. Routing: router request ko sahi specialist ko bhejta hai — general, code ya research — cost bachti hai kyunki bada model sirf jab zaroorat ho tab istemal hota hai.
Q29Orchestrator-workers aur evaluator-optimizer kya hain?
Orchestrator-workers: orchestrator task ko subtasks me todta hai, workers ko assign karta hai, results combine karta hai — jaise research task topic ke hisaab se split. Evaluator-optimizer: ek model output generate karta hai, doosra evaluate karta hai aur feedback deta hai — Ch 7 wali reflection ka hi general roop.
Q30Double texting kya hai aur ye risky kyun hai?
Double texting matlab doosra message bhejna jab model abhi pehle ka jawab generate kar raha ho. Ye model ko confuse kar sakta hai aur tokens waste kar sakta hai agar doosra message context badal de. Sirf tab istemal karo jab tasks independent hon.
Q31Prototype product kyun nahi hota? Deploy se pehle kya karna chahiye?
Deploy se pehle application ko test karo, prompts aur models ko version karo, dependencies pin karo, aur secrets ko code ke bahar store karo. LangGraph Platform hosting, scaling aur Studio interface deta hai; Docker deployment ko machines ke across reproducible banata hai; production vector store ke liye Supabase with pgvector istemal hota hai.
Q32langgraph.json me kya hota hai? Supabase kyun istemal hota hai?
langgraph.json configuration file hai jo graph, uski dependencies aur environment variables ka naam deti hai. Supabase with pgvector extension production vector store hai — development ke local Chroma store ki jagah. Code Supabase se URL aur key se connect hota hai, embeddings ke liye table banata hai, aur wahan vectors store/retrieve karta hai.
Q33Testing kyun continuous process hai? RAGAS aur LangSmith kya karte hain?
LLM outputs non-deterministic hote hain — wahi prompt alag answers de sakta hai. Isliye testing ek baar ka check nahi, evaluation → monitoring → improvement ka loop hai. RAGAS metrics deta hai, LangSmith tracing, datasets aur evaluation runs deta hai. Loop: evaluate → failures dhoondho → data/chunking/retrieval/prompt fix karo → re-evaluate — sirf bada model lena nahi.
Q34Production me kya monitor karna chahiye? Security me kya dhyaan rakhein?
Latency, token usage, cost, error rates aur user feedback track karo; problems par LangSmith tracing se individual runs inspect karo. Security: authentication, authorisation, input validation, API keys ki protection — keys ko client code me expose mat karo, prompt injection se bacho, aur model ko bina checks ke untrusted code ya data access mat do.
Q35LLMs ka future kya hai? Responsible AI me kya aata hai?
Kitab predict karti hai: chhote, saste aur zyada capable models, zyada multimodal models, zyada agents, aur models ko tools/data ke saath combine karke applications. Bottleneck model capability se application design ki taraf shift hoga. Responsible AI: bias, fairness, privacy, transparency, accountability — harmful outputs test karo, user data protect karo, users ko batao ki woh AI se baat kar rahe hain.
Q36Shuru kaise karein? Kitab ka practical plan kya hai?
Ek real problem chuno, minimal version banao, real users se test karo, evaluate karo, aur iterate karo. Companion repository aur LangChain documentation se aage badho. Kitab ka aakhri sandesh: seekhne ka tareeka build karna hai — responsible tareeke se, evaluation aur user feedback ke saath.
