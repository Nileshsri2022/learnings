Ch 1 — The Process Is Your Edge

Edge kahan rehta hai? Edge model ya dataset mein nahi hai — edge process mein hai: tum kaise define karte ho, test karte ho, validate karte ho aur deploy karte ho. Conviction evidence nahi hoti; ek backtest jo "achha lagta hai" woh evidence nahi hai jab tak usko banane wala process sound na ho.

Where the edge lives

  • Edge ek repeatable advantage hai jo costs ke baad bhi survive kare.
  • Workflow ek loop hai: trading setup define karo → learning task define karo → features banao → model karo → simulate karo → deploy karo → monitor karo → jo seekha woh wapas setup mein daalo.
  • Har stage par ek decision gate hai; gate par failure ka matlab hai wapas jao — usko paper over mat karo.

Four regime classes

Poori book mein chaar regime classes use hoti hain: Risk-On, Risk-Off, Caution aur Recovery/Crisis. (Book ke regime labels chapter ke hisaab se thode vary karte hain; Chapter 16 inko precisely define karta hai.) Regimes sirf "bull/bear" nahi hain — ye volatility, correlation aur trend se define hote hain, aur ye badal dete hain ki kaunse factors kaam karte hain.

Factors

Book value, growth, size, momentum, quality, low-volatility aur doosre factors introduce karti hai. Ek factor ek claim hai — ek persistent, economically motivated return source — sirf ek backtest artefact nahi.

Key lesson: momentum tab tak kaam karta hai jab tak woh reverse na ho; drawdowns premium ki keemat hain; aur process — model nahi — woh cheez hai jo ek achhe backtest ko live loss banne se rokti hai.

Ch 3 — Market Microstructure

Market andar se kaise kaam karta hai — liquidity, order book, bars, jumps aur data cleaning. Microstructure woh jagah hai jahan trading ki cost paida hoti hai, aur jahan se bahut saare signals bhi aate hain.

Liquidity aur trading ki cost

  • Spread, depth aur resiliency; adverse selection, inventory costs.
  • Order types: market, limit, stop, hidden/iceberg, pegged, post-only.
  • Intraday volume U-shaped hai: pehle aur aakhri 30 minutes mein har ek mein daily volume ka 15–17% hota hai, jabki midday ke aadhe ghante mein lagbhag 2.6% — lagbhag 6 guna zyada.

Market data: L1, L2, L3

  • L1 (best bid/ask), L2 (depth), L3 (individual orders); TAQ, NBBO, mid-price / last / close conventions.
  • Paanch data sources compare kiye gaye hain (ITCH, DataBento, IEX, ek data vendor ka TAQ, minute bars, 61 columns).
  • Latency arbitrage: lagbhag 1 opportunity per minute per symbol, 5–10 microseconds tak chalti hai, lagbhag 0.5 basis points ki value.
  • Off-exchange trading 2019 mein 37% se badh kar early 2020s mein 50% se zyada ho gaya.

Ch 5 — Synthetic Financial Data

Jab real data kam ho, expensive ho ya private ho, to synthetic data banao — lekin sirf tab jab woh real data jaisa behave kare. Synthetic data real data ka replacement nahi hai, ek complement hai.

Synthetic data kya hai

  • Taxonomy: fully synthetic, partially synthetic, hybrid, augmented.
  • Use cases: rare events (crises, jumps, tail risk), privacy-preserving sharing, backtesting, stress testing.
  • Quality: distributional similarity, correlation preservation, tail behaviour, temporal structure.
  • Methods: statistical models, copulas, GANs, diffusion models, LLM-based generation.

GANs (TimeGAN) aur diffusion

  • TimeGAN ka test: discriminator accuracy 68%, AUC 0.87 — matlab synthetic data real se distinguishable hai. Generator 5,000 epochs tak train kiya gaya, phir bhi difference bacha raha — yeh mode collapse ka sign hai.
  • Diffusion models GANs se zyada stable train hote hain, lekin slow hain. VAEs stable hain lekin blurry outputs dete hain.
  • LLM-based generation (jaise GReaT): LLM ko tabular data generate karne ke liye train kiya jata hai; lekin mode collapse aur hallucinated values ka risk rehta hai.
  • Synthetic data = augmentation, replacement nahi. Real data par validate karo.

Privacy aur differential privacy

  • Privacy budget (epsilon) aur utility ke beech trade-off; epsilon badhane se accuracy badhti hai lekin privacy kam hoti hai.
  • Re-identification risk: kuch cases mein synthetic data bhi real records ko reveal kar sakta hai.
  • Example: ek bank ka synthetic credit data — 1 million rows, 10 columns; privacy budget epsilon = 1.0 par accuracy lagbhag 85%, epsilon = 0.1 par lagbhag 60%.

Evaluation — sirf "looks good" kaafi nahi

  • Distributional metrics: KS test, Wasserstein distance, Jensen-Shannon divergence.
  • Correlation preservation: real vs synthetic correlation matrices compare karo.
  • Downstream task: synthetic data par train kiya model real data par test karo — agar performance drop hota hai to synthetic data kaam ka nahi hai.

Key lesson: synthetic data ka use tab karo jab real data scarce ho ya privacy issue ho — lekin hamesha real data par validate karo. Agar synthetic data real data se distinguishable hai, to usko training mein use karna dangerous hai.

Ch 6 — Strategy Research Framework

Modelling se pehle setup: ek strategy ek contract hai — uske terms, uska benchmark, uska decision point. Bina contract ke backtest ka koi matlab nahi hai.

Strategy contract

  • Ek strategy contract mein hota hai: universe, signal, execution rules, costs, risk limits.
  • Setup → Hypothesis → Test → Decision: pehle hypothesis likho, phir test karo. Agar pehle data dekha aur phir hypothesis banayi, to woh backtest nahi, data mining hai.
  • Baseline: har strategy ko ek simple baseline se compare karo — jaise 10-ETF momentum (Sharpe lagbhag 0.6–0.7).

Walk-forward aur CPCV

  • Walk-forward validation: train → validate → test, phir window aage badhao. Isse time-series leakage avoid hota hai.
  • Combinatorial Purged Cross-Validation (CPCV): training aur test ke beech purge gap rakho, taaki overlapping information leak na ho.
  • Embargo: test set ke baad ek gap rakho — taaki model ne test period ki information na dekhi ho.

Multiple testing

  • Agar tum 100 strategies test karte ho, to kuch to sirf chance se achhi dikhengi. Multiple testing correction (jaise Bonferroni ya Benjamini-Hochberg) use karo.
  • Deflated Sharpe Ratio: Sharpe ratio ko multiple testing ke liye adjust karo.
  • Figure 6.1: walk-forward validation diagram.
  • Figure 6.2: CPCV diagram — purge aur embargo ke saath.
Key lesson: ek strategy ka backtest tabhi meaningful hai jab uska setup pehle se define ho. Agar setup baad mein banaya gaya, to backtest ek self-fulfilling prophecy hai.

Ch 7 — Defining The Learning Task

Strategy se learning problem kaise banaye — labels, horizon aur evaluation metric hi decide karte hain ki model kya seekhega. Galat label = galat model.

Labels

  • Fixed-horizon labels: jaise 21-day forward return. SPY 21-day labels: 248,436 labels → effective sample 11,830 (overlapping labels ki wajah se effective sample chhota hota hai).
  • Triple-barrier labels: profit target, stop loss, aur time limit — jo pehle hit ho woh label.
  • Meta-labelling: pehle ek primary model (jaise momentum) se signal lo, phir ek secondary model se us signal ko filter karo (sahi/galat).
  • Label leakage: agar label mein future ki information hai to model "too good" dikhega — lekin live mein fail hoga.

Information Coefficient (IC)

  • IC = prediction aur realised return ke beech correlation. IC > 0.05 generally achha mana jata hai; IC ceiling lagbhag 0.08 hai (Chapter 20).
  • t-statistic > 3.0 ka rule: IC ka t-stat 3 se zyada hona chahiye taaki woh statistically significant ho.
  • Figure 7.1: label construction diagram.
  • Figure 7.2: IC vs horizon — IC horizon ke saath decay karta hai.

Causality

  • Correlation ≠ causation. Ek feature jo past mein kaam karta tha, woh future mein kaam nahi karega agar uska causal mechanism nahi hai.
  • Granger causality, causal graphs, aur do-calculus — Chapter 15 mein detail mein.

Features hi signal hain — price, volume, carry, fundamental aur cross-sectional features kaise banaye, aur kaunse estimators use karein. Feature engineering mein hi asli edge chhupa hota hai.

Price aur volume features

  • Returns: log returns, cumulative returns, volatility-adjusted returns.
  • Momentum: 12-1 momentum (last 12 months, last month exclude karo), 6-1, 3-1.
  • Mean reversion: z-score, Bollinger Bands, RSI.
  • Volume: volume-weighted average price (VWAP), on-balance volume, volume imbalance.

def sharpe_ratio(returns, risk_free=0.04):
    """Annualised Sharpe ratio."""
    excess = returns - risk_free
    return excess.mean() / returns.std() * (252 ** 0.5)

# Example: 12% return, 18% vol, 4% risk-free

Result yahan aayega.

def walk_forward(n, train=1000, test=250, purge=21):
    """Walk-forward folds: train -> purge -> test, phir window aage."""
    folds = []
    start = 0
    while start + train + purge + test <= n:
        folds.append((start, start + train,
                      start + train + purge,
                      start + train + purge + test))
        start += test
    return folds

def allocator_weights(vols, method="equal"):
    """Equal, inverse-vol ya inverse-variance weights."""
    import numpy as np
    vols = np.array(vols, dtype=float)
    if method == "equal":
        w = np.ones_like(vols) / len(vols)
    elif method == "inv_vol":
        w = (1.0 / vols)
        w = w / w.sum()
    else:  # inverse variance
        w = (1.0 / vols ** 2)
        w = w / w.sum()
    return w

    """RAGAS-style scores ka simple average aur verdict."""
    scores = [faithfulness, relevancy, precision, recall]
