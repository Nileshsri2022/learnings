Chapter 1 — Introduction

Machine learning ki zaroorat isliye padi kyunki hand-written rules toot jate hain — jab task me bahut saare cases, exceptions ya badalta hua input ho, to har rule haath se likhna possible nahi hota. Examples se seekha hua model naye cases par generalise karta hai. Examples: spam filtering, image recognition, aur aise systems jinhe data badalne par adapt karna hota hai.

Machine learning kis tarah ke problems solve kar sakta hai

Kitab ki vocabulary pehle samajh lo — ye words poori kitab me aayenge:

  • Sample / data point — ek row (jaise ek flower).
  • Feature — ek measured property (ek column).
  • Target — wo quantity jise predict karna hai.
  • Supervised learning — labelled examples se known target predict karna. Classification discrete label deta hai (jaise iris ki species); regression continuous number deta hai (jaise ghar ka price).
  • Unsupervised learning — bina target ke structure dhoondhna: clustering similar points ko group karta hai; dimensionality reduction / manifold learning data ko compress ya visualise karta hai.

Apna task aur apna data jaano

Model se pehle business ya scientific goal se shuru karo, sahi metric chuno, modelling se pehle data ko dekho, aur model aur evaluation chunte waqt end goal ko dimaag me rakho.

Pehla application: Iris species classify karna

Meet the Data

load_iris se milta hai: 150 samples, 4 features (sepal length, sepal width, petal length, petal width — cm me) aur 3 species (setosa, versicolor, virginica). X ek 150×4 feature matrix hai; y me integer labels 0, 1, 2 hain, aur target_names se species ke naam milte hain. Pehle 5 rows print karne par pehli row hai [5.1, 3.5, 1.4, 0.2] label 0 (setosa) ke saath.

Measuring Success: Training aur Testing Data

Data ko do hisson me baanto: training set (fit karne ke liye) aur test set (generalisation judge karne ke liye — ye model ne kabhi nahi dekha hota). train_test_split with random_state=0 se milta hai: 112 training aur 38 test samples (75% / 25%). Jo model sirf training data ko rat-ta hai, wo test set par fail hoga; unseen data par accuracy hi asli goal hai.

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split

iris_dataset = load_iris()
X_train, X_test, y_train, y_test = train_test_split(
    iris_dataset['data'], iris_dataset['target'], random_state=0)

# X_train: 112 samples, X_test: 38 samples (75% / 25% split)

First Things First: Look at Your Data

Model banane se pehle data ko dekho. Pair plot (Figure 1-1) me saare feature pairs ek dusre ke against plot kiye jate hain, species ke hisab se rang diye jate hain. Isse dikhta hai ki setosa clearly alag hai, jabki versicolor aur virginica overlap karte hain — aur petal measurements species ko sepal measurements se behtar separate karte hain.

Building Your First Model: k-Nearest Neighbors

Pehla model: KNeighborsClassifier with n_neighbors=1. Steps simple hain:

  1. Estimator banao: knn = KNeighborsClassifier(n_neighbors=1)
  2. Fit karo: knn.fit(X_train, y_train) — model training data ko store kar leta hai.
  3. Predict karo: knn.predict(X_new)

Figure 1-2 dikhata hai ki ek naya flower measurement apne single nearest training point se classify hota hai — jo training point sabse paas hai, uski species naye point ki species ban jati hai.

Making Predictions

Naya sample X_new = [[5, 2.9, 1, 0.2]] predict karne par milta hai class 0 (setosa) — printed prediction array hai [0] aur predicted species name hai "setosa".

Evaluating the Model

knn.score(X_test, y_test) se test accuracy milti hai 0.97 (97%) — matlab 38 me se 37 test flowers sahi. Training accuracy isse zyada hoti hai; ye gap overfitting vs generalisation ka pehla sign hai. Ek aur baat: ek single test score sirf ek estimate hai — is par poora bharosa mat karo, Chapter 5 me iska sahi tareeka (cross-validation) aayega.

from sklearn.neighbors import KNeighborsClassifier

knn = KNeighborsClassifier(n_neighbors=1)
knn.fit(X_train, y_train)

X_new = [[5, 2.9, 1, 0.2]]
prediction = knn.predict(X_new)   # array([0]) -> "setosa"

print("Test set score: {:.2f}".format(knn.score(X_test, y_test)))
# Test set score: 0.97  (37 of 38 test flowers correct)

Summary aur Outlook

Poora workflow ye hai: load / inspect data → split → fit → predict → evaluate. Is chapter ka sabse bada lesson: model choice, data representation aur evaluation kisi ek algorithm se zyada matter karte hain.

Chapter 2 — Supervised Learning

Supervised learning me labelled examples se seekhte hain. Classification ek class label predict karta hai (binary ya multiclass); regression ek real number predict karta hai. Ek hi model family ke aksar classifier aur regressor dono versions hote hain.

Generalization, Overfitting aur Underfitting

  • Underfitting — model itna simple hai ki training pattern bhi capture nahi kar pata (training aur test accuracy dono low).
  • Overfitting — model training noise ko rat leta hai (training accuracy high, test accuracy low).
  • Generalisation — naye data par performance. Yehi asli metric hai.

Figure 2-1 me classic U-shaped test-error curve dikhti hai: complexity badhne par pehle test error girta hai, phir badhne lagta hai. Figure 2-2 me wahi data par teen fits dikhte hain — too-simple, well-fitting, aur too-complex.

Model Complexity vs Dataset Size

Rule simple hai: zyada data → zyada complex model chal sakta hai. Kam data ho to simple, regularised models behtar generalise karte hain.

Sample Datasets (is chapter ke)

forge (26 points, 2 classes, 2 features), wave (40 points, 1 feature, regression), cancer (569×30, binary), Boston Housing (506×13, regression) — plus synthetic blobs / moons / circles illustrations ke liye.

k-Nearest Neighbors

Classification: k sabse paas wale training points ka majority vote. Regression: unke targets ka average. Forge data par k=1 se jagged boundary banti hai (Figure 2-3), k=3 se smoother (Figure 2-4). Cancer data par accuracy k badhne ke saath pehle badhti hai phir girti hai — peak k=5–7 ke aas-paas. Wave regression me k=1, 3, 9 compare kiye gaye (Figures 2-8 to 2-10): bada k prediction ko smooth karta hai.

Strengths: simple, training time zero, kam assumptions. Weaknesses: prediction slow, bahut features ya sparse data par kharab, scaling sensitive. Key parameter: n_neighbors.

Linear Models

Regression me y ko features ka weighted sum + intercept fit kiya jata hai; coefficients coef_ me, intercept intercept_ me hota hai. Ordinary least squares (OLS) wave data par deta hai R² training ~0.66, test ~0.68; Boston Housing par training R² 0.75, test 0.66 ek run me.

  • Ridge (L2): alpha badhne par coefficients zero ki taraf shrink hote hain. Figure 2-14 me coefficients shrink hote aur training/test scores cross hote dikhte hain; alpha=1 aur alpha=10 compare kiye gaye.
  • Lasso (L1): coefficients ko exactly zero kar sakta hai — matlab feature selection bhi karta hai. alpha=1 par Boston ke sirf kuch features ke non-zero coefficients bachte hain.
  • Classification: logistic regression aur LinearSVC ek linear decision boundary seekhte hain; forge par boundary ek seedhi line hoti hai (Figures 2-18, 2-19), aur cancer dataset par logistic regression se ~0.95 test accuracy milti hai. Multiclass one-vs-rest se handle hota hai.

Strengths: fast, interpretable coefficients, large sparse data par achha. Weaknesses: extra features ke bina non-linear relations nahi seekh sakta; scaling sensitive. Key parameter: alpha (regularisation strength; SVMs me C).

Naive Bayes Classifiers

Har class ke liye feature frequencies count karta hai, ye assume karke ki features class diye hone par independent hain. GaussianNB continuous data ke liye, MultinomialNB aur BernoulliNB counts / binary data ke liye. Cancer par accuracy ~0.94. Strengths: bahut fast, achha baseline, high-dimensional text par achha. Weaknesses: independence assumption aksar galat hoti hai; calibration kharab. Key parameter: alpha (smoothing).

Decision Trees

Features par yes/no tests ki sequence — ek tree banta hai; leaves pure hote hain jab unme ek hi class ho. Cancer par max_depth=4 wala tree ~0.95 test accuracy deta hai. Complexity control: max_depth, max_leaf_nodes, min_samples_leaf. Tree export_graphviz se visualise hota hai (Figures 2-29, 2-30). feature_importances_ batata hai kaunsi feature sabse zyada matter karti hai — cancer tree me sabse important features hi splits dominate karte hain. Strengths: interpretable, scaling ki zaroorat nahi, mixed data handle karta hai. Weaknesses: aasani se overfit karta hai, chhote data changes par unstable. Key parameters: max_depth, max_features.

Ensembles of Decision Trees

  • Random forests: bahut saare trees ka average — har tree bootstrap sample aur random feature subset par train hota hai. Cancer par 100 trees ka forest ~0.97 test accuracy deta hai, aur feature importances single tree se smoother hoti hain.
  • Gradient boosting: trees sequentially bante hain, har tree pichhle ki galtiyan correct karta hai. Cancer par ~0.96–0.97, learning_rate aur max_depth complexity control karte hain.

Strengths: best off-the-shelf accuracy me se ek, robust. Weaknesses: slower, kam interpretable, bahut parameters. Key parameters: n_estimators, max_features, learning_rate, max_depth.

Kernelized Support Vector Machines

Kernel trick data ko implicitly higher-dimensional space me map karta hai, jahan linear boundary kaam kar jati hai; RBF (Gaussian) kernel common default hai. Two-moons data par linear model fail hota hai, RBF SVC succeed karta hai (Figures 2-40 to 2-44). C (regularisation) aur gamma (kernel width) tune karne par grid se best result C=10, gamma=0.1 ke aas-paas milta hai, cancer data par scaling ke baad test accuracy ~0.97. Scaling essential hai — bina scaling ke SVM accuracy collapse kar jati hai. Strengths: medium data par strong, kernels se flexible. Weaknesses: scaling aur tuning chahiye, large data par slow. Key parameters: C, gamma.

Neural Networks (Deep Learning)

MLP — layers of units with weights; hidden layers non-linear activation (relu ya tanh) apply karte hain. Two-moons par hidden_layer_sizes=(100, 100) wala MLP classes ko separate kar deta hai (Figure 2-51). Cancer par unscaled MLP ~0.86 score karta hai, lekin StandardScaler ke baad ~0.97 — tuning alpha aur hidden sizes matter karta hai. Complexity estimate: weights ki sankhya hidden units aur features ke saath badhti hai. Strengths: bahut complex functions seekh sakta hai, images/text par state of the art. Weaknesses: scaling, tuning aur zyada data chahiye; train slow; interpret karna mushkil. Key parameters: hidden_layer_sizes, alpha, activation, solver.

Uncertainty Estimates from Classifiers

  • decision_function — boundary se signed distance deta hai (positive = us class ke liye confident).
  • predict_proba — class probabilities deta hai (jo models support karte hain — jaise logistic regression, random forests).

Two-moons data par boundary ke paas wale points ki probabilities 0.5 ke aas-paas hoti hain. Multiclass problems me highest probability binary case se kam certain hoti hai. Take-away: probabilities ko ranking ke liye use karo, aur un cases me jahan galat confident prediction mehenga padta hai.

Chapter 3 — Unsupervised Learning aur Preprocessing

Unsupervised learning me koi target nahi hota — goal structure dhoondhna hai: grouping (clustering), compression/visualisation (dimensionality reduction), ya ek representation seekhna jo baad ke supervised step me help kare.

Challenges — unsupervised me evaluation mushkil kyun hai

Ground truth nahi hoti, isliye evaluation indirect, visual, ya downstream task se hoti hai. "Sahi" number of clusters ya components ek judgement hai — koi ek sahi jawab nahi hota.

Preprocessing aur Scaling

Distance-based aur gradient methods ke liye features comparable scales par hone chahiye. Chaar scalers:

ScalerKya karta haiKab use karo
StandardScalerZero mean, unit varianceDefault choice — SVM, k-NN, neural nets
MinMaxScalerRange 0–1 me laata haiJab bounded range chahiye ho
RobustScalerMedian / IQR use karta haiOutliers ho to — robust rehta hai
NormalizerHar row ko unit-length banata haiJab direction matter kare, magnitude nahi

Code pattern (yaad rakho): fit sirf training data par karo, phir transform train aur test dono par. Test data par fit karna leakage hai — information leak ho jati hai.

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)   # fit SIRF train par
X_test_scaled = scaler.transform(X_test)         # test par sirf transform

Cancer data par SVC ke saath: unscaled accuracy ~0.93, MinMax-scaled ~0.97 kitab ke example me. Exact gain model par depend karta hai, lekin scaling SVMs, k-NN aur neural networks ke liye essential hai, aur trees ke liye irrelevant hai.

Principal Component Analysis (PCA)

PCA maximum variance ki orthogonal directions dhoondhta hai (principal components), components_ me store hote hain, aur explained_variance_ratio_ batata hai har component kitni variance explain karta hai. Cancer data par pehle do components ~63% variance explain karte hain (pehla ~44%, dusra ~19% printed ratios ke hisab se), aur do-component scatter plot malignant ko benign se reasonably well separate karta hai (Figures 3-3, 3-4). Whitening components ko unit variance par rescale karta hai.

Feature extraction with PCA — Eigenfaces

PCA Labeled Faces in the Wild data par (1,833 images, 40×30 pixels cropping ke baad, 62 people jinke kam se kam 20 images hain) face-like components deta hai (Figure 3-8) — inhe eigenfaces kehte hain. 100 components ko features bana kar logistic regression se achhi face recognition milti hai.

Non-Negative Matrix Factorization (NMF)

NMF ek non-negative matrix ko do non-negative matrices (W aur H) me factorise karta hai, isliye components additive parts hote hain. Synthetic data par ye underlying part patterns recover karta hai (Figure 3-10). Faces par NMF components local face parts (aankhein, munh) jaise dikhte hain, poore-face eigenfaces ki tarah nahi (Figure 3-11) — aur ye wahan useful hai jahan sirf non-negative combinations ka matlab banta hai.

Manifold Learning with t-SNE

t-SNE ek visualisation method hai; ye local neighbourhoods preserve karta hai, global distances nahi. Digits data par (1,797 8×8 images) t-SNE digits ke well-separated clusters deta hai (Figure 3-13), jabki PCA unhe zyada mix karta hai. Ye slow aur stochastic hai, aur iske axes ka koi interpretable matlab nahi hota — iska output bina soche-samjhe model ke features ke roop me use mat karo.

Clustering

k-Means Clustering

k cluster centres chuno, har point ko nearest centre assign karo, centres ko means par move karo, converge hone tak repeat karo. Two-moons data par ye moons ko dhoondhne me fail hota hai (Figure 3-20); blobs par achha kaam karta hai. Failure cases: alag sizes, densities, ya non-spherical shapes wale clusters. Vector quantisation: har point ko uske centre se replace karna data ko compress karta hai.

Agglomerative Clustering

Har point se alag shuru karo aur sabse paas wale clusters ko merge karte jao; linkage choices (ward, average, complete) result badal dete hain. Dendrogram merge history dikhata hai (Figure 3-27). Faces data par ye groups dhoondhta hai jo largely logon se correspond karte hain.

DBSCAN

Dense regions me points ko group karta hai — eps (neighbourhood radius) aur min_samples parameters hain; sparse regions ke points ko noise (-1) label milta hai. Two moons par ye dono shapes recover kar leta hai jahan k-means fail hota hai (Figure 3-30); faces data par ye kuch bade clusters + bahut noise points dhoondhta hai, isliye wahan kam useful hai. Strengths: arbitrary shapes dhoondhta hai, k ki zaroorat nahi, outliers mark karta hai. Weaknesses: eps/min_samples aur scaling sensitive.

Clustering ko evaluate karna

  • Ground truth ke saath: adjusted Rand index (ARI) aur normalised mutual information (NMI) agreement measure karte hain (1 = perfect). Faces data par methods ~0.5–0.8 score karte hain algorithm ke hisab se.
  • Bina ground truth: silhouette score measure karta hai ki point apne cluster se kitna paas hai vs agle cluster se; zyada behtar hai, lekin ye spherical clusters ko favour karta hai.

Categorical Variables

Categorical feature ke values ka ek fixed set hota hai (jaise colour, city). Adult census example: features jaise age, workclass, education, marital-status, occupation — aur target hai income >50K ya ≤50K. Zyada features ka matlab zyada overfitting risk — isliye regularisation aur cross-validation zaroori hain. Figure 4-6 training/test R² ko polynomial degree ke against dikhata hai.

Univariate Nonlinear Transformations

Ek feature par log, exp, sin ya cos apply karne se relation linearise ho sakta hai. Kitab ka example wave data ka sine-like pattern use karta hai aur dikhata hai ki log transform skewed data par linear model ki help karta hai. Choice data ko dekh kar karni chahiye — andhere me transform mat lagao.

Automatic Feature Selection

  • Univariate statistics (SelectPercentile with f_regression / f_classif) — target se sabse correlated k features rakhta hai; cancer par top features select karne se accuracy full-feature result ke paas rehti hai.
  • Model-based selection (SelectFromModel) — wo features rakhta hai jinhe ek model (jaise random forest ya Lasso) important paaya.
  • Iterative selection (RFE / RFECV) — baar-baar sabse kam important feature drop karke re-fit karta hai, aur cross-validation se features ki sankhya chunta hai; cancer par RFECV 30 me se ~20–30 features select karta hai kitab ke run me.

Lesson: selection model ko fast aur stable bana sakta hai, lekin ye cross-validation ke andar hona chahiye — warna leakage hota hai.

Sabse achhe features aksar domain knowledge se aate hain, automation se nahi. Example: bike-sharing / time-series case — hour of day, day of week, aur holiday hai ya nahi jaise features add karne se (cyclical time ke liye sin/cos encoding aur POSIX time ke saath) model generic transforms se kahin zyada improve hota hai.   1. Wo features use karo jo expert ko pata hain ki matter karte hain.
  2. Raw data se features engineer karo (jaise dates se cyclical features).
  3. Past se seekho (lag features).

Chapter 5 — Model Evaluation aur Improvement

Model banane se zyada important hai usko honestly evaluate karna. Is chapter me cross-validation, grid search, aur sahi metrics choose karne ka tareeka hai.

Cross-Validation

Data ko k folds me baanto; k−1 folds par train karo, bache hue fold par test karo, rotate karo, aur average lo. Iris par logistic regression ke saath 5-fold cross_val_score scores deta hai ~0.96–1.0, mean ~0.98 — single split se zyada reliable estimate. Strategies:

  • Stratified k-fold — har fold me class proportions same rakhta hai.
  • Leave-one-out — har fold me ek sample (expensive).
  • Shuffle-split — random splits banata hai.
  • GroupKFold — groups (jaise same patient) ko ek saath rakhta hai.

Figure 5-1 5-fold scheme dikhata hai.

Grid Search

GridSearchCV parameter grid ko cross-validation ke saath search karta hai aur deta hai best_params_, best_score_ aur best_estimator_. Simple example: cancer data par SVC, C aur gamma ke upar — best score ~0.97–0.98, best parameters C=10, gamma=0.001–0.1 ke aas-paas (grid par depend karta hai).

from sklearn.model_selection import GridSearchCV
from sklearn.svm import SVC

param_grid = {'C': [0.1, 1, 10, 100], 'gamma': [0.001, 0.01, 0.1, 1]}
grid = GridSearchCV(SVC(), param_grid, cv=5)
grid.fit(X_train, y_train)

print(grid.best_params_)   # e.g. {'C': 10, 'gamma': 0.1}
print(grid.best_score_)    # ~0.97-0.98 (cross-validation score)

Danger — validation set ko overfit karna: test set par tune karna, ya same validation set par baar-baar tune karna, validation set ko overfit kar deta hai. Final untouched test set rakho, ya nested cross-validation use karo (outer loop evaluation ke liye, inner loop tuning ke liye) — isse unbiased estimate milta hai. RandomizedSearchCV parameter combinations ko sample karta hai — ye zyada efficient hai jab kuch parameters kam matter karte hain. Parallelisation: n_jobs=-1 saare cores use karta hai.

Chapter 6 — Algorithm Chains aur Pipelines

Preprocessing (scaling, encoding) sirf training data par fit hona chahiye, aur prediction ke waqt wahi steps apply hone chahiye. Haath se karne par leakage aur galtiyan hoti hain. Pipeline iska fix hai.

The General Pipeline Interface

Ek Pipeline steps ko chain karta hai: har step (aakhiri ke alawa) ek transformer hota hai (fit/transform), aur aakhiri step ek estimator hota hai (fit/predict). Example: Pipeline([("scaler", StandardScaler()), ("svm", SVC())]) — pipeline fit karne par scaler training data par fit hota hai, use transform karta hai, phir SVM fit hota hai.

Building Pipelines

make_pipeline wahi pipeline estimator objects se banata hai, steps ko class names se automatically naam deta hai (lowercased). Steps ko access karo pipe.steps ya pipe.named_steps se, aur parameters ko double-underscore syntax se, jaise svc__C.

from sklearn.pipeline import Pipeline, make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC

pipe = Pipeline([("scaler", StandardScaler()), ("svm", SVC())])
pipe.fit(X_train, y_train)
print(pipe.score(X_test, y_test))

# ya chhota tareeka:
pipe2 = make_pipeline(StandardScaler(), SVC())
# parameter access: pipe.named_steps["svm"].C  /  grid me "svc__C"

Using Pipelines in Grid Searches

Pipeline par GridSearchCV preprocessing aur model parameters ko ek saath search karta hai — jaise {"svc__C": [...], "svc__gamma": [...]} ya {"scaler": [StandardScaler(), MinMaxScaler()]} se scaler khud choose karna. Ye preprocessing tune karne ka sahi tareeka hai — scaler har cross-validation fold ke andar dobara fit hota hai, isliye koi leakage nahi. Cancer data par pipeline grid search ~0.98 test accuracy tak pahunchta hai.

Grid-Searching Which Model To Use

Pipeline ka ek step alag-alag models ke liye ek interchangeable jagah bhi ho sakta hai — jaise ek list me logistic regression aur random forest — aur grid search unhe fairly compare karta hai, kyunki har model ko same folds aur same preprocessing milti hai.

Accessing Step Attributes

Fit karne ke baad pipe.named_steps["svm"].coef_ (ya .support_vectors_) se fitted model ke attributes milte hain; GridSearchCV ka best_estimator_ best pipeline hold karta hai.

Parameter Selection with Preprocessing

Chapter dikhata hai ki SVC ke liye best C/gamma scaler par depend karta hai — isliye dono ko ek saath tune karna chahiye, alag-alag nahi.

TIP

Golden rule: preprocessing aur model ko hamesha ek hi Pipeline object me rakho. Isse workflow reproducible, leak-free aur tunable banta hai — aur production me deploy karna bhi aasan hota hai.

Chapter 7 — Working with Text Data

Text unstructured hota hai: ek hi matlab bahut tareekon se likha ja sakta hai, word order matter karta hai, aur vocabulary bahut badi hoti hai. Pehle text ko numbers me badlo, phir standard classifiers lagao.

Types of Data Represented as Strings

  • Categorical strings — fixed values (jaise colour ka naam).
  • Free-form text — sentences, documents.
  • Identifiers — jaise IDs.

Example Application: Sentiment Analysis of Movie Reviews

IMDb movie reviews — 25,000 training aur 25,000 test reviews, positive/negative labelled. Goal: review ke text se sentiment predict karna.

Representing Text Data as a Bag of Words

Text ko words me tokenise karo, saare words ki vocabulary banao, aur har document ko har vocabulary word ke count se represent karo. Toy example — teen chhote documents ("This is how you get ants" etc.) se chhoti vocabulary aur sparse count matrix banti hai. CountVectorizer tokenisation aur counting karta hai; movie-review vocabulary default settings se ~89,000 words ki hoti hai, aur resulting matrix sparse hoti hai (zyadatar entries zero).

Bag-of-Words with More Than One Word (n-Grams)

Sirf single words (unigrams) use karne se word order kho jata hai; bigrams aur trigrams (jaise "not good") short phrases aur negation capture karte hain. ngram_range=(1, 2) se movie-review model improve hota hai.

Advanced Tokenization, Stemming aur Lemmatization

  • Lowercasing aur punctuation handle karna.
  • Stemming — words ko root tak kaatna (jaise "running" → "run"); cruder hai aur non-words bana sakta hai.
  • Lemmatization — word ko dictionary form tak reduce karna; zyada sahi hota hai.
  • Dono related words ko conflate karte hain — vocabulary chhoti hoti hai.

Stopwords

Bahut common words (the, and, is) jinme sentiment kam hota hai; inhe hatane se (ENGLISH_STOP_WORDS) help ho sakti hai, lekin "not" jaise words sentiment ke liye zaroori hain — inhe mat hatao. Table 7-1 sabse frequent words aur stopword removal ka effect dikhati hai.

Rescaling the Data with tf–idf

tf–idf (term frequency–inverse document frequency) counts ko rescale karta hai: jo words bahut documents me aate hain, unhe down-weight karta hai; rare, discriminative words ko up-weight karta hai. TfidfVectorizer counting aur rescaling dono karta hai. Movie reviews par tf–idf + logistic regression ~0.89 test accuracy deta hai kitab ke run me, plain counts se ~0.88 ke muqable; exact numbers settings par depend karte hain.

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

# counts + tf-idf + classifier, ek pipeline me
pipe = make_pipeline(TfidfVectorizer(), LogisticRegression())
pipe.fit(X_train_text, y_train)
print(pipe.score(X_test_text, y_test))
# ~0.89 test accuracy (plain counts se ~0.88)

Sabse bade positive coefficients positive-sentiment words se correspond karte hain (jaise "excellent", "great"), sabse bade negative negative-sentiment words se. Ye ek useful sanity check hai ki model ne sensible associations seekhe hain, artefacts nahi.

Chapter ek minimal example estimator deta hai aur dikhata hai ki wo Pipeline aur GridSearchCV ke andar kaam karta hai.

from sklearn.base import BaseEstimator, ClassifierMixin

class MyEstimator(BaseEstimator, ClassifierMixin):
    def __init__(self, param1=1.0):
        self.param1 = param1          # parameters __init__ me

    def fit(self, X, y):
        # training yahan; fitted attributes _ se end hote hain
        self.classes_ = sorted(set(y))
        return self

    def predict(self, X):
        # prediction logic yahan
        return [self.classes_[0]] * len(X)

Q1Supervised aur unsupervised learning me kya farq hai?

Supervised learning me labelled examples hote hain — har input ke saath sahi output (target) diya hota hai, jaise iris flower ki species ya ghar ka price. Model in examples se seekh kar naye data par target predict karta hai. Unsupervised learning me koi target nahi hota — model data me structure dhoondhta hai, jaise clustering (similar points ko group karna) ya dimensionality reduction. Kitab ke hisab se supervised me classification aur regression aate hain; unsupervised me clustering, PCA, NMF aur t-SNE.

Q2Classification aur regression me kya antar hai?

Classification discrete label predict karta hai — jaise iris ki species (setosa / versicolor / virginica) ya email spam hai ya nahi. Regression continuous number predict karta hai — jaise ghar ka price ya temperature. Ek hi model family ke aksar dono versions hote hain: jaise logistic regression classification ke liye aur linear regression regression ke liye. Interview me ye bhi batao ki metric bhi alag hoti hai — classification me accuracy/precision/recall, regression me MSE/MAE/R².

Q3Overfitting kya hai aur ise kaise pehchano?

Overfitting tab hota hai jab model training data ka noise rat leta hai — training accuracy high hoti hai lekin test accuracy low. Pehchan: train aur test score ke beech bada gap. Kitab ke iris example me bhi training accuracy test accuracy (0.97) se zyada thi — ye pehla sign hai. Fix: zyada data, simpler model, regularisation (Ridge/Lasso, alpha badhao), cross-validation se evaluate karo, aur early stopping ya pruning use karo. Underfitting iska ulta hai — model itna simple hai ki training pattern bhi capture nahi kar pata, dono accuracies low hoti hain.

Q4Train/test split kyun zaroori hai? 75/25 ka matlab kya hai?

Train/test split isliye zaroori hai kyunki model ko unseen data par judge karna hai — jo model sirf training data rat-ta hai, wo real duniya me fail hoga. Kitab ke iris example me train_test_split with random_state=0 se 112 training aur 38 test samples mile (75%/25%). Training set par fit karo, test set par evaluate karo. Lekin ek single test score sirf ek estimate hai — seed badalne par score badal sakta hai, isliye reliable estimate ke liye cross-validation use karte hain (Chapter 5).

Q5k-NN kaise kaam karta hai? k ka kya role hai?

k-Nearest Neighbors naye point ke k sabse paas wale training points ko dekhta hai. Classification me unka majority vote leta hai; regression me unke targets ka average. k=1 par boundary jagged hoti hai aur model noise sensitive hota hai; bada k boundary ko smooth karta hai lekin bahut bada k alag class ke points ko bhi vote de deta hai. Cancer data par accuracy k badhne par pehle badhti hai phir girti hai, peak k=5–7 ke aas-paas. Key parameter: n_neighbors. Weakness: prediction slow hota hai, bahut features ya sparse data par kharab, aur scaling sensitive hai.

Q6Ridge aur Lasso regression me kya farq hai?

Dono linear regression me regularisation add karte hain — coefficients ko shrink karke overfitting kam karte hain. Ridge (L2) coefficients ko zero ki taraf shrink karta hai lekin exactly zero nahi karta; alpha badhne par saare coefficients chhote hote jate hain. Lasso (L1) coefficients ko exactly zero kar sakta hai — matlab ye feature selection bhi karta hai. Kitab ke Boston Housing example me alpha=1 par Lasso ke baad sirf kuch features ke non-zero coefficients bachte hain. Dono ka key parameter alpha hai. Interview tip: jab bahut saare irrelevant features hon to Lasso behtar; jab saare features thode-thode useful hon to Ridge behtar.

Q7Logistic regression linear model kyun hai, naam me regression kyun hai?

Logistic regression naam me regression hone ke bawjood ek classification model hai. Ye linear decision boundary seekhta hai — features ka weighted sum nikaal kar use sigmoid function se probability me badalta hai. Forge data par iski boundary ek seedhi line hoti hai. Cancer data par isse ~0.95 test accuracy milti hai. Multiclass problems me ye one-vs-rest strategy use karta hai. Ye linear models ki family me aata hai isliye iska naam regression hai — historically ye regression se aaya hai, lekin kaam classification ka karta hai.

Q8Naive Bayes ka 'naive' assumption kya hai?

Naive Bayes ye assume karta hai ki saare features class diye hone par ek dusre se independent hain — jo real duniya me aksar galat hota hai, isiliye 'naive' kaha jata hai. Phir bhi ye bahut fast hai, achha baseline deta hai, aur high-dimensional text data par achha kaam karta hai. GaussianNB continuous features ke liye, MultinomialNB counts ke liye, BernoulliNB binary features ke liye. Cancer data par iski accuracy ~0.94 hai. Key parameter alpha (smoothing) hai. Weakness: independence assumption galat hone par calibration kharab hoti hai.

Q9Decision tree overfit kyun karta hai aur ise kaise roko?

Decision tree har split par data ko aur chhote hisson me baant ta hai — agar roka na jaye to ye training data ko poori tarah yaad kar lega, har leaf pure ho jayega, aur naye data par fail hoga. Rokne ke tareeke: max_depth limit karo, max_leaf_nodes set karo, min_samples_leaf badhao. Kitab ke cancer example me max_depth=4 wala tree ~0.95 test accuracy deta hai. Tree ki strength: interpretable hai, scaling ki zaroorat nahi, mixed data handle karta hai. Lekin ye chhote data changes par unstable hota hai — isiliye random forests aur gradient boosting behtar hain.

Q10Random forest gradient boosting se kaise alag hai?

Random forest bahut saare trees ko parallel train karta hai — har tree bootstrap sample aur random feature subset par — aur unka average/ vote leta hai. Isse variance kam hoti hai. Gradient boosting trees ko sequentially train karta hai — har naya tree pichhle trees ki galtiyan correct karta hai. Dono cancer data par ~0.96–0.97 accuracy dete hain. Random forest ke key parameters n_estimators aur max_features hain; gradient boosting ke learning_rate aur max_depth. Random forest zyada robust aur parallelizable hai; gradient boosting thoda zyada accurate ho sakta hai lekin tuning sensitive hoti hai aur overfit ka risk zyada hota hai.

Q11Kernel trick kya hai? RBF kernel kyun popular hai?

Kernel trick data ko implicitly higher-dimensional space me map karta hai, jahan ek linear boundary kaam kar jati hai — bina wo mapping actually compute kiye. RBF (Gaussian) kernel sabse common default hai kyunki ye smooth, non-linear boundaries bana sakta hai. Two-moons data par linear model fail hota hai lekin RBF SVC succeed karta hai. SVM ke key parameters C (regularisation) aur gamma (kernel width) hain — kitab ke grid me best C=10, gamma=0.1 ke aas-paas, cancer par ~0.97 accuracy. Yaad rakho: SVM ke liye scaling essential hai — bina scaling ke accuracy collapse kar jati hai.

Q12MLP (neural network) kab use karna chahiye aur kab nahi?

MLP tab use karo jab data complex ho aur bahut data available ho — ye bahut complex functions seekh sakta hai aur images/text par state of the art hai. Lekin iske liye scaling zaroori hai (cancer par unscaled MLP ~0.86, StandardScaler ke baad ~0.97), tuning chahiye (hidden_layer_sizes, alpha, activation, solver), aur training slow hoti hai. Tabular data par kam data ho to random forest ya gradient boosting aksar behtar aur fast hote hain. MLP ko interpret karna bhi mushkil hota hai. Kitab ka rule: pehle simple model try karo, phir complex ki taraf badho.

Q13decision_function aur predict_proba me kya farq hai?

decision_function boundary se signed distance deta hai — positive value ka matlab hai us class ke liye confident hona. predict_proba class probabilities deta hai (jaise 0.8 ka matlab 80% chance). Har model dono support nahi karta — predict_proba sirf un models me hota hai jo probabilities de sakte hain, jaise logistic regression aur random forests. Two-moons data par boundary ke paas wale points ki probabilities 0.5 ke aas-paas hoti hain — matlab model unsure hai. Interview tip: probabilities ko ranking ke liye use karo, aur un cases me jahan galat confident prediction mehenga ho.

Q14StandardScaler, MinMaxScaler aur RobustScaler me kab kaunsa use karein?

StandardScaler zero mean aur unit variance karta hai — ye default choice hai, SVM, k-NN aur neural nets ke liye. MinMaxScaler range 0–1 me laata hai — jab bounded range chahiye ho. RobustScaler median aur IQR use karta hai — outliers hone par ye robust rehta hai kyunki mean/std outliers se affect hote hain. Normalizer har row ko unit-length banata hai — jab direction matter kare, magnitude nahi. Sabse important rule: fit sirf training data par karo, phir transform train aur test dono par — test par fit karna leakage hai.

Q15Data leakage kya hai? Ek example do.

Data leakage tab hota hai jab test data ki information training me leak ho jati hai — to test score asli se zyada achha dikhta hai aur model real duniya me fail hota hai. Classic example: scaler ko poore dataset (train + test) par fit karna — test data ka mean/std training me use ho gaya. Sahi tareeka: scaler ko sirf train par fit karo, phir test par sirf transform karo. Isi tarah feature selection bhi cross-validation ke andar honi chahiye. Pipeline iska fix hai — scaler har CV fold ke andar dobara fit hota hai, isliye koi leakage nahi.

Q16PCA kaise kaam karta hai? Explained variance ratio kya batata hai?

PCA maximum variance ki orthogonal directions (principal components) dhoondhta hai. Pehla component sabse zyada variance wali direction hoti hai, dusra usse perpendicular, aur aise hi aage. explained_variance_ratio_ batata hai har component total variance ka kitna hissa explain karta hai. Cancer data par pehle 2 components ~63% variance explain karte hain (pehla ~44%, dusra ~19%). Agar pehle kuch components zyada variance cover kar lein, to data ko kam dimensions me represent karke bhi zyada information bach jati hai. Whitening components ko unit variance par rescale karta hai.

Q17Eigenfaces kya hain? NMF PCA se kaise alag hai?

Eigenfaces PCA ko face images par apply karne se milte hain — principal components face-like dikhte hain. Labeled Faces in the Wild data (1,833 images, 62 people) par 100 components ko features bana kar logistic regression se achhi face recognition milti hai. NMF (Non-Negative Matrix Factorization) matrix ko do non-negative matrices me factorise karta hai, isliye iske components additive parts hote hain — faces par NMF components local parts (aankhein, munh) jaise dikhte hain, jabki eigenfaces poore face jaise dikhte hain. NMF wahan useful hai jahan sirf non-negative combinations ka matlab banta hai.

Q18t-SNE kya hai aur iski limitations kya hain?

t-SNE ek manifold learning method hai jo high-dimensional data ko 2D/3D me visualise karta hai. Ye local neighbourhoods preserve karta hai — paas wale points paas rehte hain — lekin global distances preserve nahi karta. Digits data par t-SNE well-separated clusters deta hai jabki PCA mix karta hai. Limitations: ye slow aur stochastic hai (har run alag ho sakta hai), iske axes ka koi interpretable matlab nahi hota, aur iska output bina soche model ke features ke roop me use nahi karna chahiye. Ye visualisation ke liye hai, feature engineering ke liye nahi.

Q19k-Means kab fail hota hai? DBSCAN kab behtar hai?

k-Means spherical clusters assume karta hai — ye tab fail hota hai jab clusters alag sizes, densities ya non-spherical shapes ke hon. Two-moons data par k-means moons ko dhoondhne me fail hota hai, lekin blobs par achha kaam karta hai. DBSCAN dense regions me points ko group karta hai — ye arbitrary shapes dhoondh sakta hai, k ki zaroorat nahi, aur outliers ko noise (-1) mark karta hai. Two moons par DBSCAN dono shapes recover kar leta hai. Lekin DBSCAN eps aur min_samples ke liye sensitive hai aur scaling par depend karta hai. Faces data par DBSCAN kuch bade clusters + bahut noise deta hai, isliye wahan kam useful hai.

Q20Clustering ko evaluate kaise karte hain jab ground truth na ho?

Ground truth hone par ARI (adjusted Rand index) aur NMI (normalised mutual information) use karte hain — 1 ka matlab perfect agreement. Faces data par methods ~0.5–0.8 score karte hain. Bina ground truth ke silhouette score use karte hain — ye measure karta hai ki point apne cluster se kitna paas hai vs agle cluster se; zyada behtar hai, lekin ye spherical clusters ko favour karta hai. Yaad rakho: unsupervised me evaluation hamesha indirect hoti hai — visual inspection ya downstream task se — kyunki koi sahi jawab nahi hota.

Q21One-hot encoding kyun zaroori hai? Integers se kya problem hai?

Categorical values ko integers (0, 1, 2) se encode karna misleading hai kyunki model ko lagta hai ki categories me order aur equal spacing hai — jaise city 2, city 1 se double hai, jo bekaar hai. One-hot encoding har category ke liye ek binary column banata hai — koi order imply nahi hota. pandas me get_dummies aur scikit-learn me OneHotEncoder ye karta hai. ColumnTransformer ke saath OneHotEncoder categorical columns par aur StandardScaler numeric columns par lagakar dono ko ek pipeline me rakha ja sakta hai. Unseen categories (test me nayi category) ko handle_unknown='ignore' se handle karo.

Q22ColumnTransformer kya hai aur make_column_transformer se kya fayda?

ColumnTransformer alag columns par alag transformers lagata hai aur results ko concatenate kar deta hai — jaise categorical columns par OneHotEncoder aur numeric columns par StandardScaler. Isse preprocessing model pipeline ke andar rehti hai aur leakage avoid hota hai. make_column_transformer wahi kaam chhote tareeke se karta hai — column types ko dtype se infer karta hai (numbers vs strings). Interview me ye batao ki preprocessing ko pipeline ke andar rakhna hi sahi tareeka hai, haath se karna leakage aur galtiyon ko invite karta hai.

Q23PolynomialFeatures se overfitting ka risk kyun badhta hai?

PolynomialFeatures features ke squares aur products add karta hai — isse linear model curves fit kar pata hai, jaise wave data par quadratic fit. Lekin har naya feature model ko zyada freedom deta hai, isliye overfitting ka risk badhta hai. Isliye polynomials ke saath regularisation (Ridge/Lasso) aur cross-validation zaroori hain. Figure 4-6 me training/test R² ko degree ke against dekh kar sahi degree chuni ja sakti hai — jahan test R² girne lage, wahan degree zyada ho gayi hai.

Q24Feature selection ke teen tareeke kya hain?

Pehla: univariate statistics — SelectPercentile (f_regression/f_classif) target se sabse correlated k features rakhta hai; cancer par top features se accuracy full-feature result ke paas rehti hai. Dusra: model-based selection — SelectFromModel wo features rakhta hai jinhe ek model (random forest ya Lasso) important paaya. Teesra: iterative selection — RFE/RFECV baar-baar sabse kam important feature drop karke re-fit karta hai aur cross-validation se features ki sankhya chunta hai; cancer par RFECV 30 me se ~20–30 features select karta hai. Sabse important: selection cross-validation ke andar honi chahiye, warna leakage hota hai.

Q25Expert knowledge se feature engineering automation se behtar kyun hoti hai?

Sabse achhe features aksar domain knowledge se aate hain, automation se nahi. Kitab ka bike-sharing example: hour of day, day of week aur holiday hai ya nahi jaise features add karne se model generic transforms se kahin zyada improve hota hai. Teen strategies hain: wo features use karo jo expert ko pata hain ki matter karte hain; raw data se features engineer karo (jaise dates se cyclical features, sin/cos encoding); aur past se seekho (lag features). Interview me ye example dekar dikhao ki tum sirf algorithms nahi, problem ko samajhte ho.

Q26Cross-validation single train/test split se behtar kyun hai?

Single split ka score seed aur split par depend karta hai — ek hi number hai jo lucky ya unlucky ho sakta hai. Cross-validation data ko k folds me baant kar har fold ko ek baar test banata hai aur scores ka average leta hai — har sample ek baar test banta hai, isliye estimate zyada stable aur reliable hota hai. Iris par logistic regression ke saath 5-fold scores ~0.96–1.0, mean ~0.98 milte hain. Stratified k-fold har fold me class proportions same rakhta hai. Leave-one-out sabse zyada folds use karta hai lekin expensive hai.

Q27Grid search kya hai? Nested cross-validation kab chahiye?

GridSearchCV parameter combinations ka grid banakar har combination ko cross-validation se evaluate karta hai aur best_params_, best_score_ aur best_estimator_ deta hai. Cancer par SVC ke liye best C=10, gamma=0.001–0.1 ke aas-paas, best score ~0.97–0.98. Danger: test set par tune karna ya same validation set par baar-baar tune karna validation set ko overfit kar deta hai. Nested cross-validation iska fix hai — outer loop evaluation ke liye, inner loop tuning ke liye — isse unbiased estimate milta hai. RandomizedSearchCV tab efficient hai jab kuch parameters kam matter karte hain.

Q28Precision, recall aur F1-score me kya farq hai? Kab kaunsa use karein?

Precision = TP/(TP+FP) — predicted positives me se kitne sahi the. Recall = TP/(TP+FN) — true positives me se kitne mile. F1-score in dono ka harmonic mean hai. Kab kaunsa: jab false positive mehenga ho (jaise spam filter me achha email spam me jana) to precision; jab false negative mehenga ho (jaise cancer miss hona) to recall. F1 tab jab dono ka balance chahiye. Imbalanced data par accuracy misleading hoti hai — 90% majority class ho to hamesha-majority-predict karne wala model bhi 0.90 accuracy de deta hai, isiliye precision/recall/F1 dekho.

Q29ROC curve aur AUC kya batate hain? Precision-recall curve kab behtar hai?

ROC curve true positive rate ko false positive rate ke against plot karti hai, threshold badalne par. AUC is curve ke neeche ka area hai — 1.0 perfect, 0.5 random. Cancer data par random forest aur logistic regression dono ka AUC ~0.99 hai. Precision-recall curve tab behtar hoti hai jab data heavily imbalanced ho aur positive class rare ho — kyunki ROC me true negatives ki badi sankhya curve ko achha dikha sakti hai jabki precision-recall rare class par focus karta hai. Average precision PR curve ka summary hai.

Q30Regression ke liye kaunse metrics use hote hain?

Regression me teen main metrics hain: mean squared error (MSE) — errors ka square average, bade errors ko zyada penalise karta hai; mean absolute error (MAE) — errors ka absolute average, interpret karna aasan; aur R² (coefficient of determination) — model variance ka kitna hissa explain karta hai, 1.0 perfect hota hai. Kitab Boston Housing example ke liye R² aur MSE use karti hai — OLS se training R² 0.75 aur test R² 0.66 milte hain ek run me. Model selection me scoring argument se metric choose karo jo business goal se match kare.

Q31Pipeline kyun use karna chahiye? Pipeline ke fayde kya hain?

Pipeline preprocessing aur model ko ek hi object me chain karta hai — har step (aakhiri ke alawa) transformer hota hai, aakhiri estimator. Fayde: preprocessing sirf training data par fit hoti hai (leakage nahi), prediction ke waqt wahi steps automatically apply hote hain, aur GridSearchCV ke saath preprocessing aur model parameters ek saath tune hote hain — scaler har CV fold ke andar dobara fit hota hai. Cancer data par pipeline grid search ~0.98 test accuracy tak pahunchta hai. Parameters ko double-underscore syntax se access karte hain, jaise svc__C. Kitab ka golden rule: preprocessing aur model ko hamesha ek Pipeline me rakho.

Q32Bag of words kya hai? Iske limitations kya hain?

Bag of words text ko words me tokenise karke har document ko vocabulary words ke counts se represent karta hai. IMDb reviews ki vocabulary default settings se ~89,000 words ki hoti hai aur matrix sparse hoti hai. Limitations: word order kho jata hai — 'not good' aur 'good' alag nahi dikhte; har word equally important mana jata hai; aur vocabulary bahut badi ho jati hai. Fixes: n-grams (bigrams/trigrams) word order aur phrases capture karte hain, aur tf-idf common words ko down-weight karta hai.

Q33tf-idf kya hai aur ye plain counts se behtar kyun hai?

tf-idf (term frequency–inverse document frequency) counts ko rescale karta hai: jo words bahut documents me aate hain unhe down-weight karta hai, aur rare, discriminative words ko up-weight karta hai. TfidfVectorizer counting aur rescaling dono karta hai. IMDb reviews par tf-idf + logistic regression ~0.89 test accuracy deta hai, plain counts se ~0.88 — chhota lekin consistent fayda. Ye isliye behtar hai kyunki 'the' jaise common words har document me hote hain aur sentiment ke baare me kuch nahi batate, jabki rare words zyada informative hote hain.

Q34Stemming aur lemmatization me kya farq hai?

Dono related words ko ek form me laate hain taaki vocabulary chhoti ho. Stemming words ko root tak kaat deta hai (jaise 'running' → 'run') — ye crude hai aur non-words bana sakta hai. Lemmatization word ko dictionary form tak reduce karta hai — ye zyada sahi hota hai lekin slow ho sakta hai. Dono se related words conflate hote hain. Stopwords (the, and, is jaise common words) hatane se bhi help ho sakti hai, lekin 'not' jaise words sentiment ke liye zaroori hain — inhe mat hatao.

Q35LDA (topic modeling) kya hai?

Latent Dirichlet Allocation bina labels ke documents me topics dhoondhta hai — topics words ke groups hote hain jo ek saath aate hain. Movie reviews ke subset par topics emerge hote hain jaise 'war / action film' topic aur 'family / children' topic, har topic ke top words list hote hain. LDA components ko documents cluster karne ke features ke roop me bhi use kar sakte hain. Ye unsupervised hai — koi labels nahi chahiye, topics data se khud emerge hote hain.

Q36Prototype se production system tak jaane me kya challenges hain?

Notebook me prototype production system nahi hota. Challenges: data drift (duniya badal jati hai, model purana ho jata hai), monitoring (predictions par nazar rakhni hoti hai), retraining (naye data se model update karna), aur testing. Testing ke tareeke: offline evaluation held-out data par, A/B testing (naya model users ke ek fraction ko dikhao aur business metric compare karo), aur live monitoring. Scaling ke liye out-of-core/partial-fit learning, subsampling ya distributed tools (jaise Spark) use karte hain.
