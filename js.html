What is JavaScript?

JavaScript web ki teesri layer hai. HTML structure deta hai, CSS style deta hai, aur JavaScript page ko jeevant (dynamic) banata hai — bina JS ke page static hota hai, JS ke saath interactive.

Teen layers ka model HTML = content aur structure. CSS = dikhawa (styling). JavaScript = behaviour — button dabane par kuch hona, data badalna, bina page reload kiye content update hona. Interview me ye teen-layer model aksar poochha jata hai.
Browser APIs — browser ki di hui taakat JS akela sab nahi karta; browser uske upar APIs deta hai: DOM API (page ke elements banana/badlana/hatana), Geolocation API (GPS location), Canvas / WebGL APIs (2D/3D graphics), Audio/Video APIs (media chalana/control karna). Ye APIs JS language ka hissa nahi hain — browser deta hai. Isiliye Node.js me DOM nahi hota.
Third-party APIs Dusre developers ki banayi APIs jo tum apni site me use karte ho — live map embed karna, social feed dikhana, payment flow. Ye aam taur par ek JS library/file ke roop me load hoti hain.
JS kaise chalta hai — engine aur JIT Har browser tab me ek JS engine hota hai. Code upar se neeche chalta hai. JS interpreted language hai, lekin modern engines speed ke liye JIT (just-in-time) compilation use karte hain — code chalte-chalte machine code me badal jata hai.
Client-side vs server-side JS Client-side = user ke browser me chalta hai (ye module wahi hai). Server-side = server par chalta hai, jaise Node.js — wahi language, alag environment: wahan DOM nahi hota, lekin file system, database aur HTTP server hote hain.
Page me JS jodne ke 3 tareeke Internal: <script> element — aam taur par <body> ke end me, taaki HTML pehle load ho jaye. External: <script src="script.js"> — best practice (alag file, caching, reuse). Inline handlers jaise onclick="..." — buri practice, kabhi mat use karo: HTML/JS mil jata hai, maintain karna mushkil, aur kai server security configs (CSP) inhe block karte hain.
Script loading — defer vs async Normal <script> head me ho to HTML parsing ruk jati hai jab tak script download + run na ho. Hal: script body ke end me rakho, ya defer use karo (parallel download, HTML parse ke baad, order me chalta hai), ya async (parallel download, taiyaar hote hi chal jata hai, order ki guarantee nahi). DOMContentLoaded event tab fire hota hai jab HTML poora parse ho jaye. Modern pattern: <script type="module"> head me — modules by default deferred hote hain.
Modules ko server chahiye ES modules (type="module") CORS ke under aate hain — file:// se load nahi honge. Local test ke liye local server chalao.
Comments // single line aur /* multi-line */ — code me note likhne ke liye.

Storing the information you need — Variables

Variable ek dabba (container) hai — naam dekar usme value rakhte ho, baad me naam se value nikaalte ho.

Declare aur initialize let myName; declare hai. myName = "Chris"; initialize hai. Dono ek saath: let myName = "Chris";. Declare karke initialize na karo to value undefined hoti hai. Jo variable kabhi declare hi nahi hua, use use karne par ReferenceError aata hai.
var vs let var purana tareeka hai — ye hoist hota hai (declaration se pehle use ho sakta hai) aur ek hi scope me dobara declare ho sakta hai bina error ke. let block-scoped hai, dobara declare karne par SyntaxError: Identifier 'x' has already been declared aata hai. Rule: let use karo, var nahi.
const — binding constant hai, value nahi const declare karte waqt initialize karna hi padega (const x; SyntaxError hai), aur reassign nahi ho sakta (x = 2 par TypeError). LEKIN object/array ki contents badal sakti hain: const arr = [1]; arr.push(2); bilkul chalega — sirf binding bandhi hai, value nahi. Siddhant: "Use const when you can, and use let when you have to."
Naming rules Naam me letters, digits, _, $ chalenge; digit se shuru nahi ho sakta; lower camelCase convention hai (myName, myAge); naam case-sensitive hai (myName ≠ myname); reserved words (let, const, function, return) naam nahi ban sakte; naam aisa rakho ki padhne wala samajh jaye.
Data types aur dynamic typing Number (integers aur floats ek hi type — 10 aur 3.14 dono number), String, Boolean (true/false), Array, Object. JS dynamically typed hai — ek hi variable pehle number, phir string rakh sakta hai: let x = 5; x = "hello"; legal hai.
typeof operator typeof 42 → "number", typeof "hi" → "string" — value asal me hai kya, ye check karne ka tareeka.

Basic math in JavaScript — numbers and operators

Ek hi Number type Integers (10) aur floats (3.14) dono Number hain. Literals: binary 0b101, octal 0o17, hex 0xff. Bahut bade integers ke liye alag type BigInt hai (yahan sirf zikr hai, gehrai Data structures section me hai).
Sabse mashhoor jaal: "74" + 3 "74" + 3 → "743" — kyunki ek operand string hai, + concatenation ban jata hai. Pehle convert karo: Number("74") + 3 → 77.
toFixed() string return karta hai (3.14159).toFixed(2) → "3.14" — dhyaan do, ye string hai, number nahi. Aage math karna hai to dobara Number() lagega.
Arithmetic operators + add, - subtract, * multiply, / divide, % remainder (modulo), ** exponent (2 ** 3 → 8, Math.pow(2, 3) ke barabar).
Operator precedence Pehle * / %, phir + -; ** parentheses ke baad lekin multiply/divide se pehle; same precedence ho to left-to-right. Parentheses sab par bhaari hain — intent saaf karne ke liye use karo.
x++ vs ++x x++ pehle PURANI value return karta hai, phir increment. ++x pehle increment, phir nayi value. let y = x++; me y ko purani value milegi. Interview favourite hai ye.
Assignment operators +=, -=, *=, /= shorthand hain — x += 5 matlab x = x + 5.
Comparison — hamesha strict === strict equal, !== strict not equal, < > <= >=. Loose == type coercion karta hai ("5" == 5 true hai, "5" === 5 false) aur subtle bugs deta hai — hamesha ===/!== use karo.

Handling text — strings in JavaScript

Quotes zaroori hain Bina quotes ke text code samjha jayega aur error aayega — closing quote bhoolne par "unterminated string literal" SyntaxError.
Teen tarah ke quotes Single '...', double "...", backtick `...` — shuru aur end match hone chahiye. Template literals (backtick) sabse powerful: ${} me variable AUR expression dono chalega (`Sum: ${2 + 2}`), aur asli line breaks ke saath multi-line strings bhi banti hain.
Concatenation vs template literal "Hello " + name kaam karta hai, lekin template literal zyada saaf aur aaj ka preferred tareeka hai.
Escaping Double-quoted string ke andar literal quote chahiye to \". Escape sequences: \n newline, \t tab, \\ backslash.
String + number = string "Front " + 242 → "Front 242" — number khud string ban jata hai. Ulta chahiye to explicit conversion: Number("42") → 42, String(42) → "42".
window.prompt() User se input maangta hai — return hamesha string hota hai, ya Cancel par null.

Arrays

Array ek ordered list hai. Mixed types chalenge ([1, "hi", true]), arrays ke andar arrays bhi (nested/multidimensional).

Access aur length arr.length items ki gintee. Zero-based index: arr[0] pehla, arr[2] = "new" se value badalti hai. indexOf(item) index deta hai, na mile to -1.
push/pop/shift/unshift — return values dhyaan se push(item) end me jodta hai, nayi length return karta hai. unshift(item) shuru me jodta hai, nayi length return karta hai. pop() end se hatata hai, hataya gaya item return karta hai. shift() shuru se hatata hai, hataya item return karta hai. Interview me yahi return-value farak poochha jata hai.
splice(index, count) index se shuru karke count items hatata hai (aur chaaho to naye insert bhi karta hai). Ye asli array ko BADALTA hai — slice se confuse mat hona, wo copy banata hai.
map() aur filter() — naye arrays, asli surakshit map() har item par function chalakar results ka NAYA array deta hai. filter() sirf wo items rakhta hai jahan test function true de — ye bhi naya array. Asli array dono me nahi badalta.
split / join "a,b,c".split(",") string → array. arr.join(",") ya toString() array → string. Round-trip pattern data parsing me roz kaam aata hai.
MDN exercises Invoice total: "Product:price" strings ko split(":") karo, Number(price), += se jodo, toFixed(2) se dikhao. Search history top-5: naya search unshift() se front me, length 5 hote hi pop() se sabse purana bahar — MAX_HISTORY constant cap rakhta hai.

Making decisions in your code — conditionals

if / else if / else Condition true ho tabhi code chalta hai. else optional hai. Braceless form (if (x) doSomething();) legal hai lekin discouraged — hamesha braces {} lagao.
Truthy / falsy — sirf 6 falsy values Condition me variable akela test ho sakta hai (if (x)). Falsy sirf ye 6 hain: false, undefined, null, 0, NaN, '' (empty string). Baaki SAB truthy hai — [], {}, "0", "false" bhi truthy hain. Ye list ratta maro, interview me seedha poochhi jati hai.
Logical operators && AND (sab true), || OR (kam se kam ek true), ! NOT (ulta kar deta hai).
Classic galti: if (x === 5 || 7 || 10) Ye hamesha true hai — kyunki 7 aur 10 apne aap me truthy hain. Har test poora likho: if (x === 5 || x === 7 || x === 10).
switch — break bhoolna matlab fall-through Ek value, kai cases — lambi if/else chain se saaf. break na lagao to execution agle case me gir jati hai (fall-through). default optional hai — kuch match na ho to wahi chalta hai.
Ternary operator condition ? valueIfTrue : valueIfFalse — compact if/else jo value return karta hai. Misaal: theme chooser theme === "dark" ? "black" : "white". Chhote decisions ke liye best; lambe logic ke liye if/else hi padhne me asaan hai.
Nested if if ke andar if — multi-level checks ke liye (jaise machine on hai AND score threshold cross hai).

Looping code

Loop matlab kaam ko dohraya jaye — article ki running misaal: ek loop canvas par 100 random circles banata hai. Loop collections par chalte hain: Array, Set, Map, NodeList.

for...of — sabse simple for (const item of collection) { ... } — har item ek-ek karke. Index ki zaroorat na ho to yahi use karo.
Classic for loop for (initializer; condition; final-expression) — jaise for (let i = 0; i < 10; i++). Off-by-one bugs: 1 se shuru karna (0 ki jagah), ya <= array.length likhna (< ki jagah) — aakhri index length - 1 hota hai.
for kab, for...of kab Index chahiye (jaise list ke aakhri item se pehle "and" lagana, ya arr[i] aur arr[i+1] ek saath dekhna) to classic for. Warna for...of.
break vs continue break loop ko turant khatm kar deta hai (misaal: contacts me naam milte hi search roko). continue current iteration ka baaki hissa skip karke agle par jata hai (misaal: integer squares list karte waqt non-integers skip karo).
while aur do...while while (condition) — condition true rahe tab tak; update body ke andar hona chahiye warna loop kabhi khatm nahi hoga. do...while body kam se kam ek baar chalti hai, condition baad me check hoti hai — yahi ek guaranteed farak hai.
Infinite loop warning Jis loop ki condition kabhi false na ho, wo page ko hang kar dega. Hamesha pakka karo ki loop khatm ho sakta hai.
map()/filter() bhi loop hi hain Callbacks ke roop me function expressions / arrow functions diye jate hain — arr.map(x => x * 2) bhi ek tarah ka loop hai.

Functions — reusable blocks of code

Function vs method Naam ke baad () ho aur wo loop/if na ho, to function call hai. Jo function kisi object ka hissa ho (document.querySelector(), arr.push()) use method kehte hain; akela khada function (parseInt()) plain function hai.
Declaration hoist hoti hai, expression nahi Function declaration (function foo() {}) hoisted hai — definition se pehle call kar sakte ho. Function expression (const foo = function() {};) hoist NAHI hoti — defining line se pehle call kiya to ReferenceError.
Parameters vs arguments Definition me likhe naam = parameters (function greet(name)). Call ke waqt di gayi asal values = arguments (greet("Chris")). Interview me ye farak seedha poochha jata hai.
Default values function greet(name = "Chris") — argument na mile to default use hota hai. Bina default ke missing argument undefined hota hai.
Arrow functions (event) => { ... } chhota syntax. Ek parameter ho to parentheses hata sakte ho (event => ...). Body ek hi line ki ho to braces aur return dono hata sakte ho — value apne aap return hoti hai (implicit return): const double = x => x * 2;
Anonymous functions as callbacks Bina naam ka function kisi dusre function ko argument ke roop me dena — event handlers aise hi likhe jate hain: addEventListener("keydown", (event) => { ... }).
Scope — apartment building wali misaal Function ke andar declare hua variable usi function ka hai — bahar ka code use dekh nahi sakta. Global scope poori building ka shared hissa hai. Do alag <script> blocks dono top level par const name declare karein to SyntaxError: Identifier 'name' has already been declared — kyunki dono ek hi global scope share karte hain. Lekin function dobara declare karne par error nahi aata — aakhri declaration jeet jati hai (silently overwrite).
Block scope let/const kisi if/for block ke andar declare ho to block ke bahar dikhai nahi deta. var block se bahar nikal jata hai — ye bhi ek wajah hai let/const prefer karne ki.

Introduction to events

Events browser ke signals hain — kuch hua: user ne click kiya, key dabayi, form submit hua, page load hua.

Listener vs handler Listener mechanism hai (addEventListener()); handler wo function hai jo event fire hone par chalta hai. Aam bolchal me dono shabd ek dusre ke liye use ho jate hain.
addEventListener hi sahi tareeka hai Ek hi element ke ek hi event par KAI handlers lag sakte hain, aur baad me hataye bhi ja sakte hain. Event types try karne layak: click, focus/blur, dblclick, mouseover/mouseout.
removeEventListener ko wahi reference chahiye Handler hatana hai to bilkul wahi function reference pass karna padega jo lagaya tha. Isiliye anonymous inline handlers hataye nahi ja sakte — removal chahiye to named function use karo.
onclick property — purana tareeka, ek hi handler btn.onclick = function() {...} — ek event par sirf EK handler; dusra assign kiya to pehla overwrite. addEventListener isiliye behtar hai.
Inline handlers — kabhi nahi HTML me onclick="..." likhna HTML/JS ko milata hai, maintain karna mushkil hai, aur kai server security configs (CSP) block karte hain.
Event object — e.target Handler ko ek event object milta hai (naam convention: e, evt, event). e.target = jis element par event asal me hua. Keyboard events me KeyboardEvent.key batata hai kaunsi key dabi.
preventDefault() — default action roko Browser ke default behaviour ko rokta hai. Sabse aam misaal: form validation — submit par input galat ho to e.preventDefault() karke form submit hone se roko aur error dikhao.

Event bubbling

Bubbling kya hai Event kisi element par fire ho to pehle usi par, phir uske har ancestor par ek-ek karke chalta hai: BUTTON → DIV → BODY → HTML → document. Matlab button (jo div ke andar hai) par click karne se div ka click handler BHI chalega.
Problem aur fix: stopPropagation() Classic problem: video box jisme "hide" button hai — video par click karne se parent box ka handler bhi chal jata hai aur video hide ho jata hai. Fix: event.stopPropagation() — event ko upar jane se rok deta hai.
Event capture — ulti direction Handlers capture phase me bhi chal sakte hain (ancestors pehle, innermost aakhir me) — addEventListener ke teesre argument me { capture: true } do. By default capture OFF hota hai. Itihaas: Netscape capture use karta tha, IE bubbling; W3C standard ne dono jod diye (capture → target → bubble).
Event delegation — ek listener, kai bacche Har child par alag listener ki jagah parent par EK listener lagao aur event.target se pata karo kaunsa child click hua. Misaal: 16-tile colour grid — ek listener container par, click hue tile ka rang badal jata hai. Fayde: kam listeners (efficient), aur baad me jude children par bhi apne aap kaam karta hai. Ye pattern Practice Labs me live hai.
target vs currentTarget target = jahan event SHURU hua (bubbling ke dauraan constant rehta hai). currentTarget = jis element ka handler ABHI chal raha hai.

Object basics

Object sambandhit data + functionality ka sangrah hai — asal duniya ki cheez (ek insaan) ko properties (name, age) + methods (sayHello, walk) me model karna.

Object literal const person = { name: "Chris", age: 38, bio() { ... } }; — properties data rakhti hain, methods properties me rakhe functions hain. Method shorthand bio() { ... }, purana bio: function() { ... } ki jagah.
Dot vs bracket notation person.age vs person["age"]. Bracket notation tab lazmi hai jab property ka naam ek variable me ho — person[propertyName]. Objects "associative arrays" (dictionary) ki tarah kaam karte hain.

How to use promises

Promise ki 3 states pending (chal raha hai) → fulfilled (value ke saath pura) ya rejected (reason/error ke saath fail). Ek baar settle ho jaye to state badalti nahi.
Core API .then(handler) success par, .catch(err) failure par, .finally() dono haal me (cleanup ke liye). fetch() promise deta hai — yahi sabse aam istemal hai.
Chaining — .then() naya promise deta hai Isiliye chains flat banti hain, nested nahi. Har step ki return value (ya returned promise) agle .then() ko milti hai.
Ek catch poori chain ki hifazat Chain ke end me ek .catch() kisi bhi step ki error pakadta hai — handlers ke andar throw hui exceptions bhi. Callback hell par yahi sabse badi jeet hai.
Promise.all / Promise.race Promise.all() — kai promises parallel, sab ke results order me; ek bhi reject ho to turant reject. Promise.race() — jo pehle settle ho, wahi jeeta.
Promise banana new Promise((resolve, reject) => { ... }) — executor turant chalta hai; success par resolve(value), failure par reject(reason). Classic pattern: setTimeout ko lapetna — const wait = ms => new Promise(r => setTimeout(r, ms));
Gotcha 1: .then() kabhi synchronously nahi chalta Promise pehle se resolved ho, tab bhi callback microtask queue me jata hai: Promise.resolve().then(() => console.log(2)); console.log(1); → pehle 1, phir 2.
Gotcha 2: return bhoolna = floating promise .then() ke andar promise return na karo to chain uska intezaar kiye bina aage badh jati hai.
Gotcha 3: fetch 404 par reject nahi hota Sirf network failure reject hota hai — response.ok khud check karo (Network requests section me bhi yahi kaha gaya tha).

Closures

Regular expressions

Regex text me pattern dhoondhne ki bhasha hai. Is section me overview ke saath chaaro sub-guides (Assertions, Character classes, Groups and backreferences, Quantifiers) bhi hain. Practice Labs me live regex tester hai.

Banane ke 2 tareeke Literal /pattern/flags (load par compile, constants ke liye fast) aur new RegExp("pattern", "flags") (runtime compile — pattern variable/user input se aaye to yahi; string me backslashes double-escape karo: new RegExp("\\d+")).
Flags g global, i ignore case, m multiline (^/$ har line par), s dotAll (. newlines bhi match kare), u unicode, y sticky (sirf lastIndex se match), d hasIndices (result me indices).
Methods regex.test(str) boolean; regex.exec(str) match array + index/input ya null; str.match(regex) (g ke saath saari matches, bina g ke pehli match + groups); str.matchAll(regex) (poore match objects ka iterator — g lazmi); str.search(regex) index ya -1; str.replace/replaceAll; str.split(regex).

Assertions — position match karte hain, characters nahi

Zero-width assertions ^ input ki shuruaat (ya m ke saath line ki), $ end, \b word boundary (word char \w aur non-word char ke beech), \B non-word boundary, lookahead x(?=y) (x ke baad y ho, y consume nahi hota) aur negative x(?!y), lookbehind (?<=y)x aur negative (?<!y)x. Misaalein: shabdon ke liye /\b\w+\b/g; password check /(?=.*[A-Z]) ("kam se kam ek uppercase"). Dhyaan: [^...] ke andar ^ ka matlab negation hai, start-of-input nahi.

Character classes

Classes aur escapes [abc] inme se koi ek; ranges [a-z], [0-9]; [^abc] negation (in KE ALAWA kuch bhi); . line terminators ke alawa koi bhi char (s flag ke saath wo bhi). Escapes: \d digit, \D non-digit, \w word char [A-Za-z0-9_], \W non-word, \s whitespace, \S non-whitespace; \t \n \r \f \v \0, \xHH, \uHHHH, \u{...} (u chahiye); \p{...} unicode property escapes (\p{Letter} — u lazmi). Alternation x|y character class NAHI hai — scope ke liye grouping chahiye: /(ab|cd)e/. Gotchas: [...] ke andar zyadatar special chars apna matlab kho dete hain, lekin ], \, shuru wala ^, range wala - ab bhi dhyaan maangte hain; \w sirf ASCII hai — asal shabdon ke liye \p{L} + u.

Groups and backreferences

Capturing, named, non-capturing (...) capturing group — pattern ko group bhi karta hai aur match yaad bhi rakhta hai (match[1], match[2]... opening paren ke order me). (?<name>...) named group — match.groups.name, zyada readable. (?:...) non-capturing — sirf group, yaad nahi; jab value na chahiye ho to yahi default rakho. Backreferences \1, \2 pehle group ke MATCHED TEXT ko dobara match karte hain — (['"]).*?\1 matching quotes wali quoted string pakadta hai; named version \k<name>. Replacement me $1 use hota hai: str.replace(/(\w+)@(\w+)/, "$2, $1"). Gotcha: g flag ke saath String.match() groups gira deta hai — matchAll() use karo.

Quantifiers

Greedy vs lazy * 0+, + 1+, ? 0 ya 1, {n} bilkul n, {n,} n ya zyada, {n,m} n se m ke beech. Quantifiers by default greedy hain (jitna zyada ho sake) — /<.*>/ "<b>hi</b>" ko poora kha jayega. ? lagao to lazy (jitna kam ho sake) — /<.*?>/ sirf "<b>" match karega. Classic demo: "[a] and [b]" par /\[.*\]/ vs /\[.*?\]/. Gotcha: nested quantifiers ((a+)+) lambe inputs par catastrophic backtracking kara sakte hain — patterns simple rakho.

Spread syntax

... kya karta hai ... ek iterable/object ko usi jagah phaila (expand) deta hai. Teen jagah: function calls f(...args) (Function.prototype.apply ki jagah), array literals [...a, ...b] (concat, copy, insert), object literals {...obj} (shallow copy, merge — baad wali properties jeet-ti hain).
Rest vs spread — ek hi token, ulte kaam Rest EK value me JAMA karta hai (destructuring/params me); spread EK value ko kai me PHAILATA hai. Context tay karta hai kaunsa hai.
Copy hamesha SHALLOW hoti hai [...arr] / {...obj} — nested objects share hote hain: copy.nested.x badla to asli bhi badla. Deep copy ke liye structuredClone(). Spread sirf enumerable OWN properties copy karta hai (prototype nahi, non-enumerables nahi) aur setters trigger NAHI karta (Object.assign karta hai — yahi farak hai).
Gotchas (1) Object spread ka order matter karta hai — {...defaults, ...user} me user jeet-ta hai. (2) Array/call spread ke liye iterable lazmi hai — plain object ko array me spread karna TypeError ([...{a:1}]); lekin koi bhi value object me spread ho sakti hai (non-objects kuch contribute nahi karte, strings apne indices deti hain). (3) Bahut bade arrays ko function call me spread karne par engine ki argument-length limit aa sakti hai.

Representing dates & times

MDN ka naya dates chapter — purana Date ab legacy hai; asal kahani Temporal ki hai.

Instant — ek pal, epoch se naapa hua Zyadatar date-times ek unique pal (instant) ko pehchante hain. Instant ek agreed epoch se nanosecond offset hai — JS (Unix ki tarah) January 1, 1970, 00:00:00 UTC use karta hai. Temporal.Instant yahi store karta hai (epochNanoseconds / epochMilliseconds). Instant akela time-of-day ya date nahi batata — uske liye calendar + time zone chahiye.
Calendars aur ISO 8601 Gregorian: 12 mahine/saal, 28–31 din/mahina, leap year ~har 4 saal — lekin dusre calendars alag hain, kabhi assume mat karo. Temporal.ZonedDateTime (ZDT) = Instant + calendar + time zone. Date fields: year/month/day, yearOfWeek/weekOfYear/dayOfWeek (year cross karne wala hafta dusre saal ka ho sakta hai), dayOfYear. Leap MONTHS bhi hote hain (Chinese calendar) — isiliye monthCode ("M07") computation ke liye hai aur naam Intl.DateTimeFormat se lo. Helpers: daysInMonth, daysInYear, inLeapYear...
Time zones — offset badalta rehta hai Time zone offset = UTC se farak. Offsets itihaas me badle hain: standardization (France 1911 me GMT par gaya), siyasat (kabze wala France Berlin ke +01:00 par — aaj bhi wahi hai; Samoa −11:00 se +13:00 par gaya aur Dec 30, 2011 gayab ho gaya), aur daylight saving time ("spring forward, fall back" — Paris +01:00 ↔ +02:00). ZDT helpers: hoursInDay (hamesha 24 nahi!), startOfDay() (hamesha 00:00 nahi!), getTimeZoneTransition(). Temporal.Now.timeZoneId() environment ka zone deta hai.
Plain types — jaankari jitni chahiye utni PlainDateTime = ZDT minus time zone; PlainDate = minus zone aur time; PlainTime = minus zone aur date; PlainYearMonth / PlainMonthDay poore mahine / har saal dohrane wali tareekh ke liye (in par arithmetic NAHI hoti). Kyun alag types? DST wala kamaal: Nov 3, 2024 (US clocks back) ko 00:00 + 12h — ZDT par 11:00 AM (asal duration), PlainDateTime par 12:00 PM (wall-clock) — shorba pakana (duration) vs 12 ghante ki shift (wall-clock) alag sawal hain.
Arithmetic, serialization, immutability add()/subtract()/since()/until(); Duration years…nanoseconds store karta hai (negative bhi). Sab Temporal objects immutable hain — with()/withCalendar()/withTimeZone() naye objects banate hain; overflow/transition bugs se bachne ke liye manual with() ki jagah add()/subtract() prefer karo. Serialization RFC 9557 (ISO 8601 par based) toString()/toJSON() se; wapas from() se parse. Comparison: static compare(a, b); equals() sakht hai (ZDT me zone + calendar bhi match). round() bhi hai.
Temporal.Now instant(), zonedDateTimeISO(), plainDateTimeISO(), plainDateISO(), plainTimeISO() — Temporal.Now.zonedDateTimeISO("Europe/Paris") system zone jo bhi ho, Paris ka current time deta hai.
Legacy Date — naye code me avoid karo Date ≈ millisecond epoch offset + ISO 8601 assumed ZDT jaisa. Pariwaar: "set", "get", "to", parse/UTC methods; getMonth() 0-indexed hai (December = 11). Kyun chhoda gaya: mutable hai; constructor/Date.parse() ke string formats standardize nahi ho sakte; fixed time zones nahi hain. Naye code me Temporal use karo (environment me na ho to polyfill).
Source: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Representing_dates_times

JavaScript typed arrays

Buffers — ArrayBuffer aur SharedArrayBuffer Memory ke ek span ke low-level representations. Naam me "array" hai lekin arrays se lagbhag koi lena-dena nahi — seedha padh/likh nahi sakte, ek VIEW chahiye. Buffer actions: allocate (nayi zero-filled memory), copy (slice()), transfer (transfer() — ownership move, asli unusable; SharedArrayBuffer transfer NAHI ho sakta), resize (maxByteLength tak; SAB sirf GROW ho sakta hai, shrink nahi).
ArrayBuffer vs SharedArrayBuffer ArrayBuffer ek waqt me ek hi execution context ka hota hai — kahin bhejna = transfer, asli gaya. SharedArrayBuffer transfer nahi hota — kai contexts ek saath access karte hain, isiliye race conditions mumkin hain aur Atomics kaam aata hai (Agents section dekho).
Views — typed arrays aur DataView Typed array views data ko type ke hisaab se padhte hain; DataView low-level granular control deta hai. Dono ke paas buffer, byteOffset, byteLength hote hain; ArrayBuffer.isView() dono par true deta hai. Typed array constructors length ko BYTES me nahi, ELEMENTS me lete hain.
Types (sab ek hi TypedArray methods share karte hain) Int8Array (−128..127, 1 byte), Uint8Array (0..255, 1), Uint8ClampedArray (0..255, 1 — values ko CLAMP karta hai, Canvas data ke liye), Int16Array (2 bytes), Uint16Array (2), Int32Array (4), Uint32Array (4), Float16Array (2), Float32Array (4), Float64Array (8), BigInt64Array (8), BigUint64Array (8).
Fixed length — push/pop/splice nahi Length badalne wale methods (pop, push, shift, splice, unshift, flat, concat, flatMap) NAHI hain; baaki array methods shared hain. Extra: set() (kai indices ek saath, tezi se) aur subarray() (usi buffer par naya, sankra view). Resizable buffer par bina fixed byteLength wala view length-tracking hota hai — buffer ke saath apne aap resize hota hai.
Bracket access proxied hai Out-of-bounds read → undefined; out-of-bounds write khamoshi se kuch nahi karta. uint8[-1] = 0, uint8[2.5] = 0, uint8[NaN] = 0 sab no-ops hain; Object.keys(uint8) → ["0","1","2"]. Object.freeze(uint8) TypeError deta hai.
DataView kab jeet-ta hai Jab endianness control chahiye (default big-endian; little-endian getter/setter args se), mixed types ek hi buffer me, ya unaligned offsets par multi-byte reads/writes. Typed arrays platform ke native byte order par chalte hain.
Ek hi memory, kai interpretation 16-byte buffer par Int32Array view 0,2,4,6 rakhta hai; usi buffer par Int16Array view use 0, 0, 2, 0, 4, 0, 6, 0 padhta hai (little-endian); Float32Array view unhi bits ko ek chhoti float value ki tarah padhta hai. Text: TextDecoder().decode(uint8) UTF-8 ke liye. Typed arrays use karne wali APIs: FileReader.readAsArrayBuffer(), fetch() body, ImageData.data (RGBA Uint8ClampedArray). Normal array me wapas: Array.from(typedArray) ya spread.

JavaScript resource management

Kuch cheezein khud band karni padti hain — file handles, network connections, stream readers. Bhool gaye to leak.

Problem fileHandle.close() bhoolna (Node khud band karne ki koshish karega lekin MDN saaf kehta hai — is par bharosa mat karo), WebSocket/RTCPeerConnection (connection pools bahut limited hain), reader.releaseLock() bhoolna — stream lock reh jata hai aur dusra reader TypeError deta hai.
Manual release kyun dard hai (1) Inconsistency — har resource alag tareeke se band hota hai (close(), releaseLock(), disconnect()…). (2) Error handling — beech me throw ho to release wali line tak pahunchte hi nahi (fix try...finally hai, lekin har baar yaad rakhna padta hai). (3) Scoping — variable band hone ke baad bhi usable dikhta hai. (4) Multiple resources — do readers ke liye do nested try...finally; dusra acquire fail ho to pehla leak, pehle ka release fail ho to dusra leak.
Hal: using / await using declarations const jaise, lekin variable scope se bahar jate hi (normal exit, error, return/break/continue — har haal me) resource apne aap release ho jata hai: { using reader1 = stream1.getReader(); using reader2 = stream2.getReader(); /* use karo */ } — extra braces block scope banate hain. using script ke top level par nahi chal sakta (script-scope variables hamesha rehte hain — resource kabhi free nahi hoga), lekin module ke top level par chal sakta hai.
Disposable protocol Resource disposable tab hai jab uske paas [Symbol.dispose]() method ho. Disposal order: reverse declaration order (reader2 pehle, reader1 baad me); ek ki disposal error dusron ko nahi rokti. await using ko [Symbol.asyncDispose]() chahiye (promise return kare) — cleanup sequential hota hai, concurrent nahi. Non-disposable par using lagaya to declaration line par hi TypeError; null/undefined allowed hain (conditional acquisition). Dispose method declaration ke waqt save ho jata hai — baad me badalna be-asar hai.
DisposableStack / AsyncDisposableStack Jab using fit na ho (acquire ek scope me, dispose dusre me): use(resource) disposable register karta hai; adopt(resource, disposeFn) protocol-na-manene wale resource ko lapet-ta hai (jaise object URL: disposer.adopt(url, URL.revokeObjectURL)); defer(fn) bina-resource wali cleanup action; move() resources bahar transfer karta hai — constructor pattern: local stack me banao, safal ho to this.#disposables = disposer.move(), fail ho to local stack dispose kar dega. Stack khud disposable hai: using disposer = new DisposableStack().
SuppressedError using errors ko nigalta NAHI — body ki error throw hoti hai, bas pehle resources band hote hain. Cleanup bhi throw kare to dono ek SuppressedError me jati hain: error = BAAD wali error, suppressed = PEHLE wali. Do failing resources par chain banti hai: aakhir me release hue ki error e.error me, pehle wali e.suppressed.error me, asal body error e.suppressed.suppressed me.
Chaabiyan (pitfalls) using bhoolna (koi syntactic clue nahi ki kuch disposable hai — type checker + linter chahiye); use-after-free (aliases/closures resource ko scope ke baad bhi zinda rakh sakte hain — JS me Rust jaisi ownership nahi); har resource ki semantics samajhna ab bhi zaroori hai. Ek sundar pattern: Promise.all + AbortController ko adopt karna — koi request fail ho to baaki in-flight requests abort ho jati hain.
Source: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Resource_management

Internationalization

Intl object — har kaam ke liye ek class Locale info (Intl.Locale); formatting (Intl.DateTimeFormat, DurationFormat, ListFormat, NumberFormat, RelativeTimeFormat); collation (Intl.Collator); plurals (Intl.PluralRules); segmentation (Intl.Segmenter); display names (Intl.DisplayNames).
Shared design (Intl.Locale ke alawa) sab ek jaise: new Intl.SomeObject(locales, options) banao, phir format() / compare() / segment() call karo. locales BCP 47 tag, Intl.Locale, ya unka array; undefined = runtime default. Formatter object ek baar bana kar baar-baar use karo — har call database dobara nahi dhoondta.
BCP 47 tags Locale = language (lazmi) + script + region + variants, - se jude. Region bahut matter karta hai (en-US MM/DD/YYYY vs en-GB DD/MM/YYYY); script bhi (sr-Latn vs sr-Cyrl, zh-Hans vs zh-Hant). Conventions -u- extension se ya options se: calendar (gregory vs hebrew — 2022-01-01 = "28 Tevet 5782"), hourCycle, numberingSystem, collation (German phonebk ä ko ae manta hai), caseFirst, numeric ("10" "2" ke baad). Defaults resolvedOptions() se milte hain — new Intl.Locale("en-US").calendar undefined hai kyunki Locale sirf wahi rakhta hai jo tumne diya.
Kaunsa locale use karein navigator.languages browser preference deta hai, lekin andhe bankar mat use karo — site sirf English/French me ho to Japanese visitor ko Japanese numbers/dates ke saath English text milega (ajeeb mixture). Site ki apni bhasha prefer karo: language switcher, backend ka Accept-Language, document.documentElement.lang, ya hardcoded locale. Fallback arrays ghat-te order me do (["yue-Hant","zh-Hant-HK","zh-Hant","zh"] — pehla supported jeet-ta hai). Helpers: Intl.getCanonicalLocales(), har class ka supportedLocalesOf().
Output ki guarantee nahi hai Results engines ke beech badal sakte hain (V8 vs SpiderMonkey — dono CLDR data use karte hain lekin post-processing alag); output me non-breaking spaces ya bidi control characters ho sakte hain. Intl output ko kabhi hardcoded constants se compare mat karo — sirf dikhao. Testing: saare supported locales test karo, kai engines par, expected output haath se mat likho — snapshot testing karo.
format() vs formatToParts() vs toLocaleString() Har formatter ke paas dono hain; formatToParts() {type, value} parts deta hai (currency $, integer 5, decimal ....) taaki beech me apna text ghusa sako. toLocaleString() shortcut hai (Number.prototype.toLocaleString() waghera) lekin har call localization database dobara dhoondta hai — repeated calls ke liye formatter object hi efficient hai.
DateTimeFormat Inputs: Date, Temporal plain types. Kaam: dusra calendar (Islamic/Hebrew/Chinese), dusra time zone, chune hue components ("Thursday" vs "Thu"), locale conventions (12h vs 24h). Components do tareeke se — manual per-component options, ya dateStyle/timeStyle shortcuts — dono ek saath use karna error hai. formatRange(start, end) common hisse deduplicate karke range banata hai ("March 10 – 26, 2023").
NumberFormat Inputs number/string/BigInt. Pehle numberingSystem, phir style: "decimal", "percent" (×100), "currency" (+ currency option), "unit" (+ unit). notation: "scientific", "engineering", "compact" ("short" → 12K, "long" → 12 thousand). Digit options (min/max fraction vs significant digits, rounding...) — {minimumFractionDigits: 4, maximumFractionDigits: 4} par 1234.56789 → 1,234.5679; significant wale par → 1,235. Asal separator/decimal/sign characters locale ke hote hain, customize nahi hote.
ListFormat, RelativeTimeFormat, DurationFormat ListFormat arrays ko locale-sahi jodta hai — "apple, banana, and cherry" (type:"conjunction"), "or" wali ("disjunction"), units wali ("unit") — har bhasha me comma nahi hota aur Oxford comma par English me bhi behes hai. RelativeTimeFormat {numeric:"auto"} ke saath format(1, "day") → "tomorrow", format(-1, "hour") → "1 hour ago". DurationFormat durations ko ("3 hours, 4 minutes, and 5 seconds") format karta hai.
Collator — sorting ke liye === / > mat use karo compare(a, b) Array.sort ke compareFn jaisa number deta hai. Kyun chahiye: orthographic variants (naïve vs naive barabar hone chahiye), case (apple vs Apple), code-point order ≠ dictionary order (ï code point se z ke baad hai lekin i ke paas hona chahiye), normalization (ñ ek char vs n + combining tilde), strings me numbers ("test-10" "test-2" ke baad). Ek hi locale me bhi orders alag hain: German phonebook (ä = ae) vs dictionary (umlauts ignore, sirf farak padne par).
PluralRules aur Segmenter PluralRules.select(n) plural CATEGORY deta hai (one, two, few, other…) — shabdon ko pluralize NAHI karta, wo tumhara kaam hai. type:"cardinal" (default) vs "ordinal" (1st/2nd/3rd). Segmenter strings ko graphemes (user ko dikhne wale characters — 🇺🇸🇨🇳🇷🇺🇬🇧🇫🇷 = 20 UTF-16 code units, 10 code points, lekin 5 graphemes), words (Chinese me bhi chalta hai — har bhasha spaces nahi use karti), sentences me todta hai. Segments {segment, index, isWordLike} objects hain.
UI helpers Intl.supportedValuesOf("calendar") supported values deta hai — dropdowns isse bharo. Intl.DisplayNames identifiers ko localized naamo me badalta hai (types: language, region, script, currency, calendar, dateTimeField). Practice Labs me Intl playground live hai.

JavaScript data types and data structures

Dynamic + weakly typed Variables kisi type se bandhe nahi hote — ek variable har type ki value rakh sakta hai (let foo = 42; foo = "bar"; foo = true;). Weakly typed = type na mile to error ki jagah implicit conversion (42 + "1" → "421"). Suhuliyat hai, lekin galat direction me hue conversion se subtle bugs bhi. Symbol aur BigInt ke implicit conversions jaanboojh kar mana hain.
Primitives aur typeof table Object ke alawa sab types primitives hain (immutable, seedha represented). typeof: Null → "object" (test === null se karo), Undefined → "undefined", Boolean → "boolean", Number → "number", BigInt → "bigint", String → "string", Symbol → "symbol". null/undefined ke alawa sab ke wrappers hain; primitive par property access use apne aap wrapper me lapet deta hai; null/undefined par property access TypeError deta hai — yahi optional chaining ki wajah hai.
null vs undefined undefined = value ki अनुपस्थिति (bare return;, missing property, uninitialized let x;, find()/Map.get() ke misses). null = object ki अनुपस्थिति — sabse aham istemal prototype chain ke end par. null ek keyword hai; undefined ek aam identifier (global property) hai — asal me farak mamuli hai kyunki undefined ko kabhi redefine/shadow nahi karna chahiye.
Number — IEEE 754 ki sachchai Double-precision 64-bit. Safe integers sirf ±(2^53 − 1) tak (Number.MIN_SAFE_INTEGER/MAX_SAFE_INTEGER, check Number.isSafeInteger()) — usse bahar integers approximate ho jate hain. Range se bahar: Infinity, -Infinity, 0, -0. +0 vs −0: +0 === -0 true hai, lekin 42 / +0 = Infinity aur 42 / -0 = -Infinity. NaN — ill-defined arithmetic ka result; JS ki ekmatra value jo khud ke barabar nahi. Bitwise operators numbers ko pehle 32-bit integers me badalte hain.
BigInt Arbitrary-bade integers ke liye — n suffix ya BigInt() se banta hai. Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2 TRUE hai (dono 9007199254740992), lekin BigInt ke saath FALSE — yahi iska kaam hai. 1n !== 1 (strict) lekin 1n == 1 (loose). Fractions nahi rakh sakta; BigInt aur Number ko arithmetic me milana TypeError deta hai; >>> mana hai.
String — UTF-16 aur immutability String 16-bit UTF-16 code units ka sequence hai; length code units ginta hai — jo asal Unicode characters ki gintee se alag ho sakti hai. Strings immutable hain — methods nayi strings dete hain. "Stringly-typing" ki chetaavni: complex data ko strings me rakhna aasan lagta hai lekin separators/escapes toot-te hain — text ke liye strings, complex data ke liye proper structures me parse karo.
Symbol aur Object Symbol ek unique, immutable primitive hai jo property key ban sakta hai — dusre code ki keys se takrane ki guarantee ke saath. Object hi ekmatra mutable values hain; functions callable objects hain. Keys strings ya symbols (dusre types string me badal jate hain). Do property prakaar: data property (value, writable, enumerable, configurable) aur accessor property (get/set, enumerable, configurable). [[Prototype]] hidden property dusre object ya null ki taraf ishara karti hai. Arbitrary data ke liye objects ki ergonomics/security/performance samasyaein hain — Map use karo.
Coercion ke teen raaste Primitive coercion (koi preferred type nahi — +, == object ke saath): [Symbol.toPrimitive]("default") → valueOf() → toString(). Numeric: hint "number", wahi order. String: hint "string" — order ULTA: toString() → valueOf(). Worked example: {} + [] → "[object Object]" (valueOf object deta hai isiliye ignore, toString kaam karta hai). [Symbol.toPrimitive]() primitive na de to TypeError; sirf Date aur Symbol ise override karte hain.

Equality comparisons and sameness

JS me barabari check karne ke CHAAR tareeke hain — aur ye ek "loose se strict" spectrum nahi hai.

Strict equality === Koi implicit conversion nahi. Types alag → unequal. Numbers: barabar jab dono NaN na hon aur value ek ho, YA ek +0 aur dusra −0 ho. Lagbhag hamesha sahi choice yahi hai. Yehi Array.prototype.indexOf() aur case-matching bhi use karte hain — isiliye [NaN].indexOf(NaN) -1 hai aur switch (NaN) { case NaN: } kabhi match nahi hota. Do edge cases ye nazar-andaaz karta hai: signed zero, aur NaN (khud samet har cheez se unequal — (x !== x) sirf tab true jab x NaN ho).
Loose equality == Symmetric hai. Algorithm: same type → value compare; ek null/undefined ho to dusra bhi wahi hona chahiye (null == undefined true); object vs primitive → object primitive me convert; boolean → number (true→1); number vs string → string number me; number vs BigInt → mathematical value; string vs BigInt → BigInt() conversion (fail → false). Misaal: 0, 0n, "0", new String("0") — chaaro ke saare pairwise == TRUE hain. Loose equality predict karna mushkil aur coercion ki wajah se slow hai — discouraged hai. (Quirk: document.all kuch contexts me undefined jaisa vyavhaar karta hai.)
Same-value equality — Object.is() Do values har context me functionally identical hain ya nahi. === se do jagah alag: Object.is(NaN, NaN) → true; Object.is(+0, -0) → false. Internally wahi jagah use hota hai jahan equivalent identity chahiye (jaise Object.defineProperty se immutable property ko wahi value se redefine karna no-op hai, alag value throw karti hai).
Same-value-zero equality Same-value jaisa, lekin +0 aur −0 barabar. Ye koi JS API ke roop me exposed NAHI hai — lekin Array.prototype.includes(), TypedArray.prototype.includes() aur Map/Set ki key comparison YAHI use karti hai. Isiliye includes NaN ko dhoondh leta hai jabki indexOf nahi.

Memory management

Memory life cycle Har language me: (1) memory allocate karo, (2) use karo (read/write), (3) zaroorat khatm ho to release karo. Step 2 har jagah explicit hai; steps 1 aur 3 JS me zyadatar implicit (automatic) hain.
Allocation JS me kab hoti hai Value initialization par (const n = 123, literals, addEventListener ko diya () => {}), function calls se (new Date(), document.createElement("div")), aur nayi values dene wale methods se (s.substring(0, 3) — strings immutable hain isiliye engine sirf range store kar sakta hai; a.concat(a2) — naya array). Sabse zyada memory samasyaein "use" wale hisse me hoti hain — asal mushkil ye jaanna hai ki memory kab bekaar hui.
Reference-counting GC — naïve, koi modern engine nahi use karta Zero references wala object garbage. Fatal flaw — circular references: x.a = y; y.a = x; function ke andar; function return ke baad dono bekaar hain lekin har ek ke paas ek reference hai, isiliye kabhi collect nahi hote. Circular references memory leaks ki aam wajah hain.
Mark-and-sweep — saare modern engines yahi use karte hain "Bekaar" ko "unreachable" se badal do. Roots (JS me global object) se shuru karo, recursively jo kuch referenced hai use mark karo; jo na pahuncha, sweep. Zero-reference wale unreachable hote hi hain, aur cycles bhi handle ho jate hain (function ke baad x/y pair global se unreachable hai — collect ho jayega). Generational/incremental/concurrent GC isi algorithm ke sudhaar hain, nayi paribhasha nahi. Seema: GC ko manually control ya trigger NAHI kar sakte (core JS me shayad kabhi nahi); object free karna ho to use explicitly unreachable banao.
WeakMap/WeakSet GC ke saath kaise kaam karte hain Keys kamzor (weakly) pakdi jati hain — mark-and-sweep key ko sirf WeakMap ke hawale se reachable nahi manta; key kahin aur se referenced na ho to collect ho sakti hai, phir value bhi. Do guarantees isiliye hain: (1) keys sirf objects ya non-registered symbols (primitives forge ho sakte hain — 1 === 1 lekin {} !== {} — wo hamesha rehte; registered symbols jaise Symbol.for("key") bhi forgeable hain, isiliye mana; well-known symbols jaise Symbol.iterator fixed hain, isiliye allowed); (2) iterable nahi (liveness observe karna ya collect hone wali key pakadna mumkin nahi hona chahiye — GC jitna invisible ho utna behtar).
Ephemeron trap Value khud key ko reference kare (wm.set(key, {key})) to key collect nahi ho payegi — value strongly held hai, key latak jayegi. Fix: entries ephemerons hain — key ki connectivity value ki connectivity tay karti hai, ulta nahi; GC teen phases me chalta hai (mark, ephemeron resolution, sweep). Mental model: WeakMap keys rakhta hi nahi — data key object par hi ek hidden #marker Symbol se chipka deta hai; isiliye iteration aur clear() namumkin hain.
WeakRef aur FinalizationRegistry WeakRef object ka weak reference hai — object GC ho sakta hai, zinda ho to deref() se milta hai, mar jaye to undefined. Kaam: cache Map<string, WeakRef<blob>> (WeakMap yahan nahi chalega — uski KEYS weak hoti hain, values nahi). FinalizationRegistry collection par notify karta hai — jaise murda WeakRef wali stale cache entries hatana (pehle !cache.get(key)?.deref() check lazmi, warna callback usi key par lagi NAYI live entry uda sakta hai). Callback kab fire hoga — ya hoga bhi — iski koi guarantee nahi. Jahan mumkin ho dono se bacho; critical cleanup ke liye deterministic tareeke (try...finally, using) use karo.
Aam leak sources Bhooli hui globals, kabhi na hatne wale timers/listeners, DOM nodes pakde hue closures.

Agent communication and coordination

Agents = alag-alag JS execution contexts (jaise main thread aur workers). JS spec khud agents banane ki API NAHI deta — web par workers hain, aur baat-cheet messages aur shared memory se hoti hai.

Messages aur MessageChannel Parent new Worker("./worker.js", {type: "module"}) banata hai; default channel: parent worker.postMessage() bheje, message event par sune; worker self.postMessage() / message on self. Kisi bhi do agents ke liye dedicated MessageChannel — const {port1, port2} = new MessageChannel(); ek port worker ko transfer list ke saath do, phir port.start() karke sunna shuru karo.
Data bhejne ke 3 model (1) Copying (default): har agent ka apna heap; postMessage structured clone se copy karta hai (fixed supported types; unsupported par DOMException). Copies independent hain lekin reconstruction ki memory cost hai; MessagePort copy NAHI ho sakta — sirf transfer. (2) Transferring: dusra argument transfer list deta hai; source detached ho jata hai (transferred ArrayBuffer ka byteLength 0, operations throw). Pure-JS transfer: buffer.transfer() / transferToFixedLength(). (3) Sharing: sirf SharedArrayBuffer — dono taraf alag instances, ek hi memory; mutations dono ko dikhte hain.
SharedArrayBuffer par pabandi kyun Shared memory high-precision clock bana sakti hai (Spectre risk) — isiliye browsers use sirf cross-origin isolated sites par dete hain (headers: Cross-Origin-Embedder-Policy: require-corp + Cross-Origin-Opener-Policy: same-origin; check: window.crossOriginIsolated === true). Sharing sirf ek agent cluster ke andar hoti hai (window + uska dedicated worker ek cluster hai). SAB transfer/detach nahi ho sakta; resizable SAB sirf grow() ho sakta hai; view bhejne se view+buffer objects copy hote hain lekin memory shared rehti hai.
Ordering problem aur data race Ek agent ke andar run-to-completion ordering ki guarantee deta hai; agents ke beech koi guarantee nahi. Race demo: dono agents shared Int32Array par 10,000,000 baar i[0] += 1 karein — final value aam taur par 20,000,000 se KAM hoti hai aur har run alag, kyunki += read-add-write hai — dono ek hi purani value padh kar ek increment gayab kar sakte hain.
Atomics.load/store Plain indexed read/write ki koi visibility guarantee nahi — compiler/CPU operations reorder kar sakta hai (guide saabit karta hai ki dono console.log 0 print kar sakte hain jabki code-order se kam se kam ek non-zero hona chahiye). Atomics.load/store reordering rokte hain aur synchronization points banate hain: atomic store se PEHLE ki non-atomic writes, matching atomic load ke BAAD ki reads ko dikhti hain ("ready flag" pattern).
Compound atomic ops Atomics.add/sub/and/or/xor += waghera ki jagah — har read-modify-write ek atomic block hai, kabhi interleave nahi hoti (10M+10M race ab bilkul 20,000,000 deti hai). Atomics.compareExchange() (CAS) read → check → write ki jagah leta hai — atomicMultiply pattern while (true) me tab tak retry karta hai jab tak observed === oldValue na mile. Atomics.exchange() bina shart swap — purani value padhte hue reset (load+store me baantne se beech ke increments khamoshi se gir jate).
Wait karne ke tareeke Busy waiting (while (Atomics.load(...) !== 1);) thread block karta hai; Atomics.pause() CPU ko hint deta hai. Atomics.wait() block karke CPU chhod deta hai; likhne wala Atomics.notify() se jagata hai — dono sirf Int32Array/BigInt64Array par. Atomics.wait() web ke main thread par THROW karta hai (wo thread ke dusre jobs rok dega); wapas aane ke karan: "ok" / "not-equal" / "timed-out". Atomics.waitAsync() promise deta hai ({async, value}) — main thread par bhi chal sakta hai. Trade-offs: bahut chhote waits ke liye busy waiting sabse tez; lambe waits ke liye wait sabse efficient; thread ke paas dusre aham kaam hon to waitAsync best.
Mutex, semaphore, deadlock Mutex: ek waqt me ek agent critical section me. Implementation: shared[0] = 1 unlocked / 0 locked; lock() = CAS loop + Atomics.wait; unlock() = store + notify; critical sections ko try...finally me lapeto taaki throw par bhi lock chhute. Dhyaan: mutex sirf ek PROTOCOL hai — physically kuch block nahi hota; sab agents use maanein tabhi kaam karta hai. Sudhaar: owner ID, re-entrancy counter (nested lock() self-deadlock karta hai), fairness. Spinlock variant: wait ki jagah busy waiting + Atomics.pause() — kam contention par efficient, lekin main thread par KABHI nahi. Semaphore: mutex ka generalization — N agents ek saath (permit count CAS se ghatao, 0 par wait; release par Atomics.add + notify); permits = 1 matlab binary semaphore = mutex. Deadlock: agents cycle me ek dusre ka intezaar karein (A ke paas X hai, Y chahiye; B ke paas Y hai, X chahiye) — bachav: fixed lock-acquisition order, try...finally release, discipline.
Torn reads aur lock-free code Byte-by-byte padhi gayi multi-byte value beech me badal jaye to tear ho sakti hai. Ek hi element ki atomic reads/writes kabhi tear nahi hotin; Atomics.isLockFree(size) batata hai kaunsi sizes (isLockFree(4) → true, isLockFree(7) → false). Int16/Uint16/Int32/Uint32 indexed access se bhi kabhi tear nahi hote; floats ko Atomics ya haath ka lock chahiye. Lock-free code = CAS retry loops — koi explicit lock nahi, uncontended sabse tez, contention par retries.
Handoff pattern (producer/consumer) Lock + readiness flag ek saath: shared[0] = state (0 empty / 1 full), shared[1] = value. Producer empty ka intezaar karke likhe, store(0, 1), notify; consumer full ka intezaar karke padhe, store(0, 0), notify. Shart: bilkul ek producer aur ek consumer — kai producers khaali slot dekh kar ek dusre ko overwrite kar sakte hain (unhe apas me mutex chahiye).

    Interview FAQs

    Current-era interviews me sabse zyada poochhe jane wale JavaScript sawal — har jawab usi section se juda hai jo is SPA me padhaya gaya hai. Sawal par tap karke jawab kholo.

    JavaScript kya hai? HTML aur CSS se kaise alag hai?

    Teen layers: HTML = structure/content, CSS = styling, JavaScript = dynamic behaviour. Bina JS page static hai; JS use interactive banata hai — values store karna, events par react karna, DOM badalna.

    Browser APIs vs third-party APIs — farak aur misaalein?

    Browser APIs browser me built-in hain (DOM, Geolocation, Canvas, Audio/Video) aur JS language ka hissa nahi hain. Third-party APIs dusre developers/services ki hain (map embed, social feed, payment) — aam taur par library ke roop me load hoti hain, aksar API key ke saath.

    JavaScript interpreted hai ya compiled? JIT kya hai?

    JS interpreted language hai, lekin modern engines speed ke liye JIT (just-in-time) compilation use karte hain — code chalte-chalte machine code me badalta hai.

    <script> kahan rakhein — body ke end, head, defer ya async?

    Normal script head me HTML parsing rok deta hai. Body ke end me rakho, ya defer (parallel download, parse ke baad, order me chale) ya async (taiyaar hote hi chale, order ki guarantee nahi). Modules by default deferred hote hain.

    Inline event handlers (onclick="...") kyun kabhi use nahi karne chahiye?

    HTML aur JS mil jate hain, maintain karna mushkil hota hai, aur kai server security configs (CSP) inhe block karte hain. addEventListener use karo.

    var vs let vs const — saare farak?

    var: function/global scope, hoist hota hai, dobara declare ho sakta hai. let: block scope, dobara declare par SyntaxError, reassign ho sakta hai. const: block scope, initialize lazmi, reassign nahi — lekin object/array ki contents badal sakti hain (binding constant hai, value nahi). Rule: const jab ho sake, let jab zaroorat ho, var kabhi nahi.

    Hoisting kya hai? Kya hoist hota hai, kya nahi?

    Declarations ka code ke upar uth jana. Function declarations poori hoist hoti hain (pehle call kar sakte ho); var declaration hoist hoti hai lekin value nahi; let/const/classes TDZ me hote hain — declaration se pehle use karne par ReferenceError.

    undefined vs "not defined" (ReferenceError) me farak?

    Declare karke value na di ho → undefined (variable exist karta hai). Kabhi declare hi na hua ho → use karne par ReferenceError.

    typeof null kya deta hai, kyun? Aur typeof NaN?

    typeof null → "object" — language ki mashhoor purani galti; null test karne ke liye === null use karo. typeof NaN → "number" — isiliye validation me Number.isNaN() bhi lazmi hai.

    "74" + 3 = "743" kyun, 77 kyun nahi?

    Ek operand string hai to + addition ki jagah concatenation ban jata hai — 3 string me badal kar jud jata hai. Pehle Number("74") se convert karo to 77 milega.

    == vs === — hamesha strict kyun?

    == type coercion karta hai ("5" == 5 true), jo subtle bugs deta hai. === bina conversion ke compare karta hai ("5" === 5 false) — predictable hai. Hamesha ===/!==.

    x++ vs ++x me farak?

    x++ pehle purani value return karta hai, phir badhata hai. ++x pehle badhata hai, phir nayi value deta hai. let y = x++; me y ko purani value milegi.

    6 falsy values kaunsi hain?

    false, undefined, null, 0, NaN, '' (empty string). Baaki sab truthy — [], {}, "0", "false" samet. (Guide ki poori list me -0 aur 0n bhi hain.)

    String ka aakhri character kaise milega?

    str[str.length - 1] — ya naye tareeke se str.at(-1).

    indexOf() na milne par kya deta hai aur kyun matter karta hai?

    -1 deta hai. Matter isiliye karta hai kyunki -1 truthy hai — if (str.indexOf("x")) jaisa code galat chalega; hamesha !== -1 ya includes() se check karo.

    slice vs splice me farak?

    slice copy banata hai (asli array safe), end exclusive hai. splice asli array ko badalta hai — items hatata/jodta hai. Strings par slice wahi copy-wala kaam karta hai.

    replace() sirf pehli occurrence kyun badalta hai? Sab kaise badlein?

    String pattern ke saath replace() pehli match hi badalta hai aur nayi string deta hai (strings immutable hain). Sab badalne ke liye replaceAll(), ya g flag wala regex.

    push() kya return karta hai? pop() kya?

    push() nayi length; pop() hataya gaya item. unshift() bhi nayi length, shift() bhi hataya item.

    map() vs forEach() vs for...of — kab kaunsa?

    map() jab results ka NAYA array chahiye. forEach() jab sirf har item par kuch karna hai (kuch return nahi karta). for...of jab loop ko beech me rokna (break) ya index ke saath kaam ho — aur ye async/await ke saath bhi seedha chalta hai.

    if (x === 5 || 7 || 10) me bug kya hai?

    7 aur 10 apne aap me truthy hain, isiliye condition hamesha true hai. Har test poora likho: x === 5 || x === 7 || x === 10.

    switch me break bhool jao to kya hota hai?

    Fall-through — execution agle cases me girti rehti hai jab tak break ya switch ka end na mile. Kabhi-kabhi jaanboojh kar use hota hai, aam taur par bug hai.

    break vs continue — misaal ke saath?

    break loop pura khatm (contacts me naam milte hi search roko). continue sirf current iteration skip (integer squares list karte waqt non-integers skip karo).

    Function declaration vs expression — kaunsi hoist hoti hai?

    Declaration (function foo() {}) hoist hoti hai — pehle call kar sakte ho. Expression (const foo = function() {}) nahi — defining line se pehle call par ReferenceError.

    Parameters vs arguments me farak?

    Parameters definition me likhe naam hain; arguments call ke waqt di gayi asal values. Missing argument undefined hota hai, jab tak default value na ho.

    addEventListener("click", myFunc()) kyun toot-ta hai, myFunc kyun chalta hai?

    Parentheses function ko TURANT chala dete hain aur uski return value (aam taur par undefined) handler ban jati hai. Bina parentheses ke function ka reference jata hai — click par chalega. Arguments dene hon to arrow wrapper: () => myFunc("hi").

    Scope kya hai? Global vs function vs block?

    Variable kahan dikhai deta hai, wahi uska scope. Global = sab jagah; function scope = usi function ke andar; block scope = usi {} block ke andar (let/const). var blocks se bahar leak ho jata hai.

    Function bina return ke kya return karta hai? return kya karta hai?

    undefined. Aur return function ko wahi turant khatm karke value caller ko de deta hai — uske baad ka code nahi chalta.

    Event listener vs event handler me farak?

    Listener mechanism hai (addEventListener()); handler wo function hai jo event par chalta hai. Bolchal me dono ek dusre ke liye use ho jate hain.

    Event bubbling kya hai? Handlers kis order me chalte hain?

    Event target element se shuru hokar har ancestor par chadhta hai: BUTTON → DIV → BODY → HTML → document. Capture phase iska ulta hai ({ capture: true } se).

    stopPropagation() kya karta hai? Kab use karein?

    Event ko ancestors ki taraf aage badhne se rok deta hai. Kab: jab child ka handler parent ke handler ko trigger na kare — jaise video par click karne se poora box hide na ho jaye.

    Event delegation kya hai aur kyun behtar hai?

    Har child par listener ki jagah parent par EK listener, aur event.target se pata karo kaunsa child click hua. Fayde: kam listeners, aur baad me jude children par bhi apne aap kaam.

    event.target vs event.currentTarget?

    target = jahan event shuru hua (bubbling me constant). currentTarget = jis element ka handler abhi chal raha hai.

    preventDefault() kya karta hai? Asal misaal do.

    Browser ka default action rokta hai. Misaal: form submit par validation fail ho to e.preventDefault() karke form bhejne se roko aur error dikhao.

    Dot notation vs bracket notation — bracket kab LAZMI hai?

    Jab property ka naam variable me ho (person[propertyName]), ya naam me spaces/special characters hon, ya naam runtime par bane. Warna dot saaf aur aam hai.

    Method ke andar this kya hota hai?

    Wo object jis par method call hua (dot se pehle wala). Isiliye ek hi method alag-alag objects ke data ke saath kaam karta hai. Dhyaan: method ko callback ki tarah alag karke pass karne par this kho jata hai.

    new keyword asal me kya karta hai (4 steps)?

    (1) Khaali object banata hai, (2) this ko usse bandhta hai, (3) constructor ka code chalata hai, (4) object return karta hai.

    Factory function vs constructor function?

    Factory ek aam function hai jo naya object bana kar return karta hai — new nahi chahiye. Constructor new ke saath chalta hai, this par properties lagata hai, naam Capital se shuru hota hai.

    querySelector vs getElementById? querySelectorAll kya deta hai?

    querySelector koi bhi CSS selector lekar pehla match deta hai — aaj ka recommended tareeka. getElementById sirf id se, purana tareeka. querySelectorAll saare matches ki NodeList deta hai (asal array nahi).

    fetch() kya return karta hai?

    Ek Promise — data NAHI. Promise pehle Response object par resolve hota hai; data ke liye ek aur step chahiye: response.json() ya response.text() (dono bhi promises dete hain).

    fetch() 404 par reject kyun nahi hota? HTTP errors kaise handle karein?

    Fetch sirf network failure ko rejection manta hai; 404 ek valid response hai, isiliye promise resolve hota hai. Khud response.ok check karo aur false ho to throw new Error(...) karo taaki .catch() use pakde.

    JSON JS object literal se kaise alag hai? JSON me kya allowed nahi?

    JSON sakht hai: keys aur strings hamesha double quotes me, no trailing commas, no comments. Allowed nahi: functions, undefined, NaN, Infinity, Date, Set, Map, single quotes. JSON.parse() string → object; JSON.stringify() object → string.

    Teen tarah ke errors kaunse hain?

    Syntax errors (parse hi nahi hua, kuch nahi chalega), runtime errors (chalte waqt fail), logic errors (chal jata hai lekin galat kaam — sabse mushkil, koi message nahi aata).

    try...catch kya hai? Khud throw kab karein?

    try block throw kare to catch chalta hai — error handled ho jata hai, app crash nahi hoti, recovery mumkin hai. Khud throw new Error("...") tab karein jab khamosh galat data (jaise NaN) return karna zyada khatarnak ho — Error message + call stack ke saath aata hai.

    Feature detection kya hai? Browser sniffing se kyun behtar?

    Feature use karne se pehle test karna: if ("geolocation" in navigator) { ... }. Sniffing browser ke naam/version par andaza lagata hai (nazuk, galat ho sakta hai); detection asal capability check karta hai.

    Promise kya hai? Uski teen states? resolve do baar call ho to?

    Promise future ki value ka object hai. States: pending → fulfilled (value) ya rejected (reason). Ek baar settle hone ke baad state nahi badalti — dusri resolve/reject calls ignore ho jati hain.

    .then(success, failure) vs .then(success).catch(failure) — farak?

    Do-argument wala form success ke APNE andar throw hui errors NAHI pakadta (failure sirf original promise ki rejection ke liye hai). .catch() chain ki har error pakadta hai — hamesha wahi prefer karo.

    Promise.all vs allSettled vs any vs race — kab kaunsa?

    all: sab chahiye, ek fail = sab fail. allSettled: sab chalao, har ek ki report chahiye. any: pehli safalta hi kaafi hai. race: pehla settlement — classic use timeout: Promise.race([fetch(url), delay(5000).then(() => { throw new Error("timeout"); })]).

    Promise.resolve().then(() => console.log(2)); console.log(1); — pehle 1 kyun?

    .then() callbacks microtasks hain — wo current synchronous code ke BAAD chalte hain, chahe promise pehle se resolved ho. Isiliye pehle 1 (sync), phir 2 (microtask).

    Event loop kya hai? Macrotasks vs microtasks?

    Call stack khaali hone par event loop queues se kaam uthata hai. Microtasks (promise callbacks) poori ki poori pehle khaali hoti hain; phir ek macrotask (timer, event) chalta hai; phir dobara microtasks. Isi order ki wajah se async code ka output predict hota hai.

    JS single-threaded hai — to Web Workers kya hain, aur wo kya nahi kar sakte?

    Workers asal background threads hain — bhaari computation wahan chalao taaki UI freeze na ho. Wo DOM/window/document ko chhoo NAHI sakte, main thread se sirf messages (postMessage) se baat karte hain, aur data copy (structured clone) hokar jata hai, share nahi.

    Closure kya hai? Ek asal use do.

    Function + uske banne ki jagah ka lexical environment. Function bahari scope ke variables ko scope khatm hone ke baad bhi yaad rakhta hai. Asal uses: private state (counter factory), memoization, callbacks jinhe aas-paas ka data chahiye. Loop me var wala bug (sab handlers 11) closure + shared binding ki hi kahani hai — fix let hai.

    Prototype chain kya hai? __proto__ vs .prototype me farak?

    Har object apne prototype se juda hota hai; property lookup chain par chadhta hai Object.prototype tak (jiska prototype null hai). __proto__ kisi object ka prototype link hai; .prototype sirf functions ki property hai jo unke instances ka prototype banti hai. Methods prototype par rakho — saare instances share karte hain, memory bachti hai.

    class asal me kya hai? JS class-based hai ya prototype-based?

    Prototype-based. class constructor function + prototype par methods + wired inheritance chain ki saaf syntax (sugar) hai. Isiliye class methods prototype par rehte hain aur instanceof chain walk karta hai.

    super() this se pehle kyun lazmi hai?

    Derived class ka this parent constructor ke chalane se banta hai — super() se pehle this exist hi nahi karta, use karne par ReferenceError aata hai.

    Private fields (#) _convention aur closures se kaise alag hain?

    #field hard privacy hai — class body ke bahar se bilkul inaccessible, subclasses se bhi nahi, keys/JSON me nahi dikhta. _name sirf ek samjhota (convention) hai — koi bhi padh sakta hai. Closures se privacy milti hai lekin per-instance functions ki cost ke saath aur class syntax se bahar.

    Map vs plain object — kab kaunsa? Array dedupe kaise karein?

    Keys non-string/unknown hon, size ya guaranteed insertion order chahiye → Map. Fixed shape, string keys → object. Dedupe: [...new Set(arr)].

    WeakMap kis liye hai? Use iterate kyun nahi kar sakte?

    Objects par aisi data chipkane ke liye jo object ke marne par saath mar jaye (private data, caches) — memory leak nahi hota. Iterate isiliye nahi kar sakte kyunki keys kab collect hongi ye GC tay karta hai — iteration liveness ko observable bana degi, jo GC ko invisible rehna chahiye is siddhant ke khilaf hai.

    Generator (function* / yield) kya hai? Array ki jagah kyun?

    Generator ruk aur resume ho sakne wala function hai — har next() agle yield tak chalta hai. Kaam: lazy/infinite sequences (Fibonacci, bade ranges) bina poori array banaye, aur apne objects ko iterable banana.

    Iterator vs iterable me farak?

    Iterable ke paas [Symbol.iterator]() hai jo iterator deta hai (Array, String, Map, Set...). Iterator ke paas next() hai jo {value, done} deta hai. for...of, spread, destructuring iterables khaate hain.

    Proxy kya hai? Teen traps aur ek asal use batao.

    Proxy object ke fundamental operations ko intercept karta hai. Traps: get, set, has, deleteProperty, apply... Asal uses: validation (set me galat value reject), defaults (get me fallback), logging. Reflect default behaviour ko trap ke andar saaf tareeke se forward karne ke liye hai.

    Strict mode kya hai? Modules strict hote hain kya?

    JS ka restricted variant jo khamosh galtiyon ko errors banata hai: undeclared variable ko assign karna ReferenceError, non-writable property par assignment TypeError, with aur octal literals SyntaxError, plain calls me this undefined. Haan — saare modules aur class bodies by default strict hote hain.

    ?. (optional chaining) && chaining se kaise alag hai? Isse assign kar sakte hain?

    ?. sirf null/undefined par short-circuit hota hai; && har falsy (0, "", false) ko missing manta hai. Assign NAHI kar sakte — obj?.x = 1 SyntaxError hai.

    ?? vs || — 0 aur "" ki misaal ke saath?

    0 || 10 → 10 (galat — 0 asal value thi), 0 ?? 10 → 0 (sahi). "" || "Guest" → "Guest", "" ?? "Guest" → "". ?? sirf null/undefined par default deta hai. Aur a || b ?? c bina parentheses ke SyntaxError hai.

    Destructuring: rename + default ek line me? Swap bina temp ke? Parentheses kyun?

    const { name: userName = "Guest" } = user; Swap: [a, b] = [b, a]; Bina declaration wale assignment me ({a, b} = obj) parentheses lazmi hain — warna { block samjha jayega.

    Spread vs rest — aur kya {...obj} deep copy hai?

    Ek hi ... token: rest jama karta hai (params/destructuring me), spread phailata hai (calls/array/object literals me). {...obj} SHALLOW copy hai — nested objects share hote hain; deep copy ke liye structuredClone().

    localStorage vs sessionStorage vs IndexedDB vs cookies?

    localStorage: strings, ~5–10MB, persist, synchronous. sessionStorage: wahi API, tab band = saaf. IndexedDB: asal async browser database — badi structured data ke liye sahi choice. Cookies: chhoti, har request ke saath jati hain — auth/session ke liye, app data ke liye nahi. Secrets localStorage me kabhi nahi (XSS padh sakta hai).

    Canvas vs SVG — kab kaunsa? Drawn circle par click handler kyun nahi lag sakta?

    SVG DOM-based vector hai — icons/charts ke liye, CSS se style hota hai. Canvas pixel-based hai, har frame redraw — games/particles ke liye. Canvas ke andar DOM nodes hote hi nahi, isiliye drawn shapes par handlers nahi lag sakte; hit-testing haath se karni padti hai.

    Browsers sound ke saath autoplay kyun block karte hain? play() kya return karta hai?

    User ko bina chahe awaaz se bachane ke liye. play() ek Promise return karta hai — block hone par wahi reject hota hai; isiliye use handle karna chahiye, ya pehle mute karke user gesture ka intezaar karna chahiye.

    Greedy vs lazy quantifiers — /<.*?>/ kya match karta hai jo /<.*>/ nahi?

    Quantifiers by default greedy hain — /<.*>/ "<b>hi</b>" ko poora kha jayega. Lazy /<.*?>/ sabse chhota match deta hai — sirf "<b>".

    Mera global regex ek baar chala, phir null kyun aaya?

    g/y flag wala regex stateful hota hai — exec/test lastIndex se resume karte hain. Fix: lastIndex = 0 reset karo ya har baar naya regex banao.

    try...catch...finally — finally kab chalta hai? finally return kare to?

    finally hamesha chalta hai — try ke return/throw par bhi. Aur finally ke andar ka return try/catch ke return ko override kar deta hai — ye jaal yaad rakho.

    throw new Error("x") vs throw "x" — farak?

    Error object ke paas name, message aur stack hota hai — debugging ke liye zaroori. String phenkne par ye sab gayab; hamesha Error (ya uski subclass) phenko.

    ES modules CommonJS se kaise alag hain? Live bindings kya hain?

    ESM static structure (imports pehle se analysable — tree-shaking mumkin), browser me async loading, aur live bindings: imported naam exporter ki value ka read-only live view hai — exporter badle to importer ko nayi value dikhti hai. CommonJS values copy karke deta hai aur synchronously load hota hai.

    Modules file:// par kyun nahi chalte? Bare specifier kya hai?

    Module scripts CORS ke under hain — file:// origin nahi deta, isiliye HTTP server lazmi hai. Bare specifier ("lodash" jaisa bina path wala naam) browser khud resolve nahi kar sakta — import map chahiye; browser me hamesha ./lib.js jaisa pura path extension ke saath likho.

    Date legacy kyun hai? Temporal kya theek karta hai?

    Date mutable hai, string parsing ke formats standard nahi hain (Date.parse har engine me alag behave kar sakta hai), fixed time zones support nahi hain, mahine 0-indexed jaise jaal hain. Temporal immutable types deta hai (Instant, ZonedDateTime, PlainDate...), nanosecond precision, asal time-zone/calendar support, aur DST par sahi arithmetic.

    PlainDate vs ZonedDateTime — kab kaunsa?

    Jo tareekh har jagah wahi rehni hai (birthday, hotel dates) → PlainDate. Jo pal duniya bhar me ek hai aur local roop zone ke hisaab se chahiye → ZonedDateTime. DST wala farak: Nov 3, 2024 ko 00:00 + 12h — ZDT 11:00 AM deta hai (asal duration), PlainDateTime 12:00 PM (wall-clock).

    ArrayBuffer vs typed array vs DataView — kab kaunsa?

    ArrayBuffer khaali memory hai — seedha padh/likh nahi sakte. Typed array ek type ke hisaab se view hai (native byte order). DataView jab endianness control, mixed types, ya unaligned access chahiye. Typed arrays ki length fixed hoti hai — isiliye push/pop/splice nahi hain.

    using vs try...finally — do resources par kya toot-ta hai?

    Do resources ke liye nested try...finally chahiye; dusra acquire fail ho to pehla leak, pehle ka release fail ho to dusra leak. using dono ko scope-exit par reverse order me apne aap dispose karta hai, aur body + cleanup dono fail hon to errors SuppressedError me jud jati hain (error = baad wali, suppressed = pehle wali).

    typeof null === "object" kyun hai? null kaise test karein?

    Language ke shuruaati implementation ki galti jo compatibility ke liye reh gayi. Test hamesha value === null se karo. Aur null (object ki jaanboojh kar अनुपस्थिति, prototype chain ka end) vs undefined (value ki अनुपस्थिति — missing property, uninitialized variable) ka farak yaad rakho.

    Safe integer range kya hai? MAX_SAFE_INTEGER + 1 === + 2 kyun true hai?

    ±(2^53 − 1). Usse aage doubles har integer ko alag represent nahi kar sakte — +1 aur +2 dono 9007199254740992 par round ho jate hain, isiliye equal. Bade integers ke liye BigInt hai — lekin BigInt ko Number ke saath arithmetic me milana TypeError deta hai.

    NaN khud ke barabar kyun nahi? Test kaise karein?

    IEEE 754 ka niyam hai — NaN ill-defined operations ka result hai aur har comparison me false deta hai, khud ke saath bhi. Test: Number.isNaN(x) (global isNaN pehle coercion karta hai, isiliye woh kam bharosemand hai). Object.is(NaN, NaN) bhi true deta hai.

    == vs === vs Object.is vs SameValueZero — chaaro ka farak?

    == coercion ke saath compare. === bina coercion; NaN kabhi equal nahi, +0/-0 equal. Object.is === jaisa lekin NaN ko equal aur +0/-0 ko alag manta hai. SameValueZero === jaisa lekin NaN ko equal manta hai (+0/-0 equal) — yahi includes() aur Map/Set keys use karte hain, isiliye [NaN].includes(NaN) true hai lekin [NaN].indexOf(NaN) -1 hai.

    Mark-and-sweep vs reference counting — cycles refcounting me kyun leak hote hain?

    Reference counting me object tabhi free hota hai jab uske references zero hon — circular references (x.a = y; y.a = x) ek dusre ko hamesha 1+ par rakhte hain, function khatm hone ke baad bhi. Mark-and-sweep roots (global) se reachability dekhta hai — cycle unreachable ho to poora collect ho jata hai. Saare modern engines mark-and-sweep (ke sudhare hue roop) use karte hain.

    postMessage: copy vs transfer vs share — kab kaunsa?

    Copy (structured clone) default hai — data independent, lekin bade data par cost. Transfer ownership move karta hai — source detached ho jata hai (ArrayBuffer ka byteLength 0), bade buffers ke liye best. Share sirf SharedArrayBuffer se — ek hi memory, lekin cross-origin isolation chahiye (Spectre ki wajah se) aur races se bachne ke liye Atomics.

    Data race kya hai? i[0] += 1 atomic kyun nahi?

    += teen kadam hai — read, add, write. Do agents beech me interleave ho jayein to ek increment gayab ho jata hai (10M + 10M hamesha 20M se kam). Atomics.add() poora read-modify-write ek atomic block me karta hai — result hamesha sahi.

    Atomics.wait main thread par kyun nahi chal sakta?

    wait() thread ko block karke sula deta hai — main thread so gaya to page ke saare jobs (rendering, input) ruk jayenge, isiliye web par ye main thread par throw karta hai. Main thread ke liye Atomics.waitAsync() hai — promise deta hai, thread free rehta hai.

    Mutex vs semaphore vs spinlock — kab kaunsa?

    Mutex: ek waqt me ek agent critical section me. Semaphore: N agents tak (permits). Spinlock: busy-wait wala lock — bahut kam contention aur bahut chhote waits ke liye, lekin main thread par kabhi nahi (page freeze ho jayegi). Deadlock se bachav: fixed lock order aur try...finally me release.

    Intl: locale kaise chunein? navigator.languages andhe bankar kyun nahi?

    Site ki apni bhasha prefer karo (language switcher, Accept-Language, html lang) — browser preference site ki uplabdh bhashao se match na kare to ajeeb mixture banta hai (English text ke saath Japanese dates). Formatter object ek baar bana kar reuse karo — toLocaleString() har call database dobara dhoondta hai. Aur Intl output ko kabhi hardcoded string se compare mat karo — engines ke beech badal sakta hai.

    Object.keys vs getOwnPropertyNames vs Reflect.ownKeys vs for...in?

    Object.keys: sirf own enumerable string keys. getOwnPropertyNames: own saari string keys (non-enumerable samet). Reflect.ownKeys: own saari — strings + symbols, enumerable + non-enumerable. for...in: enumerable string keys, inherited samet. Isiliye spread/Object.assign sirf own enumerable copy karte hain.
